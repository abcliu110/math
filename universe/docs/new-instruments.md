# 新器材设计：培育数学思维的 22 种器材

> 状态：**设计稿，未实现**。写于 2026-11-11。
> 读者：接手的 agent 和开发者。读完应该知道：为什么要加这批器材、每种器材学生怎么用、怎么写成器材包、怎么判分、怎么验收、先做哪个。
> 依据：`essences.md`（十二种本质）、`design-v2.md`（器材合同、证据等级）、`direction.md`（统一内核、多个工作台）、`expert-review.md`，以及 2026-11-11 对 `main` 的盘点（第 1 节）。
> 说明：文中的教学判断来自公认的教具和教法，**没有经过真实学生验证**；知识点只写名称，编号在实现时对照 `js/core/curriculum.js` 填。

## 1. 为什么要加：现有器材的盘点

2026-11-11 在浏览器里实测（147 种器材，其中 35 种是工作区内部的步骤，不上架；301 道题）：

| 现象 | 数据 | 说明 |
|---|---|---|
| 题目只用了很少几种器材 | 「数字」167 题、「运算器」139 题、「读数」61 题、「比较」46 题 | 多数题是“放几个数、接一个运算、看结果”，练的是计算流程 |
| 证明类器材没有题 | 猜想板、参数扫描器、反例构造器、不变量追踪器、证明脚手架、归纳阶梯：都是 0 题 | 器材做了，没有用上 |
| 工作台没有题 | 式子工作台 0 题，十格阵 0 题 | 同上 |
| 所有题的证据等级都是 ① | `coverage.md` 的“最高证据”一列全是 1 | “看见不等于证明”这条主线没有落地 |
| 图形类 39 种，大半是同一件事 | 菱形、梯形、筝形等十几种都是可拖的多边形 | 学生的动作相同，引发的思考也相同 |
| 分数只有一种器材 | 分数条，1 题 | 分数是小学最难的概念之一 |
| “调参数、读结果”的器材多 | 三角形的角、圆、正多边形、长方体、取整…… | `essence.md` 自己把它们叫“能算的演示” |

结论：缺的不是数量，是**让学生预测、比较、找规律、说理由**的器材。

## 2. 准入标准（每种新器材都要过）

| # | 标准 | 怎么检查 |
|---|---|---|
| S1 | **先猜后看**：结果出来之前，学生先给出自己的判断 | 器材有“猜”的输入；没猜之前结果不显示（见 3.1） |
| S2 | **能做错**：错的做法有看得见的后果 | 设计里写出至少两种错法和各自的后果 |
| S3 | **两种表示联动**：形和式、表和图、实验和计算 | 设计里写出是哪两种，改一处另一处跟着变 |
| S4 | **入门容易，可以挖深**：低年级能玩，高年级能问“为什么” | 首批题目里至少一道低年级题、一道要求证据 ③ 或 ④ 的题 |
| S5 | **对得上本质**：能回答 `essences.md` 的三个问题（揭露哪种本质、怎样碰到、怎样判断碰到了） | 每种器材的“判据”一行 |

过不了 S1 和 S2 的，只是演示，不进主线。

## 3. 公共约定和要新增的公共机制

### 3.1 器材包怎么写（沿用现有合同）

- 每种器材一个包：`packs/<id>.js`，`U.registerPack({ id, version, needs, types })`；在 `index.html` 和 `tools/gen-manifest.js` 登记（见 `next-steps.md` 1.3 的清单）。
- 必填：`workspaceRole`、`handles`、`essence`、`label`、`prefix`、`group`（必须是 `U.GROUPS` 之一）、`grades`、`alias`、`props`、`outputs`（每个写 `kind` 和 `dim`）、`icon`、`size`、`draw`，以及 `compute` 或 `init / step / read`（有状态）。
- lint 要求可写属性 ≥ 3；不够的在 `lint: { minProps, why }` 里写理由。
- 需要自己的操作界面的器材，写 `inspector: 'workbench'` 和 `wbUI: '<名字>'`，在 `U.WB_UIS` 里登记名字，画法写在 `js/ui/wb-kit.js`。**界面只按 `wbUI` 找画法，不按器材名判断。**
- 题目用 `workbench` 字段进入对应工作台；新工作台的名字要加进 `U.WORKBENCHES`。
- 学生的每个操作都走 `UI.Intent.run`（一步、可撤销），不直接改实体。
- 精确优先：能用有理数就用有理数；用到近似值的输出标 `approx`，相关结论的证据最高到 ②。

### 3.2 先猜后看（新机制：`guess`）

现在的 `predict` 是题目级的（开题时问一次）。新器材需要**器材级**的“每一轮都先猜”：

- 器材声明 `guess: { port: '<输出口>', label: '先猜' }`。声明了的输出口，在学生填猜测之前显示成“？”，连出去的线上也没有值。
- 学生填了猜测，输出才揭开；器材多一个输出 `hit`（猜对了没有，`bool`）和 `gap`（差多少，`num`，可选）。
- **猜错不扣分**，只记事件 `guess { right, gap }`（`design-v2.md` 0.2 第 4 条：猜错被罚会让孩子不敢猜）。
- 实现位置：`js/core/world.js` 求值时按声明遮住输出；`js/ui/stage-readout.js` 画“？”和猜测框。
- 这个机制也用到现有器材上：几何工作区的面积、角度、图形分类读数，做题时默认遮住（题目写 `reveal: 'guess'`）。

### 3.3 规则库（新模块：`js/core/rulelib.js`）

猜规则台、总是 / 有时 / 从不、找错台都需要“一条可以判定的说法”。统一成一个结构：

```js
U.RuleLib.add({
  id: 'num.mod3-1', domain: 'num',              // num | tri | quad | frac | expr | seq
  say: '除以 3 余 1 的数',                        // 给学生看的话（揭晓时用）
  test: (x) => Q.eq(Q.mod(x, Q(3)), Q(1)),       // 精确判定
  space: { kind: 'int', lo: 1, hi: 100 },        // 例子从哪里取（系统造反例时也用）
  level: 2,                                      // 难度 1–4
  near: ['num.mod3-2', 'num.odd'],               // 容易混的规则（学生的猜测像它时，系统拿它们来区分）
});
```

- `proof.js` 里的 `RULE_NAMES`、`conjecture.js` 里的 `LAWS` 迁进来，旧器材改成读规则库。
- 图形域的 `test` 用 `U.Shapes.describe` 和 `figure.js` 的精确判定（全是有理数比较）。
- 学生自己写的规则用现有的小解析器（`conjecture.js` 的 `parse`），加上“是偶数 / 是质数 / 除以 m 余 r / 大于 / 小于”几个谓词。

### 3.4 对手（新模块：`js/core/game.js`）

取石子、汉诺塔这类器材要一个会下的对手：

- `U.Game.define({ id, start(props), moves(state), apply(state, move), over(state), winner(state) })`；
- `U.Game.best(game, state)`：小状态空间直接穷举（带记忆），返回最好的走法和“这个局面是必胜还是必败”；
- 难度：`0` 随机走、`1` 偶尔走错（留给学生赢的机会）、`2` 总走最好的。**默认是 1**，学生找到策略后才建议调到 2 检验。

### 3.5 证据事件

沿用 `U.Evidence.emit`。新增三种 kind（`js/core/evidence.js` 的 `levelOf` 要认）：

| kind | 数据 | 等级 |
|---|---|---|
| `strategy` | `{ wins, against: 2 }`：对最强的对手连赢 3 局 | ②（策略没被打破） |
| `exhaust` | `{ states, checked }`：`checked === states` | ③（局面全查过） |
| `explain` | `{ steps, filled, order: true }`：证明排序排对且每步选对依据 | ④ |

### 3.6 每种器材的写法（下面各节统一用这个格式）

**一句话** · **定位**（本质、年级、分组、界面）· **学生怎么用** · **能做错什么** · **声明**（属性、状态、输出）· **复用** · **判分和证据** · **首批题目** · **验收** · **工作量**（小：1 个包加 3 道题；中：还要一个 `wbUI`；大：还要新的内核模块）

## 4. 第一梯队：最值得做的三种

### 4.1 猜规则台（`guessrule`）

**一句话**：系统藏着一条规则，学生自己造例子去问“这个算不算”，猜出规则；然后角色互换。

**定位**：E9（规律、猜想与证明）、E8；1–9 年级；分组「关系」；`wbUI: 'guessrule'`，工作台 `guess`。

**学生怎么用**
1. 开局系统给两个例子：一个“算”，一个“不算”。
2. 学生造一个例子（数：输入一个数；图形：在几何工作区里画或拖一个图形），**先猜**它算不算，再提交，系统回答是或否。例子进两栏：“算”“不算”。
3. 学生觉得知道了，写出猜想（从谓词里选，或者自己写式子）。
4. 系统在规则的取值范围里找一个**能区分两者的例子**（学生的规则说算、真规则说不算，或反过来）。找到就摆出来：“你的规则说它算，可它不算。”找不到（在范围内两条规则一致）才揭晓。
5. 揭晓后显示：用了几个例子、其中几个是“有信息量的”（当时两种答案都有可能）。
6. 互换：学生从规则库选一条或自己写一条，系统来猜（系统按“每次排除一半候选”的策略出例子），学生回答是或否。答错了系统会指出矛盾。

**能做错什么**
- 只造“算”的例子（确认偏差）：系统提示“你还没有试过一个你认为不算的例子”，并在总结里标出来。
- 猜想太宽或太窄：系统拿出反例。
- 互换时自己答错：系统指出“你说 7 算、10 不算，可按你的规则 10 也算”。

**声明**
```js
props: { domain: choice['数','三角形','四边形','分数'], level: int 1–4, rule: text（学生出题时自己写）, role: choice['我来猜','我出题'] }
state: { ruleId, yes: [], no: [], guesses: [], revealed: false }
outputs: { tried: num（试了几个例子）, informative: num（有信息量的例子数）, solved: bool, lv: num（证据等级）}
guess: { port: 'answer' }   // 每个例子先猜
```

**复用**：规则库（3.3）；`conjecture.js` 的解析器；几何工作区（图形域的例子就是工作区里选中的图形，`U.Shapes.describe` 判定）；`proof.js` 反例构造器的搜索。

**判分和证据**：按性质判，不按步骤——`solved`、`informative ≥ 3`、至少有一个“不算”的例子是学生自己造的。学生的猜想在整个取值范围里和真规则一致：数域范围有限时记 `enumerate`（③）；图形域只能记 `scan`（②）。

**首批题目**
1. 二年级「找规律」：规则“双数”。里程碑：造出一个不算的例子；猜对。
2. 五年级「因数与倍数」：规则“除以 3 余 1”。陷阱：猜成“单数”——系统拿 4 反驳。
3. 七年级「三角形」：规则“有两条边相等”。延伸：学生出题，系统猜。

**验收**：`tests/ui-guessrule.js`（真实鼠标）：三道题的参考解通过；只造正例时出现提示；错的猜想被反例推翻；互换时系统在 7 个例子内猜出规则库里的任一条 2 级规则。

**工作量**：大（规则库是新模块）。规则库做完后，4.2、5.1 都能用。

### 4.2 找错台（`findbug`）

**一句话**：给一份完整的解题过程，其中一步是错的，学生找出是哪一步、说明违反了哪条规则，再改对。

**定位**：E4（平衡与等价）、E9；3–9 年级；分组「关系」；`wbUI: 'findbug'`，工作台 `findbug`。

**学生怎么用**
1. 屏幕上是一份分步的解答（3–7 步），每一步是一个式子或一句话。
2. **先猜**：这份解答对不对？（有的题整份是对的——不能让学生养成“一定有错”的预设。）
3. 学生点他认为错的那一步。点错了：系统把这一步重新算给他看（“这一步两边都减 5，等式还成立”），这一步打上绿勾，不扣分。
4. 点对了：从四个选项里选“它违反了什么”（选项来自规则的名字，如“移项要变号”“分母不能直接相加”“两边要乘同一个数”）。
5. 把这一步改对（在式子工作台里重做这一步），后面的步骤跟着重算。

**能做错什么**：点错步（看到这一步为什么是对的）；选错理由（系统用一个具体的数代进去，显示两边不等）；改了以后还是错（同样代数检验）。

**声明**
```js
props: { caseId: choice（错例库里的一条）, shown: bool（显示每步的依据）, mine: text（学生自己编的错例，进阶） }
state: { picked: null | 步号, reason: null | 规则 id, fixed: bool, wrongPicks: [] }
outputs: { found: bool, reasonOk: bool, fixed: bool, tries: num }
```

**错例库**（`js/core/buglib.js`）：每条 `{ id, grade, steps: [{ form, rule }], bugAt, bugRule, wrong, note }`。`steps` 用形式层（`js/core/form.js`）表示，`rule` 是 `rules-exec.js` 里的规则 id。**错的那一步由系统验证确实不成立**（`U.applyRule` 的不变量检查失败），对的步骤验证确实成立——lint 保证错例库本身没有错。首批 30 条，取自现有 107 道陷阱题的 `traps[].wrong`。

**复用**：形式层和可执行规则（任务 F、G，已完成）；式子工作台（改正那一步）；陷阱题。

**判分和证据**：`found`、`reasonOk`、`fixed` 各一个里程碑。不产生证据等级。

**首批题目**
1. 四年级「运算律」：25 × (4 + 8) = 25 × 4 + 8。
2. 五年级「异分母分数加法」：1/2 + 1/3 = 2/5。
3. 七年级「解一元一次方程」：3x + 5 = 20 → 3x = 25。
4. 一份完全正确的解答（学生要敢说“没有错”）。

**验收**：`tests/ui-findbug.js`；错例库 lint（每条的错步确实错、其余步确实对）进 `tests/run.js`。

**工作量**：中（内核现成，主要是界面和错例库）。**成本最低的一种。**

### 4.3 改规则的世界（`whatif`）

**一句话**：改掉一条习以为常的规则，看数学变成什么样。

**定位**：E5（不变量与变换）、E9；5–9 年级；分组「图形」和「数与运算」各一种；做成三个器材，共用一个包 `packs/whatif.js`。

**(a) 球面三角形（`sphere-tri`）**
- 学生在一个可以转动的球上点三个点，系统用大圆弧连成三角形，读出三个角和内角和。
- **先猜**：内角和是多少？然后把三角形拉大，看内角和从略大于 180° 一直涨到 540°。能做出三个直角的三角形（北极加赤道上相隔 90° 的两点）。
- 两种表示：球面上的图，和旁边“内角和 − 180°”与“三角形面积占球面的比例”两条读数（它们成正比，高年级题）。
- 精确性：一般位置是浮点，输出标 `approx`，证据最高到 ②；预设的几个位置（八分之一球面）给精确值。
- 首批题目：八年级「三角形内角和」的延伸——“内角和一定是 180° 吗？”；“做一个有三个直角的三角形”。

**(b) 出租车几何（`taxi`）**
- 格点城市，只能横着竖着走。距离 = 横向格数 + 纵向格数。
- 学生标出“到中心距离是 4 的所有路口”，**先猜**它们围成什么形状——结果是一个斜放的正方形。
- 再问：这个“圆”的周长除以直径是多少？（4，全是整数，精确。）到两点距离相等的点在哪里？（有时是一条折线，有时是一片区域。）
- 全部是整数运算，证据可以到 ③（路口有限，全部列出）。
- 首批题目：六年级「圆」的延伸；八年级「线段的垂直平分线」的延伸。

**(c) 换一种运算（`newop`）**
- 给一张运算表（如钟面加法、取较大数、a ★ b = a + b − 1、连接两个数字），学生填表、读表。
- 系统问：交换律还成立吗？结合律呢？有没有“什么都不改变的数”（单位元）？每个数都有“抵消它的数”吗？学生**先猜**，再找例子或反例；表是有限的，系统可以全部检查（③）。
- 和「同余钟」联动：钟面乘法里，哪些数没有倒数？（和格数有公因数的。）
- 首批题目：四年级「运算律」——“减法有交换律吗？找一个反例”；七年级「有理数」延伸。

**能做错什么**：猜“内角和总是 180°”“圆总是圆的”“运算都能交换”——反例立刻出现，结论改写成“在平面上 / 在这种距离下 / 对这种运算”。

**复用**：`modclock`；系统枚举器；几何工作区的格点吸附（出租车）。球面要新写投影和大圆弧（约 150 行，独立，不进内核）。

**判分和证据**：反例记 `counterexample`；出租车和运算表的全查记 `enumerate`（③）。

**验收**：`tests/ui-whatif.js`：三个直角的球面三角形内角和显示 270°；出租车“圆”上的路口数等于 4r；运算表的四条性质和穷举结果一致。

**工作量**：出租车 小；换一种运算 小；球面 中。

## 5. 第二梯队：七种

### 5.1 总是、有时、从不（`asn`）

**一句话**：判断一句话是“总是对”“有时对”还是“从不对”，并拿出相应的证据。

**定位**：E9、E8；3–9 年级；分组「关系」；`wbUI: 'asn'`。

**学生怎么用**
1. 给一句话，如“两个奇数的和是偶数”“周长越大面积越大”“一个数乘以另一个数，结果比原来大”。
2. **先猜**：总是、有时、从不。
3. 按选的答案交证据，要求不同：
   - 选“有时”：交一个成立的例子**和**一个不成立的例子；
   - 选“从不”：系统在范围里扫，找到成立的例子就推翻；
   - 选“总是”：系统先扫（找到反例就推翻）；扫不到，只算 ②，界面写“在 1 到 100 里没找到例外”。要到 ③ 或 ④，得接「系统枚举器」「证明排序」或「归纳阶梯」。
4. 结论的措辞跟着证据等级走（`design-v2.md` 2.7）。

**能做错什么**：把“有时”当成“总是”（最常见）——反例出现；交的两个例子其实都成立——系统指出“这两个都是成立的，还缺一个不成立的”。

**声明**
```js
props: { claim: choice（规则库里 kind 为 claim 的说法）, custom: text, answer: choice['还没选','总是','有时','从不'], exYes: text, exNo: text }
outputs: { right: bool, lv: num, refuted: bool, counter: num }
```

**复用**：规则库（3.3）；参数扫描器、反例构造器的搜索；证据等级。图形类的说法（“周长越大面积越大”）的例子取自几何工作区里的两个图形。

**判分和证据**：`right`；“有时”要求两个例子各自经系统验证；“总是”的等级由接了什么证明器材决定。

**首批题目**：三年级「乘法」——“乘出来的数比原来大”（× 0、× 1 是反例；六年级再加 × 1/2）；五年级「多边形面积」——“周长相等的长方形面积也相等”；七年级——“n² ≥ n”（整数时总是，分数时有时）。

**验收**：`tests/ui-asn.js`；20 条说法的标准答案和穷举结果一致（内核测试）。

**工作量**：小（规则库做完之后）。

### 5.2 最优化沙盘（`optimize`）

**一句话**：在一个限制下，把某个量调到最大或最小；先试，再猜，再说明为什么。

**定位**：E5、E10（对称）、E12（建模）；4–9 年级；分组「图形」；直接在几何工作区里做，器材只管限制和记录。

三个场景，一个器材（`scene` 属性切换）：

| 场景 | 限制 | 目标 | 答案和理由 |
|---|---|---|---|
| 围篱笆 | 周长固定 20（用「锁长」的推广：周长锁） | 长方形面积最大 | 正方形；长和宽相差 2d 时面积少 d² |
| 靠墙围 | 三边共 20，一边靠墙 | 面积最大 | 10 × 5；和“对称补成整圈”联系 |
| 将军饮马 | A、B 在河同侧，到河边取水 | 路程最短 | 把 B 翻到河对岸，连直线 |

**学生怎么用**
1. **先猜**答案（围篱笆：长是几？将军饮马：取水点在哪？在河上点一下）。
2. 拖动（长方形的一个顶点 / 取水点 P），器材实时记下每次试的（参数，目标值），画成散点——图形和“参数—目标值”图像联动（S3）。
3. 学生在散点图上看到最高点，报告答案。
4. “为什么”：围篱笆用代数（接式子工作台：(5 + d)(5 − d) = 25 − d²）；将军饮马用工作区的「翻转」工具把 B 翻过去，折线变直线。

**能做错什么**：猜“越扁越大”或“取水点在正中间”——自己拖出来的散点会反驳。

**声明**
```js
props: { scene: choice, total: int（周长或三边和）, grid: bool（只取整数）, showCurve: bool }
state: { trials: [{ x, y }] }
outputs: { best: num（试过的最好值）, at: num, n: num（试了几次）, hit: bool（达到真正的最值）}
guess: { port: 'best' }
```

**复用**：几何工作区、约束锁（`gcon`，要加“周长固定”一种约束）、翻转工具、散点图器材、式子工作台。

**判分和证据**：`hit`；`n ≥ 5`（真的试过）；整数格点上试遍全部情况记 `enumerate`（③）；用翻转完成将军饮马的构造记 `proof`（④）。

**首批题目**：三年级「周长」——周长 20 的长方形有哪些？哪个面积最大？八年级「轴对称」——将军饮马；九年级「二次函数」——靠墙围，把散点接成抛物线，读顶点。

**验收**：`tests/ui-optimize.js`：周长 20 时面积读数全是精确值，最大 25；将军饮马的最短路程等于 A 到 B′ 的距离（精确，可能带根号，用 `U.Real`）。

**工作量**：中（要加周长约束）。

### 5.3 海龟作图（`turtle`）

**一句话**：用“前进、转弯、重复”的指令让小海龟画图。

**定位**：E6（递推与迭代）、E8、E5；3–9 年级；分组「图形」；`wbUI: 'turtle'`，工作台 `turtle`。也是“学生当作者”最自然的入口。

**学生怎么用**
1. 指令是积木块（不打字）：`前进 n`、`左转 a°`、`右转 a°`、`重复 k 次 [...]`，高年级加 `变量` 和 `自己定义的指令`。
2. **先猜**：这段指令画出什么？（四选一的小图）然后运行，海龟一步一步走（接世界时钟，可以暂停、单步）。
3. 反过来：给一个图（正三角形、五角星、螺旋），学生写指令画出来。画完和目标图比（用 `U.Geo` 的全等判定，精确）。

**能做错什么**：画正三角形时转 60°（内角）而不是 120°（外角）——图形不闭合，海龟没回到起点，缺口看得见。这是这个器材最有价值的一个错。

**数学上碰到什么**：外角和是 360°（重复 k 次、每次转 360/k）；五角星转 144°，共转了两圈；变量（边长 n）；相似（把所有 `前进` 乘 2）。

**声明**
```js
props: { program: text（积木的 JSON）, speed: int, target: choice（目标图，可空）, grid: bool }
state: { x, y, heading, path: [], pc }
outputs: { fig: fig（画出的折线，可以放进几何工作区）, closed: bool, turned: num（一共转了多少度）, len: num（走了多远）, match: bool }
```
角度限定为 15° 的倍数时，坐标用 `U.Real`（a + b√c）精确；其他角度标 `approx`。

**复用**：世界时钟；`fig` 值类型（输出能进几何工作区，量面积、量角）；`macro.js`（自己定义的指令）。

**判分和证据**：`match`、`closed`、`turned`；“任意正 n 边形都转 360°”——学生把 k 做成变量并通过 3–12 的全部检验记 `scan`（②）。

**首批题目**：三年级「角」——画正方形；四年级——画正三角形（陷阱：转 60°）；七年级「多边形的外角和」——写一个画任意正 n 边形的指令；延伸：五角星为什么转了 720°。

**验收**：`tests/ui-turtle.js`：正方形程序 `closed` 且 `turned = 360`；转 60° 的三角形 `closed = false`；输出的 `fig` 放进工作区后面积读数正确。

**工作量**：大（积木编辑界面是新的）。

### 5.4 逼近器（`approach`）

**一句话**：一步一步靠近一个到不了的数，看差距怎样变小。

**定位**：E7（极限与逼近）——现有器材里这一块几乎是空白；5–9 年级；分组「时间与变化」。

四个场景（`scene` 属性）：

| 场景 | 每一步 | 两种表示 | 逼近什么 |
|---|---|---|---|
| 取一半 | 剩下的再取一半：1/2 + 1/4 + 1/8 + … | 一条长为 1 的线段被涂色；分数的和 | 1（差是 1/2ⁿ，精确） |
| 割圆 | 圆内接正多边形边数翻倍：6、12、24、48…… | 圆里的多边形；周长除以直径的值 | π（值是近似，标 ≈；同时给外切多边形的上界，夹在中间） |
| 0.999… | 多写一个 9 | 数轴放大镜（每步放大 10 倍）；1 − 0.99…9 = 1/10ⁿ | 1 |
| 逼近根号 2 | 二分：1.4² 小了，1.5² 大了…… | 数轴上的区间；正方形面积和 2 的差 | √2（区间端点是精确的有理数） |

**学生怎么用**
1. **先猜**：一直做下去，会不会到？会不会超过？
2. 点“下一步”（接时钟可以自动走），看图和数一起变。旁边一栏是“还差多少”，每步缩小的倍数看得见。
3. 系统问：“你说一个很小的数，我告诉你要走几步差距就比它小。”学生说 1/1000，系统答 10 步——极限的定义，用游戏的方式碰到。

**能做错什么**：猜“永远差一点，所以 0.999… 比 1 小”——让学生找一个夹在 0.999… 和 1 之间的数，找不到。猜“割圆最后会超过 π”——外切多边形的值始终在上面。

**声明**
```js
props: { scene: choice, step: int（走到第几步）, eps: text（学生说的“很小的数”）, both: bool（同时显示上界）}
state: { n }
outputs: { value: num | real, gap: num, lower: num, upper: num, stepsFor: num（差距小于 eps 要几步）}
guess: { port: 'value' }
```

**复用**：时钟；`seq`；`U.Real`；数轴器材。

**判分和证据**：`step ≥ 6`；学生答对 `stepsFor`；“取一半的和等于 1”可以接「归纳阶梯」到 ④（差恰好是 1/2ⁿ）。割圆只到 ②（近似）。

**首批题目**：五年级「分数加法」——1/2 + 1/4 + 1/8 + … 加到第 8 项是多少？一直加会超过 1 吗？六年级「圆的周长」——割圆；七年级「有理数与无理数」——0.999… 和 1；八年级「平方根」——二分逼近 √2。

**验收**：`tests/ui-approach.js`；内核测试：取一半第 n 步的差精确等于 1/2ⁿ；割圆的下界 < 3.14159 < 上界，边数翻倍后区间缩小。

**工作量**：中。

### 5.5 证明排序（`proofsort`）

**一句话**：把打乱的证明步骤排成正确的顺序，每一步选它的依据。

**定位**：E9；5–9 年级；分组「关系」；`wbUI: 'proofsort'`。比现有的「证明脚手架」（填空）门槛低，放在它前面。

**学生怎么用**
1. 屏幕左边是结论和已知条件，右边是 4–7 张打乱的步骤卡，其中 1–2 张是**多余的或错误的**干扰卡。
2. 学生把卡拖成一列。每放一张，选“依据”：已知条件、上面的第几步、或一条已学的规律（下拉）。
3. 系统检查：每一步用到的事实，是否都在它上面出现过（依赖图的拓扑序）；依据选得对不对。
4. 配图联动：几何证明旁边有工作区里的图，点一步，图上相应的边和角亮起来（S3）。

**能做错什么**：顺序颠倒（用了还没证的结论——系统标出“这一步用到的‘∠1 = ∠2’还没有出现”）；选了干扰卡（循环论证的卡：用结论证结论）。

**声明**
```js
props: { proofId: choice（证明库的一条）, showFig: bool, distract: int（干扰卡几张）}
state: { order: [], reasons: {} }
outputs: { ok: bool, filled: num, steps: num, lv: num }
```
证明库（`js/core/prooflib.js`）：每条 `{ id, grade, given, claim, steps: [{ id, text, needs: [步或已知], rule }], distractors: [...] }`。lint 检查 `needs` 无环、每步可达。

**复用**：`U.Evidence`（`explain` 事件，3.5）；`deduce.js`（依赖检查）；几何工作区的高亮。

**判分和证据**：排对且依据全对，记 `explain`，等级 ④。

**首批题目**：五年级——“两个奇数的和是偶数”（2a + 1 + 2b + 1 = 2(a + b + 1)）；七年级——对顶角相等；八年级——等腰三角形两底角相等（作顶角平分线，全等）；八年级——平行四边形对角线互相平分。

**验收**：`tests/ui-proofsort.js`；证明库 lint 进 `tests/run.js`。

**工作量**：中。

### 5.6 两种解法对照（`twoways`）

**一句话**：同一道题的两种解法并排，找出它们每一步的对应关系。

**定位**：E12（建模）、E3、E4；3–9 年级；分组「关系」；不是新的器材类型，是一种**题目版式**加一个小器材「对应线」。体现 `direction.md` 第 2 节第 5 条“同一个量，从形、式、数几个角度看”。

**学生怎么用**
1. 屏幕分左右两栏，各是一个工作台（如左：线段图，右：式子工作台；或左：算术法的竖式，右：方程）。两边解的是同一道题。
2. 一边已经做完，另一边学生自己做；或者两边都做完，学生的任务是**连对应**：左边的这一段 / 这一步，对应右边的哪一项 / 哪一步。
3. 改一边的数（题目里的 20 改成 26），另一边跟着变（两边接同一个「数字」）。
4. 系统问：两种方法哪里一样、哪里不一样？（选择题，记为发现。）

**能做错什么**：连错对应——系统改一边的数，学生看到“你连的那一项没有跟着变”。

**声明**（器材「对应线」`match`）
```js
props: { pairs: text（学生连的对应，JSON）, expect: text（标准对应）}
outputs: { right: num（连对几对）, all: bool }
```
题目字段：`layout: 'split'`，`left: { workbench, build }`，`right: { workbench, build }`。

**复用**：全部现有工作台；来历追踪（判断“这一项是不是从那个数来的”——`W.from`）。需要 `UI.Stage` 支持同屏两个工作台（专注模式的分屏版）。

**首批题目**：三年级——鸡兔同笼：列表法和假设法；五年级——“和倍问题”：线段图和方程；七年级——方程组：代入消元和图像交点（直线器材）。

**验收**：`tests/ui-twoways.js`：改左边的数右边同步；对应连错有反馈。

**工作量**：大（分屏是界面层的新能力）。依赖 6.3 线段图。

### 5.7 质因数积木（`primeblocks`）

**一句话**：每个质数一种颜色的积木，一个数就是一摞积木。

**定位**：E2（分解与组合）；4–7 年级；分组「数与运算」。

**学生怎么用**
1. 输入一个数（如 60），**先猜**它由哪些质数乘起来，再看它变成积木：2、2、3、5。
2. 两摞并排（60 和 84）：共有的积木自动对齐——那就是最大公因数；两摞合起来、共有的只算一次——最小公倍数。
3. 反过来搭：给 2、2、3 三块，能搭出哪些数？（全部因数——每块用或不用。）学生**先猜**有几个因数。
4. 约分：分子分母两摞，把共有的积木成对拿掉。

**能做错什么**：把 1 当质数（没有这种积木）；把 9 当成一块（要拆成 3、3）；猜因数个数猜成“积木的块数”。

**声明**
```js
props: { a: int 2–9999, b: int（可空）, mode: choice['分解','公因数','搭因数','约分'], show: bool }
inputs: { a: num, b: num }
outputs: { gcd: num, lcm: num, count: num（因数个数）, prime: bool, blocks: set }
guess: { port: 'count' }
```

**复用**：`numtheory.js`（分解）；分数条（约分时联动）；系统枚举器（全部因数，③）。

**首批题目**：五年级「质数和合数」——把 36 拆到不能再拆；五年级「最大公因数」——24 和 36；五年级「约分」——24/36；延伸：有 12 个因数的最小的数是几？

**验收**：内核测试：1–1000 的 gcd、lcm、因数个数和直接计算一致；`tests/ui-primeblocks.js`。

**工作量**：小。

## 6. 教具类：十二种

这一组多是公认有效的实物教具。搬到屏幕上时，每一种都要加上实物做不到的东西（精确的读数、自动找反例、和式子联动），否则不如用实物。

### 6.1 取石子、汉诺塔、一笔画（`games`，三个器材一个包）

**定位**：E6（递推）、E9、E5；2–9 年级；分组「关系」；`wbUI: 'game'`。

**(a) 取石子（`nim`）**
- 一堆 n 颗，两人轮流取 1 到 k 颗，取到最后一颗的赢。学生和系统对弈。
- **先猜**：先手赢还是后手赢？
- 旁边一张“局面表”：从 0 颗开始，每个数标“必胜”还是“必败”，学生自己填（S3：对局和表联动）。填对到 n，策略就出来了：留给对方 (k + 1) 的倍数。
- 能做错：凭感觉下，输给难度 2 的系统；表填错——系统用那个局面和他下一局，让他输一次。
- 声明：`props: { n: int 5–30, k: int 2–5, first: choice['我先','电脑先'], level: int 0–2, last: choice['取到最后的赢','取到最后的输'] }`；`outputs: { won: bool, streak: num, tableOk: num（表填对到几）, lv: num }`。
- 证据：对难度 2 连赢 3 局记 `strategy`（②）；表填对到 n 记 `exhaust`（③）；写出“留 (k + 1) 的倍数”并通过「归纳阶梯」到 ④。
- 题目：二年级——10 颗，每次取 1 或 2（「有余数的除法」）；五年级——改规则后策略怎么变。

**(b) 汉诺塔（`hanoi`）**
- 3 根柱子，n 个盘。**先猜**最少几步。系统记步数；学生填表 n = 1、2、3、4 的最少步数，找递推（T(n) = 2T(n − 1) + 1）和通项（2ⁿ − 1）。
- 能做错：多走了（系统显示“最少 7 步，你用了 11 步”）；猜成 2n。
- 声明：`props: { n: int 1–7, pegs: int 3, showMin: bool }`；`outputs: { moves: num, min: num, done: bool, optimal: bool }`；`guess: { port: 'min' }`。
- 证据：n ≤ 4 时局面可以全部搜索（③）；递推用「归纳阶梯」到 ④。
- 题目：四年级「找规律」；七年级「乘方」——64 个盘要多少步。

**(c) 一笔画（`euler`）**
- 给一张图（点和边），学生一笔画完每条边、不重复。**先猜**能不能画成。
- 画不成的图，学生试几次后系统问：数一数每个点连着几条边。奇数条的点有几个？
- 学生自己加边、删边，把画不成的图改成画得成的（七桥问题）。
- 声明：`props: { graph: choice（图库）, edit: bool }`；`state: { path: [] }`；`outputs: { done: bool, odd: num（奇点个数）, possible: bool }`；`guess: { port: 'possible' }`。
- 复用：`graph` 值类型；系统穷举小图的全部走法（③）。
- 题目：二年级——“日”字能不能一笔画；六年级——七桥问题，加一座桥让它能走通。

**验收**：`tests/ui-games.js`；内核测试：`U.Game.best` 对取石子的判断和 n mod (k + 1) 一致；汉诺塔最少步数是 2ⁿ − 1；一笔画的 `possible` 和“奇点是 0 个或 2 个且连通”一致。

**工作量**：大（对手模块 3.4 是新的）；三个器材共用。

### 6.2 代数砖（`tiles`）

**一句话**：x²、x、1 三种砖，拼成长方形就是因式分解。

**定位**：E2、E8、E3；6–9 年级；分组「关系」；放进几何工作区的块（`workspaceRole: 'piece'`），工作台 `geometry`。

**学生怎么用**
1. 砖有三种：x × x 的大方块、x × 1 的长条、1 × 1 的小方块（负的用另一种颜色）。x 的长度可以拖（S4：x 是“任意一个”，拖到任何长度拼法都成立）。
2. 给式子 x² + 5x + 6，取出 1 块大的、5 条、6 个小的。**先猜**：能拼成一个长方形吗？长和宽是多少？
3. 拼。拼成了，长和宽就是 (x + 2)(x + 3)。旁边的式子工作台同步写出面积 = 长 × 宽（S3）。
4. 反过来：给 (x + 1)(x + 4) 的长方形框，数出里面有几块什么砖——就是展开。
5. 完全平方：x² + 6x + ? ，补几个小方块能成正方形——配方法。

**能做错什么**：x² + 5x + 5 拼不成长方形（缺一块或多一块，看得见）——“有的式子分解不了”；把 x 拖到恰好等于 2 时，长条和两个小方块一样长，学生可能误以为 x = 2 才成立，再拖一下就看到拼法不变。

**声明**
```js
// 砖是 piece 器材 tile，kind: 0 | 1 | 2（x²、x、1），sign: ±1
// 管理器材 tiles：
props: { expr: text（要拼的式子）, x: num（x 现在多长，拖动改）, neg: bool（用不用负砖）}
outputs: { area: expr（现在这些砖的面积之和）, rect: bool（是否拼成了长方形）, w: expr, h: expr, match: bool（面积等于要拼的式子）}
guess: { port: 'rect' }
```

**复用**：几何工作区的块（拖、转、吸附、拼合 `geo.merge`、`U.Geo.assemble` 判断拼成长方形）；`poly`（多元多项式）和式子工作台；面积读数。

**判分和证据**：`rect && match`；x 取 3 个以上不同的长度拼法都成立，再由 `poly` 验证 (x + 2)(x + 3) 展开恒等于原式——记 `proof`（④，代数恒等是精确判定）。

**首批题目**：七年级「整式的乘法」——(x + 1)(x + 4) 里有几块什么砖；八年级「因式分解」——x² + 5x + 6；九年级「配方法」——x² + 6x 补成正方形；陷阱：x² + 5x + 5。

**验收**：`tests/ui-tiles.js`：拼成后 `w`、`h` 是 x + 2、x + 3；拖动 x 后仍 `rect`；x² + 5x + 5 任何拼法 `rect = false`。

**工作量**：中（块和拼合现成，要加“边长是式子”的块）。

### 6.3 线段图和双数轴（`barmodel`）

**一句话**：把应用题画成几条线段，再列式。

**定位**：E12（建模）、E3、E1；1–7 年级；分组「数与运算」；`wbUI: 'bar'`，工作台 `bar`。应用题是小学最大的难点之一，现有器材里没有任何建模工具。

**学生怎么用**
1. 题面在上面。学生拖出线段（条），给每条起名（“哥哥”“弟弟”），把已知的数标在线段上，未知的标“？”。
2. 线段可以对齐、等分（“弟弟的 3 倍”：把哥哥的条分成 3 段，每段和弟弟一样长）、加括号（“一共 48”）。
3. 画完，学生**先猜**答案大概是多少（S1，估算），再列式。式子的每个数必须从图上点出来（来历追踪）。
4. 双数轴模式（比例、百分数、速度）：上下两条数轴，对应的刻度对齐（3 千克 ↔ 12 元，1 千克 ↔ ？）。

**能做错什么**：“比弟弟多 5”画成 5 倍；倍数关系画反——系统不直接说错，而是按学生的图算一遍，把结果放回题面：“按你的图，哥哥 12 岁，弟弟 60 岁。”（S2）

**声明**
```js
props: { story: text, bars: text（JSON：每条的名字、段、标注）, mode: choice['线段图','双数轴'], unit: text }
outputs: { model: eqn（图表示的等量关系）, answer: num, consistent: bool（图和题面的数不矛盾）}
guess: { port: 'answer' }
```
图到等量关系的转换是确定的：等长的段是同一个未知数，括号是和。`model` 是方程值类型（`eqn.js`），可以直接接方程台（S3）。

**复用**：`eqn`、方程台、解方程天平；来历追踪；`ratio.js`。

**判分和证据**：按性质——`model` 和题目的标准关系等价（方程等价是精确判定），不要求图画得和参考解一样。

**首批题目**：二年级——“小明有 8 个，小红比他多 5 个”；三年级「倍的认识」——和倍、差倍问题；六年级「百分数」——双数轴：打八折后 60 元，原价多少；六年级「比例」——3 千克 12 元，5 千克多少元。

**验收**：`tests/ui-barmodel.js`；内核测试：10 种典型结构（和、差、倍、和倍、差倍、部分与整体……）的图转成的方程解出标准答案。

**工作量**：大（新工作台）。**对小学阶段覆盖面最大的一种。**

### 6.4 分数面积模型和数轴上的分数（`fracarea`）

**一句话**：一个长方形横着切、竖着切，看分数乘法到底在做什么；同一个分数再放到数轴上。

**定位**：E3（度量与单位）、E2；3–6 年级；分组「分数」（现在这一组只有分数条）。

**学生怎么用**
1. 单位正方形。竖着切成 b 份、涂 a 份，是 a/b。
2. 乘法 2/3 × 4/5：先竖着涂 4/5，再横着取其中的 2/3，重叠的部分就是积。**先猜**：积比 4/5 大还是小？（“乘法越乘越大”是最顽固的误解之一。）
3. 加法 1/2 + 1/3：两个正方形切法不同，加不起来；把两个都再切（通分），小格一样大了，才能数。
4. 数轴模式：同一个分数显示成数轴上的一个点。5/4 超过 1——“分数不一定比 1 小”。等值分数落在同一个点。
5. 除法 3/4 ÷ 1/8：3/4 里能量出几个 1/8（包含除）。

**能做错什么**：1/2 + 1/3 直接数成 2/5——系统把两个图叠在一起，格子对不上；猜“乘出来更大”——涂出来的重叠部分明显更小。

**声明**
```js
props: { a: text（分数）, b: text, op: choice['一个分数','乘','加','除','比大小'], view: choice['面积','数轴','都要'], cut: int（再切几份，通分用）}
inputs: { a: num, b: num }
outputs: { result: num, cells: num（重叠了几格）, total: num（一共几格）, bigger: bool }
guess: { port: 'result' }
```

**复用**：分数条；数轴；精确有理数。

**判分和证据**：`result` 精确；`cut` 用对（通分）；“两个真分数相乘，积比两个都小”可以接 5.1 做成总是 / 有时 / 从不。

**首批题目**：三年级「分数的初步认识」——把 3/4 放到数轴上；五年级「分数加减」——1/2 + 1/3；六年级「分数乘法」——2/3 × 4/5，先猜大小；六年级「分数除法」——3/4 里有几个 1/8。

**验收**：`tests/ui-fracarea.js`；内核测试：分母 2–12 的全部乘、加结果与 `Q` 一致。

**工作量**：小到中。

### 6.5 函数机和四联动（`fmachine`）

**一句话**：喂一个数、吐一个数的机器，猜它的规则；同一个函数的表格、图像、式子、情境四种样子连在一起。

**定位**：E1（对应）、E8、E12；3–9 年级；分组「函数」。

**学生怎么用**
1. 猜规则模式：机器里藏着规则（× 2 + 1）。学生喂数，**先猜**吐出什么，再看。猜对连续三次后写出规则。（和 4.1 的区别：这里的规则是函数，例子是输入输出对。）
2. 两台机器串起来（复合）；倒着跑（已知输出求输入——反函数、解方程）。
3. 四联动：表格（输入输出对）、图像（点）、式子、情境（“每分钟注水 3 升，原来有 5 升”）。改任何一个，其余三个跟着变：拖图像上的直线，式子里的 k、b 变；改式子，表格重算。
4. 系统问：表格里“每多 1，多几”在图像上是什么？（斜率）“x = 0 时”在情境里是什么？（原来有的）

**能做错什么**：只喂 0 和 1 就下结论（× 2 + 1 和 x² + x + 1 在 0、1 处一样——系统喂 2 来区分）；把正比例和一次函数混了（b ≠ 0 时“翻倍”不成立）。

**声明**
```js
props: { rule: text（式子，可藏）, hidden: bool, view: choice['机器','四联动'], story: choice（情境库）, domain: choice['整数','分数'] }
inputs: { x: num, f: fn }
outputs: { y: num, f: fn, table: table, slope: num, solved: bool }
guess: { port: 'y' }
```

**复用**：`fn`、`table`、`expr`；直线、抛物线、散点图、代入器；规则库（3.3，`domain: 'fn'`）。

**判分和证据**：`solved`；学生的规则和真规则作为多项式恒等（精确）——是 ④ 级的判定，但学生得到它的过程是举例，证据标 ①，并提示“你试了 5 个数，都对；它们作为式子确实相等”。

**首批题目**：三年级「找规律」——机器 × 3；六年级「正比例」——哪台机器“输入翻倍，输出也翻倍”；八年级「一次函数」——四联动，水箱注水；九年级「二次函数」——只喂 0、1 被骗的那道。

**验收**：`tests/ui-fmachine.js`：四联动改任一个其余同步；内核测试：区分用的输入确实能区分 `near` 里的规则。

**工作量**：中。

### 6.6 勾股剪拼和圆面积切拼（`dissect`）

**一句话**：用剪和拼，把“面积相等”做成看得见的证明。

**定位**：E5（不变量）、E7；5–8 年级；分组「图形」；不是新器材类型，是几何工作区上的两套**预置题目**加一个切圆的器材。

**(a) 勾股定理**
- 直角三角形三边上各一个正方形。两个小正方形按给定的切法剪成 5 块，学生把它们拼进大正方形。拼满，没有缝、没有重叠（`U.Geo.assemble` 精确判定）。
- **先猜**：两个小正方形的面积加起来，和大的比，谁大？
- 拖动直角顶点改变三角形，切法跟着变，仍然拼得满（S4）。把直角改成钝角：拼不满——定理的条件看得见（S2）。
- 证据：一个三角形拼满是 ①（一个例子）；切法对任意直角三角形都成立，由系统用符号边长 a、b 验证各块的面积和——记 `proof`（④），并写明“这个切法对任意直角三角形都行，因为每一块的边长只用到 a 和 b”。

**(b) 圆面积**
- 器材 `circlecut`：把圆切成 n 个扇形（4、8、16、32……），交错拼成近似的平行四边形。n 越大越像长方形：底是半个周长 πr，高是 r。
- **先猜**：拼出来的图形面积和圆比，变了没有？底边是圆的什么？
- 接 5.4 逼近器：n 翻倍时“底边的弯曲程度”读数趋向 0。
- 声明：`props: { r: num, n: int（4–128，2 的幂）, spread: num（拼的进度 0–1）}`；`outputs: { base: real, height: num, area: real, wobble: num（标 ≈）}`。
- 证据：面积相等对每个 n 都精确成立（只是重排）；“变成长方形”是极限，写明是逼近（②）。

**复用**：几何工作区（剪、移动、旋转、拼合、对齐到目标）；`U.Real`（π）；现有的「剪拼平行四边形」是同一类。

**首批题目**：五年级「平行四边形、三角形、梯形的面积」——已有，补梯形；六年级「圆的面积」；八年级「勾股定理」——拼，再把角改成钝角。

**验收**：`tests/ui-dissect.js`：3-4-5、5-12-13 和一个非整数直角三角形都拼得满；钝角时拼不满。

**工作量**：勾股 中（切法要对任意 a、b 精确）；圆 中。

### 6.7 钉板（`geoboard`）

**一句话**：在格点上围多边形，数格点，自己发现面积公式。

**定位**：E9、E2；3–8 年级；分组「图形」；几何工作区的一种模式（顶点只能落在格点上——已有格点吸附，加一个“只许格点”的开关）。

**学生怎么用**
1. 围一个多边形。系统标出边上的格点数 B 和内部的格点数 I（可以隐藏面积，让学生自己用割补算）。
2. 学生把（B、I、面积）记进一张表（数据表器材）。攒够几行，找规律：面积 = I + B/2 − 1（皮克公式）。
3. 把猜出的公式写进「猜想与反例」，系统拿新的格点多边形去试（②）。
4. 低年级用法：围出面积是 4 的所有不同形状；围一个周长 12 的长方形。

**能做错什么**：公式猜成 I + B/2（差 1）——系统造一个反例；只试了长方形就下结论——系统给一个三角形。

**声明**：几何工作区加 `lattice: true`；新读数器材 `latticecount`：`inputs: { fig }`，`outputs: { B: num, I: num, area: num }`，`guess: { port: 'area' }`。

**复用**：几何工作区；`figure.js`（面积精确）；数据表；猜想与反例；规则库。

**判分和证据**：表里 ≥ 5 行且含非长方形；公式通过扫描（②）。皮克公式的证明超出范围，题目明说“这是一个定理，证明要到大学”。

**首批题目**：三年级「面积」——围出面积是 6 的三种形状；五年级——用割补算格点三角形的面积；八年级——发现皮克公式。

**验收**：内核测试：随机 200 个格点多边形，B、I 和面积满足皮克公式；`tests/ui-geoboard.js`。

**工作量**：小。

### 6.8 展开图和小方块搭建（`solidnet`）

**一句话**：先判断这个展开图能不能折成正方体，再折给你看；用小方块搭出符合三视图的立体。

**定位**：E5、E1；1–9 年级；分组「图形」。现有的「三视图」只能看，不能搭。

**(a) 展开图（`net`）**
- 6 个正方形连成的平面图（学生也可以自己拼）。**先猜**：能不能折成正方体？哪两个面相对？
- 点“折”，动画一步步折起来（简单的 3D 线框投影，不引入 3D 库）；折不成的会有两个面叠在一起，标红。
- 11 种能折成的展开图，学生去找——系统枚举全部 35 种六连方，学生逐个判断（③）。
- 声明：`props: { cells: text（格子坐标）, fold: num（折的进度）, marks: text（面上的记号）}`；`outputs: { foldable: bool, opposite: text, overlap: num }`；`guess: { port: 'foldable' }`。

**(b) 小方块搭建（`cubes`）**
- 在 4 × 4 的底板上点格子加方块、减方块。三个视图实时显示（S3）。
- 给三视图，搭出立体；**先猜**最少要几块、最多能有几块。
- 表面积和体积读数（先猜后看）：拿掉一个角上的方块，表面积变不变？
- 声明：`props: { heights: text（每格几层）, target: choice }`；`outputs: { front: fig, left: fig, top: fig, volume: num, surface: num, match: bool }`。

**复用**：`views.js`（三视图的投影）；长方体；系统枚举器。

**首批题目**：一年级「立体图形」——搭一个和图一样的；四年级「观察物体」——按三视图搭，最少几块；五年级「长方体和正方体」——哪些展开图能折成正方体；陷阱：“田”字加两格。

**验收**：内核测试：35 种六连方里 `foldable` 恰好 11 种；`tests/ui-solidnet.js`。

**工作量**：中（3D 线框投影和折叠动画）。

### 6.9 影子测高和缩放对比（`scale`）

**一句话**：边长乘 k，周长、面积、体积各乘几？用相似去量够不着的高度。

**定位**：E3、E12、E5；5–9 年级；分组「图形」。

**(a) 缩放对比**：几何工作区里选一个图形，点“放大 k 倍的副本”（已有等比放缩）。两个图形并排，学生**先猜**面积是原来的几倍，再看读数。把（k、周长比、面积比）记进表，找规律：k 和 k²。立体的（小方块搭的）再加体积 k³。把 k 改成 1/2、3/2 检验。
- 能做错：猜“面积也是 k 倍”——最常见的错，读数立刻反驳；用小方格把大图形铺满，数出来是 k² 个（④：铺满是结构性的理由）。

**(b) 影子测高（`shadow`）**：一根已知高度的杆和它的影子，一棵树和它的影子。学生拖动太阳（改变光线角度），两个影子一起变。量得到的：杆高、杆影、树影；量不到的：树高。**先猜**树高，再列比例。
- 两种表示：场景图，和从中抽出的两个相似三角形（叠在一起对比）。
- 声明：`props: { pole: num, tree: num（藏起来）, sun: num（角度，取使 tan 为有理数的几个值）, show: bool }`；`outputs: { poleShadow: num, treeShadow: num, ratio: num, height: num }`；`guess: { port: 'height' }`。

**复用**：等比放缩（2026-11 已做）；图形关系器材（相似判定）；比、比例；数据表。

**首批题目**：六年级「比例」——影子测高；六年级「图形的放大与缩小」——放大 2 倍面积是几倍；九年级「相似」——面积比等于相似比的平方。

**验收**：`tests/ui-scale2.js`：k = 2、3、3/2 时面积比读数精确等于 k²。

**工作量**：小。

### 6.10 树状图和概率面积模型（`ptree`）

**一句话**：把“两步试验”画出来数，和实验的结果对照。

**定位**：E11（随机与分布）、E2、E1；5–9 年级；分组「统计与概率」。

**学生怎么用**
1. 定义两步试验（掷两次硬币；从袋里摸两次，放回或不放回）。学生自己画树：第一步几个分支、每支的概率，第二步……
2. 每条路径的概率 = 沿途相乘；学生**先猜**某个事件（“至少一次正面”）的概率，再点出属于这个事件的路径，相加。
3. 面积模型：单位正方形，横边按第一步分、竖边按第二步分，每个小长方形的面积是一条路径的概率（和 6.4 分数面积模型是同一个图，S3）。
4. 接实验：同一个试验用硬币、摸球袋器材真的做 400 次，直方图和树算出来的概率对照（实验和计算两种表示）。

**能做错什么**：把“一正一反”当成一种结果（概率猜 1/3）——树上是两条路径，实验频率接近 1/2；不放回时第二步的概率没改——路径概率之和不是 1，系统标红。

**声明**
```js
props: { tree: text（JSON）, event: text（选中的路径）, view: choice['树','面积','都要'], replace: bool }
outputs: { p: num（事件的概率，精确分数）, total: num（所有路径之和，应为 1）, paths: num, dist: dist }
guess: { port: 'p' }
```

**复用**：`dist` 值类型（输出的分布可以直接接直方图，和骰子的实验分布比）；系统枚举器；硬币、摸球袋、骰子。

**判分和证据**：`total = 1`；`p` 精确；全部路径列出即穷举（③）。

**首批题目**：五年级「可能性」——掷两次硬币，一正一反的可能性；九年级「概率」——摸两次球，放回和不放回；延伸：三个骰子的和（接系统枚举器）。

**验收**：内核测试：路径概率之和恒为 1；`tests/ui-ptree.js`。

**工作量**：中。

### 6.11 估算器（`estimate`）

**一句话**：先估再算，看差多少。

**定位**：E3、E7；1–9 年级；分组「数与运算」。可以接在任何计算前面，是 3.2「先猜后看」的独立器材版。

**学生怎么用**
1. 接一个会算出结果的器材（运算器、面积读数……）。结果被遮住。
2. 学生给估计值——可以给一个数，也可以给一个范围（“在 300 和 400 之间”）。
3. 揭开：显示实际值、差多少、差百分之几；范围估计显示“估中了，而且范围不大”或“估中了，但范围太宽”。
4. 累计看板：最近 10 次的误差是不是在变小（学生自己看得见进步）。
5. 另一种模式“数量级”：一步台阶有多高？教室能装多少个篮球？答案是区间，重在估的过程（分步估：长、宽、高各估一次）。

**能做错什么**：没有“错”，只有准不准。估得离谱（差 10 倍以上）时系统问“你是怎么估的”，引到“先把数凑整”。

**声明**
```js
props: { lo: text, hi: text（范围）, mode: choice['一个数','一个范围','数量级'], unit: text }
inputs: { actual: num }
state: { history: [] }
outputs: { gap: num, pct: num, inRange: bool, trend: num }
```

**复用**：取整；读数；事件流（`guess` 事件）。

**判分和证据**：不判对错；里程碑是“估了、看了、误差在 20% 以内”。

**首批题目**：三年级「估算」——29 × 31 大约是多少；五年级「小数乘法」——4.8 × 0.52 比 4.8 大还是小；六年级——估圆的面积（比外面的正方形小、比里面的正方形大）。

**验收**：`tests/ui-estimate.js`。

**工作量**：小（做完 3.2 以后几乎不用写代码）。

### 6.12 尺规作图（`compass`）

**一句话**：只给直尺和圆规，作出垂直平分线、角平分线。

**定位**：E9、E10（对称）、E5；7–9 年级；分组「图形」；几何工作区的一种工具配置（`tools` 白名单只留：直尺连线、圆规画圆、取交点）。

**学生怎么用**
1. 题目给已知图形和要求（“作线段 AB 的垂直平分线”）。工具只有三个。
2. 圆规：点圆心，再点一个点定半径（半径可以“保持不变”带到另一个圆心——等长的传递）。圆和圆、圆和线的交点可以点出来成为新的点。
3. 作完，**拖动已知的点**（A 或 B）：真正的作图跟着变还成立；“凑出来的”（凭眼睛放的点）会散掉——这是这个器材最关键的检验（S2）。
4. 系统问：为什么这条线上的点到 A、B 一样远？（接 5.5 证明排序。）

**能做错什么**：凭眼睛画（拖动后不成立）；两个圆半径不等（交点不在垂直平分线上）。

**声明**：新步骤器材 `gcircle2`（圆心加圆上一点）、`gmeet`（两个对象的交点，`which` 选第几个）；工作区声明 `tools: ['seg', 'circle', 'meet']`。
交点一般带根号：单层根号用 `U.Real` 精确（`next-steps.md` 9.4 已写明“还没做”，这里要补上）；更复杂的标 `approx`。

**复用**：几何工作区；规则 `geo.*`；依赖图（拖动后重算）；`U.Real`。

**判分和证据**：按性质——结果线过 AB 中点且垂直（精确判定），**并且在系统自动拖动 A、B 到 3 个新位置后仍然成立**。这样判的是“作法”而不是“碰巧”。作法成立记 `proof`（④，前提是全程精确）。

**首批题目**：七年级——作一条线段等于已知线段；八年级「轴对称」——垂直平分线、角平分线；八年级——过直线外一点作垂线；九年级「圆」——作三角形的外接圆。

**验收**：`tests/ui-compass.js`：标准作法通过；凭眼睛放的点在系统拖动后被判不成立。

**工作量**：大（圆和圆的精确交点是内核的缺口）。

## 9. 怎么验证这批器材真的在培育思维

测试通过只说明功能存在。按 `direction.md` 第 9 节和 `expert-review.md` 第 1 节，每种器材在宣布完成之前要有：

1. **一次真实使用者的录屏**：一个目标年级的孩子，不看说明，用 15 分钟。记录：是否完成、卡在哪里、说了什么。
2. **一个“说得出来”的问题**：结束后问“你发现了什么？”“为什么？”——器材设计里的“判据”一行就是标准答案的方向。
3. **一个迁移题**：换一个场景，不给器材，看孩子能不能认出同一个结构。例如玩过取石子（留 3 的倍数）之后，问“报数游戏，每次报 1 到 2 个数，报到 20 的赢，你想先报还是后报？”

器材的事件流里要留下这几项（实现时加进 `events.js`）：每次猜测和实际值（`guess`）、有信息量的例子占比（猜规则台）、第一次点对错步之前点了几步（找错台）、达到的证据等级。**这些是研究数据，不是分数。**

## 10. 不做什么

- 不做 3D 引擎（展开图、球面只用线框投影）；不引入第三方库。
- 不做计时竞速和排行榜；游戏类器材的对手默认会让一让。
- 不把“猜错”记进错题本，不扣分。
- 不为了数量把同一种操作做成多个器材（现有的十几种可编辑多边形就是教训）；能做成“一种器材加规则库 / 题库”的，不做成多种器材。
- 新器材不许绕过意图层和事务（`ui-robustness.md`）；不许在界面里按器材名判断。

## 11. 还没定的问题

1. **先猜后看遮住输出以后，下游的器材怎么办**：下游没有值，判分的 `when` 可能要等。建议：遮住只是界面的，内核里值照常流动，判分照常；需要用户确认。
2. **规则库里图形域的例子空间**：系统造反例时从哪里取图形？建议：限定在格点、坐标 ±6 以内的三角形和四边形，可以穷举。
3. **找错台的错例来源**：先用现有陷阱题；将来应当来自真实学生的错误（`expert-review.md` 第 1 节第 2 条）。
4. **线段图要不要允许“不规范”的图**：学生的画法千差万别。建议：第一版只支持“条、等分、括号、标注”四种元素，判分只看图表示的等量关系。
5. **分屏（两种解法对照）对窄屏的影响**：1288 像素宽的窗口放两个工作台很挤。可能要等布局层再改一轮。
6. **知识点编号**：本文只写了知识点的名称，实现每道题时对照 `js/core/curriculum.js` 填 `points`。
7. **内容审查**：每种器材的“为什么”和首批题目，上线前要有一位数学老师逐条看过，并留下记录（现在没有这个流程）。
