# 方向决策：统一的是内核，不是界面

> 状态：**提议，待用户确认**（第 8 节有一个必须由用户回答的问题）。
> 写于 2026-11-09，依据当时的 `main`（92 种器材、72 道题）和用户一路的反馈。
> 读者：接手的 agent 和开发者。读完应该知道：我们做的是什么、为什么这样做、哪些文档和代码要跟着变、怎么验证这个方向对不对。

---

## 1. 要回答的问题

产品一直是这样描述的：**一个统一的数学世界，所有东西都是“器材”，用“连线”连起来，值在线上流动**（`design-v2.md` 第 0.3 节）。

用户反复碰到的问题是：几何器材很难编辑、剪和拼不顺手、代数和算术怎么放进来、每个器材一张卡片太散……每次我们的回答都是“在统一的模型上再加一层视图或工作区”。这说明真正的问题不是某个功能，而是：

> **“一切都是器材加连线”的统一世界，到底是不是对的？还是该做几个各自极好用的专用工具，只共享内核？**

## 2. 决策

**两者都不原样成立。采用这一条：**

1. **统一的是内核**：精确的值、带不变量检查的变换规则、来历追踪与步骤历史、判分与证据等级、存档与分享。这一层保持唯一，所有工作台共用。
2. **界面做成多个专用工作台**：每一类数学活动有自己的、直接操作的工作台，手感各不相同，但共用一套交互语法（选中、工具、吸附、撤销、历史）。
3. **“器材加连线”的画布只是工作台之一**，叫“关系画布”（或“数据流画布”），用在“数据怎么流”类的问题上。它不再是所有人的首页。
4. **每道题打开时，直接进入它所属领域的工作台。**
5. **“统一”的价值用“跨工作台”体现**：同一个量，可以从形、式、数几个角度看。例如几何里剪拼得到的面积，接进式子工作台，写出 S = a × h。
6. **连线保留在“创作”阶段**：学生当作者、搭出没人写过的东西，靠的是组合，连线最适合。每个工作台提供“打开背后的连线”，让学生看见自己的步骤其实是一张图。

## 3. 为什么这样决定

### 3.1 题库统计（当前代码实测）

统计每道题**参考解**里学生要不要连线（参考解是我们自己写的，所以这既反映数学本身，也反映我们当初的设计选择）：

| 领域 | 题数 | 需要连线 |
|---|---|---|
| 数与运算 | 24 | 16 |
| 函数 | 7 | 4 |
| 统计与概率 | 5 | 4 |
| 建模 | 3 | 3 |
| 分数 | 2 | 2 |
| 图形与几何（工作区） | 2 | 2 |
| 时间与变化 | 6 | 1 |
| 图形 | 13 | **0** |
| 关系 | 9 | **0** |
| 代数 | 1 | 0 |
| **合计** | **72** | **32** |

- 72 题里只有 32 题需要连线。图形和关系两类，一根线也不用接，只改参数就能通关。
- 连线用得多的，是“数据怎么流”的问题：运算链、统计流程、函数复合、建模。

### 3.2 连线适合什么，不适合什么

| | 适合连线 | 不适合连线（要直接操作对象） |
|---|---|---|
| 活动 | 运算链、统计流程、函数复合、建模 | 几何的剪、拖、转、拼；代数的移项和合并；竖式的对齐、进位、拆数 |
| 学习价值在哪里 | “这个数从哪来”——连线本身就是内容 | 摆弄那个对象——接线是额外负担 |

### 3.3 我们已经在往这个方向走

几何“工作区”做的事，就是把卡片藏起来、改成在画面上直接操作；式子工作台也是。每一次都说成“在统一模型上加一层视图”，其实是承认：**不同领域需要不同的操作手感**。继续把它们都硬塞成卡片，只会让每个领域都难用。

### 3.4 用户的反馈模式

用户一路的反馈（器件难编辑、剪拼不顺手、图形放上去看不见、要能直接拖动改大小、要对齐线、双击依次选中……）都指向同一件事：**他们要的是摆弄图形本身，不是接线。**

## 4. 目标架构

```
┌────────────────────────────────────────────────────────────┐
│ 工作台（界面层，各自专用、直接操作）                            │
│  几何画板 │ 式子工作台 │ 数位/竖式工作台 │ 数据图表台 │ 关系画布  │
└──────────────┬─────────────────────────────────────────────┘
               │ 共用的交互语法：选中、工具、吸附、撤销、历史、命中测试栈、浮动工具条
┌──────────────▼─────────────────────────────────────────────┐
│ 内核（唯一）                                                  │
│  精确的值（有理数、根号、式子、图形、表格……）                     │
│  变换规则（匹配、应用、保持什么不变）                            │
│  世界：对象与依赖（今天的“器材和连线”，在这一层是内部实现）         │
│  来历追踪、步骤历史、判分与证据等级、存档与分享                   │
└────────────────────────────────────────────────────────────┘
```

要点：

1. **“器材和连线”降为内核内部的表示。** 每个工作台里的对象（点、线、式子、数位）背后仍然是世界里的实体和依赖，所以撤销、存档、判分、来历追踪都是现成的。只是学生不必看到卡片和端口。
2. **工作台 = 视图 + 工具集 + 历史面板。** 工作台声明：它显示哪些值（`shows`）、有哪些工具、怎么画、怎么命中、有哪些把手。这就是 `next-steps.md` 10.5.4 里的 `workspace` 声明，已经有雏形。
3. **共用的交互语法**由 `ui-robustness.md` 的 U 系列任务实现（意图层、事务、状态分层、布局引擎、坐标换算、命中测试栈）。每个新工作台不许另造一套。
4. **关系画布**保留现在的卡片和连线界面，用在数据流类的问题上，以及“创作”阶段。
5. **“打开背后的连线”**：任何工作台里，都可以展开看到“这些步骤构成的图”，让“过程可见”和“学生当作者”有落点。

### 5.3 保持不变的

- 内核全部（值、规则、追踪、判分、证据、存档）；
- 现有的 92 种器材和 72 道题（它们成为内核层的对象，或者留在关系画布里）；
- `next-steps.md` 里已经做完的任务 A–G；
- U 系列任务和 V 系列任务（它们正是在做共用的交互语法和几何工作台的好用程度）。

## 6. 不做什么（非目标）

- **不是推倒重来。** 内核和现有器材全部保留，改的是界面入口和叙述。
- **不是让每个工作台各自为政。** 共用的交互语法必须统一，否则学生每换一个工作台就要重新学。
- **不删除连线。** 它留在关系画布和创作阶段。
- **不一次做完所有工作台。** 先把几何工作台做到真正好用（它已经在做），再做式子工作台，再做数位工作台，数据图表台最后。

## 8. 必须由用户回答的问题

这个方向对不对，取决于产品的主要目标。设计文档里两种说法都有：

- **A. 学习产品**：让孩子理解 1–9 年级数学（“142 个知识点，每个点用最好的方法，由浅入深”）。
- **B. 创作环境**：让学生搭出没人写过的东西（“最终检验：学生当作者”）。

**我的建议是 A 为主、B 为进阶**：先用专用工作台让孩子学得顺，学会之后，再打开背后的连线，进入创作。这个决策就是按这个来写的。

## 9. 怎么验证这个方向是对的

我们没有真实孩子的使用数据；这个判断是从代码、题库和用户的反馈推出来的。要验证，需要一个很小的实验：

**“好用”的定义**：一个孩子（或老师），不看说明，在 15 分钟内，用某个界面完成一道几何题。

**做法**（几何题，因为几何工作台已经有了）：
1. 做出两个界面：**A. 关系画布**（器材卡片和连线，用现有的“三角形、剪刀、摆放、拼合”器材）；**B. 几何工作台**（现在的工作区）。
2. 找 5–8 个孩子（建议 5–6 年级，刚学过或正在学面积），每人用其中一个界面，做同一道题：“平行四边形沿高剪开，拼成长方形”。分组随机。
3. 录屏。记录：是否完成、用时、卡住的次数和位置、孩子说的话。
4. 结束后问两个问题：“你觉得自己做了什么？”“为什么拼成长方形面积不变？”——后一个才是学习证据。

**判断**：
- 如果 B 的完成率、用时明显好于 A，并且答得出“为什么面积不变”，方向成立；
- 如果差不多，说明几何工作台还没有做到位（先修 V 系列），或者连线对这个年龄段并不是障碍；
- 如果 A 更好，要认真重新考虑本文的结论。

这个实验也应当成为以后的验收方式：**每个工作台，在宣布“完成”之前，都要有一次真实使用者的录屏**，不能只靠测试。
