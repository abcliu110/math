# 器件设计：从“带参数的卡片”到“能动手的数学操作台”

> 状态：**设计稿，未实现**。写于 2026-11-14。
> 读者：项目负责人、接手的 agent 和开发者。读完应该知道：现在的器件为什么不好用、好器件的标准是什么、161 种器件各自怎么处理、目标是哪十一个操作台、器件合同要改什么、先做哪个、怎么知道做对了。
> 和其他文档的关系：`direction.md` 定了“统一内核、多个工作台”；`new-instruments.md` 定了新器材的五条准入标准（先猜后看、能做错、两种表示联动、低门槛高上限、对得上本质）并加了 22 种器材。本文不推翻它们，补的是它们没管的一件事：**学生的手怎么碰到数学**。
> 如实说明：本文的盘点数据是 2026-11-14 用脚本从 `main` 读出来的（第 1 节）。初稿曾写“卡片上没有任何点或拖的机制”，是错的：有“点一下设属性”的机制，约 25 种器件在用，已更正。器件的分类（第 3 节）是按器件声明和画法判断的，**我没有逐个上手用过全部器件，也没有任何学生试用的数据**。教学判断来自公认的教具，未经本项目验证。

---

## 0. 结论

1. **问题不在器件少，在交互方式。** 161 种上架器件里，只有几何工作区和 5 个工作台可以直接操作对象（拖、画、摆）；另有约 25 种在卡片上画了可点的按钮或区域（点一下改一个整数属性）；其余约 130 种只能在属性面板里填数，看卡片重画。除几何工作区外，没有一个器件能拖。学生多数时候在调参数，没有在做数学。
2. **题目没有跟上方向。** 432 道题里 423 道（98%）仍在关系画布上；251 道用到“数字、运算器、读数、比较”这四个管道件，其中 110 道只用它们。`direction.md` 说要多个工作台，题库还没有搬过去。
3. **建议：收敛成十一个操作台，每个做深。** 现有器件大部分并进操作台，成为它的一种预设或模式；连线退到幕后，成为进阶功能。
4. **建议：给器件合同加“直接操作”这一条。** 现在卡片上只有“点一下把某个属性设成某个整数”这一种机制（`data-pick-k`），没有拖动，也没有吸附。这是最底层的缺口。
5. **验证只有一个办法：让孩子用。** 先做一个样板操作台，找 3 到 5 个孩子试 15 分钟，再决定其余的怎么做。

读这张表得到三件事：

- 学生实际接触到的“数学实验室”，主要是“放数字、接运算器、看读数”。这是在搭计算流程。
- 最近加的器材（线段图、分数面积模型、钉板等）教学设计是好的，也在卡片上画了 ＋／− 这样的按钮，但动作仍然是“点按钮改一个数”：线段图有 10 个属性、函数机 12 个、取石子 18 个。想把一条线段拉长、把一刀切在某个位置，做不到。
- 器件越加越多，器材架越来越难找。图形一类就有 51 种，其中十几种只是“不同形状的可拖多边形”。

## 2. 好器件的六条标准

前五条是 `new-instruments.md` 的 S1–S5，照用。本文加第 0 条，并把它排在最前面，因为它决定了其余五条有没有机会发生。

| # | 标准 | 怎么检查 |
|---|---|---|
| **H0** | **直接操作**：学生的手碰的是数学对象本身，不是代表它的输入框。动作就是数学动作：拖一个点、切一刀、拿走一块、往盘子里加一个砝码 | 完成这个器件的核心任务，不需要打开属性面板 |
| S1 | 先猜后看 | 同 `new-instruments.md` |
| S2 | 能做错，错了有看得见的后果 | 同上 |
| S3 | 两种表示联动：动一处，另一处跟着变 | 同上 |
| S4 | 低门槛、高上限 | 同上 |
| S5 | 对得上十二种本质 | 同上 |

再加两条工程上的要求：

- **零说明上手**：不看文字，30 秒内能做出第一个有意义的动作。检查方法只能是看真人用。
- **少而通用**：一个操作台能覆盖多个年级的多个知识点。检查方法：它能承载的题目数。

### 现有器件按 H0 分成四档

| 档 | 含义 | 数量（约） | 例子 |
|---|---|---|---|
| 一 | 能直接操作对象 | 6 | 几何工作区、竖式工作台、数据图表台、式子工作台、排除表 |
| 二 | 教学设计好，卡片上有按钮可点，但不能拖、不能直接摆弄对象（少数连按钮也没有） | 约 30 | 线段图、分数面积模型、代数砖、钉板、质因数积木、函数机、解方程天平、剪拼、折纸、展开图、小方块搭建、树状图、海龟作图 |
| 三 | 调参数、读结果的演示（只能用属性面板） | 约 70 | 三角形的角、圆、长方体、正多边形、取整、百分数、比、抛物线顶点、圆周角 |
| 四 | 管道件：只在连线时有意义 | 约 55 | 数字、运算器、读数、比较、取列、代入器、分式运算、各种读数器 |

第二档是最值得投入的：设计已经有了，缺的是把“点按钮改数”换成“直接拖、直接切”。

## 3. 161 种器件的去向

处理方式只有四种：

- **做成操作台**：成为十一个操作台之一的主体。
- **并进操作台**：不再是独立器件，成为某个操作台的一种预设、模式或视图。题目里用“操作台 + 预设”表达。
- **留在关系画布**：管道件。关系画布是进阶功能，它们照旧。
- **做成活动**：游戏、证明、推理一类。它们不是工具，是有规则的任务，单独一类，不占器材架。

| 目标操作台 | 现有器件的去向 |
|---|---|
| **1 数轴** | 数轴（主体）；解集数轴、取整、估算器、逼近器并入，成为“区间”“取整”“估算”“逼近”几种模式 |
| **2 计数块与数位** | 竖式工作台两个（主体，合成一个）；筹码、十格阵、数位板、带余除法、质因数积木、数的性质并入 |
| **3 面积模型** | 点阵、长方形、分数面积模型、代数砖合成一个：同一块可切分的长方形，边可以是整数、分数或字母。整式运算、因式分解、乘方成为它的“式子视图” |
| **4 分数与比** | 分数条、线段图、比、百分数、缩放对比、影子测高、套餐对比。主体是“可以切、可以对齐比较的条”，加双数轴 |
| **5 天平与方程** | 天平、解方程天平、方程卡、变形、解、验根、方程组、方程台、方程组台、解方程、不等式、解集运算、造方程、变量盒。式子工作台作为它的“式子视图” |
| **6 坐标与函数** | 直线、抛物线、反比例、交点、抛物线的三个精确点、函数卡一组 5 种、函数机、扫描变量、取值表、数对、两辆车。主体是一张坐标格：表、图、式三联动，可以直接拖点、拖线 |
| **7 几何画布** | 几何工作区（主体）；全部 `g*` 步骤器件、12 种可编辑图形、三角形、四边形、圆、图形变换、量图形、图形关系、三角形的角、量角器、圆周角、绕点旋转、直线与圆、折纸、剪拼、剪拼平行四边形、钉板、尺规作图、正多边形、最优化沙盘 |
| **8 立体** | 长方体、展开图、小方块搭建、三视图合成一个：搭、展开、从三个方向看 |
| **9 数据与概率** | 数据图表台（主体）；数据表两种、取列、散点图、拟合器、预测器、统计量、复式统计表、直方图、骰子、硬币、摸球袋、树状图、系统枚举器、数列统计 |
| **10 变化与数列** | 数列、取第 n 项、迭代器、二阶递推、通项、时钟、记忆器、同余钟、海龟作图。主体是“一步一步走”的时间线，和坐标台联动 |
| **11 代数式** | 式子工作台（主体）；代数式卡、代数式读数、代入器、分式卡、分式运算、分式读数、开方、特殊角的三角函数 |
| **留在关系画布** | 数字、运算器、读数、比较、选择、真假运算、数列变换、符号数读数、符号点读数、面积读数，以及全部引脚 |
| **做成活动** | 猜想与反例、猜想板、参数扫描器、反例构造器、证明脚手架、证据检查、归纳阶梯、证明排序、总是有时从不、找错台、猜规则台、排除表、两种解法对照、取石子、汉诺塔、一笔画、换一种运算、出租车几何、球面三角形、三角形的世界、量杯倒水 |

说明：

- 这张表是初稿。每一行在动手之前都要有人把涉及的器件逐个打开用一遍，确认没有分错。
- “并入”不删除内核里的计算。器件的 `compute` 仍然是操作台背后的规则和构造，只是不再作为一张独立的卡片出现在器材架上。
- 20 种零使用的器件先不动，等对应操作台做的时候一起处理。

## 4. 十一个操作台：学生的手做什么

每个操作台写四项：手上的动作、联动的表示、错了看见什么、覆盖年级。

| 操作台 | 手上的动作 | 联动的表示 | 错了看见什么 | 年级 |
|---|---|---|---|---|
| 数轴 | 拖点；拉开一段；跳一步；放大某一段 | 点的位置 ↔ 数 ↔ 算式（跳了几步） | 跳过头、落不到整格上 | 1–9 |
| 计数块与数位 | 拿、放、十个捆成一捆、拆开一捆 | 块 ↔ 数位上的数字 ↔ 竖式 | 一位上超过九个块放不下；不够减拿不出来 | 1–5 |
| 面积模型 | 拖边改长宽；横切、竖切；把一块挪走 | 面积图 ↔ 乘法算式 ↔ 展开的式子 | 两种切法面积对不上 | 2–9 |
| 分数与比 | 切条；把两条对齐比长短；拉伸 | 条 ↔ 分数 ↔ 比 ↔ 百分数 | 两条对不齐；份数不整 | 3–7 |
| 天平与方程 | 往两边加、拿；两边同时做同一件事 | 天平 ↔ 方程 ↔ 数轴上的解 | 天平倾斜 | 1–9 |
| 坐标与函数 | 拖点；拖直线改斜率和截距；在表里填一个值 | 表 ↔ 图 ↔ 式 | 点不在线上；表里的值和图对不上 | 5–9 |
| 几何画布 | 拖顶点；画线（自动找中点、垂足、交点）；剪、拼、转、翻 | 图形 ↔ 度量 ↔ 名称 | 拼不上；量出来不相等 | 3–9 |
| 立体 | 搭方块；展开；转着看 | 立体 ↔ 展开图 ↔ 三视图 ↔ 体积 | 展开图折不回去；视图对不上 | 1–9 |
| 数据与概率 | 把数据点拖进图；改分组；摇、抽、掷 | 原始数据 ↔ 图 ↔ 统计量 | 平均数被一个极端值拉走；频率和猜的概率差很远 | 3–9 |
| 变化与数列 | 走一步；回退一步；改规则 | 步骤 ↔ 表 ↔ 图 | 按自己的规则走不到题目给的那一项 | 3–9 |
| 代数式 | 拖一项去合并；提公因式；代入一个数 | 式子 ↔ 面积模型 ↔ 代入后的值 | 变形前后代入同一个数，值不一样 | 6–9 |

### 操作台之间怎么连

不用学生接线，但内核里仍然是连线。三种方式，由浅到深：

1. **台内联动**：一个操作台里的几种表示本来就是同一个值的不同画法，天然联动。
2. **拖一个量过去**：把一个操作台上的量（一个数、一条线段的长、一个式子）拖到另一个操作台上，内核自动建一根线。学生看到的是“这个数跟过来了”，并且原来那边一改，这边跟着变。
3. **打开背后的接线**：进阶功能。一个按钮，显示当前台面背后的关系图。这就是现在的关系画布，定位从“主界面”变成“看原理、做创作”的地方。

## 5. 器件合同要改什么

现在的合同（`design-v2.md` 第 1 节、`new-instruments.md` 3.1）管的是：属性、输入输出、计算、画法。下面是要加的。

### 5.1 直接操作（新增，最重要）

器件声明它身上有哪些“可以动手的地方”，以及动了之后改什么：

```
handles: [
  { id: 'vertex', at: (c) => [...点的位置...], drag: (c, to) => ({ set: { ... } }) },   // 拖
  { id: 'cut',    zone: (c) => 区域,            tap:  (c, at) => ({ act: { ... } }) },   // 点
]
```

- 现有的 `data-pick-k`（点一下设一个整数属性）保留，它就是这套机制里“点”的最简单形式；新增的是拖动、吸附和非整数的值。
- 界面层只认这个声明，不认器件名（沿用 `ui-robustness.md` 的规则）。
- 每个动作仍然走 `UI.Intent.run`：一步、可撤销、进事件日志。
- 拖动时要吸附到有数学意义的位置（整格、等分点、已有的点），吸附规则由器件声明，做法同几何工作区的 `snap`。
- 现在几何工作区的拖顶点、画线、吸附是写在界面层里的专用代码。做第二个操作台时，把它提出来变成这套公共机制，不要再写一套。

验收：对每个操作台，核心任务全程不打开属性面板。

### 5.2 属性面板的定位

属性面板不取消，但只给两种人用：出题的人（设置题目的初始状态），和进阶的学生（想看全部参数）。做题时默认不需要它。

合同里现有的“可写属性 ≥ 3”这条 lint 要重新考虑：它是在鼓励器件多放参数，和 H0 的方向相反。建议改成：器件要么有至少一个 `handles`，要么在 lint 里写明它为什么只能调属性。

### 5.3 多表示

一个操作台声明它有哪些“视图”，每个视图是同一份状态的一种画法，并且每个视图上都可以动手：

```
views: { area: {...}, expr: {...}, table: {...} }
```

题目可以指定开哪几个视图、哪个视图先遮住（配合“先猜后看”）。

### 5.4 预设

被并入的器件变成操作台的预设：一份初始状态加一组打开的视图和工具。例如“梯形”是几何画布的一个预设，“解方程天平”是天平台的一个预设。器材架上列的是操作台，点开之后才是预设。

题目里现在写的 `shelf: ['ftrap', 'gcut']` 以后写成 `bench: 'geometry', preset: 'trapezoid', tools: ['cut']`。旧写法在迁移期间继续支持。

### 5.5 工具条的规则

从几何工作区这一轮得到的经验，定成所有操作台的规则：

- 一行，不超过 10 个按钮；次要的收进菜单。
- 工具不要求先选对象：有选中的就用它；只有一个对象就是它；有多个就等学生点一下。
- 能自动判断的不做成按钮（中点、垂足、交点并进了“连线”）。
- 每个工具有快捷键，写在提示里。

## 6. 题库怎么办

432 道题不能一次重写。分三类处理：

| 类 | 数量（约） | 处理 |
|---|---|---|
| 只用四个管道件的题 | 110 | 逐题看它想教什么，改到对应的操作台上。多数是算术和比较，去数轴、计数块、面积模型、天平 |
| 用了专用器件的题 | 约 300 | 器件并入操作台后，题目的数据改成“操作台 + 预设”。判分条件（`when`）大部分不用变，因为内核的值没变 |
| 活动类的题 | 约 20 | 不动 |

每做完一个操作台，搬它对应的题。搬完的题在 `coverage.md` 里标出来。

## 7. 路线

| 步 | 做什么 | 做完的标志 |
|---|---|---|
| 1 | 把直接操作的公共机制（5.1）从几何工作区里提出来 | 几何工作区改用公共机制，全部现有测试通过 |
| 2 | 做第一个样板操作台：**面积模型**。理由：现成的四种器件（点阵、长方形、分数面积模型、代数砖）可以直接合并；覆盖 2–9 年级；乘法、分配律、分数乘法、因式分解都用它 | 10 道题在样板上能做，全程不开属性面板 |
| 3 | **找 3 到 5 个孩子试**样板和几何画布，每人 15 分钟 | 有记录：谁在哪一步卡住、卡了多久、说了什么 |
| 4 | 按试用结果改合同和样板 | 第 3 步里卡住的地方，再试一次不卡 |
| 5 | 依次做天平与方程、数轴、分数与比。每做一个，搬它的题 | 每个台 20 道题以上 |
| 6 | 其余操作台；器材架改成列操作台；关系画布改成“打开背后的接线” | 关系画布上的题少于总数的 20% |

第 3 步不能跳过，也不能由 agent 代做。前面两步做错了，到这一步就能知道；跳过它，后面四步可能全在错的方向上。

## 8. 不做的事和风险

- **不删内核。** 值的种类、精确计算、判分、证据等级、事件日志都不变。变的是学生碰到它们的方式。
- **不一次重写。** 一个操作台一个操作台来，旧器件在迁移期间继续能用。
- **不再加新的独立器件。** 在样板验证之前，新想法都记到 `ideas.md`，以“某个操作台的预设”的形式写。
- 风险一：操作台做得太大，变成另一个难懂的东西。对策：每个台的工具条不超过 10 个按钮（5.5），核心动作不超过 4 种（第 4 节的表）。
- 风险二：合并之后，原来某个器件独有的教学点丢了。对策：并入之前逐个打开用一遍，把它独有的东西写成预设。
- 风险三：这份设计本身是错的。它来自对代码的盘点和公认的教具，没有来自孩子。对策就是路线的第 3 步。
- 多个会话同时改这个仓库。做第 1 步之前先和其他会话对齐，否则公共机制会被各写一套。

### 2026-11-15 补：拖的时候就看见“两边一起动”

用户反馈：天平和方程组没有把“两边同加同减”在操作当中表现出来；鸡兔同笼也偏弱。改动：

- **通用机制**：把手拖动中，界面把“拖的是哪个把手、鼠标在哪、按下时的属性”交给器材（`c.drag = { grip, x, y, p0 }`），器材可以画出这一下会带来什么。界面仍然不认器材名。
- **天平与方程**：新增“两边一起动”（属性 `sync`，默认开）。拖走一个砝码，另一个盘里的一个对称地跟着走，盘下面各写“− 1”，式子写成 `x + 6 − 1 = 10 − 1`；从托盘往一个盘里加，另一个盘也加。另一个盘里没有同样的东西时只能拿这一边，天平会歪。关掉就是原来的“只动一边”。步骤栏在每一步后面写做了什么（两边−1、两边÷2、只动一边）。
- **两架天平**：盘里的东西可以一个一个拖出来（另一个盘跟着少），托盘往天平上拖是两边各加一个；把一架拖到另一架上、还没松手时，就画出两个盘各拿走什么、盘下面写 `− (2x + 2y)` 和 `− 16`，并说明“那一架说它们一样重，所以还是平的”。
- **换一换（鸡兔同笼）**：加了一架“现在 / 目标”的天平；还差的数切成一段一段，每段是换一个补上的数（段数就是假设法的那一步除法）；“每个都少算”按钮是抬腿法，也是天平两边同时减；拖把手时被换掉的每个头上写 +2。
- 没做的：两架天平仍然不能歪（没有“只动一边”的错）；系数为负的方程组仍然摆不出来；这些画面没有孩子试用过。

### 2026-11-15 补：换一换接到两架天平；五个新操作台

- **换一换 → 两架天平**：换一换卡片上的“写成两架天平”把同一道题写成 x + y = 个数、la·x + lb·y = 总数，卡片直接变成两架天平（复用同一套画法和拖法）；解出来点“回到换一换”，乙的个数带回来。每盘超过 30 个砝码或 6 个盒子时摆不下，按钮是灰的。
