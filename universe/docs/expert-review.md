## 1. 专家会做、但我们没有要求过的事

我们到现在做的事，几乎都是**工程**：内核、器材、界面、测试。专家会先问另一类问题：**这个东西真的让孩子学会数学了吗？我们怎么知道？** 下面这些，是整个过程里没有人提出过的。

| # | 专家会做的事 | 为什么 | 我们现状 |
|---|---|---|---|
| 1 | **先定义学习目标，再设计活动**：每个知识点写成“学完以后孩子能做到什么”，对应课标的学业质量要求 | 没有目标就无法判断“学会了” | 知识点表只有标题和本质标签，没有可观察的目标 |
| 2 | **建立易错点库（误解库）**：从真实学生的错误里整理，每个误解对应一个诊断题和一个纠正活动 | 数学学习的难点往往是“错得有规律”，不是“不会” | 陷阱靠我们凭经验写，没有来自真实学生的数据 |
| 3 | **做认知任务分析**：专家和新手做同一道题，记录他们的思路差异，据此决定怎么搭脚手架 | 决定提示怎么分层、什么时候放手 | 三层提示是我们凭直觉写的 |
| 4 | **画先修关系图并验证**：哪个知识点依赖哪个，用学生数据检验，不靠想象 | 决定出题顺序和复习 | 复习规则是固定间隔，没有先修关系 |
| 5 | **用纸笔或最简原型先找真实孩子试**，再决定做什么（“绿野仙踪”法：人在幕后假装是软件） | 几十行代码就能验证的方向，不要用几万行来验证 | 先做了整套引擎，再让一个成年用户试，发现了一连串基础问题 |
| 6 | **测量学习效果**：前测、后测、延迟测（过一两周再测），有对照组 | 玩得开心不等于学会了 | 所有验收都是“功能存在”，没有一项衡量学习 |
| 7 | **和一线老师一起设计**：一节课 40 分钟、教室里有什么设备、老师怎么用它、怎么布置作业、怎么看班级结果 | 软件要进课堂，先要放得进课堂 | 老师端只有一个班级看板的数据层 |
| 8 | **可访问性**：对比度、字号、色觉障碍、键盘操作、屏幕阅读器、触屏 | 法律和伦理要求，也影响所有孩子的可用性 | 最近才第一次测出文字对比度不合格（30 处里 10 处低于 4.5:1） |
| 9 | **儿童数据合规**：未成年人个人信息的收集、存储、授权（中国的《个人信息保护法》《未成年人保护法》以及网络保护相关规定；若面向海外还有 COPPA、GDPR-K） | 面向孩子的软件，合规是前提 | 目前所有数据只在浏览器本地，这是合规上的优势，但没有写成明确的原则，也没有审视分享链接、作业文件里会带出什么 |
| 10 | **内容的正确性审查**：每道题、每条提示、每个“为什么”，由数学教师或教研员逐条审，有记录 | 一个错的“为什么”会教会孩子错的东西 | 题目和解释都由我们生成，没有人工审查记录 |
| 11 | **阅读负担分析**：题面用的字、句子长度是否适合这个年级（低年级识字量有限，中文应用题读题本身就是难点） | 读不懂题，就测不出数学 | 没有分析 |
| 12 | **低端设备和离线环境**：学校的旧平板、旧电脑、没有网络或网络很慢 | 决定性能预算和打包方式 | 有单文件版（当时实测约 1 MB），这是优势；但没有在旧设备上测过 |
| 13 | **版权与素材来源**：教材内容、图片、字体、第三方库的许可 | 避免侵权，也避免日后被迫下架 | 没有梳理 |
| 14 | **长期维护和版本**：课标会改版，教材会换，题库怎么跟着更新，旧的学习记录怎么办 | 产品要活很多年 | 存档有版本迁移，但题库和课标没有版本对应 |
| 15 | **公平和包容**：不同地区、城乡、性别、语言背景的孩子是否都能用；情境题里的生活经验是否带偏见 | 避免一部分孩子被默认排除 | 没有审视 |
| 16 | **教学法的明确选择**：具体到抽象（CPA）、有指导的发现、变式教学、先做再说、错例分析……每道题用的是哪种，为什么 | 不同知识点适合不同教法 | 我们用了“先猜再动手再说出发现”，但没有按知识点选择 |

## 2. 专家会从哪些最原始的素材入手

我们现在手里的是**整理好的素材**：`content/grades/` 里的知识点表、我们自己写的十二种本质、一批我们自己出的题。专家会认为这些都是**二手的**，会回到下面这些一手素材：

### 2.1 课程和教材（定义“要教什么”）

- **《义务教育数学课程标准（2022 年版）》原文**：包括核心素养、学段目标（一至四学段）、内容要求、学业要求、教学提示。我们的“142 个知识点”需要和它逐条对照，不是自己整理的表。
- **多个版本的教材、教师用书、配套练习册**（例如人教版、北师大版、苏教版等）：专家会看同一个知识点在不同教材里怎么引入、用什么情境、用什么表示，以及练习的难度梯度。
- **国家中小学智慧教育平台等官方资源**：看官方推荐的教学课例和资源。

### 2.2 学生（定义“孩子真实是怎么想的”）

- **学生作业、试卷、错题本的真实样本**：整理错误的类型和比例，这是误解库的来源。
- **一对一的出声思考记录（think-aloud）**：让孩子一边做题一边说，录音录像，逐字整理。
- **课堂录像**：看老师怎么讲、孩子在哪里卡住、哪些提问最有效。
- **学生访谈**：“你为什么这样做？”“你觉得这两个一样吗？”

### 2.3 老师（定义“怎么教、怎么用”）

- **老师访谈和跟岗**：一节课怎么安排、哪些知识点最难教、哪些环节最想要工具。
- **教研员和特级教师的课例和评课记录**。

### 2.4 研究文献（定义“已经知道什么”）

- 数学学习轨迹和发展水平的研究，例如几何思维的 van Hiele 层次、计数和数感的发展轨迹。
- 常见数学误解的研究（例如分数、小数、代数字母的理解、比例推理）。
- 具体到抽象（Bruner 的 CPA）、新加坡的条形图模型、荷兰的现实数学教育（RME）等教学法的研究。
- 国际测评的题目和分析：**TIMSS**、**PISA** 的公开题目和学生表现数据。
- 数学史和数学哲学的资料：例如 Pólya 的解题思想、Lakatos 的“证明与反驳”（与我们的证据等级一脉相承）。

### 2.5 已有的工具（定义“别人做到什么程度”）

- **GeoGebra**、**Desmos**：专家会先用它们做同样的事，找出它们做得好的和不够好的地方，而不是从零开始想。
- **DragonBox** 等把代数变成游戏的产品，以及 Cuisenaire 棒、Dienes 方块、算盘、十格阵这类实物教具。
- 已有的智能辅导系统（例如 Cognitive Tutor、ASSISTments）和它们公开的研究、数据。

## 3. 他们会用的具体方法和工具

### 3.1 研究和设计方法

| 方法 | 做什么 | 用在哪里 |
|---|---|---|
| **任务分析、认知任务分析** | 把一道题拆成步骤，记录专家和新手的差异 | 设计三层提示和脚手架 |
| **知识成分建模**（knowledge components，Q 矩阵） | 每道题标注它考察哪些最小的知识成分 | 诊断、先修图、复习 |
| **学习轨迹 / 学习进阶** | 把一个概念从最初级到最成熟的理解水平排成梯子 | 决定每个工作台的难度梯度 |
| **设计研究法**（迭代：设计 → 小范围试 → 改） | 每一轮只改一件事，并有证据 | 整个项目的节奏 |
| **纸笔原型和“绿野仙踪”原型** | 不写代码，用纸、剪刀、真人扮演软件 | 在做引擎之前验证几何剪拼的活动本身是否有效 |
| **可用性测试**：**5 个用户就能发现大多数问题**，出声思考，录屏 | 找出卡点 | 每个工作台发布前 |
| **启发式评估**（Nielsen 的 10 条原则）、**认知走查** | 几位专家对照检查清单，不需要用户 | 快速发现明显问题 |
| **可用性量表**（如 SUS）、任务成功率、任务时间、错误次数 | 把“好用”变成数字 | 验收 |
| **前测 / 后测 / 延迟后测**，有对照组或基线 | 衡量学习效果，用效应量表示 | 判断是否真的有用 |
| **A/B 实验** | 比较两种设计 | 例如关系画布和几何工作台 |
| **学习分析和知识追踪**（Bayesian Knowledge Tracing、因子分析等） | 从使用数据估计孩子掌握了什么 | 复习排期、老师看板 |
| **项目反应理论（IRT）** | 估计每道题的难度和区分度 | 题库质量 |

### 3.2 内容和正确性的工具

| 工具 | 做什么 |
|---|---|
| **计算机代数系统**：SymPy（开源）、Sage、Mathematica、Maple | 独立验证精确计算：分数、根式、多项式变形、方程的解、因式分解 |
| **动态几何软件**：GeoGebra、Cabri | 独立验证几何结论：面积、交点、全等、中点、垂线 |
| **形式化证明助手**：Lean 4 加 mathlib、Coq、Isabelle | 验证“变换规则保持不变量”这类核心规则本身是对的，不只是测几组数 |
| **基于性质的测试**（如 fast-check、Hypothesis）、**差分测试**、**蜕变测试** | 随机生成大量输入，和独立实现比对结果；检验“剪开再拼起来面积不变”这类性质 |
| **标准库的参考实现**：Python 的 `fractions`、`decimal` | 对照我们的有理数运算 |

### 3.3 可用性和无障碍的工具

| 工具 | 做什么 |
|---|---|
| **WCAG 2.2** 作为检查清单 | 对比度、字号、键盘操作、触屏目标大小 |
| **axe-core**、**Lighthouse**、**Pa11y**（可接进自动化测试） | 自动检查可访问性问题 |
| **屏幕阅读器**（NVDA、VoiceOver、TalkBack）和**真实的使用者** | 自动工具查不出的问题 |
| **色觉障碍模拟**（浏览器开发者工具里有模拟）和**真实的色觉障碍用户** | 检查是否只靠颜色区分 |
| **录屏、热力图、会话回放** | 看孩子到底点了哪里 |
| **多种浏览器和真机**（Safari、Firefox、iPad、安卓平板、低端旧设备） | 兼容性和性能 |

### 3.4 管理和合规

- **教研员评审和教师评审表**：每道题有评审人、日期、意见。
- **数据保护影响评估**：列出收集哪些数据、存在哪里、谁能看到、保存多久。
- **许可证清单**：代码、字体、图片、教材内容的授权。

## 4. 除了我们（AI 代理）之外，还有什么可以证明结果

**我们现在的“证明”只有一种：我们自己写的测试通过。** 这只能说明代码和它自己的预期一致。下面这些来源是独立于我们的，能证明得多：

| 独立来源 | 能证明什么 | 谁来做 |
|---|---|---|
| **计算机代数系统（SymPy、Sage）** 对比 | 所有精确计算（分数、根式、多项式、方程的解）是否正确 | 可以自动化：生成几千个随机算例，两边比对 |
| **GeoGebra** 对比 | 几何构造的结果（交点、面积、剪拼）是否正确 | 半自动：导出构造，让 GeoGebra 计算后比对 |
| **形式化证明助手** | 变换规则保持不变量，是对所有输入成立，不只是测试过的输入 | 需要懂 Lean 或 Coq 的人 |
| **数学教师、教研员的逐条审查** | 题目、提示、“为什么”在数学上是否正确；是否符合课标；是否适合这个年级 | 人工，应有书面记录 |
| **真实的孩子** | 好不好用、能不能学会；有没有 AI 想不到的卡点 | 真人，见第 5 节 |
| **前测后测的数据** | 是否真的提高了学习效果，用效应量表示 | 需要研究设计，必要时请教育研究者协助 |
| **无障碍审计和真实的残障用户** | 是否真的可用 | 外部审计或志愿者 |
| **第三方代码审查和安全审查** | 实现质量、数据安全 | 外部工程师 |
| **公开的基准** | 题目难度和国际水平的对照（例如公开的 TIMSS 题） | 人工或半自动 |

**关键原则**：AI 代理写的东西，不能只由 AI 代理验证。至少要有一道**独立的、与代码无关**的检查：由 CAS 或 GeoGebra 做计算比对，由人审内容，由孩子试用。

## 5. 如果由专家来启动这个项目，前三个月会怎么做

1. **第 1–2 周：定义和收集。**
   - 拿到课标原文和一两套教材，把知识点和课标的内容要求逐条对应；
   - 找 3–5 位一线数学老师做访谈（最难教的知识点、最想要的工具）；
   - 收集 100–200 份真实的学生错误样本（试卷、作业），分类整理成易错点库。
2. **第 3–4 周：用最便宜的方式验证活动本身。**
   - 选一个知识点（例如 5 年级平行四边形的面积），用**纸和剪刀**做剪拼活动，找 5–8 个孩子试，录像；
   - 同样的活动，用 GeoGebra 做一遍，再试一次；
   - 看孩子在哪里卡住、说了什么，把“为什么面积不变”能不能说出来作为学习证据。
3. **第 5–8 周：做最小的软件原型，只覆盖那一个知识点。** 每周找孩子试一次，每次只改一件事。
4. **第 9–12 周：扩到一个领域（几何面积）**，同时做前测后测和教师试用，并开始对照 CAS 和 GeoGebra 做自动化验证。
5. **到这时才决定**要不要建设统一内核、多少个工作台、先做哪些。

对比我们的做法：我们是先建了统一内核和 90 多种器材，最近才开始找人试。专家会认为顺序反了，但内核本身没有白做——它在第 4 步以后会成为可复用的底座。

## 6. 修订后的项目题目（需求说明）

下面是把“专家会做的事”并进来以后，完整的项目题目。用户原来的七条要求保留（第 6.3 节），新增的部分标了“新增”。

### 6.1 项目名称和一句话

**数学小宇宙：一个让 1–9 年级孩子在动手中理解数学原理、并能看清每一步过程的学习实验室。**

### 6.2 对象和范围

- **主要使用者**：1–9 年级的学生；**协同使用者**：数学老师、家长。（新增：老师和家长不是附属功能，是需求的一部分。）
- **学习范围**：义务教育阶段（1–9 年级）全部数学内容，以《义务教育数学课程标准（2022 年版）》的内容要求为准，逐条对应。（新增：以课标原文为准，而不是自己整理的知识点表。）
- **目标定位**：**学习产品为主，创作为进阶**（用户已确认，见 `direction.md`）。
- **使用环境**：（新增）课堂（40 分钟一节课、老师统一布置）、家庭自学、低端旧平板和旧电脑、网络差或离线。

### 6.3 核心要求（用户原有的七条）

1. **统一的底层数学原理**：数、代数、几何等共用精确的值、变换规则和不变量。
2. **强大的、可以互相连接的实验对象**：不同领域的对象可以组合，例如几何的面积接进代数的式子。
3. **系统能理解数学原理**：系统知道一个结论成立的依据，而不只是算出结果。
4. **能拆解全部义务教育数学知识**：每个知识点有可衡量的覆盖。
5. **简单易用**：（修订）一个孩子或老师，不看说明，在 15 分钟内能完成一道代表性的题目。
6. **实验过程中数学过程清晰可见**：每一步都能回看、修改、撤销。
7. **数学模型和现实世界相连**：用真实数据建模，并回到情境里检验。

### 6.4 新增要求

**A. 学习有效（最重要的新增）**
- A1. 每个知识点有**可观察的学习目标**（学完能做到什么），对应课标的内容要求和学业要求。
- A2. 每个知识点有**易错点库**，来源于真实学生的错误样本；每个易错点有一道诊断题和一个纠正活动。
- A3. 每个知识点有**先修关系**，并用学生数据检验。
- A4. 选用的教学方法（具体到抽象、变式、有指导的发现等）**按知识点明确写出**，并说明理由。
- A5. 有**学习效果的测量**：前测、后测、延迟后测；至少对一个知识点做过对照实验并公布结果。

**B. 内容正确**
- B1. 所有精确计算有**独立验证**：与计算机代数系统（如 SymPy）的结果自动比对，通过率 100%。
- B2. 所有几何计算有**独立验证**：与动态几何软件（如 GeoGebra）的结果比对。
- B3. 变换规则“保持不变量”的核心规则，有**形式化证明**或穷尽的性质测试。
- B4. 每道题、每条提示、每个“为什么”都有**数学教师的审查记录**（人、日期、意见）。
- B5. 题面的**阅读负担**符合年级（用字、句长有检查）。

**C. 可用、可访问**
- C1. 文字对比度 ≥ 4.5:1，字号不小于规定，不只靠颜色区分（WCAG 2.2 AA）。
- C2. 全部功能可以用键盘完成；触屏上的点击目标不小于 24 像素。
- C3. 在 Safari（iPad）、Firefox、Chrome 和至少一种低端旧设备上能用；首次加载和拖动流畅。
- C4. 每个工作台发布前，通过**真实使用者的可用性测试**（至少 5 人，录屏）。

**D. 课堂和家庭可用**
- D1. 老师能在 5 分钟内布置一次作业，并看到全班在每个知识点和易错点上的情况。
- D2. 家长能看到孩子具体在哪里不懂，而不只是分数。
- D3. 一节课（40 分钟）内能完成一个完整的学习活动。

**E. 数据和合规**
- E1. 面向未成年人的数据**默认只存在本机**；任何分享（链接、作业文件）都明确告诉用户会带出什么。
- E2. 有数据保护评估，符合适用的未成年人个人信息保护规定。
- E3. 所有第三方代码、字体、图片有许可证清单；教材内容的使用有授权依据。

**F. 可持续**
- F1. 题库和课标有版本对应，课标更新时有迁移办法。
- F2. 每次改动有自动检查（精确计算比对、对比度、界面手势测试、性能预算），**检查全绿才能发布**。
- F3. 用户每次报告的问题，先写成一个会失败的真实操作测试，再修。

### 6.6 不做什么

- 不用“测试通过”替代“孩子学会了”。

## 7. 如果“题目”指题库里的数学题

专家会这样审查题库（72 道题，每道都过一遍）：

1. **对课标**：这道题对应课标哪一条内容要求？达到的是什么水平（了解、理解、掌握、运用）？
2. **对易错点**：它要暴露哪个常见误解？这个误解的证据（真实错例）在哪里？
3. **对数学**：题面、提示、“为什么”是否数学上正确、表述是否严谨？答案是否唯一，如果不唯一是否都被接受？
4. **对年级**：用字和句长是否适合？情境是否是孩子熟悉的、没有偏见的？
5. **对难度**：难度是否通过真实学生的数据校准，而不是凭感觉？
6. **对教法**：这道题用的是什么教学方法？是不是适合这个知识点？
7. **对可用性**：孩子读完题面，知道要做什么吗？第一步卡住的比例是多少？
8. **对独立验证**：参考解的结果，是否经过 CAS 或 GeoGebra 的独立计算？

据我所知，题库里**没有记录显示**有哪道题完成了上面 8 步中的第 1、2、5 步（这三步都需要真实素材）；这一条我没有逐题核对，请以人工检查为准。如果要修订题库，应该先从课标原文和真实错例做起，再改题，而不是在现有的题上继续加。
