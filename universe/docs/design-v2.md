## 0. 目标与本文要改的方向

### 0.1 目标（四层）

不是刷题 App，而是一个统一的数学实验室：一个有自己规律的世界，学生进去动手、猜想、试错、发现。

| 层 | 要求 |
|---|---|
| 学什么 | 1–9 年级 142 个知识点，每个点用全世界最好的方法，由浅入深，深到奥数；每个概念看得见、摸得着 |
| 怎么学 | 设计单位是**问题**；先猜、再玩、说出发现；错的动作有看得见的后果；按步给分、丢分定位到步；练完进复习；家长能看；老师能布置探究作业；目标是训练大脑，不是背程序 |
| 长什么样 | 一个世界一套规律：器材属性可调，全部能连，值流进流出，没有孤岛；一个时钟当心跳，输入一变全系统跟着动 |
| 高到哪里 | 追上并超过 NB：123 种器材、32 个世界首创；**最终检验：学生当作者，能搭出没人写过的东西** |

### 0.2 v1 的问题（本文要改的）

1. **先有器材清单，再往里塞学习**。v1 篇幅主要在 123 种器材上，最终验收 5 条全是计数（实验数、器材数、体积），没有一条衡量学习或创造。
2. **实验还是“照着做”**：步骤线性推进、高亮下一个器材、`check` 只认一种台面状态，一题一种做法。
3. **“说出发现”没有落点**：POE 的 E 退化成机械 observe 步，学生不说任何话。
4. **猜错被罚**：预测必须猜对才算 correct，猜错进错题——会让孩子不敢猜。
5. **心跳只有名字**：只讨论了 tick 的数据格式，驱动机制、反馈环、暂停/单步/回放都没设计。
6. **“没有孤岛”是口号**：靠事后审计（审计时 31 个孤岛、属性 ≥3 的只有 56/100），不是内核保证。
7. **作者层缺失**：保存/分享、学生出题、学生造器材都不在计划里；“器材制造器”排在最后一批且划给老师。
8. **自相矛盾**：器材数 48+121=169≠123；复习规则两套（§4.4 vs A1）；按步结果“无界面读”却被家长端引用；文末评审段落重复且截断。

### 0.3 设计主线

> **台面是一个世界；问题是进入世界的入口；学生最后成为世界的作者。**
> 规律写进内核，不靠审计；判分看数学性质，不看操作顺序；器材由问题拉动，不由清单推动。
> 器材和值类型都能注册、按需加载，内核不随它们变大；每条发现都标明证据等级，看见规律不等于证明。

### 0.4 边界（沿用 v1，不做的事）

- 不做 3D / RPG / 付费墙；不把实验做成视频
- 不碰 `anims-*.js`
- 无服务器：全部在浏览器本地，分享走链接或文件
- 信号文字一字不改（判分事实来源），直到第 2 阶段迁移到性质判分后才解除

## 1. 世界内核

### 1.1 一种器材合同

每种器材是 `TYPES` 里的一个对象，**只改这一处**就能加一种器材：

```js
TYPES.adder = {
  label: '合并器', group: '数与运算', icon: 'adder',
  grades: [1, 9],                       // 适用年级（器材架按年级/问题过滤）
  props: {                              // 属性：每个都自动成为输入端口
    op: { kind: 'num', dim: null, choices: ['加', '减'], default: 0, write: true }
    // 控件由声明自动选，不再一把滑杆走天下（见 1.1.1）
  },
  slots: null,                          // 可选：容器器材声明能装什么，见 1.10
  inputs: {                             // 额外输入端口
    in: { kind: 'num', many: true, sameDim: true }
  },
  outputs: {                            // 输出端口；所有读数都要在这里声明
    out: { kind: 'num', dim: '=in' }
  },
  // 二选一：
  compute(inp, props) { return { out: props.op ? sub(inp.in) : sum(inp.in) } },
  // step(state, inp, props, dt) { return { state, out } }   // 有状态器材
  init: null,                           // 有状态器材的初始状态
  exact: true,                          // false = 近似计算（浮点、离散化、逼近），见 1.9
  pack: 'core',                         // 所属器材包，见 1.8
  sig(inp, out, props, say) { … },      // 信号条
  draw(view, props, out, state) { … },  // 画法
  reject: { area: '…' }                 // 按维度拒绝的原因
}
```

#### 1.1.1 属性控件自动选型

设置卡不再给每个属性都画滑杆，按属性声明自动选控件：

| 属性声明 | 控件 |
|---|---|
| 有 `choices`，2–5 个 | 分段按钮 |
| `kind: 'bool'` | 开关 |
| 整数，范围 ≤ 20 | 步进器（− 数 +） |
| 整数，范围 > 20，或有理数 | 滑杆 + 数字框（点数字框弹出小键盘，见第 6 节） |
| 角度类（`dim: '角度'`） | 转盘 |
| `kind: 'expr'` | 表达式框（ƒx） |
| 被上游驱动的属性 | 任何控件都变灰，显示“由 × 驱动”，点一下跳到上游 |

器材可以用 `control: '…'` 覆盖默认选型，lint 检查覆盖值是否合法。

v1 的 `out/accepts/acceptsDist/value/ports/derive` 统一成 `props/inputs/outputs/compute|step`。evaluate 里按 `e.type` 写的特判分支（v1 说 ~80 个）全部搬进各自的 `compute`。

### 1.2 属性即端口（反孤岛写进内核）

- 每个 `write: true` 的属性**自动**获得同名输入端口：连上线，属性就由上游驱动（滑杆变灰，显示“由 数 1 驱动”）；断开，回到手动值。
- 每个 `outputs` 里的读数都能连出去。显示在器材上的数字，必须来自某个输出端口——**界面上看得见的值，一定流得出去**。
- v1 的 `binds[]` 不再单独存在：绑定就是“连到属性端口”的连线。`links` 和 `binds` 合成一张图、一个拓扑序（v1 护栏 3 自然满足）。

**器材 lint（`tools/check-types.js`，进 TYPES 的硬门槛）**：
1. 至少 1 个输出端口
2. 至少 3 个可写属性（纯源器材如“数字卡”可豁免为 1 个，需在 lint 白名单写理由）
3. 所有输出声明了 `kind` 和 `dim`
4. `compute` / `step` 二者有且只有一个
5. `compute` 是纯函数：lint 用冻结对象调用一次，任何写入即失败

孤岛数 = 0 由第 1、2 条保证，不再需要人工审计。

### 1.3 世界时钟（心跳）

心跳不是一个器材，是世界本身的时间。

```js
S.clock = { t: 0, running: false, rate: 1, dt: 1/30, seed: 20261108 }
```

- **界面**：顶栏 ▶ 播放 / ⏸ 暂停 / ⏭ 单步 / 速度 ×0.25–×4 / ⟲ 回到 t=0。
- **每一跳**：
  1. 所有有状态器材按拓扑序调用 `step(state, inp, props, dt)`，其中 `inp` 读的是**上一跳**的输出
  2. 全图按拓扑序调用 `compute`，得到本跳输出
  3. 判分（里程碑/陷阱）、重画
- **不跳的时候**：任何操作立即触发第 2、3 步（v1 的“没有运行按钮”保留）。静态问题永远不需要按播放。
- **节拍器**是一个普通器材：输出 `t`、`n`（第几拍）、`phase`。v1 待裁决 #4（`{n, phase}` 还是 `{n, t}`）由此消解：三个都作为端口给出。

**反馈环规则（世界最重要的一条规律）**：
> 连线可以成环，但环上必须至少有一个有状态器材。

- 环上有有状态器材：它读上一跳的值，等于一个延迟，环就有意义（恒温器、迭代器、逼近器、积累器、种群增长）。
- 环上全是无状态器材：拒绝连线，说原因：“这样连，数会自己追自己，永远算不完。中间放一个‘记忆器’，让它一拍一拍地算。”——这本身就是一节关于递推的课。

**确定性**：随机器材只用 `rand(S.clock.seed, entityId, n)` 取数。同一台面 + 同一操作序列 → 每一跳完全相同。考试复核、分享回放、bug 复现都靠它。

**性能**：全量重算；单跳超过 16ms 时自动降到 15 帧并在顶栏显示，实体 > 200 再做增量（v1 已列）。

### 1.5 打包器材（宏器材）

学生框选一组已连好的器材 → “打包” → 选择对外露出的输入、输出和属性 → 起名 → 得到一个新器材，出现在器材架“我的器材”组，可以反复使用、可以再打包。

- 实现：宏器材的 `compute/step` 就是对 `inner` 子场景跑一遍内核；露出的属性映射到内部某个器材的属性。
- 宏器材同样要过 1.2 的 lint（至少 1 个输出）。
- 这是“学生当作者”的地基，也是数学的核心动作：**把一个做法抽象成一个工具**。

### 1.6 迁移现有 48 种器材

| 步骤 | 内容 | 验收 |
|---|---|---|

| b | 逐组把 evaluate 特判搬进 `compute`；D 的旧键（`d.tilt/d.equal/d.tot/d.terms/d.L/d.R`）作为输出端口保留同名 | 147 条基线 + 黄金路径一字不差 |
| c | `binds[]` 转成属性端口连线；旧存档按 `v` 迁移 | 旧存档能打开 |

| e | 现有 8 种值类型 + tick 搬进 `KINDS` 注册表（1.7） | 内核里不再出现按 kind 写的特判 |
| f | 48 种器材按 1.8 分进 core 包和若干扩展包 | core 单文件 < 1.5 MB；扩展包按需加载后行为与之前一致 |

### 1.7 值类型注册表（KINDS）

器材可以无限加，但器材之间流动的“东西”如果写死在内核里，每加一种新的数学对象（集合、矩阵、向量、表达式、无理数、图……）都要改内核。所以值类型和器材一样，**只改一处就能加**：

```js
KINDS.set = {
  label: '集合',
  eq(a, b) { … },                 // 相等判定（判分、去重、回放比对都用它）
  show(v) { … },                  // 端口悬停、信号条、读数的文字表示
  draw(view, v) { … },            // 可选：在连线上流动时的小图示
  serialize(v) { … }, parse(s) { … },
  exact: true,                    // 这种值能否精确表示
  to: {                           // 可自动转换到哪些 kind（例：num → interval 单点）
    seq: v => [...v].sort(cmp)
  },
  dims: false                     // 是否携带维度
}
```

- **连线规则**：源端口 kind 等于目标端口 kind，或在源 kind 的 `to` 里有转换，才能连；否则拒绝并说原因。不允许隐式的有损转换（`exact: true` → `exact: false` 要显式经过“近似器”器材）。
- **内核只认注册表**：evaluate、判分视图 `W`、存档、回放里，凡是要比较、显示、序列化值的地方，都调 `KINDS[k].eq/show/serialize`，不写 `if (kind === 'dist')`。
- **lint**（并入 `check-types.js`）：每个 kind 必须有 `eq/show/serialize/parse`；每个器材端口引用的 kind 必须已注册。
- **首批要补的 kind**（按问题需要排期，不一次全做）：`real`（符号精确：√2、π 作为符号保留，`a + b√c` 形式精确运算，显示时才取近似）、`set`、`vec`、`expr`（代数式，供方程/恒等式问题）、`graph`（点和边，供数论、组合问题）。

### 1.8 器材包与按需加载

“无限器材”不能塞进一个文件。器材按包组织：

```
apps/web/lab/
├── lab-core.js        # 内核 + KINDS 基础类型 + 约 20 种核心器材（数字卡、合并器、乘法器、天平、数轴、分数条、坐标平面、节拍器、记忆器……）
├── packs/
│   ├── pack-number.js     # 数与运算扩展：试商台、竖式台、凑十架……
│   ├── pack-geometry.js
│   ├── pack-data.js       # 统计概率
│   ├── pack-function.js
│   ├── pack-time.js       # 时间类动态器材
│   ├── pack-proof.js      # 猜想板、反例构造器、证明脚手架、归纳阶梯……（见 2.7）
│   └── …
└── lab-nb.html        # 外壳：界面 + 加载器
```

- **包的格式**：一个包是一个脚本，调用 `registerPack({ id, version, needs: ['core@2'], kinds: {…}, types: {…} })`。包里可以注册新的 kind 和器材，不能改别的包。
- **加载**：打开问题时，按问题的 `shelf` 和开场台面里出现的器材类型，算出要加载的包；自由台面按年级预载，器材架展开某组时再加载该组的包。打开分享链接时，从场景里的器材类型反推需要的包。
- **离线 / 单文件版**：构建脚本（`tools/build-standalone.py` 扩展）可以把内核和指定的包内联成一个文件。widget 的 6 MB 限制只约束“内核 + 默认包”，不约束器材总数。
- **版本**：场景存档记录用到的包和版本；包升级时如果改了某器材的属性或端口，必须在包里写迁移函数，否则 lint 失败。
- **打包器材（1.5）**存在场景里，不需要单独的包；学生造的器材随分享链接一起走。

**扩展的真实成本**：计算、连线、判分、存档、回放对新器材是零成本的；**每种器材的画法和专属手势**（点分数条的格子、拖三角形的顶点）需要单独写，成本随器材数线性增长。为了压低这部分成本，内核提供一组通用部件：滑杆、读数牌、网格、点集、条形、可拖动的顶点和把手。新器材优先用通用部件拼画法，只有确实需要时才写专属画法。

### 1.9 精确与近似

台面上的数可能“说谎”：浮点误差、离散化、逼近。学生会把误差当成数学事实。

- 每种器材声明 `exact`；每种 kind 声明 `exact`。
- 一个值是精确的，当且仅当它的整条上游链都是精确的。evaluate 顺带算出每个值的 `exact` 标记。
- **近似值在界面上始终带“≈”**，悬停说明原因（“摆的运动是一拍一拍算的，所以是近似的”）。
- 能精确的一律精确：有理数用 Q；√2、π 用 `real` 符号保留；只有物理模拟、三角函数数值、极限逼近才近似。
- 判分视图 `W` 比较近似值时必须给容差；问题 lint 检查：对近似值用了精确相等的 `test` 直接失败。

### 1.10 容器与层级（“属于”关系）

现在实体是平的：数轴上的点、十格阵里的筹码、集合里的元素、数位块里的小方块，只能用连线勉强表示“属于”。连线的意思是“值流过去”，不是“在里面”，两者混用会让规律说不清。

- **容器器材**在合同里声明 `slots`：
  ```js
  TYPES.tenframe.slots = { cells: { accepts: ['counter'], max: 10, layout: 'grid2x5' } }
  TYPES.numline.slots  = { marks: { accepts: ['point'], max: null, layout: 'onAxis' } }
  TYPES.setbox.slots   = { items: { accepts: '*', max: null, layout: 'free' } }
  ```
- **放进去**：把器材拖到容器的槽位上就成为它的子实体（`parent`、`slot` 写入）；拖出去就解除。移动容器时子实体一起动。
- **容器的读数从子实体算**：十格阵输出“有几个筹码”“还差几个凑十”；数轴输出“点的位置列表”；集合输出 `set` 值。这些都是普通输出端口，照样能连出去。
- **子实体的属性可以由容器决定**：数轴上的点，`x` 由它在轴上的位置决定；筹码的位置由十格阵的布局决定。
- **规则**：
  - 一个实体同一时刻只属于一个容器；容器可以嵌套（数位块：千 ⊃ 百 ⊃ 十 ⊃ 一），不允许成环。
  - 拖进不接受的器材时拒绝并说原因（“十格阵里只能放筹码”“已经满 10 个了——满十就要换成 1 个十”，后者本身就是进位的课）。
  - 删除容器时询问：连里面的一起删，还是把里面的倒到台面上。
- **判分视图**增加 `W.children(id, slot)`、`W.parentOf(id)`。
- **打包器材（1.5）**可以把一个容器连同内容一起打包。
- 首批用到容器的器材：十格阵、数位块、数轴（点）、集合盒、转盘（扇区）。

## 2. 学习单位：问题

### 2.1 问题的结构

```js
const P = {
  id: 'p4.6-trial-quotient',
  points: ['4.6'],                     // 可以挂多个知识点
  alias: ['试商', '除法估商', '两位数除法'],   // 搜索用的别名/关键词
  level: 'core',                       // core 核心 / trap 陷阱 / stretch 延伸（深到奥数）
  rung: 3,                             // 台阶（见 2.2）
  hook: '一筐 192 个苹果，每袋装 32 个，能装几袋？先别算——你觉得是几？',
  scene: build => { … },               // 开场台面，可以为空
  shelf: ['num', 'div', 'trialq'],     // 本题器材架只显示这些（低年级必填）
  budget: { entities: 6 },             // 可选：资源约束，制造取舍
  predict: { ask: '能装几袋？', form: 'pick', options: [5, 6, 7], answer: 6 },
  milestones: [                        // 用性质表达，不规定顺序、不规定做法
    { id: 'm1', say: '台面上算出了 192 ÷ 32', score: 2,
      test: W => W.some('num', v => qeq(v, Q(6)) && W.from(v, 'div', [192, 32])) },
    { id: 'm2', say: '试商时调过一次商', score: 1,
      test: W => W.log.some(e => e.type === 'set' && e.k === 'q' && e.on === 'trialq') }
  ],
  traps: [                             // 常见误解对应的台面状态；触发时画后果，并记事件
    { id: 't1', wrong: '商的位置写错（试商用 19÷32）', test: W => …, show: '…' }
  ],
  goal: ['m1'],                        // 达成即完成；其余里程碑是加分
  explain: { form: 'cards', frame: '因为 32 × __ = __，所以 192 里有 __ 个 32' },
  variant: { change: '把 192 改成 200', ask: '现在能装几袋？还剩几个？' },
  params: { total: [150, 300], per: [12, 40] },  // 可选：参数化，一个问题生成无数道数（变式、复习、应用题都用）
  exam: { minutes: 6 },                // 考试时长；不写则按里程碑数 × 2 分钟，最少 3 分钟
  why: '…'                             // 做完才解锁的“为什么”，讲推理
}
```

**里程碑优先写成数据**，只有数据写不出来时才写函数：

```js
// 数据形式（首选）：按角色或类型找器材，读端口，比条件
{ id: 'm1', say: '算出了能装几袋', score: 2,
  when: { role: '商', port: 'out', op: '=', value: 6, from: { type: 'div', inputs: ['被除数', '除数'] } } }
// 组合
{ id: 'm3', all: ['m1', { type: 'balance', port: 'equal', op: '=', value: true }] }
// 函数形式（兜底）：必须标注原因，lint 统计函数形式占比，目标 < 20%
{ id: 'm4', test: W => …, why_code: '需要比较两个时刻的快照' }
```

数据形式的好处：学生出题（4.2）用的就是同一种格式；老师端能直接显示“这个里程碑要求什么”；改进清单（3.6）能按条件聚合；迁移和 lint 都更容易。

**按角色找器材**：开场台面里给关键器材写 `role`（“被除数”“x 砝码”）。判分用 `W.byRole('x 砝码')`，不按插入顺序、不按显示文字。学生自己新拖上来的器材没有角色时，按类型和连接关系匹配（`from`）。

`W` 是给判分用的只读世界视图：`W.some(type, pred)`、`W.from(value, type, inputs)`（这个值是不是由某类器材从这些输入算出来的）、`W.log`（本题事件）、`W.at(t)`（某一跳的快照，供动态题用）。**判分只能通过 `W` 读，不能读信号文字、不能按插入顺序取器材**（XP lint 规则保留并迁移到这里）。

### 2.2 六级台阶

| 台阶 | 学生做什么 | 例子 |
|---|---|---|
| 1 观察 | 动一下，看后果 | 把天平一边加一个砝码，看它倒向哪边 |
| 2 预测 | 先猜，再验证 | 两条 k 相同的直线会相交吗？ |
| 3 构造 | 搭出满足条件的台面，做法不限 | 用不超过 4 张卡让天平平衡 |
| 4 解释 | 说出或“搭给我看”为什么 | 为什么周长一定时正方形面积最大？ |
| 5 推广 | 改参数，规律还成立吗 | 换成 3 个骰子，最常见的和是几？ |
| 6 出题 | 自己出一道题给同学 | 见第 4 节 |

台阶 2–5 之间有一条贯穿的“真相主线”：**举例 → 猜想 → 找反例 → 证明 → 推广**，见 2.7。延伸题（深到奥数）必须走到“证明”这一级。

每个知识点至少 3 个问题：**核心题**（台阶 1–3）、**陷阱题**（专打该点的 `wrong` 字段）、**延伸题**（台阶 4–5，深到奥数；`olympiad` 字段有的才做，不硬凑）。

### 2.3 判分

- **里程碑**：任何时刻台面满足 `test` 就得分，不要求顺序。只有“刚做过一次操作”时才检查（开场摆好的状态不算分，沿用 v1）。
- **多种解法**：只要满足性质就判对。系统记录这次的搭法指纹（器材类型多重集 + 连线结构），如果与内置参考解不同，显示“你找到了一种新做法”——这是对创造的直接奖励。
- **陷阱**：触发时画出后果（天平倾斜、点落错、图形画不出），信号条引用 `wrongWhy` 的话，不说“你错了”。记一条 `trap` 事件。
- **丢分定位**：报告按“哪个里程碑没达成 / 哪个陷阱踩了”列出，不是“第几步”。
- **提示**：练习模式下，卡住 60 秒（或连续 3 次被拒）才出提示，分三层：方向 → 用哪个器材 → 具体做法。用到第三层的里程碑只给一半分。不再默认高亮下一个器材。

### 2.4 预测：对比，不判对错

- 预测不计入 `correct`。做完后并排显示“你猜的 / 实际的”。
- 低年级（1–3）预测一律免打字：`pick`（选图或选数）、`place`（拖到数轴上的位置）、`more-less`（多 / 少 / 一样）。
- 预测与结果不同时，问一句“哪里和你想的不一样？”，进入说出发现。
- **误解信号**：同一知识点上，同一种错误预测出现 2 次以上，才标记为误解，进入复习。

### 2.5 说出发现

| 年级 | 形式 |
|---|---|
| 1–3 | 句子卡：拖词填空（“当 __ 变大，__ 就 __”），词从台面上的器材名和读数里来 |
| 4–6 | 句子卡 + 可以自由补一句 |
| 7–9 | 自由打字；或者“搭给我看”：在台面上搭一个反例或验证，系统检查它满足的性质 |

**实验报告**（4 年级起可选，延伸题和探究作业必填）：四栏，前三栏系统从事件流预填草稿，学生改写或补充：

| 栏 | 预填内容 |
|---|---|
| 我猜的 | 预测和猜想板上写的猜想 |
| 我试了什么 | 关键操作摘要（用了哪些器材、改了哪些参数、扫了什么范围）+ 台面快照 |
| 我发现了 | 说出发现的原话 + 证据等级（2.7） |
| 我还想问 | 空，学生写；可以一键变成“出成一道题”（4.2） |

报告存进 `math-inquiry-v1`（主页面已有的键），家长端、老师端、作业提交都读它。

发现存成 `explain` 事件，进“我的发现”（主页面统一读，不再关在实验台自己的存储里），家长端能看到原话，老师端能按题汇总。不给发现打分对错，只记“说了 / 没说”。每条发现都带证据等级（2.7），由系统根据学生在台面上做了什么判定。

### 2.7 真相主线：证据等级

实验能让人看见规律，但看见不等于证明。实验台必须诚实地告诉学生：你现在手里的是哪一种证据。

**四个等级**（每条发现、每个问题的结论都标一个）：

| 等级 | 含义 | 台面上怎么达到 | 例子 |
|---|---|---|---|
| ① 举例 | 试了几个例子，都对 | 默认等级 | 掷 1000 次骰子，和为 7 最多 |
| ② 没找到反例 | 系统性地找过，找不到反例 | 用“反例构造器”或参数扫描器在一个范围内扫过，结果都满足 | 1 到 1000 内每个大于 2 的偶数都能写成两个质数之和 |
| ③ 穷举证明 | 情况有限，全部检查过 | 用“系统枚举器”列出**全部**情况并逐一验证；系统确认枚举是完整的 | 两个骰子 36 种情况全列出，和为 7 有 6 种，最多 |
| ④ 结构证明 | 用对所有情况都成立的变换或推理说明 | 用证明类器材完成：保持不变量的变换（剪拼、平移、配对）、证明脚手架填完每一步、归纳阶梯走完“第一级 + 每一级推下一级” | 平行四边形剪下三角形平移，拼成长方形；1+3+…+(2n−1)=n² 的形数点阵逐层加 L 形 |

**规则**：
- **系统判定等级，学生不能自选。** 判定依据是事件流：用过哪些器材、扫了什么范围、枚举是否完整、证明器材是否全部填完。
- **找到反例立刻改写结论**：发现被标成“已被推翻”，并保留反例——推翻一个猜想本身就是一个发现，同样记入“我的发现”。
- **近似值（1.9）参与的结论最高只能到 ②**，并提示“台面上的计算是近似的”。
- **措辞跟着等级走**：① 说“到目前为止都对”；② 说“在 1 到 1000 里没找到例外”；③④ 才说“一定成立”。界面上用不同的图标，家长端和老师端照样显示。
- **区分“对所有情况”与“对台面上这些情况”**：穷举只在情况有限时有效；问题 lint 检查：结论里含“所有 / 任意 / 一定”的问题，目标等级必须是 ③ 或 ④，或者明确写出范围。

**证明类器材**（进 `pack-proof.js`，从 v1 候选池提前）：

| 器材 | 作用 | 产出的证据等级 |
|---|---|---|
| 猜想板 | 把一条发现写成“如果……那么……”，绑定到台面上的读数 | 记录猜想，① |
| 参数扫描器 | 让某个属性自动走遍一个范围，记录结论是否一直成立 | ② |
| 反例构造器 | 在范围内自动搜反例，找到就停下并摆到台面上 | 推翻，或 ② |
| 系统枚举器 | 按规则列出全部情况，并证明列全了（计数核对） | ③ |
| 不变量追踪器 | 对一个变换（剪拼、平移、配对、交换）追踪某个量是否保持不变 | 配合变换，④ |
| 证明脚手架 | 把推理写成一串步骤，每步必须引用台面上已验证的事实或已学的规律 | ④ |
| 归纳阶梯 | 第一级 + “第 k 级推出第 k+1 级”，后者用代数式（`expr` kind）而不是具体数完成 | ④ |

**例子：从骰子到证明**
1. 举例：掷 100 次，看条形图——和为 7 最多？（①）
2. 预测：掷 10000 次还是 7 最多吗？
3. 枚举：用系统枚举器列出 36 种情况，数每个和出现几次（③，“一定成立”）
4. 推广：三个骰子最常见的和是几？先猜，再枚举 216 种情况
5. 结构：为什么中间的和最多？用配对（和为 s 与和为 14−s 一一对应）说明对称（④）

**这条线的边界（诚实说明）**：
- 台面能做的证明，是变换证明、穷举证明、归纳证明和有引用的推理链。它不能替代书面证明，也不检查任意自由写出的数学论证。
- ④ 级证明的判定靠器材的结构约束（变换保持面积、阶梯两级都完成、脚手架每步都有引用），不是通用的定理证明器。
- 目标是让学生**体验到“从看见到确信”中间缺了什么**，知道例子不够，知道什么样的理由才够。

### 2.6 88 个现有实验的迁移

1. 写转换脚本：每个旧 `step.check(S, D)` 包装成一个里程碑 `test`，按原顺序编号；旧 predict 步转成 `predict`（`expect` → `answer`）。
2. 转换后行为与旧版一致（基线不变），这时候还是“一种做法”。
3. 逐题改写：去掉对顺序的依赖、补陷阱和说出发现、低年级预测改成 `pick/place`。改写顺序按 01-problems 列的硬伤优先：4.1（问法错误）、5.5（没有 x，换成 x 砝码）、4.8（并行时间块，真的建模洗杯子、烧水）、5.6（题面与台面不一致）。

## 3. 学习数据：一条事件流

### 3.1 唯一真相来源

```js
// localStorage: math-events-v1（只追加；超过 5 MB 时把 30 天前的事件压缩成每题摘要）
{ t, who: 'student', pid, mode: 'practice'|'exam'|'free'|'assignment', aid?,
  type: 'start'|'act'|'reject'|'predict'|'milestone'|'trap'|'hint'|'explain'|'finish'|'submit',
  data: { … } }
```

所有视图都从事件流现算，不再各写各的：

| 视图 | 从事件流算什么 | 取代 |
|---|---|---|
| 复习排期 | 每个知识点的掌握度（见 3.2） | `math-review-v1` 的写入逻辑（键保留，改为派生缓存） |
| 错题本 | 未达成的里程碑、踩过的陷阱，点击回到该题、该里程碑 | 按知识点的错题 |
| 家长端 | 本周练了什么、哪里没懂（具体到里程碑/陷阱）、孩子的原话发现 | v1 §8 |
| 老师看板 | 全班 × 问题 × 里程碑的达成率、最常踩的陷阱 | `math-lab-proc-v1` |
| 考过 N 次 | `submit` 事件计数 | `nb-lab-exam-v1` 与 `math-lab-proc-v1` 两个来源 |

实验台在 iframe 里，事件通过 `postMessage({type:'mathEvent', e})` 交给主页面写入，主页面只认 `e.source === labNbFrame.contentWindow`（沿用 A1 的写法）。

### 3.2 复习规则（只有这一套）

掌握度按知识点算，取该点所有问题的最近结果：

| 情况 | 下次复习 |
|---|---|
| 核心题目标未达成，或陷阱题踩中陷阱 | 明天 |
| 达成，但用了第三层提示或被拒 ≥3 次 | 2 天 |
| 干净达成 | 4 天 |
| 干净达成且变式题也做对 | 7 天，并标“掌握” |
| 同一陷阱第二次踩中 | 明天，并在家长端标“反复出现” |

复习时出的不是原题，而是**该点的变式或另一个问题**——检验的是懂了，不是记住了这道题。

### 3.2.1 断点续做与考试恢复

- 练习、考试、作业都不再单独存状态：开题时存一份开场台面快照，之后只追加事件。恢复 = 开场快照 + 重放事件（1.3 的确定性保证结果一样）。
- **考试刷新不丢**：重开后回到原台面、原得分，计时从刷新前的剩余时间继续（刷新本身不扣时间，但记一条 `resume` 事件，老师能看到）。
- **重进同一题**时弹出选择：“接着做（上次做到 2/3）”或“重新开始”。重新开始不删旧事件，只是新开一轮。
- 旧存档（`nb-lab-practice-v1`、`nb-lab-exam-v1`）按 1.4 的版本迁移一次后停用。

### 3.3 老师布置探究作业

- 老师从问题库选问题（或用自己出的题，见第 4 节），设截止日期，生成作业文件 / 作业码。
- 学生导入后在“作业”页看到；完成后导出结果文件交给老师，老师端导入后进看板。
- 无服务器；以后要上云，只需把“导入/导出文件”换成接口，事件格式不变。
- 探究作业的提交物 = 最终台面 + 实验报告（2.5）+ 本题事件。

### 3.4 做完页与考试报告

**练习做完页**（顺序固定）：
1. 你猜的 / 实际的（2.4）
2. 这次的里程碑：达成的打勾，没达成的列出来，每条后面一个“回去做这一步”（台面回到开场状态，只高亮这条里程碑相关的器材）
3. 说出发现（2.5）
4. “为什么”解锁
5. 下一步：变式题 / 进入考试 / 返回实验库。**有没达成的里程碑时，默认按钮是“回去做这一步”，不是“进入考试”。**

**考试报告**：
- 得分、每个里程碑得失、踩中的陷阱（含后果截图）、用时、操作数、被拒绝数
- **错因**：
  - 自动错因：每个踩中的陷阱直接给出错因（来自 `traps[].wrong`）
  - 学生自选错因：对没达成且没有陷阱解释的里程碑，让学生从 6 个标签里选一个（算错了 / 概念没弄清 / 步骤漏了 / 看错题 / 没思路 / 粗心）；沿用旧台面的标签
- **下一步练什么**：按丢分最多的里程碑推荐 1–2 个问题（同一知识点的陷阱题或变式题），一键进入练习
- **体检表**（知识点页和家长端）：该知识点所有问题的里程碑达成率、最常踩的陷阱、自选错因分布、证据等级达到过的最高级

### 3.5 改进清单：数据回流给出题人

台面越用越聪明，靠的是丢分数据回到写题的人手里。

- **本机聚合**（不上传）：按 问题 × 里程碑 统计达成率、平均提示层数、平均用时；按 问题 × 陷阱 统计踩中率；按 问题 统计放弃率（开了没做完）。
- **改进清单**：老师端和“作者模式”下可见，按严重程度排序，每条给出规则化的建议：

  | 信号 | 建议 |
  |---|---|
  | 某里程碑达成率 < 50% | 题面或开场台面可能有歧义；检查提示第一层是否给了方向 |
  | 某里程碑大多用到第三层提示 | 这一步跨度太大，拆成两个里程碑 |
  | 某陷阱踩中率 > 60% | 误解很普遍：加一道专打它的陷阱题，或在核心题前加观察台阶 |
  | 放弃率 > 30% | 题太难或太长：检查预算约束、减少里程碑 |
  | 某里程碑达成率 > 95% 且没人用提示 | 太简单：考虑去掉或升台阶 |

- **回路**：
  - 内置题：改进清单可导出，作为下一批内容修订的输入；每次修订在问题上记 `revised` 日期和原因。
  - 学生出的题（4.2）：作者在“我的题”里看到自己题的改进清单——学生作者也要学会根据别人的表现改题。
  - 班级数据来自老师导入的结果文件（3.3），家里单人使用时只有本人数据。

## 4. 作者层

### 4.1 自由台面

- 实验库最上面一个入口：“自己搭”。全部器材可用（低年级默认按年级过滤，可以展开）。
- **想试试的问题**：自由台面左栏有一张卡片，列 3–5 个开放问题（按年级和台面上已有的器材挑），比如“你能让三个不同的数加起来等于 10 吗？有几种？”“把长方形的周长固定，面积最大是多少？”。点开就在当前台面上挂一个问题（不清空台面），做到了照样记事件。不点也行，台面完全自由。
- 从实验库某道题点“自己搭”时，带着这道题的变式作为想试试的问题。
- **保存为我的实验**：起名，存本机（`math-my-scenes-v1`），列表里可以再打开、复制、删除。
- **分享**：场景 JSON 压缩后放进链接的 `#` 后面（超过 8 KB 时改为导出 `.mathlab` 文件）。打开链接就是那张台面。

### 4.2 学生出题

在自己搭好的台面上点“出成一道题”：

1. 写一句问题（`hook`）。
2. 设目标：点选台面上某个器材的某个读数 → 选条件（等于 / 大于 / 小于 / 为真）→ 填值。可以加多条。（例：“天平.平衡 = 是”且“台面上器材数 ≤ 4”）
3. 选器材架：本题可用的器材。
4. 可选：设一个预测问题。
5. 系统先自检：出题人当前台面是否满足目标（必须能解）；清空答案部分后的开场台面是否**不**满足目标（不能一开始就是对的）。
6. 发布：生成分享链接 / 作业文件。

学生出的题和内置题用同一个结构（`P`），同样能被布置、被做、被统计。

### 4.3 打包器材

见 1.5。打包出的器材可以随“我的实验”一起分享；别人打开链接，器材架里就多出这个器材。

### 4.4 为什么提前做

作者层放在加器材之前（第 4 阶段，器材扩充在第 5 阶段起）。原因：

- 器材越多而没有作者层，产品越像器材大全；学生只会做内置题。
- 作者层要求内核真正统一（任何器材组合都能算、都能判、都能存），它是对第 1 阶段的最强验收。
- 学生搭出来的东西会告诉我们缺什么器材——器材优先级由真实需求决定。

## 7. 高到哪里：器材扩充

### 7.1 器材由问题拉动

v1 §3 的 123 种器材清单作为**候选池**保留。排期规则：

1. 某个问题需要它、而现有器材（包括打包器材）做不到 → 进入下一批。
2. 学生作品里反复出现同一种打包器材 → 考虑做成正式器材。
3. 世界首创不加分，按需要自然落位（沿用 v1 原则 4）。

先做依赖内核新能力的器材，证明内核：节拍器、记忆器（有状态）、迭代器、积累器、随机采样器（种子随机数）、比较器、判断灯。

### 7.2 数量对齐（第 0 阶段完成）

v1 存在 48 + 121 = 169 ≠ 123 的矛盾。第 0 阶段做法：

- 从研究底稿附录 B 重新逐件列出“目标器材总表”，每件一行：名称、来源、是否已建、需要它的问题、是否世界首创。
- 先合并 v1 待裁决的三组疑似重复（聚合器/数据表输入口、余数时钟/模算术阶梯、函数应用器/转换器），以及量角器归属。
- 世界首创空着的 4 件（#5、#8–10）回查补齐；查不到就降级，不留空洞。
- 总表定稿后，“123”这个数以总表为准；如果真实数字不同，改目标数字，不改总表去凑数。
