## 0. 目标与现状

### 0.1 远景

一个统一的数学实验室：
1. 统一的底层数学原理；
2. 器材都能互相连线；

## 1. 开工前必须知道的规则

### 1.1 精确优先

- 能精确就精确：有理数用 `Q`，根号和 π 用 `U.Real`。
- 只有物理模拟、三角函数数值、极限逼近允许近似。近似值必须带 `exact: false`（`U.val(kind, data, { exact: false })`），界面会自动显示 ≈。
- **判定**（相等、全等、平行……）一律用精确运算，不用浮点比较。图形模型就是这样做的：它只比距离的平方、叉积、点积。
- 判分里对近似值不能用精确相等。数据形式的 `when` 写 `=` 会被参考解回归测试拦下；函数形式请用 `W.near(e, port, x, tol)`。

### 1.2 加东西只改一处

- **新值类型**：调 `U.defineKind(id, { label, color, eq, show, … })`，自动获得 `serialize/parse`。可选 `toProp`（能否驱动属性）、`showApprox`、`brief`（连线气泡里的短名）、`to`（可以转换成哪些 kind）。
- **新器材**：写在 `packs/*.js` 里，通过 `U.registerPack({ id, version, types })` 注册。器材合同见 `kernel-api.md`。
- **新题目**：写在 `problems/*.js` 里。**每道题都必须**在 `tests/solutions.js` 里写一条参考解。

### 1.3 新增文件时要手动改的清单

很容易漏，漏了也不会马上报错：

1. `index.html`：加 `<script>`，注意顺序。core 在 packs 之前；新的 kind 文件放在 `registry.js` 之前。

4. `js/core/loader.js` 的 `PACK_FILES`：新增器材包时加上包名。

## 2. 任务 A：来历追踪（provenance）

### 2.1 为什么要做

现在连线上只看得见结果。比如运算器直接给出 11/15，学生看不到“先通分成 6/15 + 5/15”这一步，系统也说不出这个值是怎么来的。

远景里的“过程清晰可见”和“理解原理”，都需要每个值记得：
- 它从哪些输入来；
- 经过了哪一步；
- 中间有哪些步骤。

### 2.2 数据结构

在 `evaluate` 的结果里，给每个器材加一份追踪：

```js
D[id].trace = {
  inputs: [ { port: 'a', from: 'e3', fromPort: 'v', value: <val> }, … ],   // gather 时就能记下
  props:  { k: { value: 3, driven: true, from: 'e5' } },                     // 生效属性与来源
  steps:  [ { say: '通分：2/5 = 6/15，1/3 = 5/15', value: <val 可选>, rule: 'frac.common-denominator' }, … ],
  outputs: { r: { rule: 'frac.add', say: '分母相同，分子相加' } }           // 每个输出由哪条规则得来
}
```

- `inputs` 和 `props` 由内核在 `gather` 里自动填，器材不用管。
- `steps` 和 `outputs` 由器材在 `compute` 里填。给 compute 的 `ctx` 加两个函数：
  - `c.step(say, value, rule)`：记一步中间过程；
  - `c.because(port, say, rule)`：说明某个输出的规则。
- `rule` 是一个稳定的字符串 id，例如 `'frac.add'`、`'eq.both-sides'`、`'fig.shoelace'`。约定：
  - 规则 id 统一登记在新文件 `js/core/rules.js` 里：`U.RULES[id] = { label, essence: ['E4'], grade: [5, 6] }`；
  - lint 检查器材引用的 rule 都已登记；
  - 判分、报告、解释都按 rule 聚合。
- **追踪必须是纯数据**（可以 JSON 序列化），不能放函数，不能影响计算结果。不开追踪时（`evaluate(scene, { trace: false })`），结果必须和现在完全一样。

### 2.3 接口

```js
U.World.explain(scene, D, id, port)
// 返回这条输出的来历树（递归到没有输入的源器材为止，最多 depth 层，默认 6）：
// { id, name, port, value, rule, say, steps: [...], from: [ <同结构的子树>… ] }

U.World.explainText(tree)   // 把树转成几行人话（给报告、家长端、提示用）
```

判分视图补上 `design-v2.md` §2.1 里写了但还没实现的 `W.from(value, type, inputs)`：判断“这个值是不是由某类器材、从这些输入算出来的”。它要基于 `trace` 实现。

### 2.4 首批要接入追踪的器材

不要一次改完 56 种。先改最能体现“过程”的几种：

| 器材 | 要记的步骤 |
|---|---|
| 运算器 `op` | 分数加减：通分、分子相加、约分。乘除：约分在前还是在后 |
| 数位板 / 竖式类 | 每一位的进位、退位 |
| 带余除法 | 试商、余数小于除数的检查 |
| 天平 `balance` | 左右各是多少、差多少 |
| 量图形 `figmeasure` | 鞋带公式的每一项 |
| 三边定三角形 `tri` | 两边之和与第三边的比较、勾股的平方和 |

其他器材至少要有 `outputs` 的 rule（一句话），lint 先只给警告，不当错误。

### 2.5 界面

- 点连线上的值气泡，或者点卡片读数，弹出“这个数是怎么来的”面板：
  - 一层一层展开来历树；
  - 每一层显示器材名、规则、中间步骤。
- 练习模式第二层提示可以引用来历：例如“你的 11/15 是从这里来的，看看通分那一步”。

### 2.6 验收

- `tests/run.js` 新增“来历追踪”一组测试：
  - 2/5 + 1/3：`trace.steps` 里有通分一步；`explain` 能追到两张数字卡。
  - 关掉追踪时，所有现有测试结果不变（可以对全部参考解比较 `evaluate` 的输出）。
  - 有环（经过记忆器）时 `explain` 不会死循环：遇到有状态器材就停，标记“上一拍的值”。
  - `W.from` 能区分“同样得 6，一个是 192÷32 算的，一个是手填的 6”。
- 界面验收新增：点气泡能打开来历面板，能展开到源头。

## 3. 任务 B：方程、多元代数式、区间，以及连线类型转换

### 3.1 连线时真正执行类型转换（先做，量小）

现状：
- `U.kindOK(src, dst)` 只**检查**源 kind 的 `to[dst]` 存在；
- `world.js` 的 `gather` 收集输入时**不做转换**；
- `kinds.js` 里写了 `num → real`，但实际不会转。

要做：
- `gather` 收集输入时，如果源 kind 和口要的 kind 不同，调用 `U.KINDS[src].to[dst](data)` 得到新值。精确标记照传，`dim` 照传。
- lint：`to` 里的每一项必须是函数；转换不得把精确值变成近似值。设计要求有损转换必须经过一个显式的“近似器”器材。
- 首批转换：
  - `num → real`；
  - `num → expr`（常数多项式）；
  - `point → fig`（点图形）；
  - `fig(point) → point`；
  - `seq → set`。

验收：一张数字卡能直接接进只收 `real` 或 `expr` 的口，结果正确；不允许的转换仍然被拒绝，并说明原因。

### 3.2 多元代数式（扩展现有 `expr`）

现在的 `expr` 是一元多项式（系数数组）。改成多元多项式：

```js
// 单项式用排好序的变量指数表示：'x^2*y' ；常数项用 ''
expr = { terms: { '': Q, 'x': Q, 'x^2': Q, 'x*y': Q, … } }   // 系数为 0 的项不存
```

- 兼容：旧的一元系数数组要能转换过来。可以给 `expr` 加版本字段，或者新开一个 kind `poly`，再提供 `expr → poly` 转换，二选一，写进文档。
- 运算：`add`、`sub`、`mul`、`pow(n)`、`subst(var, value)`、`eval(env)`、`eq`（规范化后逐项比较）、`degree`、`vars`、`show`（按次数降序，`x²y` 的写法）。
- 分式（有理式）先不做，在文档里写明。

### 3.3 方程与不等式

新 kind `eqn`：

```js
eqn = { lhs: <expr>, rhs: <expr>, rel: '=' | '<' | '>' | '≤' | '≥' }
```

- **变形步骤是值的一部分。** 天平思想（E4 平衡与等价）：两边同时做同一件事。
  - `U.Eqn.apply(e, { op: 'add' | 'sub' | 'mul' | 'div', by: <expr> })` 返回新方程；
  - 两边乘除负数时不等号要反向，用 `rel` 体现；
  - 乘除 0 要拒绝并说明原因。
  - 每一步都要用任务 A 的 `c.step` 记下来。
- `U.Eqn.solveLinear(e, var)`：一元一次方程给出解；无解或有无穷多解时说明。
- `U.Eqn.isIdentity(e)`：`lhs − rhs` 规范化后为 0，就是恒等式，对应 E8 变量与任意性：“对所有 x 成立”和“对某个 x 成立”的区别。
- 方程组：二元一次方程组用消元法求解，每一步都记录。
- 区间 kind `interval`：`{ lo, hi, loOpen, hiOpen }`，允许无穷端。不等式的解集用它表示。
- 一元二次方程：判别式和求根公式要用 `U.Real` 给出精确根（例如 1 ± √2）。

### 3.4 首批器材

| 器材 | 作用 |
|---|---|
| 代数式卡 | 输入一个式子（有字母），输出 `expr`。需要一个小的式子解析器，只支持整式，数字、字母、+ − ×、乘方、括号 |
| 方程台 | 输入两个 `expr`，输出 `eqn`；属性选“两边同时做什么”；输出变形后的方程和“现在 x = ?” |
| 代入器 | 把 `expr` 或 `eqn` 里的字母换成数，输出数或真假 |
| 方程组台 | 两个 `eqn` 进，解出来 |
| 不等式数轴 | 把 `interval` 画在数轴上 |

已有的“解方程天平”（`eqscale`）和“变量盒”（`variable`）：
- 能输出 `eqn` 或 `expr` 的，加输出口；
- 原有读数不变，参考解回归必须全部通过。做法同“旧几何器材输出图形值”那次提交 `ffa3c18`。

### 3.5 验收

- 规范化：`(x+1)(x−1)` 等于 `x² − 1`；`2(x+y)` 等于 `2x + 2y`。
- 3x + 5 = 20，经过“两边减 5”“两边除以 3”得到 x = 5，每一步都有追踪。
- −2x > 4，两边除以 −2，得到 x < −2，不等号反向。
- 两边乘 0 被拒绝并说明。
- x² − 2x − 1 = 0 的根精确显示为 `1 + √2` 和 `1 − √2`。
- `x + y = 5, x − y = 1` 解得 x = 3, y = 2。
- `(x+1)² = x² + 2x + 1` 判为恒等式；`x² = 4` 判为方程。

## 4. 任务 C：数据表、拟合器与建模

### 4.1 新 kind `table`

```js
table = { cols: [ { name: '时间', dim: 'time' }, { name: '路程', dim: 'length' } ], rows: [ [Q, Q], … ] }
```

- 每一列可以有量纲，用 `U.Dim`，这样单位能一路带下去。
- 实测数据可能是小数：录入时用 `Q.fromNumber` 转成有理数。数据本身算精确（它就是这么测的），拟合结果按 4.2 的规则标精确或近似。

### 4.2 器材

| 器材 | 作用 |
|---|---|
| 数据表 | 学生可以在卡片上增删行、改数；输出 `table`；也能接一个 `seq` 或时钟采样进来生成表 |
| 取列 | `table` → `seq`（某一列），方便接已有的统计器材 |
| 散点图 | `table` 进，画两列的散点；可以叠一条 `fn` |
| 拟合器 | `table` 进，选模型：正比例 y = kx、一次函数 y = kx + b，以后扩展到反比例、二次。输出 `fn` 和残差。最小二乘在有理数上可以精确求出：正规方程的解是有理数，所以拟合结果精确 |
| 预测器 | `fn` + 一个 x，输出 y，并说明“这是模型给的预测，不是测量值” |

### 4.3 建模题模板

`design-v2.md` 里的 E12（数学建模）。在题目结构里加一个可选字段：

```js
model: {
  situation: '一辆车匀速行驶，每隔 1 小时记一次路程',   // 情境
  quantities: [ { name: '时间', dim: 'time' }, { name: '路程', dim: 'length' } ],  // 量
  relation: 'linear',          // 关系：正比例 / 一次 / 反比例 / 二次……
  check: '用模型预测第 5 小时的路程，再和实测比较'          // 回到情境检验
}
```

- `problem.js` 的 lint：有 `model` 的题，里程碑必须覆盖“选模型”“得到函数”“回到情境检验”三步。
- 证据等级：模型对数据的拟合属于 ①（举例），措辞写“和这些数据吻合”，**不说“一定成立”**。

### 4.4 验收

- 表 (1,60) (2,120) (3,180) 拟合成正比例，k 精确等于 60，残差为 0。
- 带测量误差的表，拟合出的一次函数系数是有理数，并且与手算的最小二乘结果完全相等。

## 9. 任务 E：几何构造（辅助线、剪切、移动、翻转、粘贴）—— 原型结论

> 2026-11-09 做了原型，用来验证“几何就是一张构造图”的统一方案是否可行。结论：**方案可行，但必须先解决两件事才能铺开**（见 9.3）。

### 9.1 统一方案

几何就是一张构造图：每个点、每条线都是一个小器材，由谁构造出来就和谁连线。求值、拖动、撤销、存档、判分全部沿用世界内核，不需要另起一套几何引擎。

| 操作 | 在方案里是什么 |
|---|---|
| 辅助线 | 只增加、不修改的构造（连线、中点、交点、垂足……）。原图不变，判分可以查“作没作 AB 的中点” |
| 剪切 | 用一条直线把多边形切成两块；交点仍是有理数，所以是精确的 |
| 移动、翻转、旋转 | “摆放”器材：左右翻、上下翻（以自己的左下角为准）、转 90° 的倍数、平移；和原来全等 |
| 粘贴（拼合） | 边对消：内部边一正一反抵消，剩下的边必须正好连成一圈；再核对面积之和，排除重叠和缝隙 |
| 解题 | 构造出来的性质（等面积、全等）可以继续接进其他器材；以后用“事实”值接证明脚手架 |

### 9.2 原型里已有的（`js/core/geo.js`、`packs/geo.js`、`problems/geo.js`）

- 内核 `U.Geo`：`midpoint`、`lineIntersect`、`foot`、`side`、`cut`（直线穿过边界正好两次时切成两块，凹多边形也行）、`place`（翻转 / 旋转 / 平移）、`merge`（粘贴成一个图形，去掉共线点）、`assemble`（能否正好拼成目标）。新值类型 `figs`（图形组）。
- 器材（图形组）：自由点 `gpt`、连线 `gseg`（默认画成虚线，表示辅助线）、中点 `gmid`、交点 `gint`、垂足 `gfoot`（同时输出垂线段）、围成多边形 `gpoly`、剪刀 `gcut`、摆放 `gplace`、拼合（粘贴）`gasm`、几何画板 `gboard`。
- 画板上可以直接拖：自由点改的是它的 x、y；摆放后的块改的是摆放器材的 dx、dy；按格点吸附。实现见 `js/ui/stage.js` 里的 `data-drag`：任何器材在画面里给元素加上 `data-drag`（器材 id）、`data-kx`、`data-ky`（属性名）、`data-s`（每格多少像素），就能被拖。
- 两道示例题（含参考解）：`geo-median-area`（中线把三角形面积平分，拖动顶点后仍然相等）、`geo-pgram-cut`（平行四边形沿高剪开，移过去拼成长方形）。在真实页面里拖动剪下的三角形 5 格，三个里程碑全部达成。
- 测量脚本：`node tools/geo-bench.js`。

### 9.3 实测结果与必须先解决的问题

**界面：构造不能再一个器材一张卡片。** 原型里每个点、每条线都是台面上的一张卡片，一道题就铺满了卡片和连线；画板里原图、目标、各块叠在一起，分不清谁是谁。铺开之前必须先做：
- **在画板上直接构造**：选工具（中点、连线、垂足、剪刀……），点画板上的点和线来创建，背后仍然是构造图，但这些构造器材不在台面上显示成卡片（可以作为画板这个容器的子实体）；
- **图层与图例**：原图、辅助线、剪下的块、目标分开着色，可以开关；
- 剪下的块直接在画板上拖动、点一下翻转或旋转，不需要单独的“摆放”卡片。

### 9.4 精确性的边界（照实告诉学生）

- 精确：只用直尺的构造（连线、中点、平行、垂直、两直线交点），90° 倍数的旋转，左右或上下翻转，有理数倍放缩。
- 部分精确：和圆有关的交点会出现根号，只有一个根号时用 `U.Real` 能精确表示；还没做。
- 只能近似：多层根号、任意角度的旋转（45° 需要把坐标扩成“有理数 + 有理数 × √2”，30°、60° 需要 √3，两者混在一起就超出范围）。近似值要标 ≈，证据等级最高到 ②。

### 9.5 原型没做的（铺开时要做）

- 9.3 的第 3 条（画板上直接构造）。
- 剪切只支持直线穿过边界两次（切成两块）；切成多块、沿折线剪还没做。
- 圆、圆和直线的交点、平行线、角平分线、中垂线等构造。
- “事实”值和证明脚手架的连接（例如输出“△ABM ≅ △ACM，依据 SSS”）。
- 判分视图里查询构造的辅助方法（现在示例题是用函数形式写的，带 `why_code`）。

## 10. 平台审视：支持更复杂的几何、代数、算术技巧（2026-11-09）

> 已完成（2026-11-09）：任务 F 形式层（js/core/form.js）、任务 G 可执行规则（js/core/rules-exec.js，规则 arith.*、alg.* 已实现，geo.midpoint 跳过）、J 的 BigInt 已合入（ad1484e）。以下只保留未完成的部分。
>
> 几何构造原型（第 9 节）暴露的问题不只在几何。代数变形、算术技巧（凑十、拆数、简便运算、竖式）会遇到同样的结构性缺口。本节写清楚哪里要改、按什么顺序改。任务编号接着第 9 节的 E 往下排：F–J。

### 10.1 现在擅长什么

底层是围绕“值”设计的：器材算出一个值，值沿连线流动，判分看最终的值满足什么性质。这适合“算出结果、看规律”的实验，例如分数相加、骰子统计、拟合直线。

来历追踪、方程、多元多项式、表格、规则登记补上以后，“值”这一层已经相当完整。

### 10.2 四个结构性缺口

| 缺口 | 现象 | 影响 |
|---|---|---|
| 只有值，没有形式 | 有理数一创建就自动约分（2/4 直接成了 1/2），多项式自动合并同类项（3x + 2x 直接成了 5x） | 约分、合并同类项、凑十（8 + 5 = 8 + 2 + 3）、剪拼这些“形式变了、量没变”的过程，在底层就被抹掉了，学生看不到，也没法当成一个操作去做 |
| 规则只能登记，不能执行 | `rules.js` 只记规则的名字、说明、本质和年级 | 剪、移、翻、移项、展开、因式分解、拆数、凑整各自写死在器材里，没有统一的“一步”，过程留痕和判分都没有统一的落点 |
| 一个器材一张卡片 | 几何原型里每个点、每条线都是一张卡片，一道题就铺满了台面 | 点、线、项、数位这类细粒度对象没地方放；算术和代数会遇到同样的问题 |
| 判分只看结果 | 里程碑只能查台面上某个值满足什么条件 | 判断不了“是不是用因式分解解的”“是不是最简形式”“作没作中线”；函数形式条件占比因此偏高 |

另外三处要跟着改：精确数（BigInt、二次扩域）、性能（全量重算、全量重画）、工程流程（手动维护文件清单、多会话同时改）。

### 10.5 任务 H：工作区（几何、代数、算术共用一套）

> 2026-11-09 修订。用户在原型里实际操作后反馈：每个几何器材都是一个封闭的单元，图形画出来以后很难再编辑；希望几个图形能合在一起，再在里面剪、转、作辅助线。讨论过两种做法，结论如下。

#### 10.5.1 为什么不“融化”

一种做法是：把器材放进画板以后“融化”成画板自己的点、线、面，所有操作都在画板内部的另一套模型里完成。**不采用**，原因有两个：

1. **会丢掉参数**。长方形的长和宽、三角形的三边，融化后只剩一堆点。“改一下底边，整个剪拼过程跟着变”就做不了了，而“改参数，看规律还成不成立”恰恰是实验室最有价值的地方。
2. **会出现两个世界**。画板里一套点、线和依赖关系，台面上一套器材和连线。撤销、存档、判分、来历追踪都要在画板里再做一遍，相当于在平台里又写一个平台。

#### 10.5.2 采用的做法：一个模型，换一种看法和操作方式

用户觉得难编辑，问题不在模型，而在于**每个对象都显示成一张卡片，每个操作都要拖器材、接端口**。所以只改“怎么看、怎么操作”，不改模型。

1. **模型只有一个，就是现在的世界**。图形、剪刀、摆放、合并、中点、移项、凑十，仍然是世界里的器材，用连线表示“由谁得来”。求值、撤销、存档、分享、判分、来历追踪全部沿用。
2. **工作区是一个视图**。工作区是一种容器器材（沿用 1.10 的容器）：器材放进去以后**不融化，只是不再显示成卡片**，而是在工作区里画出来，带可以拖的把手。工作区里显示的是所有相关的值（原图、合并后的图形、剪出的块、辅助线；或者一串式子），不管它们来自哪个器材。
3. **工具作用在画面上看到的任何对象上**。学生在工作区里选中一个对象（来源无所谓），再选工具。工具在背后自动创建对应的器材并接好连线，学生看不到卡片，也不用接端口。例如：选中两个三角形点“合并”得到新图形；再选中它点“剪”画一条线；再选中剪下的一块点“转 90°”。
4. **步骤历史就是那张构造图，而且是活的**。工作区旁边有一列步骤，每一步就是背后的一个器材：可以点开看、改参数、删除。回去改第一步，后面的步骤自动重算。这就是“过程清晰可见”和“推广”的底层。
5. **把手**：每种器材声明自己的把手（见 10.5.4），拖把手就是改这个器材的参数。沿用第 9 节的 `data-drag` 机制。
6. **定型**：步骤太多，或者学生想完全自由地改时，点“定型”，把当前结果固化成一个新的起点（几何是自由多边形，每个顶点都能拖；代数和算术是一个新的式子），之前的历史折叠起来。“融化”的好处作为一个可选操作保留。

#### 10.5.3 三类工作区怎么对应

| | 几何画板 | 式子工作台 | 算术工作台（含竖式） |
|---|---|---|---|
| 被变形的对象 | 图形（`fig` / `figs`） | 式子、方程（`form` / `eqn`） | 算式（`form`） |
| 每一步保持不变的 | 面积、全等（形状大小） | 方程的解 | 算式的值 |
| 典型的一步 | 剪开、平移、旋转、翻转、合并、作中点、垂线、平行线 | 移项、合并同类项、两边同除、去括号、提取公因式 | 拆数、凑十、凑整、交换、结合、进位、退位 |
| 操作手感 | 在空间里拖把手、画线、框选 | 选中一项、拖过等号、点按钮 | 选中数、点“拆”“凑”，竖式里点某一位 |
| 改前提 | 改第一步的三角形，剪拼全部重算 | 把 3x + 5 = 20 的 20 改成 26，解跟着变成 7 | 把 8 + 5 的 5 改成 6，凑十自动改成拆 2 + 4 |

三类工作区的界面不同，但背后共用：步骤器材、规则检查（`U.applyRule`，不变量按领域分别检查）、步骤历史、撤销、判分和来历追踪。

因为都在同一个世界里，结果可以互相连线。例如平行四边形剪拼得到的面积，可以接进式子工作台，把底和高当成字母，写出 S = a × h。

#### 10.5.4 接口

- **步骤器材**：一个通用的器材类型 `step`。
  - 属性：`rule`（规则 id）、`at`（作用位置，见 10.5.5）、`args`（规则参数）；
  - 输入：上一步的值；输出：这一步的结果；
  - `compute` 调 `U.applyRule`，把 `why` 写进信号条，把 `kept` 为假的情况标出来。
  - 几何里的构造（中点、交点、垂足）沿用第 9 节的构造器材，也算步骤。
  - 原型里的剪切（`Geo.cut`）、摆放（`Geo.place`）、粘贴（`Geo.merge`）要登记成规则（`geo.cut`、`geo.place`、`geo.merge`，`keeps: 'area'` 或 `'congruence'`，并提供 `check`）。`rules-exec.js` 里说 `geo.midpoint` 跳过了，这里一起补上。
- **工作区器材**：容器器材，额外声明：

```js
workspace: {
  shows: ['fig', 'figs'],            // 显示哪些 kind 的值
  tools: [ { id: 'cut', label: '剪', needs: ['region', 'line'], rule: 'geo.cut' }, … ],  // 工具：要先选中哪些对象、对应哪条规则或哪种构造器材
  draw(view, items, selection) { … },   // 画工作区；items 是所有显示的值及其来源（器材 id、端口）
  hit(view, x, y) { … },                // 点在哪个对象上：返回 { source: { id, port }, part: 稳定引用 }
}
```

- **把手**：器材可以声明 `handles(ent, out) → [ { at: 点, props: { x: '属性名', y: '属性名' } } ]`。工作区把它们画成可拖的点，拖动时按格点吸附并改对应属性。
- **新的动作 `t: 'tool'`**：`{ t: 'tool', ws: 工作区 id, tool, picks: [选中的对象引用], args }`。它在世界里新增一个步骤器材（或构造器材）、接好连线、放进工作区。这样撤销、事件流、断点续做都能直接用。
- **定型**：`{ t: 'bake', ws, from: 来源引用 }` 用当前值新建一个自由起点（自由多边形 / 新的式子），把它之前的步骤折叠（保留在存档里，可以展开查看）。

#### 10.5.5 必须先解决：引用要稳定

工具引用“这一块”“这个顶点”“这一项”时，**不能按顺序号引用**。上游一改（比如剪切多出一个交点、方程里多了一项），顺序号就会变，后面的步骤会引用错。这是参数化建模里的经典难题，必须在铺开前定下来：

- **几何**：每个点带一个稳定的名字。原图的点用 A、B、C；构造出来的点用来历命名，例如“线 l 与 AB 的交点”“BC 的中点”。剪出的块用“剪切步骤 id + 在线的哪一侧”命名。
- **代数和算术**：每一项带来源，例如“第①步里的 +5”“第②步拆出来的 2”。`form` 的节点需要加一个可选的 `tag` 字段（现在只有 `at` 下标路径）。
- **引用一律用名字或来源**，不用下标。上游改动后找不到被引用的对象时，这一步显示原因（例如“剪切线不再穿过图形”“第①步里已经没有 +5 了”），后面的步骤暂停，不会悄悄算错。

#### 10.5.8 好用的要求（交互规范）

> 2026-11-09，用户试用几何工作区后提出两条要求：
> - **所有器材都要能改大小，工作区也不例外**；工作区里的构件要能直接用鼠标拖动、改变大小，否则太难用。
> - **拖动时周围要出现对齐线**，方便移到对齐的位置上。
>
> 下面是按这两条展开、并对照当前界面截图（8ea3de1）整理的完整要求。每一条都要有界面验收测试。

**当前界面里看到的问题（截图核对）**

- 工作区卡片固定 310 × 225，图形挤在一起，不能拉大。
- 工具栏是卡片下面的一大块面板，所有工具都一直摆着，和选中的对象无关。
- “移动”要在输入框里填数字。
- 图层和标签显示内部名字（`poly(A,B,C,D)`），和“四边形1”叠在一起，看不清。
- 目标长方形实心填充，完全盖在平行四边形上，分不清谁是谁。
- 卡片标题写“6 步”，步骤列表却写“还没有步骤”。开场的构造和学生做的步骤混在一起计数。

**A. 改大小**

1. **所有器材卡片都能改大小**：右下角有拖柄；拖动时显示当前尺寸；有最小尺寸；双击拖柄恢复默认。尺寸存在实体上（例如 `e.w`、`e.h`），优先于器材的 `size()`；撤销、存档、分享都要带上。器材的 `draw` 已经收到 `c.w`、`c.h`，按实际尺寸画即可，需要逐个检查画法会不会被拉坏。
2. **工作区内容跟着卡片大小缩放**：拉大卡片，坐标范围不变、画得更大；另有“适应”按钮，按内容自动选坐标范围。
3. **工作区有自己的缩放和平移**：在工作区里滚轮缩放、拖空白处平移，不影响整个台面。
4. **专注模式**：双击工作区标题，把它放大成覆盖台面的浮层，再双击或按 Esc 还原。复杂的剪拼题在这里做。

**B. 直接用鼠标改形状、改大小**

5. **拖整块**：移动（已有一部分，要去掉输入框，改成直接拖）。
6. **拖顶点**：改形状。顶点来自自由点时改它的坐标；来自参数化器材时按器材声明的把手改参数，例如长方形的角改长和宽，见 10.5.4 的 `handles`。
7. **拖边**：整条边平移，改变形状，例如把长方形拉长、把三角形的底边挪开。
8. **改大小（放缩）**：选中后四个角出现方形把手，拖角按比例放缩；比例吸附到常见的有理数（1/2、2/3、1、3/2、2、3），保持精确；放缩中心是对角，按住 Alt 时以中心为准。
9. **旋转把手**：选中后上方出现圆形把手，拖动旋转，吸附到 90° 的倍数（以后有二次扩域坐标时，再加 45°、30°、60°）。
10. **翻转**：选中后在浮动工具条里点“左右翻”“上下翻”。
11. **画线**：选“连线”或“剪”后，直接在画布上点两下画出线，不需要先有两个点；点会自动吸附到顶点、边上的点和格点。

每一次拖动松手，都等于一个工具步骤（`t: 'tool'`），进步骤历史，可以撤销。拖动过程中只重画工作区，不重画整个台面（见任务 J）。

**C. 对齐线与吸附（用户特别提出的要求）**

12. **拖动时显示对齐参考线**：拖动的对象（整块、顶点、边）靠近下面这些位置时，出现细的参考线，并自动吸附上去：
    - 和别的对象的顶点在同一水平线或同一竖直线上；
    - 边和别的边共线（拼合时最常用）；
    - 顶点和别的顶点重合；
    - 边和别的边平行、垂直；
    - 和别的对象等距（三个以上对象时）；
    - 对齐坐标轴和格点。
13. **吸附阈值按屏幕像素算**（例如 6 像素），和缩放无关；按住 Alt 时暂时不吸附。
14. **参考线旁边写出对齐关系**，例如“和 AB 共线”“顶点重合”“和 CD 平行”，让学生看见几何关系本身。
15. **吸附后的坐标必须是精确有理数**，直接取对方的精确坐标，保证吸附以后全等、拼合这些判定仍然精确。
16. **拼合时的吸附**：剪下的块靠近目标位置时，边自动吸到对应的边上；松手后自动检查能不能拼成，能拼成时边线变绿并闪一下。

**D. 看得清**

17. **标签自动避让**，不互相重叠；名字用学生能懂的写法（A、B、C，“四边形 ABCD”“剪下的三角形”），不显示 `poly(...)` 这类内部名。
18. **图层和图例**：原图、辅助线、剪下的块、目标分颜色；**目标图形用虚线轮廓，不填充**，不遮挡别的图形；图层开关用中文名。
19. **量贴在图形旁边**：选中对象时显示面积、边长、角度；拖动时实时更新，让学生亲眼看到“面积没变、周长变了”。
20. **步骤计数和列表一致**：开场构造（题目给的）和学生做的步骤分开显示，标题只数学生的步骤。

**E. 工具栏和反馈**

21. **浮动工具条代替大面板**：选中对象后，在对象旁边浮出只对它有用的工具；工具不能用时变灰，悬停说明原因（例如“剪需要先选一个图形，再画一条线”）。
22. **错误就地显示**：例如“剪切线没有穿过图形”，在画布上靠近那条线显示，不只是写在信号条里。
23. **步骤列表能回看**：点某一步，画布预览那一步的样子；可以从那一步撤销。

**F. 键盘和触屏**

24. **键盘**：方向键移动一格（Shift 加方向键移动五格）、R 转 90°、F 左右翻、Delete 删除选中的步骤、Esc 取消当前工具。
25. **触屏**：单指拖、双指在工作区里缩放、长按出菜单；把手至少 24 像素，适合手指。

**G. 一致性**

26. 普通器材卡片和工作区用同一套选中样式、同一套改大小拖柄、同一套浮动工具条，学生学一次就会。

**验收**（界面验收里各一条）

- 拉大普通器材和工作区卡片，内容按新尺寸画出，撤销能恢复原尺寸，存档读回尺寸不变。
- 在工作区里只用鼠标：拖长方形的角改长和宽；拖三角形的顶点改形状；按比例放大一个三角形，读数显示面积变为 4 倍；旋转把手转 90°。
- 拖剪下的块靠近目标时出现“和 AB 共线”的对齐线并吸附，松手后自动判定拼成，里程碑达成。
- 吸附后的坐标是精确的有理数：拼合判定和全等判定都成立。
- 标签不重叠，图层用中文名，目标图形是虚线轮廓。
- 步骤标题的数字和步骤列表一致。

#### 10.5.9 设计意图展开：直接操作的数学工作区

> 2026-11-09，按用户的意图展开。10.5.8 是具体的功能清单；这一节说清楚背后的意图、原则，以及由此推出的更多要求。
>
> 用户的意图可以概括为一句话：**学生直接用手去“摆弄”数学对象，就像摆弄真实的纸片、尺子和算珠一样顺手；每一个手势本身就是一个数学动作，而且看得见、退得回、量得准。**

##### 一、七条设计原则

1. **直接操作优先**：能拖的不点按钮，能点的不填输入框，能在画面上做的不去面板里做。输入框只用于“精确地填一个数”。
2. **手势即数学**：每个手势都对应一个有名字的数学动作（平移、旋转、翻转、放缩、剪、拼、移项、拆数），动作完成后在步骤历史里留下这个名字。学生做的是数学，不是在操作软件。
3. **所见即所得，所得即精确**：手上拖得随意，落下的结果必须精确。吸附、比例和角度都落在精确值上，判定永远不用浮点。
4. **关系看得见**：对齐、共线、平行、垂直、相等、重合，在拖动时就显示出来，并能“锁住”成为约束。几何关系不只是结论，在操作过程中就看得到。
5. **过程能回放**：每一步都能回看、撤销、修改；整段过程能像动画一样重新播放一遍。
6. **不怕犯错**：任何操作都能撤销；不合法的操作就地说明原因；学生的东西不会丢（自动保存）。
7. **同一套手感贯穿几何、代数、算术**：选中、拖动、吸附、对齐线、浮动工具条、步骤历史，在三类工作区里一样。

##### 二、由原则推出的更多要求（在 10.5.8 之外）

**1. 约束：把“对齐”变成“关系”**

- 吸附到某个关系后（共线、平行、垂直、等长、重合、中点），出现一个小锁按钮；点一下就把这个关系锁成约束，以后拖动时一直保持。例如锁住“AB 平行于 CD”，拖 A 时 B 跟着动，保持平行。
- 约束本身就是世界里的构造器材（平行线、垂线、中点、等长），不另起机制；锁和解锁也进步骤历史。
- 被约束的把手只能沿允许的方向拖：顶点锁在线段上，就只能沿线段滑；锁在圆上，就只能沿圆走。
- 冲突的约束（例如既要平行又要垂直）不让加，并说明原因。

**2. 尺寸驱动：直接改数字**

- 边长、角度、面积的标注可以双击编辑：把边长改成 5，图形就改成边长 5；把角改成 90°，就变成直角。这是“量”和“形”的双向连接。
- 能改的只有自由度：受约束或由别的对象决定的量，标注是灰的，悬停说明“它由 BC 的中点决定”。

**3. 多选、编组、对齐和分布**

- 框选或 Shift 点选多个对象；可以编组（作为一块一起移动、旋转），也可以取消编组。
- 选中多个对象时，浮动工具条提供“左对齐、右对齐、上对齐、下对齐、水平居中、等间距分布”。

**4. 复制、粘贴、镜像复制**

- Ctrl+C / Ctrl+V 复制粘贴一块；Ctrl+D 原地复制；“镜像复制”生成翻转后的副本。复制出来的块记住“来自哪一块”，原来的块改变时，副本跟着变，除非先定型。
- 用途：拼图题需要多块全等的图形，对称题需要镜像。

**5. 工作区里直接添加图形**

- 工作区有自己的小图形库：点、线段、三角形、长方形、正方形、圆、多边形（逐点点出来）。直接拖进工作区，或者在画布上拉出一个框画出来，不需要先去台面的器材架拖器材。
- 画多边形时，每点一个顶点都会吸附到格点、已有的点和对齐线上。

**6. 尺子、量角器和标注**

- 尺子和量角器是可以拖到画面上的工具，量的结果贴在图上，可以留在画面里作为标注。
- 标注工具：标点名、标相等边（一道杠、两道杠）、标相等角、标直角、标平行（箭头），以及文字备注。标注会跟着图形移动。

**7. 动画：让变换看得见**

- 旋转、翻转、平移、剪开、拼合执行时，播放短动画（0.3–0.6 秒）：块转过去、翻过去、滑过去，剪开时两块稍微分开。
- 步骤历史上方有一条时间条：拖动时间条，就把整个过程从头播放到某一步。老师讲解、学生复盘都用它。
- 动画可以关掉（设置里，也照顾晕动症）。

**8. 幽灵对照**

- 拖动时，原来的位置留一个半透明的“幽灵”，方便对比移动了多少、形状变了没有。
- 两块可以叠在一起比较（半透明叠放），直观判断全等或面积大小；面积是否相等，同时在读数里精确判定。

**9. 视图辅助**

- 网格、坐标轴、坐标读数（鼠标悬停时显示所在格点的坐标）都可以开关。
- 缩放到选中的对象；一键回到全图。
- 每个工作区记住自己的缩放和位置，存档时一起保存。

**10. 题目给定的东西要受保护（出题人控制）**

- 题目可以声明哪些对象是“已知”的、锁定不能动（例如原来的平行四边形），哪些参数允许学生拖（例如只能拖剪下的块）。
- 被锁定的对象有锁的图标；试图拖动时提示“这是题目给的条件，不能改”。
- 出题人（包括学生出题，第 4 节）在编辑模式里设置这些。

**11. 低年级模式**

- 工具更少（只有移动、旋转、翻转、拼合），按钮和把手更大，吸附更强（更容易对上）。
- 不显示坐标和分数，只显示格子数。
- 自动检查更积极：块放对了就立刻变绿。

**12. 对齐线的思想推广到代数和算术**

- **竖式**：拖数字时显示数位对齐线（个位对个位），对不齐的位置吸不上去；进位的小数字自动落在上一位的上方。
- **式子工作台**：拖一项时显示可以放下的位置（等号另一边、某一项旁边、括号里），放到等号另一边时自动变号，并显示“移项：+5 变成 −5”；同类项靠近时出现“可以合并”的提示线。
- **算术工作台**：拆数、凑十时，拖到能凑成整十的位置时出现提示（“8 和 2 凑成 10”）。
- 原则相同：**拖动时把“能放在哪里、放下以后数学上意味着什么”提前显示出来。**

**13. 手感和性能**

- 拖动跟手：拖动过程中画面延迟不超过一帧（16 毫秒），只重画工作区。
- 吸附有“磁性”的手感：靠近时轻轻吸过去，用力拖开就脱离；被吸住时有细微的视觉反馈。
- 精确数在拖动中只算必要的部分；BigInt 已经合入，但拖动时要避免每一帧都做全量判定，判定可以在松手时做。

**14. 不丢东西**

- 每一步自动保存（已有断点续做，扩展到工作区的视图状态）。

### 10.6 任务 I：判分看路径和形式

在 `judge.js` 的数据形式条件里，新增三类查询，并在 `problem.js` 的 lint 里认这些写法：

```js
{ built: { rule: 'geo.midpoint', of: ['B', 'C'] } }      // 构造查询：作没作 BC 的中点（按角色）
{ form: { role: '结果', is: 'factored' } }                 // 形式查询：结果是不是因式分解形式
{ steps: { used: 'alg.factor', allKept: true } }          // 步骤查询：用没用某条规则、每一步是否都保持了不变量
```

- 第 9 节两道示例题的函数形式条件改写成数据形式，去掉 `why_code`。
- 题库的函数形式占比应该下降。在 `docs/coverage.md` 里记录前后对比。

### 10.7 任务 J：精确数、性能、工程流程

- **二次扩域坐标**：几何坐标支持“有理数 + 有理数 × √d”（同一道题里只用一个 d），这样 45° 旋转（d = 2）和 30°、60° 旋转（d = 3）都能精确表示。混用不同 d 时，退回近似值并标 ≈。
- **增量求值和局部渲染**：
  - 现在每次操作都全量重算（`evaluate`），全量重画台面（`worldEl.innerHTML`）；
  - 改成只重算受影响的下游器材，只重画变化的卡片或工作区；
  - 验收：工作区里 300 个对象，拖动一个点能保持流畅（每帧 16 毫秒以内），可以在测试里计时。
- **文件清单自动生成**：新增文件时现在要手动改 `index.html`、`tests/run.js`、`tools/check-types.js`、`loader.js` 四处。改成一份清单（例如 `manifest.js`），四处都从它读，或者用脚本生成。
- **一次只让一个会话改这个文件夹**：两个会话同时在 `main` 上改同一批文件，已经出现过改动互相带走、提交了未完成的改动、测试跑不起来的情况。并行工作请用独立的 git worktree，做完再合并。

### 10.8 顺序

1. **H 通用工作区**：先把几何画板改造成工作区，再做式子工作台和竖式工作台。
2. **I 判分看路径和形式**。
3. **J 的其余部分**（二次扩域、增量求值和局部渲染、文件清单）：等工作区里的对象真正多起来时做。性能验收不过，就不要往下铺内容。

H 完成后，几何的剪拼、代数的移项、算术的凑十，在平台上就是同一种东西：在工作区里对一个形式应用规则，过程自动留痕，判分既能看结果，也能看路径。
