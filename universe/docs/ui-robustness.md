# 界面健壮性设计：从根本上解决“同一件事有多条路径、各自不一致”的一类问题

> 读者：接手修复的 agent。写于 2026-11-09，对应 `main`（含 `656edfa`）。
> 本文先讲症状和复现，再讲**根因**（不是只修这一个 bug），然后给出架构方案、分步任务和验收。
> 所有数字都是在当前代码上实测的；没有核实过的地方标了“待核实”。

---

## 1. 症状

用户试用几何工作区，反馈：“有很多问题，多个图形放上去不见了等。”

在真实页面里用鼠标复现（脚本：`tools/probes/ws-drop.js`，运行方法见第 7 节）：

| 操作 | 当时的结果 |
|---|---|
| 从右边器材架把三角形、长方形、圆拖到工作区上 | 三个图形都**没有放进工作区**；成了三张普通卡片，落在同一个位置，叠在一起盖住了工作区，最上面的圆挡住了另外两个——“不见了” |
| 把台面上已有的卡片拖进工作区 | 放进去了，但三个图形都出现在各自参数里的坐标上（都从原点附近开始），互相叠在一起 |
| 放进去以后看名字 | 长方形、三角形都叫“多边形”；一个普通的四边形被叫成“目标图形” |
| 每放进一个新图形 | 工作区重新缩放一次，原来的图形突然变小、跳位置 |
| 点击器材架的瓦片添加 | 新卡片盖在工作区的工具面板上 |

其中“放不进去”“位置”“名字”“缩放”“新卡片盖住面板”已经在 `656edfa` 里修了（修复方法见第 3 节）。**但这些只是同一类问题里被用户碰到的几个**。本文要解决的是这一类问题本身。

---

## 2. 根因分析

### R1　同一个用户意图，有多条代码路径，各自实现，互不一致

“把一个东西放进容器”这一个意图，在界面里至少有这些入口，每个入口各自写了一套：

| 入口 | 位置 | 修复前的行为 |
|---|---|---|
| 从器材架拖到台面 | `panels.js` `initShelfDrag` | 只新建器材，**不检查落点是不是容器** |
| 拖台面上已有的卡片到容器上 | `stage.js` `dropOnContainer` | 放进容器，不管位置 |
| 点击器材架瓦片 | `panels.js` | 只新建，放在屏幕中央，不避让 |
| 工具创建（连线、剪、中点） | `stage.js` 工具代码（约 1047–1059 行） | 自己调 `put` |
| 拖块到工作区外 | `stage.js` 约 586–587 行 | 自己拼 `take` + `move` |

统计（`js/ui` 里的动作调用点）：`add` 5 处、`put` 5 处、`del` 4 处、`move` 3 处、`set` 12 处。**同一个动词在多个地方各自实现**，修好一处，其他几处不会跟着好。

这是“放上去不见了”的直接原因：只有“拖已有的卡片”这一条路被照顾到了，“从器材架拖”这条最常用的路径从来没走通过。

### R2　一个手势不是一个事务

一次用户手势应该是一次撤销、一条事件、一次自动保存。现在不是：

- 有三个相似的函数各自实现“一串动作”：`act`、`actMany`、`build`（`app.js` 105–145 行），逻辑重复。
- 修复前，从器材架拖进工作区是**两个**动作（先 `add`，再 `put`），**两个撤销项**。实测（`tools/probes/ws-undo.js`）：拖入一个三角形后撤销一次，台面上还剩下一张游离的三角形卡片，不是回到空工作区。**这一条目前仍然存在**（见第 3 节“未修”）。
- `stage.js` 里有 2 处直接调用 `W.act`（调整大小、拖动卡片），绕过了 `UI.App.act`；它们要靠手工调 `snapshot()` 才有撤销，容易漏。
- 事件流（`recordSession`）、自动保存（`saveFree`）、判分检查是否触发，都依赖走了 `act`。绕过去的路径，行为不可预期。

### R3　界面状态放在 scene 之外，不进存档、不进撤销

`S.wsView`（工作区的缩放和平移）在 `stage.js` 里有 33 处引用，另外还有 `wsSel`（21 处）、`wsDraw`（16 处）、`wsMsg`、`wsHidden`（图层开关）、`wsArgs`、`focusWs`、`wsSig`、`wsFit` ……这些全是全局可变状态，挂在 `UI.S` 上。

实测：
- `wsView` **不在存档里，也不在撤销快照里**。刷新页面后工作区会重新“自动适应”，图形的位置和大小和刷新前不一样。
- 撤销不会恢复视图；分享链接也带不走视图。
- `S.wsView` 被冻结的逻辑（“放一个就缩放一次”的修复）依赖它不丢，但一刷新就丢了。

没有规则说明“哪些状态该存、哪些不该存”，所以每个新功能都随手加一个 `S.xxx`。

### R4　界面层认识具体的器材，把示例题的特判写死

`stage.js` 里按具体器材类型写的判断有约 40 处：`type === 'gpiece'` 10 次，`gcut`、`gpt`、`gplace`、`gasm` 等；`panels.js`、`app.js` 里也有。例如：

- 曾经有 `if (it.type === 'fquad') return '目标图形'`：为了让“平行四边形剪拼”这道题的目标图形显示得对，把**所有四边形**都叫成了目标图形。修复后改成看题目给的 `role`。
- `STEP_TYPES = ['gseg','gmid','gfoot','gcut','gplace','gasm']` 是界面里写死的“哪些器材是步骤”。以后每加一个步骤类器材，就要改 `stage.js`。

这违反平台自己的原则：“加一种器材只改一处”（`kernel-api.md`）。后果是：几何器材越多，界面越脆；其他领域（代数、算术工作区）也要重复造一遍。

### R5　布局靠魔法数字和估算

- 工作区下面的工具面板挂在“世界坐标”里：`top = g.y + g.h + 36`。面板高度没有测量，用估算：`stage.js` 里同一个“面板高度”出现了两个不同的值——`+ 36 + 420`（算滚动范围）和 `+ 36 + 270`（避让新卡片）。它们不一致，所以一个地方算是够的，另一个地方算是被盖住的。
- `HD = 28`（卡片标题高度）散落在多处，有的地方加了一次，有的地方重复加了。（修复时就发现一处多加了 `HD`。）
- 面板随台面缩放，靠近屏幕底边时被底部的时钟栏挡住，或者跑到屏幕外。没有统一的“夹在可视区内”的逻辑。

### R6　坐标系混用，没有统一的换算层

同一个图形上的点，至少有四种坐标：屏幕像素、台面世界坐标、工作区坐标（几何单位）、器材参数（`dx`、`dy`、`ax`、`ay` 这些整数属性）。

换算函数 `scr`、`worldAt` 只有工作区用，台面的 `toWorld` 单独一套，吸附和对齐线又用自己的计算。凡是要“把鼠标位置变成某个参数”的地方，都重新推一遍，容易错（例如落点用屏幕中心而不是鼠标位置）。

### R7　测试有盲区

`tests/ui.js` 约 860 行：用真实鼠标的操作 30 处，**程序直接调用 `UI.App.act` 的 35 处**。程序调用绕过了所有手势代码，测不到“从器材架拖”这类路径。

- “从器材架拖到工作区”这条用户最先会做的路径，**从来没有被鼠标测过**，所以它坏了很久都没人发现。
- 测试大多只走“示例题的路径”（两道几何题），题目之外的通用操作（多个图形、不同位置、混着放）没覆盖。
- 没有“不变量检查”：一次手势后有没有多出游离的卡片、撤销一次能不能完全回去、存档读回是否等价、所有图形是否都看得见。
- 没有“一致性检查”：同一个意图从不同入口做，结果应该一样。

### R8　工程流程：多个会话共用一个工作树

两个会话同时在同一个文件夹里改代码，各自提交。已经发生过：**本次我正在改的、还没完成的 `wsdrop` 代码和测试，被另一个会话的提交 `656edfa` 一起提交了**（从提交内容看，是把整个文件夹里的改动一起提交的）。结果是半成品进了 `main`，作者归属也混了。之前还出现过：另一个会话改到一半的 BigInt 还没提交，别的会话跑测试时就有项目失败。

没有“谁在改哪个文件”的约定，也没有提交前的统一检查。

## 3. 现状：已修的和还没修的

### 3.1 已经修了（`656edfa`，另有测试）

- 统一的放入入口：世界动作 `t: 'wsdrop'`（`packs/piece.js` 的 `dropInto`）。从器材架拖、拖台面上的卡片，都走 `UI.Stage.dropOnContainer`，对工作区用 `wsdrop`。
- 图形落在鼠标松开的位置（用块的 `dx`、`dy`，按图形中心对齐）。
- 名字按器材名加序号（“三角形 1”“长方形 1”“圆 1”）；“目标图形”改看题目给的 `role`。
- 放进去之前先把工作区的坐标范围冻结，不再每放一个就缩放。
- 新卡片避让已有卡片和工作区的工具面板（`freeSpot`）；空工作区显示“把图形拖到这里”。
- 工作区默认大小从 300×220 改成 380×300。

### 3.2 同类问题，**还没修**（实测或读代码确认）

| 编号 | 问题 | 依据 |
|---|---|---|
| P1 | 从器材架拖进工作区还是 **两个撤销项**：先 `add`，再 `wsdrop`。撤销一次，留下一张游离的卡片 | `ws-undo.js`：拖入后实体 3 个，撤销一次变成 2 个（期望只剩工作区 1 个） |
| P2 | `S.wsView` 等不进存档、不进撤销、不进分享；刷新后重新适应 | 读代码；`ws-undo.js` 显示 `wsView` 不在存档里 |
| P3 | 工作区面板高度仍是估算值（270 和 420 两个值不一致）；靠近屏幕底边仍会被挡 | 读代码（`stage.js` 508、1180 行） |
| P4 | 删除有 4 个入口（Delete 键、工具条、对话框、工作区内部删步骤），工作区内部那个直接 `A({t:'del'})`，不经过“删容器时问一下”的流程 | 读代码（`app.js` 148–150、428；`stage.js` 313–314、1337） |

## 4. 解决方案

核心思想：**把“界面做什么”和“怎么做”分开，每个用户意图只有一个实现；界面状态有明确的归属；测试按手势、按不变量写。**

### 4.1 意图层：每个用户意图只有一个入口

新增 `js/ui/intent.js`，导出 `UI.Intent`。

- 手势代码（拖、点、键盘）**只负责识别手势并产生意图**，不再自己拼动作。例如：

```js
UI.Intent.run('drop', { id, point: { clientX, clientY }, from: 'shelf' | 'card' | 'click' })
UI.Intent.run('delete', { id })
UI.Intent.run('move', { id, to: … })
```

- 每个意图是一个函数：解析目标（落点下面是什么容器）、计算参数（用统一的坐标换算，见 4.5）、生成**一个事务**（见 4.2）。
- 规则：`stage.js`、`panels.js`、`app.js` 里**不允许**直接写 `act({ t: 'put' … })`、`act({ t: 'add' … })` 这类动作调用来表达用户手势。lint：用一个小脚本 `tools/lint-ui.js` 扫描这些文件，发现就报错。
- 现有的入口逐个改成调用意图：器材架拖放、点击添加、卡片拖放、工具创建、块拖出、删除。

### 4.2 事务：一个手势就是一个撤销项

- 把 `act`、`actMany`、`build` 合成一个 `UI.App.tx(label, fn)`：
  - 开头记快照；`fn(A)` 里用 `A(动作)` 依次执行；
  - 任何一步失败，整个回滚到快照，并就地提示原因；
  - 成功后：**一个撤销项**、**一条事件**（带手势的名字）、**一次自动保存**、**一次重新渲染**。
- 老接口 `act`、`actMany`、`build` 保留成 `tx` 的薄封装，逐步迁移。
- 拖动过程中（鼠标按下到松开）的中间状态不进撤销；松开时才提交一个事务。
- `stage.js` 里直接调 `W.act` 的 2 处，改成走 `tx` 或者明确标注“拖动预览”，松手时再提交。

### 4.3 界面状态分层：该存的存进 scene

给每个界面状态定类别，登记在 `UI.STATE_SPEC`：

| 类别 | 例子 | 放在哪里 | 入存档 / 撤销 / 分享 |
|---|---|---|---|
| **持久的视图状态** | 工作区缩放和平移 `wsView`、图层开关 `wsHidden`、卡片尺寸 | 存在实体上：`entity.ui = { view, hiddenLayers }`（和位置、大小同级） | 是 |
| **会话状态** | 选中 `sel`、`wsSel`、悬停、拖动中的 `wsDraw`、提示 `wsMsg` | `UI.S` | 否（切题或撤销时按规则清理） |
| **派生状态** | 求值结果 `S.D`、`wsSig` | `UI.S`，随时可重算 | 否 |

- 把 `S.wsView`、`S.wsHidden` 迁到 `entity.ui`；`W.load` 的版本迁移加一级，旧存档没有 `ui` 时按“自动适应”。
- `UI.STATE_SPEC` 里每个 `S.xxx` 字段都要登记类别；`tools/lint-ui.js` 检查没登记的字段。
- 撤销要能恢复持久的视图状态（它在 scene 里，所以快照自然带上）。

### 4.4 界面不认识具体器材：行为由器材声明

- 器材声明自己在工作区里的角色，界面只读声明：

```js
// 器材定义里
workspaceRole: 'step' | 'figure-source' | 'piece' | 'point' | 'target',
label(ent, out) { … },             // 在画面里叫什么（默认：器材名 + 序号）
handles(ent, out) { … },           // 把手（10.5.4 已有的设想）
```

- `stage.js` 里的 `type === 'gpiece'`、`STEP_TYPES`、`FIG_NAME` 等，全部换成读声明。
- “目标图形”是一个**题目属性**（实体的 `role` 或 `flags: { target: true }`），不是器材类型。
- 新增一种几何器材，只写它自己的声明，不改 `stage.js`；这样代数、算术工作区也能共用同一套界面。
- lint：`tools/lint-ui.js` 统计界面代码里 `type === '<具体器材 id>'` 的出现次数，设一个下降的上限（当前约 40 处，目标降到 0）。

### 4.5 统一的坐标换算层

新增 `js/ui/space.js`，导出 `UI.Space`：

```js
UI.Space.screenToStage(ev)                 // 屏幕像素 → 台面世界坐标（已算进缩放）
UI.Space.stageToWorkspace(ws, point)       // 台面世界坐标 → 工作区几何坐标
UI.Space.screenToWorkspace(ws, ev)         // 上面两步合起来
UI.Space.snap(ws, point, opts)             // 吸附到格点、顶点、边（精确有理数）
```

- 所有拖放、吸附、对齐线都用它，不再各自推一遍。
- 测试：缩放台面到 50%、200%，工作区里拖一个点到某个格点，落点精确。

### 4.6 布局引擎：挂靠元素统一摆放

- 新增 `UI.Layout.anchor(cardRect, panelSize, bounds)`：给定卡片矩形、面板尺寸（**用真实的 DOM 测量，不估算**）、可视区，自动选择位置（优先下方，放不下就右侧，再放不下就上方），并夹在可视区内。
- 所有布局常量集中到 `UI.LAYOUT`（`HD`、端口间距、面板间距、避让间距），删除散落的魔法数字，包括上面那对不一致的 `270`/`420`。
- 避让新卡片（`freeSpot`）、滚动范围、面板位置，都用同一个测量结果。
- 面板的内容很多时（图层、步骤、参数），做成可折叠、可滚动，不靠加高。

### 4.7 测试体系：按手势、按不变量

1. **手势库** `tests/gestures.js`：把真实鼠标操作封装成函数，所有界面测试都用它。至少有：
   - `dragTileTo(type, target)`（从器材架拖到某个位置或某个容器上）
   - `dragCardTo(id, target)`、`dragHandle(...)`、`clickTile(type)`、`press(key)`、`pinch(...)`
   - 每个函数返回“用户看到了什么”（屏幕上元素是否可见、文字内容），不返回内部状态。
2. **入口一致性测试**（数据驱动）：一个“意图 × 入口”的矩阵。例如“把三角形放进工作区”这个意图，从器材架拖、拖已有卡片、（以后）粘贴，三个入口各做一遍，结果必须相同（都进了工作区、一个撤销项、名字相同、在落点附近）。
3. **不变量检查**：每次手势之后自动检查（写成一个 `assertInvariants(page)`，所有界面测试的每一步后都调用）：
   - 台面上没有“游离”的卡片叠在容器上（卡片矩形与容器矩形重叠但不是子实体）；
   - 一个手势只增加一个撤销项；撤销一次，场景回到手势之前（实体、位置、视图完全一致）；
   - 存档读回，再渲染，画面和之前一致；
   - 工作区里所有图形都在可见范围内，并且有标签；
   - 控制台没有错误。
4. **随机手势序列测试**：从手势库里随机抽 200 个手势（拖入不同图形、拖动、剪、旋转、撤销、重做、刷新），每一步后检查不变量。固定随机种子，失败时打印序列，方便复现。

6. **视觉回归**（可选）：关键画面截图，和基线比较；基线图要入库，改动时需要人看。

### 4.8 工程流程

- **一个会话一个 git worktree**：并行工作用 `git worktree add ../universe-<任务名> -b <任务名>`，做完再合并回 `main`，不要多个会话在同一个工作树里改。
- **提交只加自己的文件**：禁止 `git add universe` 或 `git add -A`，必须列出具体文件。
- **统一的检查脚本** `tools/verify.js`：一条命令跑完 内核测试、器材自检、界面验收、`lint-ui`、单文件版加载，任何一步失败就退出非零。提交前必须跑过。
- **不提交半成品**：测试不能全绿，就不提交。

## 7. 复现和调试工具

两个真实鼠标探针已入库，可以直接运行，输出实体数、隐藏数、各图形位置，并可保存截图：

```bash
cd universe
# playwright 不在仓库里：请在别处 npm install playwright@1.48.2，再用 NODE_PATH 指向它的 node_modules
# 如果下载 Chromium 被网络拦住，用系统 Chrome：环境变量 CHROME 可以指定路径
NODE_PATH=<path>/node_modules node tools/probes/ws-drop.js   # 从器材架拖图形进工作区，再点击添加一个
NODE_PATH=<path>/node_modules node tools/probes/ws-undo.js   # 拖入后撤销、重做、存档、刷新，检查实体数
```

写新探针的方式：复制其中一个，改 `page.evaluate` 里的操作。要点：
- 先 `UI.App.openFree()` 并 `act({ t: 'clear' })` 得到干净台面；
- 用 `.tile[data-type="…"]` 拿器材架瓦片，`scrollIntoViewIfNeeded()` 之后再取 `boundingBox`；
- 拖放用 `mouse.move` / `down` / `move(..., { steps: 10+ })` / `up`；
- 检查要看**用户能看到的**（画布元素、标签文字），不要只看内部状态。
