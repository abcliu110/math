## 一、旋钮长出图像（记录仪）

### 孩子看到什么
操作台下面多一条折叠栏“📈 记下来”。打开后：
1. 选一个**旋钮**（横轴，比如“总腿数”）和一个**结果**（纵轴，比如“兔几只”）。
2. 孩子每在台面上拧一次旋钮、得到一个结果，小图上就多一个点。**不会自动帮他画满。**
3. 记了 3 个点以后，拧之前先让他**猜**：下一个点在哪？他拖一个虚点，然后再拧，看猜得准不准。
4. 记了 5 个点以后，才出现“全部试一遍”：一下子画出所有点。

### 为什么这能长出东西
真正有意思的不是“是一条直线”，而是**图上的意外**：

| 图上的样子 | 在哪里碰到 | 引出来的数学 |
|---|---|---|
| 直线，但**隔一个缺一个点** | 鸡兔同笼：头数 10 固定，总腿数从 20 拧到 40 | 腿数是单数时凑不出来：图上的洞就是“凑不出来” |
| 往下走的直线 | 鸡兔同笼：总腿数固定，拧头数 | 每多 1 个头，兔少 1 只：斜率是负的 |
| 中间最高的拱 | 周长固定的长方形，拧长 | 最大面积在正方形：接上**极端主线** |
| 台阶 | 分一分：拧总数，看每人几个（商） | 余数在台阶上一格一格地涨 |
| 锯齿 | 分一分：拧总数，看余数 | 周期，接上同余钟 |

第三层追问就问图：“每多 1，多几？”“为什么缺这些点？”“最高点在哪，为什么是它？”

### 做法（不改内核）
- 每台器材的 `compute(c)` 只依赖 `props`，是纯函数；整数旋钮都声明成 `I(min, max, …)`，结果都是 `kind: 'num'` 的输出。所以记录仪可以**对任何操作台通用**：监听某个 prop 的变化，读某个 output，存一对数。
- 只能选出题人允许的轴。题目里写：`graph: { x: 'T', y: 'b', keep: { n: 10 } }`；其它 prop 在记录时锁住，避免两个旋钮一起变、点就乱了。
- “全部试一遍”就是在 x 的范围里逐个调用 `compute`，拿不到合法结果的地方画空心圈（洞）。
- 新的里程碑输出：`pts`（记了几个点）、`guess`（猜对几次，误差在 1 格以内算对）、`rule`（追问里选对的规律）。

### 第一批（四台，都已有操作台）
1. `swapbench` 总腿数 → 兔几只（直线带洞）
2. `swapbench` 头数 → 兔几只（往下的直线）
3. 周长固定的长方形：长 → 面积（拱）。用的是 `areabench` 的篱笆围地（已做）
4. `groupbench` 总数 → 商、总数 → 余数（台阶、锯齿）

### 这一版不做
- 两个旋钮一起变（三维）
- 孩子自己写公式拟合（`fitbench` 已经有拖直线）
- 小数旋钮

## 二、解法图鉴

### 孩子看到什么
实验库里多一个“📖 解法图鉴”。一页一道**母题**，比如鸡兔同笼，每页有一排格子，每格一种做法：

| 格子 | 用哪台 | 现在有没有 |
|---|---|---|
| 假设法：先当全是鸡 | `swapbench` | 有 |
| 列表 / 一个一个试 | `swapbench` 的试过记录 或 `twoways` 右边 | 有 |
| 两架天平（相减） | `systembench` | 有 |
| 抬腿法：每只都抬起两条腿 | `swapbench` 的“每个都少算” | 有 |
| 分步算式：70 → 24 → 12 | 运算器（`content-g4` 的 `g4-chicken-rabbit-core`） | 有 |
| 画面积图：头数 × 2 是底 | `areamodel` 能画长方形，但没有鸡兔题 | **没有** |
| 方程 | `equation` 没有鸡兔题 | **没有** |

查过的现状：已有的鸡兔题用的数不统一（35 头 94 腿、8 头 26 腿、10 头 26 腿都有）。第一页定成 **35 个头、94 条腿**（`content-g4`、`zz-benches` 已经用它），其它格子各加一道同数的变体。

- 格子一开始是灰的，用那种方法做对一次就点亮。
- **每一格都用同一组数**（8 个头、26 条腿）。孩子会看见：方法完全不一样，答案都是兔 5 只。
- 点亮两格以后，两格中间出现一座桥：点它，进 `twoways` 式的对照，把两种做法的步骤连起来。**桥就是以后地图上的路**，先在图鉴里长出来。
- 一页至少点亮 3 格，再追问：“换成 100 个头、316 条腿，你选哪种？为什么？”没有标准答案，记进研究本。

### 做法
- 题目加两个字段：`family: 'chick-rabbit'`（母题）、`way: 'assume' | 'table' | 'system' | …`（哪种做法）。图鉴面板就按这两个字段把已有题目归到格子里，**第一页几乎不用新题**。
- 同一页的题必须用同一组数，在参考解测试里加一条检查：同 family 的题，答案一样。
- 点亮用现有的星星记录：这格对应的题拿到 ≥1 星就算点亮。

### 第一页之后
母题候选：和差问题、植树问题、盈亏问题（`surplusbench` 已有）、行程相遇。每一页都先数一数**已有**几种做法，凑不到 3 种的先不开。

## 三、通用记录仪（2026-11-26）

前四台记录仪是各台手写的，代码几乎一样（换一换、分一分两种分法、篱笆围地）。这一节把它做成**任何操作台都能开**的机制：操作台自己的代码不用改，题目里写一段配置就行。代码在 `js/core/recorder.js`。

### 题目怎么写
build 里给操作台加一段配置（`U.Recorder.props` 把它写成实体属性 `rcfg`）：

```js
W.add(s, 'gaussbench', 40, 40, Object.assign({ a: 1, d: 1, n: 4 }, U.Recorder.props({
  knob: 'n',                 // 旋钮：孩子拧的整数属性（横轴）
  out: 'total',              // 读哪个输出口（竖轴，要是数）
  keep: ['a', 'd'],          // 这一组不动的属性：换了，图上只显示新的这一组
  range: [2, 12],            // 旋钮在哪里拧（整数，最多跨 100）；一头也可以写成式子，只用 keep 里的属性，比如篱笆 [1, 'P / 2 - 1']
  guess: 'values',           // 先猜的格子：'values' 一格一个能出现的值；数字是格子间隔；省略就自动
  asks: ['个数多 1，和多几？|*多的就是新加的那个数|总是多 1|总是多 2', '…'],   // 最多两道追问，正好一个 *
  // 下面几项可以不写
  names: ['个数', '和'],      // 横轴、竖轴叫什么（默认用属性和输出口的名字，去掉括号里的说明）
  done: { flip: true, pair: true },   // 全部试一遍、判猜时按“做完的样子”算；'$' 是旋钮的值（日历写 { go: '$' }）
  reset: { pair: false },    // 拧旋钮时台面上一起复位的属性（日历：数过的天数清零）
  mark: 'max',               // 最高的点画成绿的（篱笆围地的最大面积）
  line: true,                // 全部试一遍以后，这一组的点按顺序连成线（直线、拱、V、往上弯的线开；锯齿、星期这种按格跳的不开）
})));
```

配置写错了（拼错的键、旋钮不是整数属性、输出口不是数、范围超出旋钮、追问没有 * ……），`U.Recorder.check` 会一条一条说出来；单元测试检查每道题的配置都合法。

### 包装器：注册时自动加上
`recorder.js` 接在 `U.define` 后面：每台操作台（`bench: true`、用 `compute` 算、属性名和输出口名不和记录仪撞）注册时自动包上，**没开（rcfg 空着）时和以前一模一样**。包上的东西：

| 加什么 | 是什么 |
|---|---|
| 属性（都藏着） | `rcfg` 配置；`rclog` 记下的点（`横,竖,这一组;…`）；`rcg` 猜的第几格；`rcpeek` 不猜直接看；`rcgok`、`rcgtry` 猜对、猜了几次；`rcall` 全部试一遍；`rcpick` 追问选了第几个 |
| 输出（里程碑用，名字和手写的四台一样） | `pts`（这一组几个点）、`gok`、`gtry`、`all`、`q1`、`q2`；声明成 `rec: true`，没开时不画这些口、不撑大卡片 |
| 画法 | 台面下面一条细线，接着“记下来”一块：旋钮的 − 数 +、“记下来”、“不猜，直接看”、坐标图（`RS.plot`）、追问 |
| 尺寸 | 卡片至少 660 宽，加高“记下来”那一块 |
| compute | 先猜的时候，配置里的那个输出口不给（连线、读数都拿不到答案）；再加上面那几个输出。还是纯函数 |
| 把手、标题栏读数 | 先猜的时候收起来 |
| onSet | 拧了旋钮、或换了 keep 里的属性：猜的清掉；拧旋钮再复位 reset 里的属性。操作台自己的 onSet 照常先算 |

所以**状态全在实体属性里**：存档、撤销、重放、分享都跟着走，不另外存。“全部试一遍”和判猜都用操作台自己的 `compute`（换一份属性算一遍），不用每台再写公式。

### 先猜时怎么藏答案
- **通用的做法：盖住台面。** 记满 3 个点以后，旋钮拧到没记过的值，台面整块盖上“🤔 先猜一猜”（一层不透明的框，点上去点不到下面的按钮），把手收起，标题栏不写读数，输出口不给。只露出下面的旋钮和图：在蓝线上点一格猜，或者“不猜，直接看”，盖子才揭开。
- **猜了当场判**：点格子那一下就记“猜了一次、猜对没有”（格子上带着判好的结果），之后来回拧旋钮也改不了。揭开以后，台面上做出来了，图上写“猜对了”或“其实是 …”。
- **格子**：能出现的值不超过 12 个，就一格一个（挨得太近的往旁边错开）；多了就按间隔分格，落在最近的一格算对，图上再说出真正的数。
- **更细的藏法（钩子）**：操作台声明 `recHide: true`，就不盖台面；它的 `draw`、`grips` 收到 `c.recHidden`，自己藏答案。篱笆围地用这个：台面照常能拖，只把面积写成“？”。开了记录仪的台还会收到 `c.rec`，可以不画自己的重复按钮（篱笆围地就不画“记下这一种”）。

### 换一组
`rclog` 里每个点带着“这一组”（keep 里的属性现在的值）。换了 keep 里的属性，图上和 `pts` 只算这一组的点；换回来，原来的点又出来了，记录不丢。

### 四个手写版本
- **篱笆围地换掉了**：配置是 `knob: 'w', out: 'area', keep: ['P'], range: [1, 'P / 2 - 1'], guess: 'values', mark: 'max', line: true`（2026-11-26 范围改成跟着一共几米算），加 `recHide`。`tests/ui-graph-fence.js` 一个字没改照样全过；面积推导台删掉了自己那一套（属性 8 个、输出 6 个、画图和先猜的 30 多行）。改“一共几米”现在按“换一组”处理：图上只显示这一圈的点，记录不丢。
- **换一换没换**：它的点不是“拧旋钮、读输出”记出来的，是研究本里一条一条“凑对了”或“说对凑不出来”的结果；凑不出来要画在下面一排的 ✕。通用记录仪只有“旋钮 → 一个输出”，装不下“凑不出来”这一排。
- **分一分没换**：“每份几个”一张图上有两组点（商和余数），先猜时两组都猜（蓝线左边一列橙圈猜商，右边一列红方块猜余数；2026-11-26 以前只猜余数）；“平均分”先猜时只锁住“放”的按钮，盒子还看得见。两种分法共用一套属性和输出（rec 和 rec1 分开记），换掉一种另一种的名字就撞了。硬换成通用版，孩子会少看一组点、多一层盖子，效果变差，所以留着。

### 这一版的边界
- 一个旋钮、一个输出，横轴是整数；旋钮停在小数（圆的半径 2.5）时不能记。
- 有状态的操作台（`step`）不包；和记录仪撞名的不包（换一换、分一分、跳格钟、带追问的研究台等，`U.Recorder.why(type)` 说原因）。
- 范围可以跟着这一组算（式子只用 keep 里的属性）：篱笆 24 米横轴是 1 到 11。式子只认数、属性名、+ − × ÷ 和括号。

## 顺序建议

1. **图鉴第一页（鸡兔同笼）**：主要是给已有题加字段，再加一个面板，最省事，而且马上能看出“连起来”的效果。
2. **记录仪接在 `swapbench` 上**：两种图（带洞的直线、往下的直线），正好挂到鸡兔同笼那一页的第三层追问里。
3. 再把记录仪推到 `groupbench` 和长方形面积；图鉴再开第二页。（都已做；第二页选了连加，不是候选里的和差、植树、盈亏：那几道已有的做法凑不到 3 种）

每一步都按老规矩：参考解、界面测试、完整验证“全部通过。”再提交。

## 要你拍板的
- 图鉴第一页缺的“面积图”和“方程”两格：在 `areamodel`、`equation` 上各补一道题，还是先空着（显示“还没发现”）？我倾向补上：都是已有操作台，不用新做器材。
- 记录仪默认要不要藏起来，只在第三层追问时出现？我倾向**藏起来**，免得低年级一上来就看到坐标图。
