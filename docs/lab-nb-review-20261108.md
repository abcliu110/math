## 1. 它是什么：架构速写

`S = {entities, links, seq, nid, binds}` 场景图 → `TYPES` 器材表（48 种）→ `evaluate(S)` 纯函数求值产出 `D[id] = {val, sig, ports, ...}` → 步骤 `check(S, D)` 按步判分 → 三种模式（自由 / 练习 / 考试）。学生从右侧器材架拖器材上台，用输出端口连到输入端口，改属性卡里的字段，台面实时重算并给出信号文字。

| 规模指标（实测） | 数值 |
|---|---|
| 器材类型（`prefix:'`） | 48 |
| 内联实验（`:s1`） | 93 |
| 恰 2 步的内联实验 | 83 / 93 = 89.2%（`:s3` 仅 10，`:s4` 仅 2） |
| `check:` 判分谓词 | 240 |
| `type:'predict'` 预测步 | 15 |
| `csv / Blob / createObjectURL / download` | **0** |
| `fetch / XMLHttpRequest` | **0** |
| `postMessage` | 3 |
| `<footer>` | 0 |

## 2. 特点：真正做对的地方

| 维度 | 做法 | 锚点 | 价值 |
|---|---|---|---|
| 数学内核 | 全程有理数 `Q(n,d)` + `qadd/qsub/qeq/qs/gcd/lcm`，`1/2+1/3=5/6` 精确不丢分母 | `gcd/lcm/Q/qadd`、`fracadd:s1`、`adder` 求值 | 避免浮点数把分数规律讲歪，是同类产品里少见的扎实底座 |
| 数学内核 | `Val = {kind, dim, data}` 维度代数，端口按类型拒收（数轴拒 `area`）、拒绝成环 | `DIM_VEC`、`dimVec`、`outKind`、`addLink` 校验 | 把"单位/量纲"做成类型约束，不是靠文字提醒 |
| 判分 | 判分读 `ports` 而非匹配信号文字；钟面按「开始/结束」命名取器材，不再按插入顺序；部分实验改按名字取值 | `clockPair`、`ck(s,名字)`、`check:()=>`、`hideSig` | 判分与展示解耦，抗文案改动 |
| 探究 | `predict` 预测步（15 个）、黑箱规则库（线性/平方/倒数）、绑定表达式（拓扑序 `syncBinds`、悬空绑定清理、范围钳制）、变量 x 实体 | `type:'predict'`、`box` 的 `rule`、`exprTokens`、`syncBinds` | 已有"先猜""一个变量驱动多个组件"的雏形 |
| 工程 | 撤销/重做 80 步、一键整理、10 分钟倒计时与超时自动交卷、考试报告（每步得分/用时/操作数/被拒绝数）、实验库显示考过次数与最常丢分 | `undo/redo`、`startTimer`、`submitExam`、`hist()` | 课堂可用的完整考核链路 |
| 集成 | 练习完成发 `labNbPractice`、考试发 `labNbExam`、发现发 `labNbDiscovery`；`openXp` 有 `labNbReady` 握手 + 8 次重发 + 失败提示；`message` 已校验 `e.source === window.parent` | `practiceDone`、`submitExam`、`postToParent`、`openXpAck` | 早期文档里的 G1/G7/A2 已修，别照旧文档返工 |

### P1 严重

| ID | 问题 | 证据 | 触发与后果 | 修法 |
|---|---|---|---|---|
| D04 | **判分 `done` 单调不回退，撤销可刷分** | `track()` 只把未完成步置 `done=true`，循环中 `if(st.done)continue ... else break`，从不复位；`track()` 只在 `commit()`（635）里调用，而 `undo()`/`redo()`/`clear()`/`tidy()`（946-951）只调 `afterChange()`（639），不回调 track | 做完一步 → 撤销掉那根连线 / 清空台面 → 步骤仍显示 ✓、`score()` 仍给分 → 交卷满分。更本质的问题：`done` 是单调递增的标记，不是「当前场景是否满足谓词」，判分与场景状态可以长期不一致 | `afterChange()` 统一触发按当前 `S` 重算 `done`（允许复位），或把 `done` 改成派生值：`run.steps[i].done = check(S, evaluate(S))`；predict 步单独保留 |
| D05 | **练习存档丢 `pred`，续做后预测步永久 0 分** | `afterChange()`（640）只存 `{id, S, steps:done[], ops}`；`startXp()`（1575）恢复时只回填 `done`，没有 `pred / errors / t0 / practicePosted / finished` | 练习中途刷新 → `done=true` 但 `pred` 缺失 → `score()` 该项判 0，且 `track()` 因 `done` 已 true 跳过、无法重猜；`usedMs = Date.now()-run.t0` 计时也被重置 | 存完整 `run` 快照；或续做时清空所有 `done` 重新判分 |
| D06 | **考试状态完全不落盘** | `LS` 只有 `free/hist/find`（622），`PR` 只在 `practice` 写（640）；`startTimer()` 的 `end` 是内存变量（1582） | 考试中途刷新 / 误触返回 → `goFree()` 直接载入自由模式存档 → 静默弃考，无报告，父页收不到 `labNbExam` | exam 快照 + 剩余时间持久化恢复，加 `beforeunload` 确认 |
| D07 | **近似值当精确值，并用 `===` 判分** | `circle` 用 `3.14`（221/485）且显示两位小数不带「≈」；`g6_5:s2`（1379）写死 `D[c].ports.circ===18.84 && area===28.26`；`trig` 用 `toFixed(2)` 显示 `sin45°=0.71`、`tan60°=1.73`，并按舍入值判分；`cang` 弧长/扇形面积 `toFixed(2)` 后判等；`quad/parab` 浮点根与顶点显示两位小数无「≈」 | 小学用 3.14 是教材口径、本身不错，错在**未声明近似**且按近似值精确判分；初中仍用 3.14、以及 `0.71²+0.71²=1.0082≠1` 会让学生把近似值当成恒等式。r=1、圆心角 10° 时弧长 0.17444 → 显示 0.17，相对误差 2.5% | 全部改「≈ 口径」：显示加 `≈` 或分数/根式；判分用容差 `Math.abs(a-b) < 1e-6` 或直接判变量（如 `r===3`）而非判算出的近似小数；初中学段改用 π 符号 |
| D08 | **画出来的图与显示数值脱节（度量即显失真）** | `trig` 画法（734）`opp=Math.min(120, 130*tan(r))`：60° 时 225 被截成 120，实际画出的角 `atan(120/130)=42.71°`，而标签写 60°（g9_15 正用 60°）；`parlines` 画法（721-722）截线由固定 `dx=60, dy=(y2-y1)*0.9` 决定，夹角恒约 46.5°，与属性 `a` 无关，却标「截线与直线的夹角 ${a}°」 | 学生拖角度滑杆，图形不变或变得不对，但读数在变 —— 直接违背「拖动即探、图形与度量一致」；平行线同位角/同旁内角这类题靠图看关系，图形不动等于没做实验 | 去掉 `min` 截断或按角度自适应画布；`parlines` 用 `a` 反算 `dx = dy / tan(a)`；给图形加角度弧标注 |
| D09 | **题面、图形、判分三者脱节；部分实验名不副实** | `g8_5`（1516）题名「2³×2²」实为 8×4=32；`g7_75`（1538）「3x+2x」实为 3+2=5，x 消失；`g6_11`「圆柱体积」实为 12×5；`g8_9`「分式方程」实为 6÷2；`g8_box`（1552-1553）问「规律是什么」却只验 3→7、5→11，且 `box` 信号（447）已明文写出 `输出 = 2×输入+1`；`g6_13` 鸽巢问「至少几只」答 3，判分只看商 `Q(7,3)`，接好线即通过。初值还常故意偏离题面（`g6_5` 题 r=3 / 建 r=2，`g9_98` 题 r=3,c 未定 / 建 r=2,c=90，`g8_data` 题 6,8,12 / 建 6,8,10），第一步只是「把数改成题面」 | 学生会以为自己算错；「黑箱猜规律」在答案已公开的情况下退化成代入验算；题面与初始值不一致若不说明，会被误认为初始状态就是错的 | 逐条核对题面 / `build` 初值 / `check` 三者；黑箱练习与考试都隐藏规则（当前只靠 `ruleHidden()`），并要求学生写出猜想再验证；题面明确写出「图上初始值与题目不同，先改成题目给的数」 |

### P3 探究深度（优化）

- **2 步模板占比过高**：内联实验 83/93 恰 2 步，`P45H`（1156）、`wpSteps/wmSteps/woSteps/p3Steps/H14` 生成的仍是「连线 1 分 + 看读数 2 分」。
- **约束构图几乎为零**：全文 `data-vtx` 仅 2 处（774），只有三角形能拖顶点（`vtx` 反推 A、B 并钳 A+B<180，345-350）。圆、长方形、平行四边形、角、相似、勾股、平行线、三角函数全靠滑杆，且 D08 里图形不随数值正确变化。
- **反例与多解稀缺**：「反例/换一种」标签全文仅 1 处；`fracadd`（567-579）、`balfrac`（590）、`maxarea`（602-608）是少数有对照的实验。
- **猜测闭环不完整**：15 个 predict 步全是 `check:()=>false`，猜错只是不得分，没有「再去验证/为什么错」的引导；无错因标签（「错因/易错/误区」0 处），考试报告只列「丢分在：某步」。
- **无学段标注页脚**（`<footer>` 0 处）；实验库列表虽有「N 年级 · 领域 · 器材」，但没有独立的学段/知识点标注与近似值口径声明。
