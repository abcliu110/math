# 数学世界模型

日期：2026-11-06。版本：0.2.0。

## 本质

零件在槽位里；意图改位置；**只有法则算后果**（`derived`）。View 只渲染。

## 为什么 V1 拉

V1 是 6 个互不往来的小结构体 + 一堆 setter，没有真正的「同一世界」：

- 分数板不走零件，用 `meta.fracAdded` 假装探索过
- 十格阵算不出可拖的数
- 鸡兔只有 solved 布尔，没有残差
- 派生结果是调试字符串，不是世界在说话

## V0.3：学 NB 实验室的做法（步骤打分 + 练习/考试）

借鉴 NB 实验室「按步骤给分、丢分定位、练习有提示 / 考试无提示、错误要有后果」的机制，只借机制，不借其内容或素材。

| 能力 | 说明 |
|---|---|
| `LAB_PROCEDURES` | 每个实验一组带分值的步骤，每步是对世界状态的判定 |
| `procedureStart {labId, mode}` | 练习（有提示）或考试（无提示） |
| `track` | 每次动作后记录已达成的步骤，达成后保持 |
| 失败动作计错 | 失败动作进入 `world.errors`，失败的数轴放置仍能点亮「看见拒绝」步骤 |
| `procedureReport(world)` | 得分、满分、丢分步骤、错误次数；仅练习模式给 `nextHint` |
| `fracMint` | 把合并后的和做成真实分数零件，可放上天平或数轴 |

限制（有意保留）：步骤判定是状态判定，不记录操作顺序。学生直接把数设到目标值也能得分。过程评分（按操作序列）留到后续版本。

验证：`node tools/smoke-math-world.js`（47 项）与 `node tools/smoke.js`（1062 项）。UI 尚未显示 `procedureReport`，接入界面是下一步。

### V0.3 补充：过程评分与界面接入

前一节的限制已解决：

| 能力 | 说明 |
|---|---|
| 过程评分 | 每个步骤声明允许的动作类型（`via`）和前置步骤（`after`）。只有本次动作属于允许类型，且前置步骤已完成，步骤才计分。状态恰好已存在（例如题目种子）不计分。 |
| 操作记录 | 实验内每次动作（成功或失败）记入 `world.ops`，步骤记录其所在的操作序号 `op`，报告给出 `opCount`。 |
| 界面 | 工作间右侧「实验流程」面板。练习模式显示清单与下一步提示；考试模式只显示得分与失败次数，交卷时才显示丢分步骤。 |
| 挑战交卷 | 工作间题的流程得分与丢分步骤写入挑战报告。 |
| 分数零件 | 工作间新增「做成分数零件」按钮，对应 `fracMint`。 |

模式对应关系：工作间题在「自由玩」下为练习（有提示），在「挑战模式」下为考试（无提示）。

仍未做：按操作记录做跨次统计（每一步的历史丢分趋势）；挑战交卷时，数轴题的自动判分会重建世界，该题的流程面板随之清空（现有行为）；其余题的流程保留。

验证：`node tools/smoke-math-world.js`（54 项）、`node tools/smoke.js`（1064 项）、`node tools/smoke-apparatus-drag.js`。

### V0.3 收尾：跨次统计、数轴面板修复、真实浏览器验证

## V0.4：数学实验台

实验台是自由的桌面：从零件盒拿数放上台，合并、拆分、拿走，台上合计和分母是否相同由模型算出。它和工作间共用同一个世界。

| 动作 | 说明 |
|---|---|
| `benchPut {pieceId}` | 把零件放上台（最多 6 个）。正在占着数轴或分数板的零件不能放上台。 |
| `benchTake {pieceId}` | 把零件拿回自由区。 |
| `benchMerge {ids}` | 合并两个及以上的数，结果是一个新的数（分数按正确的方法相加）。 |
| `benchSplit {pieceId, k}` | 把一个数平均拆成 k 份（2 到 6），每份是原值的 1/k。 |
| `derived.bench` | 台上的数、合计、个数、是否满台，以及分母是否不同。 |

界面：工作间里的「实验台」卡片。零件盒放 1/2、1/3、1/4、1/6、1 和 2。台面上的数点一下即可选中，「合并所选」「拆开所选」「全部拿走」作用于台面。

设计决定：台上的动作不计入实验流程。挑战模式里摆弄台子不会增加操作数，也不计失败次数，评分只看实验本身的动作。

限制：台面用按钮表示，还没有拖拽和画图；拆分只支持平均拆分；台面只在本次页面里有效，刷新后清空。

验证：模型 68 项，应用测试 1069 项，拖拽测试通过。浏览器里用 headless Edge 点过：放 1/2、1/3 合计显示 5/6 并提示分母不同；合并后得到 5/6；拆开 1/2 为三份 1/6，合计仍是 1/2。

### V0.4 收尾：拖拽、分数条、台面保留

| 项目 | 说明 |
|---|---|
| 拖拽 | 用指针事件，平板和触屏可用。从零件盒拖到台面放上；从台面拖到「拖到这里拿走」取下。移动不到 6 像素算点击。 |
| 分数条 | 台面上每个数画成分数条：每个单位一条，分成 d 段，涂 n 段。分母大于 8 或数大于 3 时只显示数字。 |
| 台面保留 | 台上的数存入 `localStorage['math-bench-v1']`，换题、切换自由玩、刷新后自动放回台上。 |
| 实验台动作不计流程 | 台上的动作在执行前去掉流程状态，挑战模式里不增加操作数和错误数。 |

仍然保留的设计：拆分只做平均拆分（每份是原值的 1/k），这是分数“平均分”的意思，不做不等分。

验证：模型 68 项，应用测试 1071 项，拖拽测试通过。浏览器里用 headless Edge 验证了拖入台面、分数条画出、拖到垃圾区拿走。

## V0.5：鸡兔可行性、过两点定直线、整数校验

| 项目 | 说明 |
|---|---|
| 鸡兔可行性 | `derived.chicken` 新增 `feasible`、`infeasibleReason`、`solutionRabbits`。无解的情形：腿数是奇数，腿数少于全鸡（2H），腿数多于全兔（4H）。无解时出现 `error` 信号，工作间显示「这道题无解」。 |
| 过两点定直线 | 新动作 `linefnFromPoints {x1,y1,x2,y2}`，k = Δy/Δx，b = y1 − k·x1。x 相同时拒绝（竖线画不了一次函数）。工作间的一次函数卡片有两点输入框和「画这条线」按钮。 |
| 整数校验 | `Q.of` 只接受整数，非整数抛错。`makePiece` 先检查分数和整数值。`apply` 捕获异常，返回 `bad-number`，不会崩溃。 |

仍未做：几何引擎、概率引擎，以及 v0.1 文档里列出的九个引擎全表。这几个都是新的数学领域，每个都要单独定范围，所以没有在这一轮里做。

验证：模型 78 项，应用测试 1072 项，拖拽测试通过。浏览器里验证了「画这条线」（(1,3)、(3,7) 得到 y = 2x + 1）和竖线的拒绝提示。

## V0.6：几何（周长一定的长方形）

| 项目 | 说明 |
|---|---|
| 状态 | `w.rect = {perim, w}`。周长固定，长 = 周长/2 − 宽，只能调宽。 |
| 派生 | `derived.rect`：宽、长、面积、是否正方形，以及最大面积（周长能被 4 整除时是正方形，否则宽取 floor(周长/4)）。信号：面积已最大（`max-area`）或还能更大（`can-grow`）。 |
| 动作 | `rectSet {w}`：宽必须是整数，范围 1 到 周长/2 − 1。 |
| 目标 | `q-maxarea` 的目标是 `rectMaxArea`：面积等于最大面积。 |
| 界面 | 工作间的「长方形 · 周长一定」卡片，宽 −1 / +1 两个按钮，显示面积与判定。 |

仍未做：概率引擎，以及 v0.1 文档里列出的其他引擎。「周长一定面积最大」的旧演示页还没有接到这个模型上，它仍是独立页面。

验证：模型 89 项，应用测试 1073 项，拖拽测试通过。浏览器里点了宽 +1 四次得到正方形 5×5（面积 25，目标达成），宽 −1 后提示“还能更大：5×5＝25”，超出范围时有拒绝提示。

## V0.7：概率（两个骰子点数之和）

| 项目 | 说明 |
|---|---|
| 状态 | `w.dice.A` 是分给 A 的点数和列表，其余归 B。 |
| 派生 | `derived.dice`：2 到 12 每个和的方法数（和为 7 有 6 种，共 36 种），每人拿到的概率（分数，用 Q 精确计算），是否公平（两人各 1/2）。 |
| 动作 | `diceToggle {sum}`：把一个和在 A 与 B 之间换一边。和不在 2 到 12 之间时拒绝。 |
| 目标 | `q-fairgame` 的目标是 `diceFair`。 |
| 界面 | 工作间的「概率 · 两个骰子」卡片：每个和一个按钮，显示方法数和归属，下面显示 A、B 各得的概率。 |

例：A 拿 {2,3,5,6,7}，方法数 1+2+4+5+6 = 18，即 18/36 = 1/2，公平。

仍未做：其他的概率问题（如抽签、条件概率），以及几何的其他图形。

验证：模型 97 项，应用测试 1074 项，拖拽测试通过。浏览器里点出 {2,3,5,6,7}，显示 A 得 1/2、B 得 1/2，目标达成。
