# 实验应该放在哪里 · 内容布局设计

日期：2026-11-06。起因：Iris 发了一张一年级单元列表页截图，问：实验应该放在哪里？需要思考设计优化。

本文先画现状（所有入口、重复、死角、看不见、叫法混乱），再给三种放法、推荐一种，
最后是本次实施清单和下阶段清单。设计原则是已定的，不重想：实验以问题为单位，
先猜再玩再说（猜→玩→说），难度来自选择不是步骤，错要有可见后果，带走一个发现；
演示是快速"看明白"的工具，实验室放少量深问题实验。

### 1.2 重复：同一个东西，三处能进

1. **9 个创意实验，至少三处能进**：演示页顶上 + 实验室问题列表 + 部分知识点页
（如 `thirteen` 挂在 1.9 的 `demo` 字段上）。三处文案、计数各自为政。
2. **实验室 9 个演示型问题是"有去无回"**：点"去做这个实验"走 `navGo('demo-*')`，
父级被重建成演示总站，点"← 返回"落到互动演示页，**回不到实验室**（导航 bug）。
3. **4 个实验室工具站与 4 个旗舰演示是两套实现**：`lab-fraction` 等与 `demo-fraction`
各一套 DOM、一套状态，改一处要改两处。
4. **`demo-fracadd`（124 列表）与实验室 bench `fracadd` 同概念两套实现**。
5. **`tenframe` 与 `maketen` 是两种凑十工具**：只有 `tenframe` 挂在知识点页上
（1.6 / 1.11 的 `demo` 字段），`maketen` 从内容路径（年级→单元→知识点）上完全看不见。

### 1.3 死角：写了要玩，但没路去

1. **年级页单元卡**（截图）：只有"内容已完成 / 闯关 x/2"，学生从年级页看不到本单元有任何动画。
2. **单元页"玩一玩本单元的演示"**：任务列出来了，但没有按钮，点不进去。
3. **闯关站 → 单元页 → 同一个死角**：站上"演示 0/2"的计数是真的，但顺着站走下去还是找不到演示。
4. **实验室 → 演示 → 返回 ≠ 实验室**（见 1.2 第 2 条）。
5. **知识点页只有一个演示按钮**：该点的第二种、第三种方法没有入口。
6. **学习路径第 1 步"动手试一试"**：名字就叫动手，却一个链接都没有。

### 1.4 看不见：从内容路径上不存在

- **8 个互动模拟**：`demo` 字段一个都没改（有意为之，见 882daab），所以任何知识点页都链不到它们；
只能从演示页往下翻 9 个创意实验才找得到。
- **实验室 4 个 bench 问题**：只能从实验室进，知识点页、单元页、闯关站都没有影子。
- **实验本身**：一个正在学 3.12（面积）的学生，在 3.12 的点页上看不到 `maxarea`（周长一定面积最大），
除非他先知道要去实验室或演示页顶上找。

### 1.5 叫法混乱：五个词，指重叠的东西

| 词 | 现在指什么 | 问题 |
|---|---|---|
| 演示 | 124 个工具 + 4 个旗舰 + 演示页标题 + 首页面板"互动演示" | 首页面板叫"互动演示"，点进去却装着实验和模拟 |
| 实验 | 创意实验 9 个 + 实验室 + "为什么小实验" | "实验"有时指 9 个，有时指整个实验室 |
| 模拟 | 8 个 PhET 式 | 与"演示"、"实验"的边界没人说得清 |
| 实验室 | 工作间（问题 + 工具 + 组合台） | 首页副文还写着"没有题目，随便玩"——现在明明是先选问题再玩，文案过时了 |
| 动画 | Iris 的新词：每个知识点多个动画 | App 里现在一个"动画"字都没有 |

演示页副文还有一个错数："顶上 8 个是创意实验"——加了 `thirteen` 之后已经是 **9 个**了。

## 2. 命名决定（先定词，再定位置）

| 词 | 指什么 | 判据 |
|---|---|---|
| **动画** | 所有能上手玩的东西（总称，Iris 的话） | 学生问"这个点有动画吗"，答案是一组，不是一个 |
| **演示** | 看明白的工具（124 + 4 旗舰） | 一看就懂，单概念，无猜测步骤 |
| **模拟** | 一个概念一种玩法（8 个） | 先猜再玩，一个概念挖深 |
| **实验** | 一个问题（9 个创意 + 实验室问题） | 先猜再玩再说，多路径，带走一个发现 |
| **实验室** | 实验的家 | 问题列表 + 工作间（工具 + 托盘 + 组合台）+ 挑战模式 |
| **演示页** | 总目录 | 暂名"互动演示"，下阶段改名"动画"并按点分组（见 §5） |

演示 / 模拟 / 实验的区别是**深浅和目的**，不是位置：同一个知识点可以同时有演示（看明白）、
模拟（一个概念玩透）、实验（一个问题想明白）——这正是"一个点多个动画，每种方法一个"的落点。

## 3. 三种放法

### 方案 A：实验室是唯一实验入口

所有问题型实验只住实验室：演示页只留 124 + 4 个演示工具；知识点页只链演示；
想做实验就去实验室的问题列表。

- 利：概念最干净，"实验去实验室"一句话说清；实验室的问题列表是唯一的实验目录。
- 弊：实验离内容最远——正在学 3.12 的学生看不到 `maxarea`；问题列表按问题排，
学生得先知道问题才找得到；实验室 13 个问题扩到 ~30 后列表本身变长；
与下一阶段"每个点多个动画"直接冲突（实验最终还是得回到点上）。

### 方案 B：全部并进演示页，按知识点分组

演示页改成按年级 → 单元 → 知识点分组的目录，每个点下列出它的全部动画；
实验室退回纯自由玩工作间（工具 + 托盘 + 组合台，无问题列表）；闯关站任务链到演示页对应点。

- 利：只有一个地方找动画；与 400+ 的结构天然契合（分组目录就是未来的目录）；
演示页不再是 141 张卡片的平铺长列表。
- 弊：改动最大——演示页要从静态手写 141 面板改成数据驱动生成 + 分组 + 筛选，
`check-views.py` / `smoke.js` / `build-standalone.py` 都要跟着改；
实验的问题形态在目录里会被压扁（问题列表是实验的灵魂，目录按点排会丢掉跨点的问题，
如莫比乌斯带）；实验室失去问题入口后，工作间只剩工具，学生不知道来这里干什么。

### 方案 C：三层，各归其位（推荐）

1. **知识点页是主入口**：该点的全部动画按方法列出，演示 / 模拟 / 实验打标签。
注册表是唯一事实来源：`animsForPoint(id) = p.demo + SIM_LINKS + LAB_QUESTIONS`（去重）。
2. **单元页是本单元总览**：每点一行，列出该点动画；闯关任务"玩一玩"的落点就在这里。
3. **年级页单元卡加计数**："动画 N 个"（从注册表算，不手写）。
4. **实验室是实验的家**：问题列表不变；演示型问题点进去后返回回实验室（修导航链）；
bench 问题只住实验室。
5. **演示页是总目录**：本次只正名（分组标签 + 修正错数）；下阶段按点分组、数据驱动生成。
6. **闯关站不变**：站 → 单元页（动画列表在那里）；任务计数不变。

- 利：实验既有家（实验室问题列表）又不离内容（点上能进）；与 400+ 兼容
（点页是天然的分组单位，演示页下一阶段按点分组生成）；改动小，本次只动点页、单元页、
实验室返回链、文案，不动导航结构和内容文件。
- 弊：实验有两个入口（点 + 实验室），要一条规则维持一致——同一份注册表，
两边都从注册表读，不手写两份；演示页的平铺列表暂时还在，400+ 时必须重构（见 §5）。

## 5. 下阶段清单（400+ 动画到来时，另起提交）

1. **演示页数据驱动生成**：`index.html` 不再手写 400+ 面板；`app.js` 加 `DEMOS` 注册表
（key → {标题，副文，年级，种类，points[]}），面板由 JS 生成，按年级 → 单元 → 知识点分组，
加年级筛选；`check-views.py` 改为校验注册表与 `NAV_DEFS` / allowlist 的一致性。
2. **演示页改名"动画"**：首页面板、面包屑、区标题一起改（见 §6 第 1 条，需拍板）。
3. **新动画接入清单**（每个动画）：注册表加一行 + `NAV_DEF` + CSS allowlist +

4. **实验室工具站与旗舰演示合一套实现**（见 §6 第 3 条，需拍板）：现在是两套 DOM/状态，
400+ 时维护成本翻倍；合并不改学生看到的东西，只改实现。
5. **每点动画的排序规则**：演示（看明白）→ 模拟（玩透一个概念）→ 实验（一个问题想明白），

## 6. 刻意没动的东西

- 演示页 141 面板不动（下阶段数据驱动重构，见 §5 第 1 条；本次动它风险大、收益小）。
- 内容文件（`grade-*.js`）不动：`demo` 字段不动，`SIM_LINKS` 住在 `app.js`——
模拟与点的对应关系是呈现层的事，不是内容本身。
- `LAB_QUESTIONS` 不动：实验室问题列表是实验的家，不拆。
- 闯关站、学习路径、模拟测、家长端、探究作业不动：闯关任务的落点在单元页动画列表，
不必在闯关站再开一个入口；学习路径第 1 步见 §7 第 2 条。
- 导航结构不动：无新视图、无新 allowlist、无新面包屑层级；`goDemoFromHere` 的返回语义不变。

## 7. 需要用户拍板的事

1. **演示页要不要改名"动画"**："互动演示"用了很久，改名要动首页面板、面包屑、区标题；
好处是与"每个知识点多个动画"的话术一致，学生找动画只认一个词。
2. **学习路径第 1 步"动手试一试"要不要链到动画**：它现在是纯文字。链的话，链到什么？
当前年级的动画？还是当前知识点的动画？（学习路径目前不绑定任何年级/知识点。）
3. **实验室 4 个工具站与 4 个旗舰演示要不要合一套实现**：学生看不出区别，只是实现层面的事；
合了以后改一处等于改两处，但要一次不小的重构和复测。
4. **400+ 动画建完后，演示页是否按点分组 + 年级筛选**：推荐是（§5 第 1 条），
但那时按实际数量再定分组细节。
