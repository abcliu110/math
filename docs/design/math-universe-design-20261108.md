## 0. 愿景与验收标准

### 0.1 愿景

**不是刷题 App，是统一的数学实验室。**

学生进入一个有自己规律的世界：器材摆上台面，属性可调，值能流动，系统随之响应。先猜再做，错了有可见后果，发现就是学习发生的时刻。

四层结构：

| 层 | 问题 | 当前状态 |
|---|---|---|
| 学什么 | 142 个知识点，1-9 年级，全世界最好方法，L1-L4 深度 | grade-1.js ~ grade-9.js 已建 |
| 怎么学 | POE 模型：先预测→动手做→说发现；步骤级判分；练完进复习 | A1 闭环已建，88/88 实验有 predict 步 |
| 长什么样 | 统一台面：48 种器材，值能流，tick 心跳让系统动 | lab-nb.html 1806 行，48 种器材在 TYPES |
| 高到哪里 | 超过 NB 实验室：123 种器材，32 个世界首创，学生能当作者 | 待施工，当前 48 种 |

### 0.2 量化验收条件（最终）

1. **88/88 → 161+/161+ 实验**通过 check-xp.js 静态验证（每批新增实验合入前必过）
2. **142/142 知识点**各有至少 1 个绑定实验（LAB_POINT_XP 全覆盖）
3. **48 → 123 种器材**全部进入 TYPES，每种有 label / group / ports / evaluate 实现
4. **A1 闭环可测**：做完实验 → `labNbPractice` 消息发出 → `math-review-v1` 写入 → 第二天今日复习中出现
5. **widget < 6 MB**：`lab-nb.html` 构建后体积检查通过

### 0.3 边界（不做的事）

- 不做 3D / RPG / 付费墙
- 不把实验变成视频（能看的外部资源已有 494 个）
- 不在闭环修好之前扩覆盖
- 不碰动画文件（`anims-*.js` 与 `lab-nb.html` 隔离）
- 练习不写 `math-lab-proc-v1`（跨次统计只算考试）
- 按步结果附加存入 `reviewStore[pointId].steps`，但无界面读取（本次不做）

### 1.3 数据流（单次操作）

```
用户操作（拖、调、连、填预测）
        │
        ▼
  act(intent)
        │
        ├─ 校验（维度、类型、范围、循环检测）
        │         └─ 拒绝 → run.errors++ → toast 说原因
        │
        ├─ 修改 S（纯 JSON，in-memory）
        │
        └─ afterChange()
               │
               ├─ syncBinds()    // 拓扑序更新绑定属性
```

- 跨设备同步：不做（家长端读本机数据）
- 老师端：本机汇总，不上传

## 2. 世界模型

### 2.1 场景图 S

场景图是台面状态的完整描述，纯 JSON，可序列化。

```js
const S = {
  nid: 42,                    // 下一个实体 id 的计数器
  seq: { adder: 3, num: 2 },  // 各类型的序号（用于命名）
  entities: {
    'e1': {
      id: 'e1',
      type: 'adder',          // 必须在 TYPES 中存在
      name: '合并器 1',
      x: 200, y: 150,         // 台面坐标
      props: { op: 0 },       // 可写属性
      k: 1                    // 缩放因子（平板用）
    },
    'e2': { id: 'e2', type: 'num', name: '数 1', x: 80, y: 140, props: { v: 3 }, k: 1 }
  },
  links: [
    { id: 'l1', from: 'e2', fromPort: null, to: 'e1' }
    // fromPort: null 表示默认输出端口；非 null 表示命名端口（'equal'/'dist' 等）
  ],
  binds: [
    { to: 'e3', k: 'r', from: 'e1' }             // 值绑定：e1 的输出驱动 e3 的 r 属性
    // 或 expr 绑定：{ to: 'e3', k: 'r', from: 'e1', expr: 'e1*2+1' }
  ]
}
```

### 2.2 Val 类型系统（8 种 kind）

所有在端口间流动的值统一用 `Val` 对象表示：

```js
// Val = { kind, dim, data }
const Val = {
  kind: 'num',      // 8 种 kind 之一（见下表）
  dim: 'length',    // 9 种维度之一（见下表）
  data: Q(3, 2)     // 有理数 Q = {n, d}，3/2 = 1.5
}
```

**8 种 kind：**

| kind | 含义 | data 类型 | 例子 |
|---|---|---|---|
| `num` | 有理数（当前主力） | `{n, d}` 有理数 | `Q(3,2)` = 1.5 |
| `bool` | 真/假（天平平衡） | `boolean` | `true` |
| `dist` | 分布（一批计数） | `number[]` | `[0,0,1,2,3,4,5,3,2,1,0]`（骰子） |
| `point` | 二维坐标 | `{x, y}` | `{x:3, y:4}` |
| `interval` | 区间 | `{op, b}` | `{op:'>', b:2}` 表示 x>2 |
| `fn` | 线性函数 | `{k, b}` | `{k:2, b:1}` 表示 y=2x+1 |
| `shape` | 几何图形 | `{type, ...}` | `{type:'tri', a:30, b:60}` |
| `seq` | 数列 | `number[]` | `[1,2,4,8,16]` |

**待第 4 批（4b 节拍器）建：**

| kind | 含义 | data 类型 | 例子 |
|---|---|---|---|
| `tick` | 心跳计数（节拍器输出） | `{n, phase}` 或 `{n, t}`（格式待裁决，见 §10.4 #4） | `{n:12, phase:0.5}` |

**9 种维度（dim）：**

`个数` / `长度` / `面积` / `体积` / `重量` / `钱` / `时间` / `角度` / `比值`

维度代数规则：
- `mul`：结果维度 = 两个输入维度之积（`长度 × 长度 = 面积`）
- `adder`：要求两个输入维度相同
- 维度不匹配时拒绝连线，并说出原因

读值统一：`qv(d) = d.val.data`（`d.value` 已删除）

### 2.3 类型对象结构（TYPES）

每种器材是 TYPES 里的一个对象，包含以下字段：

```js
TYPES['adder'] = {
  label: '合并器',          // 显示名
  group: '数与运算',        // 器材架分组
  prefix: '合并器',         // 自动命名前缀
  out: 'value',             // 输出 kind（'value'/'fn'/'bool'/'dist'/null）
  accepts: 'value',         // 接受的输入 kind（null 表示不接收）
  acceptsDist: false,       // 是否也接受 dist（特例）
  dim: 'count',             // 输出维度（可选，mul/div 会覆盖）
  defaults: { op: 0 },      // props 初始值
  fields: [                 // 可调属性（渲染为滑条/选项）
    { k: 'op', label: '运算', min: 0, max: 1, choices: ['加', '减'] }
  ],
  size: () => [170, 84],    // [宽, 高]，单位 px
  // 以下为可选：
  value: (p, port) => Q(…), // 无需连线即能算出值的器材（数字卡、分数条等）
  ports: (p, e, E, D) => ({ sum: …, mean: … }), // 命名输出端口
  sig: (e, d, sig) => { sig('ok', '…') }, // 信号条（状态标注）
  reject: { area: '天平称重量…' }, // 按维度拒绝连线的原因字符串
  rotate: true              // 是否支持旋转（rect 用）
}
```

目标（地基 4）：加一种新器材只改一处（TYPES 里加一个对象），evaluate 分支数从当前 ~80 下降。

### 2.4 evaluate 纯函数

```js
// 输入：场景图 S（只读）
// 输出：D，每个实体 id 映射到派生状态
// 无副作用，可随时调用

function evaluate(S) {
  const E = S.entities
  const D = {}           // 派生状态
  const vals = {}        // 记忆化缓存

  // val(id, port?) → Val | null
  // 递归求值，记忆化，用 busy 防止循环
  function val(id, port) { … }

  // 主循环：计算每个实体的 D[id]
  for (const id in E) {
    const e = E[id]
    const d = D[id] = { ports: {}, sigs: [] }

    // 1. 算 d.val（带类型的输出值）
    d.val = TYPES[e.type].out === 'value' ? val(id) : null

    // 2. 算命名端口（balance.equal, table.sum/mean, dice.dist 等）
    d.ports = portsFor(e, S, E, D)

    // 3. 跑 sig()（信号条）
    if (TYPES[e.type].sig) TYPES[e.type].sig(e, d, sig)

    // 4. 天平专用：算倾斜角 d.tilt / d.equal
    if (e.type === 'balance') { … }

    // 5. 应用绑定（syncBinds 已按拓扑序排好顺序）
    for (const b of S.binds.filter(x => x.to === id)) { … }
  }

  return D
}
```

关键约束：
- evaluate 是纯函数，S 只读，D 是新对象
- 循环检测：`val()` 内用 `busy` set，进入即加，返回即删
- 当前是全量重算；增量触发条件：实体数 > 200 或单次 > 16ms（未来做）

### 2.5 四种互动动词（反孤岛）

| 动词 | 数学含义 | 当前状态 | 目标 |
|---|---|---|---|
| **Flow（流）** | 值从源头流向消费者 | 48 种中 ~30 种有输出端口 | 所有算出物都能流出去 |
| **Bind（绑定/同一）** | 两组件显示同一个数，改一个另一个跟着变 | 已建（`binds[]`，拓扑序） | 属性即端口：圆半径可接数字卡 |
| **Compare（比较）** | 关系输出真值 | `bool` kind 已建，天平 `equal` 端口已通 | Bool 端口可连判断灯 |
| **Transform（变换）** | 函数作用在值/图形上得新值/图形 | fn kind 已建（直线→坐标平面） | 变换卡（第 4 批 4h） |

**反孤岛第一定律：**
> 每个组件算出来的东西，都能流出去；每个能调的东西，都能被别的组件驱动。

### 2.6 实验 POE 模型

每个实验（XP）是一个步骤数组。步骤类型有两种：

```js
const xp = {
  id: 'g4_4',
  title: '三位数乘两位数',
  tags: ['乘法'],
  steps: [
    // s0：predict 步（永远是第一步）
    {
      id: 'g4_4:s0',
      type: 'predict',
      label: '先猜一猜：答案是多少？',
      hint: '先算一算，写下你的预测，再动手做。',
      expect: 1500,              // 期望答案（用于判分）
      score: 1,
      target: T45('mul'),        // 高亮提示的器材类型
      check: () => false         // predict 步永远返回 false（靠 st.pred 驱动）
    },
    // s1+ ：do / observe 步
    {
      id: 'g4_4:s1',
      type: 'do',
      label: '把 25 × 60 算出来',
      hint: '把两个数字卡连进乘法器',
      score: 2,
      target: (S) => byType(S, 'mul'),
      check: (S, D) => {
        const mul = byType(S, 'mul')
        return mul && qeq(qv(D[mul]), Q(1500))
      }
    }
  ]
}
```

**POE 判分规则：**
- predict 步：`st.pred !== undefined`（填了数）就算完成；`st.pred === expect` 才算猜对（影响 `correct`）
- do/observe 步：`check(S, D)` 返回 `true` 才算完成
- `correct = 所有步骤得分 / 总分 >= 阈值`（预测步必须猜对，do 步必须全对）
- `confident = run.errors === 0`（全程无拒绝操作）

### 2.7 tick 心跳

台面无"运行"按钮。每次 `act(intent)` 立刻触发 `afterChange → evaluate(S) → DRAW`。

节拍器（第 4 批 4b）建成后，`tick` 是一种 Val kind，流过台面驱动动态器材（摆、弹跳球、迭代器等）。tick 的 data 格式待裁决：`{n, phase}` 还是 `{n, t}`（阻塞第 4 批 4b 开工前定）。

## 4. 学习设计

### 4.1 POE 结构（Predict-Observe-Explain）

每个实验的第一步永远是 predict 步（s0），ID 遵循 `xpId:sN` 约定，s0 = predict。

```
┌─────────────────────────────────────────────────┐
│  s0  predict   先猜一猜：答案是多少？           │
│       ├─ 学生填数 → st.pred 记录                │
│       ├─ st.pred === expect → 猜对（影响 correct）│
│       └─ st.pred !== undefined → 步骤完成       │
│                                                  │
│  s1  do        把 25 × 60 算出来                │
│       ├─ check(S, D) → true → 步骤完成           │
│       └─ target(S) 高亮提示该用哪个器材          │
│                                                  │
│  s2  observe   看结果，说说你发现了什么          │
│       └─ check(S, D) → true → 步骤完成           │
└─────────────────────────────────────────────────┘
```

**为什么先猜：** 猜了才会关注结果，结果和预期不同才有发现。predict 步的 `check` 永远返回 false（靠 `st.pred` 驱动完成），判分只看有没有填，不看对错。

### 4.2 步骤判分

```js
// run.steps[i] = { i, done, op, pred }
//   i:    在 xp.steps 中的索引
//   done: 是否完成
//   op:   完成时的 run.ops 值（用于"最少几步"评分）
//   pred: predict 步的填写值

function track() {
  const D2 = evaluate(S)
  for (const st of run.steps) {
    if (st.done) continue
    const xpStep = xp.steps[st.i]
    if (xpStep.type === 'predict') {
      // predict 步：填了数就算完成
      if (st.pred !== undefined) {
        st.done = true
        st.op = run.ops
      }
    } else {
      // do/observe 步：check 返回 true 才算完成
      if (xpStep.check(S, D2)) {
        st.done = true
        st.op = run.ops
      }
    }
    // 遇到第一个未完成的就 break（线性推进）
    if (!st.done) break
  }
}
```

**完成判定：**
- `correct = 所有步骤得分 / 总分 >= 阈值 && 预测步猜对`
- `confident = run.errors === 0`（全程无拒绝操作）

### 4.3 误解靶向

每个知识点在 grade-N.js 里有 `wrong` 和 `wrongWhy` 字段：

```js
{
  id: "1.1",
  title: "数数、一一对应、比多少",
  wrong: "数得快就是数对了；同一个东西数两次也没关系。",
  wrongWhy: "数得快容易漏数或者重数；一个东西数了两次，牌就多贴了一张，总数会比真的多一个。"
}
```

实验设计原则：
- 每个实验至少有一个步骤会触发典型误解（让学生犯常见错误）
- 犯错后有可见后果（天平倾斜、信号条报错、图形画不出）
- 错误信息引用 `wrongWhy` 的解释，不用"你错了"这种评判语

### 4.4 自适应

基于 `math-review-v1` 的 `streak`（连续答对次数）：

| streak | 下次出现间隔 | 行为 |
|---|---|---|
| 0（答错） | 1 天 | 明天复习 |
| 1 | 2 天 | |
| 2 | 4 天 | 已掌握 |
| 3+ | 7 天 | |

```js
function recordAttempt(pointId, correct, confident) {
  const prev = reviewStore[pointId] || { streak: 0 }
  let streak = correct ? prev.streak + 1 : 0
  const days = streak === 0 ? 1 : streak === 1 ? 2 : streak === 2 ? 4 : 7
  reviewStore[pointId] = {
    last: Date.now(),
    correct: !!correct,
    confident: !!confident,
    streak: streak,
    due: Date.now() + days * 86400000
  }
  saveReview()
}
```

### 4.5 完整闭环

```
┌─────────────────────────────────────────────────────────┐
│  实验台（lab-nb.html）                                   │
│  ┌──────────────────────────────────────────────┐       │
│  │  学生做实验                                    │       │
│  │  ├─ s0 predict（先猜）                        │       │
│  │  ├─ s1+ do/observe（动手做）                   │       │
│  │  └─ 全部完成 → run.practicePosted 守卫          │       │
│  └──────────────────┬───────────────────────────┘       │
│                     │ postMessage('labNbPractice')      │
│                     │ {pointId, correct, confident,     │
│                     │  steps:[{i,done,pred}...]}       │
│  └─────────────────┼───────────────────────────────────┘
│                    │
│  app.js 监听       │
│  ┌─────────────────▼───────────────────────────────┐   │
│  │  recordAttempt(pointId, correct, confident)     │   │
│  │  ├─ 写入 math-review-v1（复习库）                 │   │
│  │  ├─ reviewStore[pointId].steps = 步骤结果        │   │
│  │  └─ practicePosted = true（防重复）              │   │
│  └──────────────────────────────────────────────────┘   │
│                                                          │
│  下次打开 →                                              │
│  ┌──────────────────────────────────────────────┐       │
│  │  今日复习（due <= now 的知识点）                │       │
│  │  错题本（correct === false 的知识点）          │       │
│  │  → 点击 → 回到实验台丢的那一步                   │       │
│  └──────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────┘
```

**断点续做：** `nb-lab-practice-v1` 自动保存台面状态，离开再回来能接着做。没完成不记录学习数据（不调 `recordAttempt`），`practicePosted` 守卫防重复发消息。

**已知缺口（不阻塞开工）：** `restoreRun()` 按数组索引读取保存的步骤进度。插入 s0 predict 步后，旧的 localStorage 存档可能错位。当前设计标注在 §4.5，施工时需做版本号迁移或清空旧存档。

### 9.1 五层验证

| 层 | 方法 | 何时跑 | 工具 |
|---|---|---|---|
| 1 | check-xp.js 静态验证 | 每次提交前 | `tools/check-xp.js` |

| 5 | 信号文字不变（39 处 check 匹配） | 每批合入前 | diff 对比 |

**check-xp.js 规则（≥3 步 / 有 predict / why 讲推理 / 不匹配信号文字 / 不按插入顺序取器材）：**
- 每个实验至少 3 步
- 第一步必须是 predict（s0）
- do/observe 步的 `check` 不能匹配信号文字（改一个字实验就坏）
- 不能用 `.tx === '...'` 之类读显示文字判分
- 不能用 `filter()[N]` 按插入顺序取器材（要用 `byType` 或 `byId`）

### 9.2 六个存储 key

| key | 内容 | 写入时机 | 读取方 |
|---|---|---|---|
| `math-review-v1` | 复习库（reviewStore） | `recordAttempt` | 首页复习/错题本/家长端 |
| `nb-lab-practice-v1` | 实验台断点续做 | 实验台 autoSave | 实验台 restoreRun |
| `math-tried-demos-v1` | 玩过的演示集合 | 演示完成 | 首页"学过"统计 |
| `math-lab-proc-v1` | 跨次统计（考试交卷时记） | 挑战交卷 | 改进清单（老师端） |
| `math-teacher-v1` | 老师作业/班级数据 | 布置作业 | 老师端看板 |
| `math-parent-v1` | 家长简报（缓存） | 周报生成 | 家长端 |

### 9.3 构建流水线

```
改代码
  │
  ├─ node tools/check-xp.js     // 静态验证（88/88 → 161+/161+）
  │    └─ 失败 → 修复 → 重跑
  │
  ├─ 手动跑黄金路径基线          // 147 条 + 黄金路径
  │    └─ 差一个字就是回归 → 单独回滚
  │
  ├─ 真机复测（浏览器手动）       // 每批必做
  │    └─ 骰子 dist 失败已证明此规则不可绕开
  │
  ├─ widget 体积检查             // wc -c lab-nb.html < 6 MB
  │
  └─ git commit + push → PR     // 每批一提交
       └─ 真机验过才合入 main
```

### 9.4 每批合入标准

1. check-xp.js 通过率不下降
2. 黄金路径基线全部通过（差一个字就是回归）
3. 真机回归测试通过
4. widget < 6 MB
5. 信号文字 39 处不变（除非刻意迁移，需单独标注）
6. 新实验必过 XP lint（≥3 步 / 有 predict / why 讲推理 / 不匹配信号文字）

### 9.5 六个护栏（ground rules）

1. **ports 是加法不是替换**：D 的现有键（d.tilt/d.equal/d.tot/d.terms/d.L/d.R/Ln/Rn）在迁移完成前一字不动
2. **信号文字一字不改**：39 处 check 匹配信号文字是判分事实来源
3. **绑定边和链接边用同一张图同一个拓扑序**
4. **每批跑基线**：开场 147 条 + 黄金路径，差一个字就是回归
5. **widget < 6 MB**
6. **不碰动画文件**：anims-*.js 与 lab-nb.html 隔离

### 10.2 六件地基（施工顺序）

施工顺序不是层号顺序：地基 3 → 地基 4 → 地基 5 → 地基 1 → 地基 2 → 地基 6。

| 编号 | 地基 | 所属批 | 施工顺序 | 最关键的验收标准 |
|---|---|---|---|---|
| 地基 3 | 崩溃 bug U01（删绑定器材台面冻住） | 批 0 | 第 1 | case 'del' 清 binds；val() 对不存在 id 返 null；evaluate 绑定校验先判实体存在。**测试用例：删除一个有绑定的器材，台面不应冻住，被绑属性应回落到默认值。** |
| 地基 4 | 类型对象合一 | 批 1（F2） | 第 2 | 加一种器材只改一处；evaluate 分支数下降 |
| 地基 5 | 值类型缺口（point/interval/expr/seq/dist 补完） | 批 1（F1）+ 批 4（E3） | 第 3 | dist 能连线；掷 100 次表和图自动更新 |
| 地基 1 | 学习闭环 A1（练习写记录） | 批 2（A） | 第 4 | 练错的步骤第二天出现在今天复习里 |
| 地基 2 | 质量关 check-xp.js 全覆盖 | 批 3（C） | 第 5 | 通过率从 15/88 上升；不再有 2 步模板 |
| 地基 6 | 基础器材 D6（十格阵/数位块/转盘/量角器） | 批 5（D） | 第 6 | 各设计稿先行；G2/G3 各至少 1 个点实验用上 |

### 10.3 五条施工原则（批内排序用）

1. **依赖先行** — 硬约束，违反就是建脆地基
2. **胶水靠前** — 7 种胶水在 4a，但必须在孤岛补端口之后（批 1 F1/F2 之后）
3. **课堂刚需靠前** — 凑十架/竖式台/试商台在 3a/3b，D6 在批 5
4. **世界首创不优先** — 首创按依赖自然落位，不加分
5. **每批一提交，真机验过才合入** — 骰子 dist 失败已证明此规则不可绕开
