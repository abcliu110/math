# Methods and Technologies for Making Mathematics Experiments — Worldwide Catalog (ages 6–15)

**Date read:** 2026-11-06. **Method:** web-index search only (`browser_search`); **no page was verified live in a browser and no site was signed into.** Every claim below is therefore `index` confidence unless marked otherwise. Treat licences / prices as check-before-shipping: several sources are secondary summaries. Primary sources (official docs, original papers) are preferred and named where found.
**Scope:** school mathematics, primary–junior high (6–15). "Math experiment" = an interactive, manipulable representation in which the learner changes something and sees a mathematical consequence — not a video alone, not a static worksheet.

---

## Summary

- **Methods:** the strongest, best-evidenced design patterns are POE / predict-then-reveal, productive failure (problem-first, then consolidate), variation / 变式 (vary one thing, hold the rest), CPA + multiple linked representations, virtual manipulatives, worked-example fading + self-explanation, number talks / estimation-first, neriage (one problem, many solutions, compare), and ST Math / Graspable Math style feedback (animate the wrong logic; make illegal moves impossible). Weakest evidence in this set: badges/checkpoint gamification as a *learning* method (motivation evidence is mixed and mostly extrinsic), and "student-as-creator" as a standalone method (strong as a capstone, weak as first exposure).
- **Technologies:** for a **lightweight single-file offline HTML app the winning core is vanilla JS + inline SVG (+ a little Canvas) + KaTeX (vendored) + a tiny hand-rolled model/state engine** — see §3.1. JSXGraph is the best single *optional* vendored library if you need dynamic geometry/graphing without a server or API key. GeoGebra / Desmos are the most powerful dynamic-geometry/graphing embeds, but both need network + (GeoGebra) a non-commercial licence / (Desmos) an API key, so they do **not** fit a truly offline single file. PhET/SceneryStack is the gold standard for *how* to build a sim (model–view separation, implicit scaffolding), but it is a TypeScript build-system stack, not a single-file library.
- **Chinese vs international split:** internationally the canon is CPA / bar modelling (Singapore), variation theory (Marton + Gu), 5E, POE, productive failure. In China the same ideas appear as 变式教学 (Gu Lingyuan, 青浦实验), 情景动画 + 互动 (洋葱学园, 火花思维), and 学科工具 inside teacher-authoring suites (希沃白板, 101教育PPT). The Chinese commercial platforms are overwhelmingly **animation-video + live-class + gamefied practice**, not open, embeddable experiment engines — their under-the-hood stacks are **not public**. NOBOOK is the exception in spirit (self-built simulation engines), but its engines are physics/chemistry/biology, not mathematics.

## 1. METHODS CATALOG — how to DESIGN a math experiment

How to read each entry: *what it is (1–2 sentences) · origin · example URL in action · best topics.*

### 1.1 Inquiry / discovery methods

| Method | What it is | Origin | Example URL | Best topics |
|---|---|---|---|---|
| **Predict–Observe–Explain (POE)** | Learner commits to a prediction (+ reason) *before* seeing the result, observes the (often surprising) outcome, then reconciles prediction vs observation. In maths the "observe" step is usually "investigate / compute / simulate". | White & Gunstone (1992), *Probing Understanding*; PEOR refinement (predict–explain–observe–react) | https://arbs.nzcer.org.nz/printpdf/7187 (NZCER: "works best with demonstrations that allow immediate observations… a similar strategy also works well in mathematics, particularly in statistics") — also http://www.recsam.edu.my/sub_jsmesea/images/journals/YEAR2009/june2009vol1/62-84.pdf | Probability (simulate-first), estimation, statistics, surprising patterns (e.g. coin runs, Monty Hall intuition), area/perimeter confusion |
| **Productive failure (PF) / problem-solving before instruction** | Learners first attempt a rich, hard problem with prior knowledge only (and fail, diversely), *then* receive instruction that compares their attempts with the canonical method. Two-phase: generate → consolidate. | Kapur (2008) *Cognition and Instruction* 26(3); Kapur (2014) *Cognitive Science* 38; Sinha & Kapur (2021) meta-analysis of 53 studies / 166 comparisons, moderate benefit for conceptual learning | https://www.structural-learning.com/post/productive-failure-education-teachers-need (Year-8 example: invent a way to compare spread of two data sets *before* teaching standard deviation) ; paper: https://d.docksci.com/productive-failure-in-learning-math_5af61a34d64ab2ce2271da27.html | Standard deviation / variance, average speed, fraction division, any concept where the naive method is instructively inefficient. **Not** for first exposure to purely procedural fluency; needs a consolidation step — failure alone does not teach. |
| **Variation theory / 变式教学 (bianshi)** | Learning = discerning a critical aspect by experiencing *variation against a background of invariance*. Vary one dimension at a time (contrast → separation → generalisation → fusion). Chinese bianshi splits into **conceptual variation** (many examples / non-examples of one concept) and **procedural variation** (hierarchical, step-by-step problem chains). | Marton & Booth (1997); Marton (2015); Gu Lingyuan (顾泠沅, 1991/1994, Shanghai Qingpu experiment) + Gu, Huang & Marton (2004) | https://thirdspacelearning.com/blog/variation-theory/ ; https://www.criced.tsukuba.ac.jp/math/apec/apec2006/16/1604_park.pdf ; Chinese: http://www.jyb.cn/education/jiaoxue/201004/t20100402_350953_2.html and https://www.pep.com.cn/kcs/yjcg/lw/lw2015/201809/t20180929_1931786.html (PEP: 概念性变式 + 过程性变式) | Almost everything, if implemented as a slider / parameter sweep: fractions (vary numerator, hold denominator), linear graphs (vary slope, hold intercept), area (vary one side), equations (vary one coefficient). This is the single most *implementable* method in code — it maps directly onto sliders. |
| **5E model** | Lesson cycle: **Engage → Explore → Explain → Elaborate → Evaluate**. Constructivist; the "explore" phase is the experiment, "explain" names what was found. | BSCS, led by Rodger Bybee (1987), building on Atkin–Karplus learning cycle | https://creditsforteachers.com/the-5e-instructional-model-explained-a-framework-for-inquiry-based-learning/ ; maths classroom study: https://ijemst.com/index.php/ijemst/article/download/469/pdf/383 | Whole-lesson / whole-app structure rather than one widget: e.g. a fractions lab framed as 5E. Best for multi-screen experiments, not single interactions. |
| **Problem-based / inquiry-based learning (PBL/IBL)** | Learning organised around investigating and resolving a meaningful, ill-structured problem; students draw on prior knowledge, decide what they need to learn, collaborate. | Hmelo-Silver (2004) *Educational Psychology Review* 16(3) — "focused, experiential learning organized around the investigation, explanation, and resolution of meaningful problems" | https://knilt.arcc.albany.edu/index.php?title=Features_of_Problem-Based_Learning&oldid=163755 | Rich contexts: design a garden (area/perimeter), plan a party budget (ratio/proportion), "which phone plan is cheapest?" (linear functions). Needs a real problem, not a dressed-up drill. |
| **Socratic questioning in interactive form** | Instead of telling, the app asks a sequence of narrowing questions ("what if the denominator doubles?", "can you make a counterexample?") and branches on the answer. In code: decision-tree prompts + "why?" follow-ups after each step. | Socratic method (classical); modern form in intelligent tutoring / self-explanation research (Chi). No single canonical paper for the interactive form — see worked-example / self-explanation below. | No single canonical example URL found — see Graspable Math / ST Math feedback entries below for the closest interactive analogues. | Misconception-heavy topics: fractions, negative numbers, equals-sign meaning, division by zero. **Gap:** few public, reusable Socratic-dialogue templates for maths exist; most implementations are hand-authored. |

### 1.2 Representation methods

| Method | What it is | Origin | Example URL | Best topics |
|---|---|---|---|---|
| **CPA — Concrete–Pictorial–Abstract** | Three-stage progression: handle physical (or virtual) objects → draw/visualise them → use symbols only. Not strictly linear; revisit concrete whenever a new concept appears. | Jerome Bruner (1966) enactive–iconic–symbolic; popularised by Singapore MOE | https://www.pearson.com/international-schools/international-schools-blog/2026/05/how-the-concrete-pictorial-abstract--cpa--model-can-support-adva.html ; https://mathsnoproblem.com/blog/teaching-maths-mastery/concrete-resources-to-abstract-learning/?utm_source=topic-clusters&utm_medium=text-link&utm_campaign=mastery-cluster | All primary maths; in an app: virtual counters/tiles (concrete) → bar/number-line drawing (pictorial) → equation (abstract), with a toggle that keeps all three visible. |
| **Multiple linked representations (Lesh translation model)** | Understanding = ability to translate *between* five representations of one idea: real-world context, manipulatives, pictures, spoken/written language, symbols. The app should link them so changing one updates the others live. | Lesh, Post & Behr (1987) | https://math.nie.edu.sg/ame/mtc2016/download/SrJoseph/P10_Empower%20Low-Progress%20Learners%20to%20Use%20Representations%20to%20Solve%20Process%20Problems.pdf ; https://www.Intechopen.com/chapters/69267 | Fractions (area model ↔ number line ↔ symbols ↔ words), functions (table ↔ graph ↔ equation ↔ story), ratio. The meta-analysis of virtual manipulatives found "simultaneous linking" is one of five affordances that promote learning — see §1.3. |
| **Bar modelling (tape / strip diagrams)** | Rectangular bars represent quantities and their relationships (part–whole, comparison, fraction/ratio). The drawing *is* the reasoning; arithmetic follows. | Singapore, Dr Kho Tek Hong's Primary Mathematics Project team, introduced into curriculum 1983, on Bruner's CPA | https://mathsnoproblem.com/en/approach/bar-modelling ; https://pslehero.org/singapore-math-bar-model.html | Word problems, fractions, ratio, percentage, before–after problems, early algebra (unknown = "?"). Extremely implementable: draggable, resizable bars + labels. |
| **Number line as a universal ruler** | One continuous line used for counting, ordering, fractions, decimals, negatives, addition/subtraction as movement, multiplication as scaling. Same object, many topics. | Long-standing; central in Singapore / US Common Core; PhET "Number Line: Integers" sim is a canonical interactive instance. | PhET maths list: http://elearn.psgcas.ac.in/PhET/en/simulations/category/math.html (lists Number Line: Integers, Fractions: Intro, etc.) | Number sense, fractions/decimals, integers, estimation, rounding. |
| **Area models** | Multiplication / distributive property as rectangle area; partition a rectangle to discover (a+b)(c+d), decimal multiplication, algebra tiles. | Long-standing; PhET Area Model suite is the canonical interactive set. | PhET list above; descriptions: https://meshmoli.weebly.com/blog/phet-colorado-physics-simulations ("Partition a rectangle into two areas to discover the distributive property… Build rectangles… relate multiplication to area") | Multiplication, distributive law, fractions × fractions, (x+a)(x+b), completing the square. |
| **Balance-scale equations** | "=" is a level balance; whatever you do to one side you must do to the other. Removing/adding the same weight, splitting into equal groups = inverse operations. | Long-standing (physical balances; "hanger math" in Illustrative Mathematics); digital form in many algebra tools. | https://www.vibemath.app/learn/solving-linear-equations-with-a-balance-model ; https://sciencestream.blog/hanger-math-solve-equations-visually ; also 101教育PPT 学科工具 "天平": https://8.ndhy.com/m/whiteBook.shtml | One- and two-step equations, equations with x on both sides, inequalities (tilt). |
| **Cut-and-reassemble (dissection)** | Cut a shape and reassemble it to prove area/congruence: parallelogram → rectangle, triangle → parallelogram, circle → near-rectangle, Pythagoras dissection. | Classical (Euclid onwards); Tangram tradition. | Polypad (Mathigon) tangram / dissection tiles — see https://www.columbusstate.edu/crmc/resources.php (lists Polypad) and https://tech-learning.visitlink.me/4tPYDE | Area of parallelograms/triangles/circles, Pythagoras, fractions of a shape, symmetry. Very strong for geometry; needs drag + snap + rotate. |

### 1.3 Interaction design methods

| Method | What it is | Origin | Example URL | Best topics |
|---|---|---|---|---|
| **Virtual manipulatives** | Screen replicas of physical manipulatives (fraction bars, base-10 blocks, algebra tiles, geoboards) *plus* digital-only advantages: precise, linkable, immediate feedback, unlimited supply. | Moyer, Bolyard & Spikell (2002); Moyer-Packenham & Westenskow (2013) meta-analysis of 66 reports — moderate effect on achievement; five affordances: focused constraint, creative variation, simultaneous linking, efficient precision, motivation | https://eric.ed.gov/?id=EJ1154970 ; https://digitalcommons.usu.edu/teal_facpub/1406/ ; Polypad as a library of them: https://tech-learning.visitlink.me/4tPYDE | Fractions, place value, algebra tiles, geometry tiles, probability (spinners/dice). |
| **Drag-and-drop / direct manipulation** | Learner moves the mathematical object itself (not a form field): drag a point, a tile, a bar segment. The gesture *is* the operation. | Direct-manipulation HCI (Shneiderman); in maths, Graspable Math / GeoGebra drag test. | GeoGebra embed/API: https://mat.geogebra.org/m/sehv2qc9 ; Graspable Math guide: https://graspablemath.com/shared/content/GM Canvas User Guide 2020-09-01.pdf | Geometry constructions, fraction bars, algebra tiles, sorting/classifying. |
| **Sliders with live consequences** | One parameter on a slider; every linked representation updates live (graph, table, number, picture). The slider *is* variation theory in code. | Variation theory (§1.1) + dynamic geometry tradition. | Desmos API quick start (slider example pattern): https://www.desmos.com/api/v0.8/docs/index.html ; PhET sims (e.g. Proportion Playground, Graphing Lines) via http://elearn.psgcas.ac.in/PhET/en/simulations/category/math.html | Functions (slope/intercept), probability (sample size), geometry (angle/side length), growth/decay. |
| **Predict-then-reveal** | Same as POE, as a UI pattern: lock the answer in (click / drag a guess) *before* the "reveal" animation runs; show prediction vs actual side by side. | POE (§1.1). | PhET "Make a prediction" pattern in sims — see https://learntoscale.org/stories-of-scaling/phet/ (implicit guidance, prediction before reveal in PhET design) ; ST Math feedback: https://thelearningstandard.org/apps/st-math | Estimation, probability experiments, function behaviour, measurement. Cheap to build, high yield — implement in *every* experiment. |
| **Worked-example fading + self-explanation prompts** | Show a fully worked solution, then fade out steps backwards (last step first — Renkl: backward fading beats forward fading), prompting "why was this step necessary?" at each faded step, until the learner solves alone. | Sweller (1988) cognitive load; Renkl, Atkinson & Maier (2002); Renkl (2005) | https://alchetron.com/Worked-example-effect ; original paper: http://www.davidlewisphd.com/courses/EDD8121/readings/2002-Renkl_et_al.pdf | Multi-step procedures: long division, solving equations, fraction addition with unlike denominators, column multiplication. |
| **One problem, multiple solutions — neriage / 练一题多解** | One rich problem, learners generate several solution methods, then whole-class comparison/discussion ("kneading/polishing" ideas) to compare efficiency, generality, elegance. In a solo app: present 2–3 *seeded* student solutions to compare and rank. | Japanese lesson study / structured problem solving (Shimizu 1999; Fujii 2016); Chinese 一题多解 tradition. | https://springerlink.fh-diploma.de/article/10.1007/s11858-016-0770-3 ("neriage… assumes students will arrive at different solution methods and focusses on a comparison and discussion") ; https://pedagogy-vestnik.buketov.edu.kz/index.php/pedagogy-vestnik/article/download/1331/532 | Any problem with ≥2 genuine routes: 25×16 (many factorisations), fraction division, area of a composite shape, "how many ways to make 24?". |
| **Estimation-first / number talks** | Short (5–15 min) routine: present one computation mentally, learners estimate / find *a* strategy, share and compare strategies; teacher records all strategies without judging. Estimation *before* exact computation. | Sherry Parrish (2010/2011) *Number Talks*; Humphreys & Parker. | https://sites.google.com/site/primarycpd/latest-news/numbertalks ; Parrish article: https://padletuploads.blob.core.windows.net/prod/45403/bdcfa68927ea1bd16042ea7097d16223/Number_Talks_Article_by_Sherry_Parrish.pdf | Mental arithmetic, fractions ("closer to 0, ½ or 1?"), multiplication strategies, rounding. In an app: "estimate first" gate + strategy gallery. |
| **Simulate-first probability** | Run many trials (dice, spinners, Plinko) *before* formalising probability; let the law of large numbers emerge visually. | PhET design; frequentist tradition. | PhET Plinko Probability / Proportion Playground via http://elearn.psgcas.ac.in/PhET/en/simulations/category/math.html | Probability, expected value, sampling variation, fairness of games. |

### 1.4 Feedback methods

| Method | What it is | Origin | Example URL | Best topics |
|---|---|---|---|---|
| **Immediate visual feedback** | The consequence is shown, not told ("✓/✗"): the shape fits or doesn't, the bar reaches the target or falls short. | PhET implicit scaffolding; ST Math. | https://thelearningstandard.org/apps/st-math ("immediate, animated feedback… animates the student's incorrect logic") | All manipulatives; especially fractions, measurement, geometry. |
| **Animating the student's wrong logic (ST Math style)** | On a wrong answer, play out *exactly what the learner's answer would do* in the world (e.g. 3×4 answered as 10 shoes → show 2 dogs barefoot), so the learner sees *why* it fails. No text lecture needed. | MIND Research Institute, ST Math (JiJi the penguin), spatial-temporal reasoning. | https://thelearningstandard.org/apps/st-math ; parent guide: https://resources.finalsite.net/images/v1653424924/smfcsdnet/h1owvvkgc1n5zb74otqu/st-math-parent-kit.pdf ("Animated informative feedback… shows students the mathematical consequences of each answer") | Multiplication, fractions, place value, any "how many are needed / will it fit?" task. **Hardest to build well** — requires a world-model per task, not a generic checker. |
| **Making illegal moves impossible (Graspable Math style)** | The notation itself enforces the rules: permissible gestures transform an expression into an equivalent one; impermissible ones shake / snap back. Learner learns the rules by *feeling* the constraints. | Ottmar et al. (2015), Graspable Math; embodied/perceptual learning. | https://graspablemath.com/shared/content/GM Canvas User Guide 2020-09-01.pdf ("symbolically permissible moves transform… while impermissible moves do not… terms shake or snap back") ; https://repository.isls.org/bitstream/1/7668/3/Closser%20et%20al.%20Sep%202022.pdf | Algebra: combining like terms, distributing, moving terms across "=", factoring. |
| **Per-step scoring + lost-point location** | Score each step, not just the final answer; pinpoint *where* the points were lost (which step, which misconception). | Formative assessment (Black & Wiliam 1998); implemented in GeoGebra Classroom / Desmos dashboards (live progress, error analysis). | GeoGebra Classroom: https://mat.geogebra.org/m/fsddzwzx ; Desmos/Amplify dashboard: https://admsample.amplify.com/tx/the-digital-experience | Multi-step problems, exams-style practice. In a solo offline app: keep a step log locally and show it. |
| **Misconception-tagged feedback** | Each wrong answer is mapped to a known misconception (e.g. "added numerators and denominators", "multiplied by 10 = add a zero") and the feedback names *that* error specifically, with a counter-example. | Misconception research (e.g. Ashlock; Swan's *Improving Learning in Mathematics*). | No single canonical public URL found in this session for a reusable misconception-tag library — this is a **gap** (§3.3). Closest: ST Math / PhET interview-driven design described at https://learntoscale.org/stories-of-scaling/phet/ | Fractions, decimals, algebra, negative numbers. Requires a misconception table per topic — author it deliberately, don't improvise. |
| **Self-explanation prompts** | After (or during) a step, ask "why did you do that?", "what would happen if you skipped this step?", "how is this like the last problem?" — typed or chosen, not just read. | Chi (1989/2000); Renkl (2005). | See worked-example fading sources above: http://www.davidlewisphd.com/courses/EDD8121/readings/2002-Renkl_et_al.pdf | Any worked example / multi-step task. Cheap: a prompt box + "compare with a model explanation". |

### 1.5 Motivation / structure methods

| Method | What it is | Origin | Example URL | Best topics |
|---|---|---|---|---|
| **Practice vs exam mode split** | Two modes with different rules: *practice* (hints, retry, no timer, feedback on) vs *exam* (no hints, timed, feedback after). Makes the stakes explicit and trains transfer. | Assessment design; common in Chinese apps (练习/测评 split) and in NOBOOK's "知识闯关 / 模拟操作测评" — https://www.isc.org.cn/article/25738890432081920.html | NOBOOK exam/assessment page: https://www.nobook.com/web-exam | All drill / fluency topics. |
| **Spaced repetition / retrieval practice inside experiments** | Revisit a concept after a delay, *by retrieving it* (not re-reading): low-stakes quiz at start of a later session, interleaved with other topics. | Roediger & Karpicke (2006) testing effect; Dunlosky et al. (2013) — practice testing + distributed practice rated "high utility"; Cepeda et al. (2006) spacing meta-analysis. | https://www.structural-learning.com/post/retrieval-practice-primary ; https://link.springer.com/article/10.1007/s11251-024-09680-w (spaced recall in precalculus) ; algorithms §2.7 | Times tables, fraction facts, vocabulary (numerator/denominator), procedures that decay fast. |
| **Badges / checkpoint paths** | Visible progress map, unlocks, streaks. Works as *organisation and feedback*, not as the learning itself. | Gamification literature; ST Math mastery levels, 洋葱学园 achievement system. | ST Math levels: https://thelearningstandard.org/apps/st-math ; 洋葱学园 human-computer loop: http://www.duozhi.com/industry/insight/2023121415727.shtml | Long courses / homework. **Evidence caution:** extrinsic rewards can crowd out intrinsic interest; use for *completion* signalling, not for bribing each answer. |
| **Open-ended inquiry tasks ("what if…?")** | After the closed task, one open prompt: "what if the shape had 5 sides?", "can you make a fraction *between* these two?", "design a spinner that is unfair *on purpose*?" | Inquiry / PBL (§1.1); 火花思维 "好奇-探索-猜想-验证-反思-应用" six-step method. | https://www.prnasia.com/story/526072-1.shtml (火花思维 six steps) ; https://www.woshipm.com/evaluating/3537810.html | Extension / fast finishers; pattern, geometry, probability. |
| **Student-as-creator (design a problem / game)** | Learner authors the experiment: build a fraction puzzle for a classmate, design a spinner + rules, code a pattern in Scratch. Creating forces the deepest representation work. | Papert / constructionism; Scratch (Resnick, MIT Media Lab). | Scratch: https://simple.wikipedia.org/wiki/Scratch_(programming_language) ; *Math Hacks for Scratch*: https://mitpressbookstore.mit.edu/book/9781718503380 | Patterns, probability games, geometry art, functions as rules. Best as a capstone after the concept is secure — weak as first exposure. |

**Chinese-specific note (methods):** 变式教学 is not a translation of Marton's theory — it is a parallel, older Chinese practice (Gu, Qingpu, from 1977) that Marton later connected with; PEP's own account stresses both conceptual and procedural variation: https://www.pep.com.cn/kcs/yjcg/lw/lw2015/201809/t20180929_1931786.html. Chinese commercial practice adds 情景动画引入 + 思考过程互动 + 教具实物配合 (火花思维: https://www.woshipm.com/evaluating/3537810.html) and 5–8-minute animation micro-lessons (洋葱学园: http://yangcongxueyuan.com/digital-resource/) — both are *delivery* patterns around the same inquiry methods, not separate learning theories.

### 2.2 Dynamic geometry & graphing

## 3. SYNTHESIS

### 3.1 Recommended minimal stack for a lightweight single-file math app

**Use this:**

```
one .html file
  inline <style>            — CSS custom properties, flex/grid, no framework
  inline <svg> per lab      — bars, tiles, number lines, shapes (DOM = clickable, accessible)
  <canvas> only where needed — particles / freehand / many-object sims
  vanilla JS, one tiny core:
    • Model  — pure functions: state → derived values (the maths, computed by law)
    • View   — render(state) → SVG/DOM (re-render on change; no framework)
    • Controller — pointer events (drag/slider/input) → model → render
    • Generator — seeded RNG + "answer-first" parameterised questions
    • Feedback — per-step log + misconception table per topic
    • Storage — localStorage: progress, SM-2-lite intervals, best scores
  KaTeX (vendored, or pre-rendered) — only if you display algebra; omit for primary arithmetic
  JSXGraph (vendored, one file) — ONLY for labs that need dynamic geometry / graphing
  matter.js (vendored) — ONLY for 1–2 playful physics-metaphor labs
```

**Why this, and not the alternatives — the reasoning:**

1. **The model *is* the experiment.** A maths experiment is not an animation; it is a *law* the learner can poke. If you write `area = w*h` as a pure function and re-render from it, then *every* combination of inputs is automatically correct, every slider is variation theory, and every wrong answer can be explained by running the model with the learner's numbers (ST Math style). Libraries that only *draw* (D3, GSAP, Lottie) cannot do this; engines that only *animate* (Manim) cannot either. PhET and NOBOOK both work this way (model–view separation; engines that compute by law) — copy the architecture, not their codebases.
2. **SVG beats Canvas for most maths, and beats every library for a single file.** Bars, tiles, number lines and shapes are *few, crisp, individually clickable* objects. SVG gives you that with zero bytes, keyboard/screen-reader access, and CSS animation. Canvas is for many-particle sims only. D3 adds ~250 KB to do what 30 lines of SVG code does for a bar model. JSXGraph earns its bytes only when you need constraint-based geometry or function plotting.
3. **Zero-dependency = zero failure modes offline.** No CDN, no API key (Desmos/GeoGebra both need network + key/licence), no build step (React/Vue/SceneryStack all need one), no account. A file that opens from `file://` on a classroom computer with no internet will outlive every hosted platform. That is the whole point of "single-file".
4. **Vendored > CDN, pre-rendered > runtime.** If you vendor KaTeX/JSXGraph, inline them. If you can pre-render equations to HTML at authoring time, do that and ship no maths-rendering JS at all.
5. **SM-2-lite, not FSRS, at v1.** FSRS needs ~1000 reviews to personalise and a fitted parameter set; SM-2 is 20 lines, works from the first review, and is provably good enough for primary fluency. Add FSRS only with a real log.

**Do NOT use (for this brief):**

| Don't use | Why not (for a single-file offline app) |
|---|---|
| GeoGebra / Desmos embeds as the core | Network + API key / non-commercial licence; large bundle; you don't own the UI; fails offline. Use as *links* ("open in GeoGebra") if at all. |
| SceneryStack / PhET stack | TypeScript + npm + build; a team-scale framework for a suite, not one file. Study its design patterns instead. |
| React / Vue / Svelte | Build tooling, bundle, no benefit at single-file scale; vanilla render(state) is simpler and debuggable. |
| Unity / Flutter / native | MBs, server/WASM hosting, app-store friction; wrong shape for a web file. |
| Manim as the lab | Renders video; not interactive. Use it only to make an intro video. |
| Raphaël | Inactive since 2019; native SVG supersedes it. |
| GSAP / Lottie as the animation system | CSS + `requestAnimationFrame` covers 90%; GSAP is 73 KB + a non-open licence with strings; Lottie is pre-baked, not computed. Reserve Lottie for a celebration animation only. |
| H5P / Genially / 希沃 / 101PPT as the *build* tool | They are hosted authoring/delivery platforms, not libraries; their output is not a plain single HTML file you own. Use their *tool lists* (balance, abacus, fraction cutter…) as a checklist of manipulatives to clone. |
| math.js / a CAS as the core | ~500 KB to check equivalence you can check with a 20-line parser for ages 6–15. Add it only for a symbolic algebra lab. |
| Three.js in the core file | Only for the 3D labs; keep it in a separate file. |

### 3.3 Gaps and weak-evidence claims — be honest

- **Claimed but weak evidence:** (a) **Badges/streaks as a learning method** — motivation effects are real but mostly extrinsic and short-lived; no good evidence that badges *teach* maths, only that they sustain *use*. (b) **"AI tutor" claims from 洋葱/火花/NOBOOK** (AI私教, AI伴学) — marketed heavily, but no public controlled study or technical description was found; treat as product claims, not evidence. (c) **Learning-styles / "visual learner" framing** in some platform marketing — not supported; the evidence is for *multiple representations for everyone*, not matching a style. (d) **FSRS's "20–30% fewer reviews"** — a developers' estimate from Anki log benchmarks, not a classroom RCT in primary maths.
- **Topics with no good method/tech yet:** (a) **A reusable, public misconception-tag library** for primary maths (fraction/decimal/algebra errors with counter-examples) — every platform builds its own privately; nothing open was found. (b) **Socratic dialogue templates** for maths — no public, reusable branching-question bank. (c) **Proof / reasoning experiments for ages 11–15** (conjecturing, counterexample-finding, "is it always true?") — geometry has GeoGebra, but *reasoning* labs (not construction labs) are thin. (d) **Collaborative (multi-player) maths experiments in a single offline file** — inherently needs a server/sync; no good offline pattern exists. (e) **Accessible (screen-reader / keyboard-only) virtual manipulatives** — PhET/SceneryStack is the only serious public work; a single-file author has almost no reusable patterns to copy.
- **Methods that are strong in theory but hard to build solo:** animating the student's wrong logic (needs a world-model per task); productive failure (needs a good consolidation script, not just "try first"); neriage in a solo app (needs believable seeded peer solutions).

### Could not verify

- **Live behaviour of any page** — all sources are index/search results; no page was opened in a live browser, no embed was run, no licence page was re-read live. Verify licences (especially GeoGebra non-commercial terms, Desmos API-key terms, GSAP "No Charge" restrictions) on the official page before commercial use.
- **Under-the-hood stacks of 洋葱学园, 火花思维, Khan Academy (modern), ST Math, NOBOOK** — no public source, repo, or engineering blog was found in this session; the table in §2.8 marks these as unconfirmed / proprietary. NOBOOK's "8 engines" are described only in marketing copy.
- **人教数字教材 authoring internals** — no public technical source found.
- **Cytoscape.js, Paper.js, Algebrite, Nerdamer, Genially, Unity/Flutter specifics** — named from general knowledge / single mentions; licences and single-file fit were **not** separately verified in this session. Verify before adopting.
- **Exact current versions / bundle sizes** (e.g. Three.js r186, KaTeX 0.16.x, math.js 15.x) change monthly; check the project's release page at build time.
- **Efficacy numbers** (e.g. ST Math gains, 洋葱 "30% efficiency" claims, 火花思维 outcomes) are vendor-reported unless a peer-reviewed citation is given; none was found for the Chinese commercial platforms in this session.
