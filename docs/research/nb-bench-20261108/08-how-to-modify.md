# 实验台如何修改：实施方案

日期：2026-11-08 01:31 JST。Iris 问现在的实验台如何修改。这篇是施工图：按什么顺序改、每个阶段改哪个文件哪个函数、改完怎么验。基准：主线 `f29bb3f`（43 种器材、144 个实验；本地 main 已是 `a858ea1` = f29bb3f + 文档提交）。只改 `apps/web/lab-nb.html`（+ 构建脚本 + 测试工具 + `app.js` 里 4 处小改）。不动旧实验室文件、不动 `anims-*`、不动 `content/grades/*.js`。

总原则：**先加安全网，再动抽象；每批只改一层；每批真机验过再合。** 可操作性核心（拖、连、算、信号条、发光提示、深色台面、SVG 风格）不动；144 个实验的内容不动（除非机械迁移）。

## 0. 准备：基线（不动行为，只录下来）

- 开分支（从 `origin/main` 起，建议 `lab-nb-ports` 起，后面每阶段一个分支或一个提交）。
- Headless 跑一遍回归基线：5 个原型实验 + 8 个新类型实验（data/pyth/quad/sys/trig/sim/hyper/ineq）+ 分数相加 + 鸡兔同笼，记录每步得分和每条信号文字，存下来。以后每阶段跑同一套，差一个字就是回归。
- 行号说明：下面引用的行号是 `f29bb3f` 的，大致位置；以函数名为准。

## 阶段 1：派生值端口（最优先、最脆弱）

**为什么先做这个**：8 个新类型的步骤判分全是匹配信号条中文（`"斜边 5，是勾股数"`、`"解集：x ＜ -1"`、`"根：2、3"`、`sin = 0.50`）。改一个字，实验就坏。这是文件里最脆弱的东西，先修它。

**改什么**：
- `evaluate`（约 270–340 行）：`D[id]={read:[],sig:[]}`（292 行）改成 `D[id]={read:[],sig:[],ports:{}}`。每个类型算出的东西写进 `ports`，带 kind + value：
  - data → `ports.mean`、`ports.median`、`ports.range`（数值）
  - pyth → `ports.c`、`ports.a2`、`ports.b2`、`ports.c2`（数值）
  - quad → `ports.disc`（判别式）、`ports.r1`、`ports.r2`（数值；无实根时为 null）
  - sys → `ports.x`、`ports.y`、`ports.point`（点）
  - trig → `ports.sin`、`ports.cos`、`ports.tan`（数值）
  - sim → `ports.ratio`、`ports.areaRatio`（比值）
  - hyper → `ports.k`、`ports.point`（点 (2, k/2)）
  - ineq → `ports.set`（区间 {lo, hi, open}）
  - 老类型：circle → `ports.circ`、`ports.area`；rect → `ports.area`、`ports.peri`；tri → `ports.c`（第三个角）；money → `ports.total`；clock → `ports.minutes`（时间值）；dice → `ports.dist`（分布）；bars/line/pie → `ports.sum`、`ports.max`、`ports.avg`
- `sig` 改成从 `ports` 派生显示：**信号文字一字不改**，只是来源从“现场算字符串”变成“读端口值再拼字符串”。学生看到的东西不变。
- `P45H`（872 行）加一个 helper：`port(s,D,type,portName,expected)`，读端口值比对。
- 144 个实验的 `check` 里匹配 sig 文字的，全部改读端口（机械替换 + 逐个 headless 验证）。同时把 `g5_5` / `g7_eq` 的插入顺序索引（`filter(...)[1]`、`nums[0]/nums[1]`）改按名字/角色取实体（`byType` 已有，438 行；多实例时按 `name` 取）。

**验收**：全文件搜不到 `.tx===` / `.tx.includes`；信号文字与基线一字不差；headless 回归基线全过；smoke 全绿。

## 阶段 2：维度标签 + 端口类型（值类型系统第一步）

**改什么**：
- 端口 kind：`number`（带 dim：count / length / area / volume / money / time / angle / ratio）、`point`、`interval`、`boolean`、`distribution`、`function`。`TYPES` 的 `out`/`accepts`（现在只有 `'value'` / `'fn'` 两个字符串）改成端口声明：每个端口有名字、kind、角色（例如 div 的 `被除数` / `除数`）。
- `act` 里 `link` 的校验（约 248–256 行）：从 `out===accepts` 改成 kind 兼容 + 维度兼容；拒绝理由说出原因（“天平不称面积”“长度不能加时间”），不要只说“只接收数”。
- `val(id)`（约 270 行）改成 `val(id, port)`：按端口解析值；记忆化按 `id+port` 键。

**验收**：接错线时 toast 说出具体原因；原有合法连线 headless 全过；新加的维度拒绝有 3 个以上真机验证用例（面积→天平、时间→长度、角度→天平）。

## 阶段 3：变量 + 绑定（属性即表达式）

**改什么**：
- 数字卡可命名为变量：`name` 就是变量名（默认 数1/数2…；命名为 x 的卡就是变量 x）。不需要新类型——数字卡就是变量。
- 属性值可以是常量或绑定：`props[k] = {bind: entityId}` 或 `{bind: variableName}`。`act('set')` 支持绑；`evaluate` 解析绑定（循环检测复用 `reach`，228 行）；循环绑定拒绝并解释（“A 依赖 B，B 依赖 A，绕回来了”）。
- 绑定手势：拖端口到另一个组件上（不是端口上）→ 弹出菜单“把 XX 绑到这个数”；卡片显示绑定来源（“半径 ← 数字卡 3”）。
- `afterChange` 不变（evaluate 全量重算，绑定多了也撑得住；真到瓶颈再做增量）。

**验收**：绑数字卡到圆的半径，改数字卡圆跟着变；绑分数条的分子到数字卡，改数字卡分数跟着变；循环绑定被拒绝并说出原因；刷新后绑定还在（自由模式自动保存要存绑定关系——现在存整个场景 JSON，绑定在里面，天然有）。

## 阶段 4：比较端口（布尔输出）

**改什么**：
- 天平输出 `ports.equal`（布尔）、`ports.heavier`（'L' / 'R' / null）；全等/相似验证：两个图形比对 → 布尔端口（新类型 `compare` 太重，先做天平的布尔端口 + 步骤判分可读）。
- 第一阶段布尔端口只显示（信号条 + 卡片）+ 可被步骤判分读取；消费者（拿布尔去驱动别的）后做，不要在这批做。

**验收**：天平平了，`ports.equal` 为真，步骤判分读它而不是读信号文字。

## 阶段 5：变换与黑箱（函数机器）

**改什么**：
- 新类型 `func-machine`（输入值端口、输出值端口、`rule` prop 由实验设定；练习/考试模式对学生隐藏 rule）。规则可以是线性（y=ax+b）、平方、倒数。
- 复用 `trig` 的“角 → 三个数”做第一个内置规则示例——它已经是黑箱的雏形（输入角，输出三个数），把它做成通用机器的第一个规则。
- 步骤判分读输出端口；预测步骤：先让学生猜输出，再放数进去。

**验收**：放 3 进去出 7、放 5 出 11，学生能通过试数猜出规则；规则隐藏时学生看不到 rule，考完才揭示。

## 阶段 6：分型属性卡 + 连接可用性

**改什么**：
- 字段加 `control` 类型：`slider`（连续数）/ `stepper`（整数）/ `choice`（分段按钮）/ `toggle`（开关）；`buildCard`（约 532–538 行）按 control 分支渲染；派生值加只读行。
- 按《属性设计分析》的 43 种表补属性：先补 12 种 1 属性的 + 5 种 0 属性的；每种至少 1 个可驱动属性 + 至少 1 个派生端口（见《反孤岛设计》§4）。
- 卡片显示“连进来的”和“连出去的”（现在只有连进来，约 536 行）。
- 拖端口时高亮所有兼容端口（类型匹配的发光），不兼容的变暗；悬停说原因。
- 依赖追踪：选中组件，高亮整条依赖链（上游从哪来、下游到哪去）。
- 线上有值：悬停连线显示流过的值（`linkSvg`，约 422 行，现在只返回两条 path）。

**验收**：mirror/view/rot 不再是滑杆；圆的卡里有周长面积；拖线时能提前看到能不能连；选中组件能看到整条链。

## 风险与回滚

- `evaluate` 重构保持 D 的键不变（`ports` 是新增键；`value` / `sig` / `tilt` / `equal` / `tot` / `Ln` / `Rn` 一个不改），否则 144 个实验的 check 全得动。

- 步骤 check 迁移用脚本 + 逐实验 headless 验证，不要手改 144 个。
- 任何一批真机复测不过就回滚该批，不动其他批。每批独立分支。
