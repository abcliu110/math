### 每种新器材的出厂标准（建完才算数，不满足不合入）

照 15 号文档的审计标准，新器材出厂必须同时满足 5 条（缺一条就返工，不留“以后再补”）：

1. **属性 ≥3 个可调**（15 号 §2 的标准；2 个的叫“差一个达标”，0–1 个的不许出厂）。控件要分型：分段按钮（选择）、开关（开/关）、步进器（整数）、滑杆（连续数）——不许“一把滑杆走天下”（18 号 U52/U73：`ineq.op` 的 0/1 滑杆、shape/rect 的 rot 滑杆就是反面例子）。
2. **属性在物体上调。** Iris 2026-11-08 10:35 JST 定下的原则：每个物体都有属性，可以调节的；调在物体上（点 → 检视器，或拖手柄），不在远处的表单里。最常用的 5 种优先加物体上手柄（角拖边改度数、圆拖半径、钟面拨指针、长方形拖边改宽/长、数轴拖端点改范围）。设置卡保留为精确输入。
3. **≥1 个可驱动属性 + ≥1 个派生端口**（07 号文档验收）。**新器材 0 孤岛**：算出来的东西必须能流出去；数学上没东西可流的（A 类）在 100 种审计里是 0 种——不要以“A 类”为借口造孤岛。
4. **端口值统一为 Val**（`{kind, dim, data}`；09 §2 的 8 种 kind：num/point/interval/fn/dist/bool/shape/seq）。不许再出现 18 号 U58 的情况：端口值有 Q、有数字、有布尔、有对象、有数组，判分与连线各写一套读法。`linkSvg` 的值显示按 Val 类型格式化。
5. **自带实验**（§7）：每种新器材至少带 1 个实验，实验过 lint；没有实验的器材不合入（器材没有实验就是摆设）。

## 4. 验证规范（什么是“验证通过”）

### 4.1 真机是唯一标准

- **桩测试不算。** `tools/smoke.js` 的 DOM 桩测不到真机指针事件、CSS、SVG、严格模式报错，只能当第一道关；而且它根本不覆盖 lab-nb.html 的脚本（§2 第 4 步）。
- **真机复测是唯一标准。** 用 commit-SHA 的 githack 链接（`https://raw.githack.com/abcliu110/math/<完整SHA>/apps/web/homepage-standalone.html`，或直连 `lab-nb.html` 同等 SHA 链接），不要 main 分支镜像（缓存旧版）。每次复测写清：测了什么操作、看到了什么、过没过。
- **复测清单（每批按需勾）：** 该批器材的黄金路径全过；改过的器材拖、连、绑、调属性对不对；练习/考试流程走得通；错题本/今天复习/家长端收没收到记录；手机/平板触屏（真机测不了触屏时写明“触屏未验”，见 §4.4）。

### 4.2 每批的验收 = 三条同时成立

1. **该批器材的黄金路径全过**（新器材进基线的方法见 §6：开场分数 + 信号文字 + 黄金路径）。
2. **基线无回归**（开场基线 + 黄金路径，差一个字就是回归）。
3. **check-xp.js 不退步**（通过数不减少；新实验全过 lint，见 §7）。

三条缺一条，不合并。

### 4.3 probe 必须走界面（2026-11-08 15:48 真机测试的教训，新加）

- **probe 的定义：** 走真实界面操作——真实按钮点击、真实输入、真实拖线。**直接改 props 的 probe 不算数。**
- **教训（真实案例）：** 黑箱规则库真机测试部分通过——平方、倒数本身都可用；但施工者 README 里的 probe 用例 a=6 在界面上输不进去（a 限 -5~5，界面报“不行：a 只能在 -5 到 5 之间”），probe 是直接改 props 做的，不是走界面。结果：规则本身是对的，界面限制没被测到，README 的 probe 用例与界面限制不一致。
- **规则：** README 批注里写 probe 用例时，**同时写明“界面上限是多少”**（如“a 限 -5~5，probe 用 a=5，不用 a=6”）。probe 用例里任何一个数超出界面限制，该 probe 无效，重做。核查者审 README 时，逐个数对一遍界面限制。
- **同理：** 黄金路径、基线数字也只认界面能走出来的操作；改 props 走出来的路径不进基线。

### 4.4 回归检查项：输入与标签同步（2026-11-08 15:48 真机测试的两个小毛病，新加）

每批的回归检查里加两条，全台面通用，不只针对出问题的那批：

1. **输入框“输完即生效”。** 数字框输完数，不按回车也要生效（15:48 真机：数字框输完要按回车才生效，是毛病）。验收：输数 → 点别处 → 值已变。
2. **标签与值同步。** 任何操作改了值，卡片上的标签/显示行要同时跟上（15:48 真机：解除表达式绑定后值已回落，卡片短暂显示旧标签）。验收：解除绑定、换绑、改值后，卡片显示与实际值一致，没有旧标签残留。

这两条写进每批的真机复测清单，勾了才算测过。

### 4.5 “触屏未验”时怎么标注

- 云端桌面浏览器测不了触屏。真机测不了触屏时，复测记录里写明 **“触屏未验”** + 原因（云端桌面浏览器无触屏）+ 待验清单（本地 repro + 平板真机：器材架抽屉、44px 触摸目标、双指缩放跟手程度、分数条格子命中）。
- “触屏未验”不堵合并（桌面真机过了就可以合），但要记进 README 批注的“未做”里（§9），不要写成“已验证”。
- 触屏相关的项（总清单 J1/J3/J4、M2）另立平板真机验证批，不混进桌面批里。

### 4.6 失败处理

复测失败先修，修不好就回滚整批（§5），不带着已知失败合并。**失败的功能不许“降级通过”**——部分通过就是部分通过，写进总清单，不写成通过（§11 范例：黑箱规则库写的是“部分通过”，不是“通过”）。

## 5. 回滚规则

- 回滚后在总清单里把对应的项标回“未做”，写清失败原因；顺序文档里该批标回“未开工”。
- **连续两批回滚就停下来**，先找原因，不赶工；等 Iris 定下一步。
- **连续两批真机失败（即使没走到回滚）也一样停下来**，等 Iris 定——回滚是手段，停下来是目的。

## 7. 实验检查（XP lint）

### 7.1 新器材自带实验的定义（4 条，缺一条不合入）

1. **≥3 步。** 2 步的“连线→读答案”模板不算实验（现状：88 个已查实验里 68 个只有 2 步，46 个生成实验未计入，18 号 U03）。
2. **有预测步。** 学生先填预测值/选项，再动手验证；预测对错本身记分，但不罚分——猜错是学习，不是失误（210994e 的 predict 类型：猜对得分、猜错不扣分）。第 7 步进行中，预测步已有 15 个实验；新实验必须带预测步。
3. **判分读端口，不读信号文字。** 判分一律读 `D[id].ports` / `qv(d)`，不许匹配 `.tx`（`.tx===` / `.tx.includes` / `.tx.startsWith` 判分里 = 0；剩 1 处 `.tx.includes` 是 `hideSig` 引擎代码，不在判分里）；不许按插入顺序取器材（不用 `filter(...)[N]`，不用 `byType` 取首个同类——18 号 U64：`byType` 161 处调用，多拖一张同类器材判分就读错；判分按名字/角色取实体）。
4. **why 讲推理。** why 写“为什么用这个方法”（因为/所以/先…再…讲过程），不是“答案是多少”。18 号 U13 的量化：93 个 why 仅 12 个含“因为/所以/因此”，68 个靠算符或“先/再/用/就是”蒙混过规则 3——规则 3 要收紧（见 §7.2）。

### 7.2 check-xp.js 的 6 条规则是门槛，不是天花板

`tools/check-xp.js` 的 6 条规则（≥3 步、有 predict 步、why 讲推理不只给答案、不匹配信号文字、不按插入顺序取器材、步骤 ID 是 `xpId:sN`）是**门槛**：新实验不过 lint 不合并。跑法：`node tools/check-xp.js`，退出码 0 = 全过，1 = 有不过的实验（列出实验 ID 和原因）。

门槛之外的两条，lint 测不出来，每批人工/脚本核对（18 号 U55/U62 的教训）：

- **答案核对（U55）：** lint 是静态正则，不执行任何 `check`、不核对任何答案。反面例子：g9_98 的弧长 6.28、扇形面积 9.42 只在 why 里，台面上没有任何器材能算出这两个数，步骤只核对了半径=3、圆心角=120°，lint 照样通过。**规则：每批新实验的期望答案，逐个手算核对**（113cef5、ebfc910 的做法：9 个 + 5 个实验的答案逐个手算/逐个对照题目核对）；答案只在 why 里、台面上算不出来的实验，不合入。
- **覆盖核对（U62）：** lint 只认内联 `steps:[` 的块（210994e 后：只统计实验定义）；46 个生成式实验不在 lint 里（39 道应用题 + 7 个初中实验），6 个非实验（骰子动作 `roll`/`reset`、连线 id `'l'`、数据表输出口 `sum`/`mean`/`max`）曾被当成实验计入跳过数，g8_data 曾被误算为 8 步；新正则还会漏掉 grade 不紧跟 id 的实验定义，全量约 152 个，88 查仍不是全量。**规则：生成式实验也要过质量关，实验数量不自动涨。** 一个生成器产出 N 个实验，N 个都要过 §7.1 的 4 条；验收时至少抽 3 套参数（最小/中间/最大，或随机种子）逐个走黄金路径；生成器本身的改动单独一批，不跟器材批混在一起。

### 7.3 实验数量不自动涨

- 参数化变式（一个模板无数道数）不等于实验数量涨了：变式要过质量关才计数。
- 新器材自带实验 1 个起步；应用题生成器每加一个模板，模板产出的实验全数过 lint 才计数。
- 总清单 05 里的实验数（约 161 个）每次同步时重数一遍，不沿用上一版的数字。

### 11.6 真实案例：2026-11-08 15:48 骰子分布端口失败（范例，以后照这个格式处理）

**经过：** 云端真机测试（githack 6355105 直连 lab-nb.html，11 分钟），5 个功能：3 通过（变量 x、表达式绑定、解除绑定回落）、1 部分通过（黑箱规则库）、1 失败（骰子分布端口）。结果已由核查者写进总清单 05 的 15:32 节（提交 6186a56），E3/F3 行已按 907b773 改过。
