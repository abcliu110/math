# 器材的抽象是否足够？

日期：2026-11-08 01:00 JST。问题：Iris 问器材的抽象是否足够。核查方式：读 `lab-nb.html` 的 TYPES / DRAW / evaluate / act / anchorIn / stateLine（代码数过，不是印象）。结论先说：**骨架够，血肉不够。** 场景图 + 纯函数求值 + `act()` 校验→变异→重算，这套骨架是对的，比旧台面的固定槽位强。但抽象在七处不够用——够现在的 101 个实验，不够“更强大”那篇路线图里要的东西。

## 1. 现在的抽象到底是什么

```js
scene  = {entities: {id: {id, type, name, x, y, props}}, links: [{id, from, to, slot}], seq, nid}
```

- **TYPES**（注册表）：每种器材声明 label / group / prefix / out / accepts / slots / defaults / fields / size。
- **DRAW**（另一个对象，438 行起）：按类型画 SVG。
- **evaluate(s)**：纯函数。`val(id)` 递归算值（带记忆 + 防圈）；再给每个实体算 `D[id] = {read, sig}`。
- **act(intent)**：add / del / move / link / unlink / set / rename / rotate / roll / segclick / dup；先校验（不合法返回 `{ok:0, why}`），再变异，再重算。
- **D**：推导数据，按实体 id 挂，键是各类型随手放的（`d.value` / `d.tilt` / `d.equal` / `d.tot` / `d.terms` / `d.L` / `d.R`）。

## 2. 七处不够

### （1）端口只有两种类型，17 种器材是孤岛

| | 数量 | 哪些 |
|---|---|---|
| 能输出值 `out:'value'` | 6 | 数字卡、分数条、合并器、乘法器、除法器、人民币 |
| 能输出直线 `out:'fn'` | 1 | 直线 |
| 能接收值 | 5 | 合并器、乘法器、除法器、数轴、天平 |
| 能接收直线 | 1 | 坐标平面 |
| **既不能输出也不能接收** | **17** | 钟面、角、三角形、平行四边形、条形图、折线图、鸡兔笼、数对、图形、立体图形、圆、扇形图、长方形、骰子…… |

所谓“值沿着连线流动”，只在 7 种器材之间流动。剩下 17 种是只能看、不能连的摆设。

更深的问题：`'value'` 是不分维度的有理数。3 米、4 秒、35 个头、1/2、5 元，全是同一个类型。接错线只能说“只接收直线”或“只接收数”，说不出“天平不称角度”“长度不能加时间”。NB 的物理端口天然有类型（电流进不了烧杯）；数学版需要维度/单位标签（个数、长度、面积、体积、钱、时间、角度），否则“接错线”这个 NB 机制在数学版是半残的。

另外每个器材只有一个输出端口；除法器/天平靠 `slots`（左/右）区分两个输入，但“需要几个输入、各是什么角色”没有声明式描述，全靠 `evaluate` 里手写。

### （2）值的模型只有有理数 + 直线

- `val()` 只认识 6 种类型；其他 18 种的值是 `null`——它们的值不存在于引擎里，只存在于画出来的字里。圆的周长和面积是信号条上的一行字，不是能流进下一个器材的值。
- 没有点、没有表、没有分布、没有布尔、没有规则（映射）。`fn` 是唯一的非数值端口，但它是一条直线 `y=kx+b`，不是一般的映射。所以黑箱输入输出机（“更强大”第 1 节要的东西）在这个抽象里表达不出来。
- 后果：7–9 年级（代数、函数、统计）写不出实验，不只是没写，是抽象不支持。

### （3）一个器材的定义散在五处

加一种器材要改：TYPES（一行）+ DRAW（一个函数）+ `evaluate` 里的 `if/else` 链（29 处 `e.type===`）+ `anchorIn` 的分支（除法器/天平手写）+ `stateLine` 的分支（直线/长方形/天平/数轴/骰子手写）。漏一处就静默失败（画不出来、没信号、端口位置不对），smoke 测不出来（stub 不跑 DRAW）。

好的抽象应该是一个类型对象自带：字段、端口（位置/角色/类型）、求值、信号、画法、动作。加一种器材 = 加一个对象，不再是改五处。

### （4）参数和状态混在一起

`props` 里既有参数（半径、k、b），也有累积状态（骰子的 `counts`——掷了多少回的结果存在 `props.counts` 里）。“恢复初始值”要不要清 `counts`？抽象没说。撤销是整个场景 JSON 快照，语义是“回到过去”，不是“重置参数”。

也没有时间的概念：没有“随时间变化”、没有值序列、没有播放。迭代/序列/运动没有落点。

### （5）没有容器 / 层级

实体是平的。数轴上的点、十格阵里的 counters、坐标平面里的点和线、分数墙里的条——这些“属于”关系只能用连线表达，而连线同时还表示“值流动”，两种关系混用一个机制。NB 有容器（烧杯装液体）；数学版需要容器抽象，或者至少一个 belongs-to 关系。

### （6）实验层没有稳定的 API，步骤是代码不是数据

- 129 处 `check:` 都是手写谓词，直接扒内部：g5_5 按插入顺序取第二张数字卡；g6_5 检查圆的信号文字。没有稳定的查询接口（按名字/类型/角色取实体、取它的值、取它的信号）。
- 步骤只能断言**当前状态**，不能问历史（“学生试了 3 个值才找到”）、不能记录预测（“猜”这个对象在抽象里不存在——先猜再玩没有落点）。
- 步骤没有稳定 ID，只有中文 label 字符串。复习闭环要“回到丢的那一步”，需要 `xpId:stepId` 这种稳定标识；label 一改，历史就断了。
- 步骤是 JS 函数，不可序列化 → 台面即作者工具做不了；实验配置分享也只能分享场景，不能分享实验。

### （7）没有版本

场景 JSON 没有 version 字段。旧存档（`nb-lab-free-v1`）读回来直接 `JSON.parse`，没有 normalize、没有迁移。新字段靠 defaults 兜底是运气，不是机制。抽象一改，旧存档就可能悄悄坏掉。

## 3. 什么是“足够”的抽象（分层设计，不是重写）

**层 0（不动）**：场景图 + `act()` 校验→变异→重算 + 纯 `evaluate` + 撤销快照。这套骨架保留。

**层 1：值的类型系统**。值 = `{kind, ...}`：有理数（带维度标签：个数/长度/面积/体积/钱/时间/角度）、点、直线、表、分布、布尔、规则（映射）。端口声明接受/输出的 kind；连线校验从“只接收数”升级为能说出原因的拒绝（“天平不称角度”）。这是 NB“接错线”机制在数学版的完整形态。

**层 2：类型对象合一**。一个类型 = 一个对象：fields（带控件类型）、ports（位置/角色/类型）、value(inputs, props)、signal(...)、draw(...)、actions。删掉 `evaluate` / `anchorIn` / `stateLine` 里的类型分支链，改成查表调用。

**层 3：参数 vs 状态 vs 推导三分**。props = 参数（能调的）；state = 累积（掷的次数、历史）；D = 推导（每次重算）。恢复初始值只动 props；时间/迭代落在 state 上（值序列、播放）。

**层 4：容器**。belongs-to 关系：点属于数轴/坐标平面，counters 属于十格阵。容器管布局和范围，孩子跟随移动、删除。

**层 5：实验即数据**。步骤 = 数据（`{id, 做, 看, 判}`），判分条件是声明式的（“合并器的值等于 5/6”），不是手写谓词；配一个稳定的查询接口（byName / byType / byRole）。预测是步骤里的一种对象（先提交一个值，再动手）。

**层 6：版本**。场景带 version；加载时按版本迁移；旧字段有默认值是迁移的一部分，不是碰巧。

## 4. 够不够，分三档说

- **够现在的**：101 个实验、2 步模板、6 种值流动——够。这套抽象撑得住现在的规模。
- **不够下一步的**：分型属性卡勉强够（字段加类型就能做）；但黑箱、变量、数据表、迭代、误解识别、多表征联动，抽象要动（层 1、3、5）。
- **不够最终的**：台面即作者工具、双向复习闭环、内容反馈环——没有层 5（实验即数据）和层 6（版本），做不了。

## 5. 顺序：先补哪一层

1. **层 2（类型对象合一）+ 层 6（版本）**：重构，不加功能，先把加器材的成本从“改五处”降到“加一个对象”。没有这层，后面每加一个东西都在五处漏。
2. **层 1（值的类型 + 维度标签）**：先只加维度标签和端口类型检查，不动值的计算。接错线的报错立刻变聪明。
3. **层 5（实验即数据 + 稳定步骤 ID）**：新实验用声明式写；老实验逐步迁移。闭环和作者工具都依赖它。
4. **层 3（参数/状态三分）+ 层 4（容器）**：跟着黑箱、数据表、迭代一起做——需要的时候再做，不提前。
5. **层 1 的后半（点/表/分布/规则值类型）**：跟着具体器材走——数据表、输入输出机、迭代器各带自己的值类型进来。

## 6. 风险

- 重构 `evaluate` 的 `if/else` 链是高风险操作：129 处步骤检查依赖现在的 D 形状（`d.value` / `d.tilt` / `d.tot` / `d.terms` / `d.L` / `d.R`）。重构必须保持 D 的键和语义不变，或者同步迁移全部 129 处检查，并用真机复测。
- 不要为了抽象而抽象：层 4（容器）和层 1 的后半（新值类型）没有对应的器材/实验需求时不要先做。
- 抽象升级和旧存档迁移要一起做，否则老用户的自由探究台面会在某次更新后悄悄坏掉。
