# 继续思考：有没有更好的方案

日期：2026-11-08 01:16 JST。Iris 让继续想有没有更好的方案。先更新地基：这篇按新主线 `f29bb3f`（43 种器材、144 个实验）想，不按上一篇的 `18a3f2d`。只思考，不改代码。

## 0. 地基变了：瓶颈从“缺数量”变成了“缺质量关”

数过新代码：

- 七八九年级新实验 43 个，其中 **34 个是 1 步**，6 个没数到 steps 字段（可能用了共享 helper 或确实没有步骤，待核实），只有 3 个是 2 步。上一篇说的“2 步模板”问题，在新一批里变成了“1 步”。
- 1 属性器材从 5 种变成 **12 种**（新加的相似、三角函数、等腰三角形、二次根式、平行线截线、圆周角、反比例全是 1 个属性）。
- 43 种器材里，能输出值的还是那 7 种；36 种没有输出端口（其中 3 种只能接收不能输出）。新类型全是孤岛。
- `数据的分析` 是三个数（a/b/c），不是数据表；没有黑箱、没有迭代、没有真变量。`why` 还是“一行答案”（“2x + 3 = 11，两边都减 3 得 2x = 8，所以 x = 4”——这是答案，不是推理）。

结论：**他补数量的速度比我想的快，但深度在变浅。** 继续按这个速度加，台面会越来越满、越来越浅。所以更好的方案不是“再加点什么”，而是先立规矩、再谈规模。

## 1. 更好的内容生产方案：从“手写实验”到“实验生产线”

现状：每个实验手写 build + steps + checks。43 个新实验 1 步为主，说明手写已经跟不上速度——写的人在赶数量。

**方案 A：实验的“完成定义”（Definition of Done）+ 自动检查——先做这个。** 每个实验必须满足：≥3 步；有预测步骤；why 讲推理不讲答案；步骤判分不用插入顺序、不用信号文字；有且只有一个核心发现。写一个 lint（`tools/check-xp.js`），跑不过就不合进 main。**质量关前移**，比事后分析有用。没有这条，方案 B 只会更快地生产浅实验。

**方案 B：实验模板生成器。** 一个模板 = 一个生成函数（种子 → 场景 + 步骤 + 判分），同一模板出无数变式（鸡兔同笼换头换腿、二次函数换 a/b/c）。写一个模板等于写一百个实验，且深度一致。先做 3 个最高频模板：分数运算、方程、鸡兔同笼类。

**方案 C：从 142 个知识点的内容反向生成实验。** 每个知识点已有 how/why/wrong/visual/method/explainBack；`wrong` 字段就是误解靶子。实验 = 针对 wrong 设计的调查。AI 起草 + 人审，比从零手写快，且每个实验都有误解靶心。

上一篇说的“声明式格式 + 参数化变式 + 台面即作者工具”方向没错，但顺序要改：**先 A（质量关），再 B（模板），最后作者工具。**

## 2. 更好的学习方案：从“照着做”到“先错后学”

**有成效的失败（productive failure，第九轮调研）**：先给开放问题让学生自己试（不给步骤），试完了再给标准解法。研究支持：先挣扎再讲授，比直接讲授记得牢。现在的实验是反的：先给步骤，照着做。

更好的方案是实验分两段：第一段“自己试”（自由模式 + 一个问题 + 预测），第二段“对照”（标准做法 + 为什么）。台面记下第一段学生试了什么，第二段针对性地讲。

**AI 导师（追问式，不是给答案式）**：台面里放一个会问问题的导师，根据学生刚才的操作提问——“你把分母从 2 改成 4，合并器的读数怎么变了？为什么？”静态 hint 是死的，追问是活的。app 是 AI 做的，台面里也该有个 AI。

**小老师**：学生做完实验，用自己的话讲一遍（录音/文字），讲给“另一个学生”听。讲的过程就是自我解释（第三轮调研：自我解释效应）。app 已有小老师讲题（文字版）；台面版是“讲给台面听”。

## 3. 更好的复习方案：新记录用 FSRS，步骤级间隔重复

FSRS 之前被否了，理由是旧记录没有 FSRS 状态、会打破已验证的 1/3/7 天语义。**那个结论只对旧记录成立。** 新台面的记录是全新的、没有历史包袱的——练习和考试的每一步都有（丢了哪步、试了几次、用了多久）。对新记录，FSRS 从零开始是干净的。

更好的方案：**步骤级间隔重复**。复习单位不是“题”，是“步”（“异分母通分”这一步丢了，三天后回来只练这一步）。FSRS 的参数（难度、稳定性）按步骤算。

再加交叉练习：复习时把不同知识点的丢步混在一起（第三轮调研：交叉练习效应），不要按章节顺序复习。

## 4. 更好的产品方案：台面不是目的地，是到处都在

现在的模型：实验室是一个地方（首页面板 → 进实验室 → 实验库）。更好的方案：**台面溶解进知识点页**。每个知识点页本身就是一个小台面（相关器材已经摆好、问题已经挂好），“实验室”只是实验库（找实验的地方），不是唯一做实验的地方。现在点 4.16 是 400ms 消息跳转到另一个地方；溶解之后，点进知识点页，台面就在那里。

**持久世界**：学生有一个自己的世界（像 Polypad 的画布），器材和场景一直都在，可以建多个场景（“我的实验”）。现在自由模式只有一个自动保存的场景；旧台面有“我的实验（最多 12 个）”，新台面没有。

**协作台面**：老师和学生同看一张台面——老师能看到学生正在拖什么、卡在哪一步，远程给提示。NB 是单人的；协作是差异化。技术上是同一套场景 + 操作同步，先做“老师看”（只读同步），再做“一起动”。

## 5. 更好的技术方案：拆 iframe，统一存储，懒加载

iframe + srcdoc + postMessage 是当前最脆弱的一环（400ms 定时器、无握手、无重试、丢了无报错）。更好的方案：**台面做成 app 的一个原生视图（模块），和 app 共享同一个 store，不用 postMessage 传话。** 单文件体积的约束用懒加载解决：进实验室时再加载台面模块，而不是把 4.31MB+ 的台面内联进每个页面。

存储统一：现在台面 3 个键 + app 约 10 个键，各自为政。更好的方案：一个 store、命名空间、版本号、迁移函数。FSRS、复习、家长端都读同一份数据。

测试：引擎拆出来（`lab-world.js`）+ Node 单元测试 + 脚本化浏览器驱动（`tools/repro-browser.js` 扩展到新台面）+ 每批提交跑一遍“黄金路径”（拖、连、算、评、考、报）。现在是无头验证 + 事后云端复测；更好的是提交前自动跑。

性能：144 个实验 + 43 种器材全塞一个文件，standalone 只会更大。懒加载 + 实验库按需取数据。

## 6. 更好的护城河：把“错在哪一步”做成核心

全球没有数学 app 有“按步丢分 + 丢分定位 + 回炉重做”这条线（第七轮调研的结论）。Polypad 有沙盒，GeoGebra 有考试，ST Math 有错误可视化，但没有一家能告诉学生“你丢在第 2 步：通分”，并把他送回第 2 步重做。

更好的方案：**所有投入都围绕这条线收敛**——实验的价值 = 它能定位丢分步骤；复习的价值 = 它能送回丢分步骤；家长端的价值 = 它能看到丢分步骤的分布。不要和 Polypad 比器材数量（比不过，也不用比）；比“知道学生错在哪一步”——这是唯一别人没有的东西。

具体：每个实验的步骤要有稳定 ID；每次练习/考试的丢分步骤要进统一记录；错题本要能一键回到丢的那一步；家长端要能看到“全班最常丢的 3 个步骤”。

## 7. 顺序（修正版：质量关提到最前面）

- **第 0 批**：质量关（实验 Definition of Done + lint）+ 快赢（握手/重试、搜索别名、标题显示、题面文字）。没有质量关，后面每批都在加浅实验。
- **第 1 批**：闭环（双向）+ 步骤稳定 ID。
- **第 2 批**：模板生成器（先做 3 个最高频模板）+ 抽象层 2/6（类型对象合一、场景版本）。
- **第 3 批**：学习模式（先错后学两段式 + 预测步骤）+ FSRS 新记录（步骤级）。
- **第 4 批**：表达力（x 器材、黑箱、数据表）+ 属性（分型卡）。
- **第 5 批**：台面溶解（知识点页即小台面）+ 持久世界。
- **第 6 批**：老师端（布置作业、协作看板）+ 反馈环。
- **第 7 批**：技术重构（拆 iframe、统一存储、懒加载、测试 harness）。
- **第 8 批**：平台（平板）。

和上一篇比，变了两处：质量关提到第 0 批（因为瓶颈变了）；技术重构往后放（先修 400ms 握手这个快赢，大拆等台面稳定了再做）。
