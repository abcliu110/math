# 新实验器材设计：14 种，其中 5 种世界上没有

日期：2026-11-08。只设计、不改代码（冻结中）。基准：主线 `17d4103`（lab-nb.html 1527 行，46 种器材，152 个实验）。设计约束见设计文档 `docs/research/nb-bench-20261108/09-unification-design.md`：值模型 `Val = {kind, dim, data}`（8 种 kind、9 种维度）、四种动词（流/绑定/比较/变换）、一个类型 = 一个对象、求值是依赖图 + 拓扑序。

## 0. 一句话结论

14 种新器材，分四类：**表达力**（变量实体、比较器、判断灯、容器）补齐值类型系统缺的 kind；**过程**（猜想板、证明脚手架、误差放大镜、反例构造器）把“猜 → 玩 → 说”和“错得明白”做成器材而不是教学法；**数据**（迭代器、撒点器、分布查看器、抽样调查器）把时间、随机、分布做成一等公民；**关系**（参数族、赛跑）把“一类问题”和“随时间比”做成可拖的器材。其中 **5 种是世界首创**（8 个平台查证无等价物）：**猜想板、证明脚手架、误差放大镜、判断灯、反例构造器**；另有 1 种**形态首创**（变量实体：概念人人有，做成“可拖上台面的器材 + 连线绑属性”的形态没有人做过）。

## 1. 现有 46 种器材一句话清点（已数过，避免重复）

数与运算（12）：数字卡、分数条、合并器、乘法器、除法器、人民币、鸡兔笼、因式分解、乘法公式、二元一次方程组、一元二次方程、x 砝码。图形（17）：钟面、角、三角形、平行四边形、图形（平移旋转对称）、立体图形、圆、扇形图、相似、勾股、三角函数、等腰三角形、圆周角、全等、直线和圆、长方形、二次根式（注：根式算在数与运算更合适，原文如此）。统计（6）：条形图、折线图、扇形图、数据的分析、数据表、两个骰子。关系（4）：数对、不等式解集、数轴、天平。函数（5）：直线、坐标平面、二次函数、反比例、黑箱。分数（2）：分数条、分式。概率（2）：摸球袋、两个骰子（骰子跨统计/概率两类）。

## 3. 新器材逐个设计

每个器材的统一格式：**名字 / 解决什么 / 字段 / 端口 / 算什么 / 四动词 / 服务知识点 / 画成什么样 / 错了怎么表现 / 为什么别的软件没有 / 优先级**。字段一律 2–4 个有意义的属性（设计文档 02 的标准）；端口写 kind + 维度；画法写清拖哪里、点哪里。

### 3.1 猜想板（Conjecture board）——世界首创 ★

**解决什么：** C2（没有一个实验让学生先猜）。预测不是教学法口号，是台面上的一个器材：学生先把猜想写下来、锁死，再动手；动手的结果自动跟预测比对，裁决对错；预测对错记分，但猜错不罚分——猜错是学习，不是失误。

**字段：**（1）`guess` 预测值（数，由学生填，可连入一个数）；（2）`mode` 比较方式（分段按钮：等于 / 大于 / 小于 / 在区间里）；（3）`stakes` 记分（分段按钮：记 1 分 / 不记分，默认记 1 分）。

**端口：** 进：`actual`（`num`，任意维度——被验证的那个值，连进来）；出：`verdict`（`bool`，对/错）、`signed`（`bool`，预测是否已锁定）。维度跟随 `actual`（猜的是面积就是面积，猜的是时间就是时间）。

**算什么：** 锁定后，`verdict = compare(actual, guess, mode)`；锁定前 `verdict = null`（没猜不算错）；`signed = 锁已按下`。

**四动词：** 流（`actual` 流进来，`verdict` 流出去给判断灯/证明脚手架）；绑定（`guess` 可以绑到一个变量上——“我猜 x 是 5”里的 x 就是 Var）；比较（它本身就是比较器 + 锁）；变换（无）。

**服务知识点：** 1.16 找规律（“下一个是几？先猜”）、4.16 鸡兔同笼（“兔有几只？先猜”）、6.5 圆（“π 大概是几？先猜 3 还是 4”）、9.10 列举法求概率与频率估计（“掷 100 次，7 出现几次？先猜”）。它是跨年级的步骤器材，不是某一年级的器材。

**画成什么样：** 一块小黑板：上半截是粉笔字写的预测值（学生点一下改数字），中间一个大锁按钮（点一下锁死，锁死后预测值变灰、改不动），下半截是裁决区（未验证时空白，验证后亮绿“猜对了”或亮黄“猜错了，再想想”）。拖蓝点连 `actual` 进来；锁是点按，不是拖。

**错了怎么表现：** 猜错不打红叉、不扣分——板子翻到背面，显示“你猜的是 X，实际是 Y，差 Z”，差值本身就是下一步的线索（“差 2，往哪个方向调？”）。锁死后想改预测？台面拒绝，理由一句话：“猜已经锁了，改猜不算猜。”

**为什么别的软件没有：** Desmos Activity 的 Function Carnival 是“学生先画预测图、再与电脑答案对照”，但预测不锁定、无自动裁决、无记分规则；PhET、NB 只有教师活动单/课堂流程里的“先预测再验证”，仿真本身无锁定、无裁决、无记分（查证表 7 号行）。把“预测—锁定—验证—裁决—记分不罚分”做成一个可连线的器材，8 个平台都没有。

**优先级：P0。** 它是 C2 和“猜 → 玩 → 说”的地基；步骤 7（实验改数据 + predict 步骤类型）的前提就是它。

### 3.2 证明脚手架（Proof scaffold）——世界首创 ★

**解决什么：** 统一报告 §3.3 的第三环。`why` 现在是一行写死的手写文字，不是台面生成的；学生说的“为什么”是背下来的，不是读出来的。脚手架从依赖图读出推理链，生成“因为……所以……”的文字，学生照着链条说出证明。

**字段：**（1）`depth` 推理展开几层（步进器：1–3 层，默认 2 层——“因为 A 所以 B”是一层，“因为 A 所以 B，因为 B 所以 C”是两层）；（2）`target` 结论指向谁（点选台面上的一个器材，默认选中器材的输出）。

**端口：** 进：`claim`（任意 kind——要证明的那个结论，连进来）；出：`chain`（`seq`，推理步骤的序列，每一步是“因为 X 所以 Y”）、`complete`（`bool`，链条是否走到了不依赖别的起点）。

**算什么：** 从 `claim` 的来源出发，沿依赖图（links + binds）往上走 `depth` 层，每一步取“上游值 → 本步值”的因果对，拼成自然语言：“因为长方形的宽是 4、长是 3，所以面积是 12；因为面积是 12，所以黑箱输出是 25。”走到没有上游的起点（数字卡、滑杆）停下，`complete = true`（链条闭合）；中途遇到未连线的输入，`complete = false`，并指出来（“这一步缺一个理由：面积从哪来？”）。

**四动词：** 流（`claim` 流进来，`chain` 流出去——可以流进猜想板当验证依据）；绑定（无）；比较（无）；变换（无——它是读依赖图的，不是算数的）。

**服务知识点：** 8.2 全等三角形的判定（“因为三边对应相等，所以全等”）、8.11 勾股定理与逆定理（“因为 3² + 4² = 25 = 5²，所以是直角三角形”）、7.11 平行线与平移（“因为同位角相等，所以两直线平行”）、9.13 相似三角形。

**画成什么样：** 一张竖着的脚手架：每一层是一块横板，板上写“因为……”，板与板之间是竖着的支撑（连线），最顶上是结论。学生点任意一块板，高亮台面上对应的器材（依赖追踪 `depOf` 已有，脚手架复用它）。层数可调：1 层只给直接理由，3 层给到数字卡。

**错了怎么表现：** 链条断了不断然说“错”——断的地方空一块板，板上写“这里缺一个理由”，学生自己去补连线。补上了，板子自动长出来。证明不是被判错，是被搭出来。

**为什么别的软件没有：** 8 个平台全都没有。GeoGebra 只有依赖关系（拖动顶点，依赖对象自动更新），不生成自然语言；Graspable Math 的 Transform 模式展示的是操作历史（一步步等价变形序列），不是按依赖链生成的“因为……所以……”；ST Math 刻意不用文字；NB 实验报告由学生自己填（查证表 8 号行）。

**优先级：P0。** 它是统一报告 §3.3 的验收物，也是设计文档步骤 2（ports 通用化）和步骤 7（实验改数据）的下游——依赖图显式化（步骤 8 的前半步）之后才能做。

### 3.3 误差放大镜（Error magnifier）——世界首创 ★

**解决什么：** “错得明白”不是一句口号。错题本现在只记“丢在哪一步”，学生回头看还是不知道自己当时错在哪。放大镜是一个可拖的镜框：把它拖到台面上任何一个器材上，它把那个器材的“错处”局部放大展示——不是打红叉，是把错的局部放大到能看清错的是什么。

**字段：**（1）`zoom` 放大倍数（滑杆：2–5 倍，默认 3 倍）；（2）`what` 放大什么（分段按钮：数值 / 形状 / 连线，默认自动——台面按信号条的 `err` 级别自动选）；（3）`freeze` 定格（开关：开 = 定格在出错那一刻，关 = 实时跟随，默认开）。

**端口：** 进：`target`（任意 kind——被放大的器材，连进来；也可以直接拖到器材上，不用连线）；出：`spot`（`bool`，这里有没有错）、`detail`（`num`，错了多少——如“差 2”或“多算了 1/2”）。

**算什么：** 读目标器材的信号条：有 `err` 级信号时，`spot = true`，`detail` = 该信号关联的数值差（信号里带数值时取数值，否则取 1）；无 `err` 时 `spot = false`，镜子里显示“这里没错”。

**四动词：** 流（`target` 流进来，`spot`/`detail` 流出去给判断灯/猜想板）；绑定（无）；比较（它内部做“实际 vs 应该”的比较，但比较规则来自目标器材的信号，不自带）；变换（无）。

**服务知识点：** 5.5 简易方程（“x + 5 写成了 x5，错在哪一位”）、7.6 解一元一次方程（“移项没变号，错的那一步放大”）、3.12 面积（“面积算成长 + 宽，错的是运算不是数”）、6.5 圆（“周长算成 π × 半径，少的那个 2 在哪”）。它是跨年级的诊断器材。

**画成什么样：** 一个圆框放大镜（带手柄）：框里是目标器材的局部放大 3 倍，错处描金边；框外沿一圈小字写“错在这”。拖手柄移动，拖框边缘改倍数。定格开时，框里是出错那一刻的快照（值冻结），旁边写“当时是这样的”。

**错了怎么表现：** 它本身就是“错了怎么表现”的器材。没错的时候，镜子里是目标器材的正常样子 + 一行小字“这里没错”；有错的时候，错处放大、金边、旁边写差值。学生自己拿着镜子找错，不是被告知错。

**为什么别的软件没有：** 8 个平台全都没有“把错误局部放大展示”的机制。最接近的是 ST Math：它的核心是“动画重演你的错误逻辑”（JiJi 按你的错误方案掉下去），是全景重演，不是局部放大；Graspable Math 是非法项抖动/弹回；NB 是步骤级定位扣分项（查证表 10 号行）。三者都是“告诉你错了”，没有一个是“把错的地方放大给你看”。

**优先级：P1。** 它依赖信号条 `err` 分级（已有）和步骤稳定 ID（步骤 7）；不依赖它也能开工，但它是“错得明白”的验收物。

### 3.4 判断灯（Judge lamp）——世界首创 ★

**解决什么：** E6 的一半 + 设计文档步骤 4。Bool 现在是天平 `d.ports` 里一个出不去的值。判断灯让 Bool 变成台面上一等公民：接收比较结果，亮真/假，再把 Bool 连出去参与逻辑。

**字段：**（1）`label` 灯的名字（文字，如“平了吗？”“是直角吗？”）；（2）`invert` 取反（开关：开 = 真变假、假变真，默认关——“非”门就是一盏取反的灯）。

**端口：** 进：`in`（`bool`——比较结果、天平 `equal`、猜想板 `verdict`、比较器输出都能进）；出：`out`（`bool`，与 `in` 相同，或取反后）。

**算什么：** `out = invert ? !in : in`；`in` 为空（没连进来）时灯灭（灰色，未判定）。

**四动词：** 流（Bool 流进来、流出去）；绑定（无）；比较（它显示比较的结果，不自己比较）；变换（取反是 Bool 到 Bool 的变换）。

**服务知识点：** 7.15 不等式与一元一次不等式组（“x = 3 是解吗？灯亮就是”）、8.2 全等三角形的判定（“三边对应相等吗？灯亮就全等”）、5.5 简易方程（天平 `equal` 连进灯，“平了吗？”）、9.9 随机事件与概率（“这个事件发生了吗？”）。

**画成什么样：** 一盏灯：圆灯罩 + 灯座。真 = 亮绿光（带光晕），假 = 亮红光（暗红，不刺眼），未判定 = 灰色。灯罩上写名字。点灯座开关取反。灯是器材架上最小的器材之一（60×80），可以摆一排做“与/或”逻辑墙（两盏灯的输出连进第三盏灯的 `in`？——不，`in` 只接受一个 Bool；多灯逻辑靠比较器出 Bool 再进灯，见 3.5）。

**错了怎么表现：** 灯不判“对错”，只显示真假——“假”不是错，是一个值。灯红着，学生看到的是“这个命题是假的”，不是“我做错了”。这是 Bool 一等公民的关键：假和真一样，都是可以用的值。

**为什么别的软件没有：** 布尔逻辑人人有，但“灯”形态 + 可连线输出布尔值，8 个平台都没有。GeoGebra 的布尔变量是复选框（条件可见性的开关），Desmos 的比较式只活在表达式列表里，Polypad 有逻辑门教具（与/或/非）但没有“接收比较结果、亮真/假、再连线输出”的判断灯（查证表 4 号行）。

**优先级：P0。** 设计文档步骤 4 的验收物就是它（“天平 `equal` 能连进判断灯”）；Bool 类型落地的第一件器材。

### 3.5 比较器（Comparator）——形态首创

**解决什么：** 比较是数学里最常用的动词之一（比大小、比多少、够不够），但台面上只有天平会比较（且只比相等）。比较器是通用的“A ? B”：两个数连进来，输出大于/小于/等于的 Bool。

**字段：**（1）`op` 比什么（分段按钮：> / < / = / ≥ / ≤，默认 >）；（2）`tol` 容差（步进器：0–0.1，默认 0——分数比较要不要容差，如 0.333… vs 1/3）。

**端口：** 进：`a`、`b`（`num`，任意维度——但要求同维度，不同维度拒绝，理由一句话）；出：`result`（`bool`）。

**算什么：** `result = compare(a, b, op, tol)`，按有理数精确比较（不用浮点）；维度不同时拒绝，不输出。

**四动词：** 流（两个数流进来，Bool 流出去）；绑定（无）；比较（它本身就是比较动词的器材化）；变换（无）。

**服务知识点：** 7.1 正数和负数、有理数与数轴（“-3 和 -5 谁大？”）、5.10 分数的意义和性质（“1/2 和 2/3 谁大？”）、7.15 不等式（“x = 3 满足 x > 2 吗？”）、4.7 条形统计图（“二班比一班多吗？”）。

**画成什么样：** 一个天平的简化版：左右两个托盘（A、B 连进来），中间一个大问号（比什么由字段定），托盘低的那边亮。或者更直接：一块牌子，上面写“A > B ?”，下面亮绿/红。和天平的区别：天平比的是“相等”，比较器比的是“大小关系”；天平是称，比较器是问。

**错了怎么表现：** 比较器不判错——“A < B”是假的时候，输出假，灯灭红，仅此而已。维度不同拒绝时，理由写在指针旁（已有机制）：“个数和面积不能比”。

**为什么别的软件没有：** 比较运算人人有（GeoGebra 表达式里写 `a > b`，Desmos 不等式），但没有一家把它做成“两个端口进、一个 Bool 端口出”的器材。形态首创，不是概念首创。

**优先级：P0。** 判断灯的搭档（比较器出 Bool，判断灯显示 Bool）；Bool 逻辑墙的另一半。

### 3.6 容器 / 集合（Container）——形态首创

**解决什么：** F4（无容器/层级）。“属于”现在只能用连线表达（A 连到 B），没有“放进去”的动作。容器是台面上第一个“放进去就是属于”的器材：东西拖进容器，就是它的元素；两个容器重叠，重叠部分就是交集。

**字段：**（1）`name` 容器的名字（文字，如“喜欢足球的”“偶数”）；（2）`rule` 准入规则（分段按钮：手动放 / 按值筛，如“偶数”“> 5”——筛子模式自动把符合的数收进来）；（3）`show` 显示（分段按钮：列出元素 / 只显示个数）。

**端口：** 进：`members`（任意 kind——拖进来的东西；也可以连线进来）；出：`count`（`num`，`count` 维度，元素个数）、`set`（`shape`，集合本身——可以再被别的容器包含或求交）、`overlap`（`num`，与另一个容器重叠时的交集个数，需两个容器重叠摆放）。

**算什么：** `count = 元素个数`；`overlap = 两个容器都含有的元素个数`（按值去重）；筛子模式下，`members` 自动过滤。

**四动词：** 流（元素流进来，个数/交集个数流出去）；绑定（无）；比较（交集个数是两个集合的比较）；变换（无）。

**服务知识点：** 3.8 集合（主——“两组人分别放进两个圈，重叠的地方是两组都有的人”，容器就是这个圈的器材化）、7.16 统计调查与直方图（分组）、5.4 可能性（样本空间就是容器）、9.9 随机事件与概率（事件 = 样本空间的子集）。

**画成什么样：** 一个圆圈（韦恩图的圈）或一个筐：东西拖进去就落在圈里，圈边变亮；两个圈拖到重叠，重叠部分自动变色（交集区），交集个数写在重叠区中央。筛子模式的容器是个漏斗：符合规则的掉进去，不符合的被挡在外面（ visibly 弹开）。

**错了怎么表现：** 东西放错容器（比如把 7 放进“偶数”筛子），筛子把它弹出来，旁边写“7 是奇数，进不来”——错的动作被挡在外面，不是事后打叉。交集个数算错时（学生数错了），容器不判错，只显示自己的数，让学生自己数一遍对上。

**为什么别的软件没有：** 韦恩图练习人人有（GeoGebra 有教师自制的交互韦恩图集，可拖点入区、做并/交列表练习），但那是预先搭好的练习，不是“把任意东西拖进去就属于、重叠就自动算交集”的通用容器器材；Polypad 只有成组/分组制表，没有集合语义（查证表 5 号行）。

**优先级：P1。** 3.8 集合的主器材；F4 的验收物。

### 3.7 反例构造器（Counterexample builder）——世界首创 ★

**解决什么：** 统一报告 §3.3 的第二环。猜想需要反例才能死得明白，但现在找反例靠学生自己瞎试。反例构造器把“约束”锁死（面积固定 = 12），让学生在约束下随便拖形状，台面自动判定“这个形状是不是反例”（周长 ≠ 12 的长方形的周长）。

**字段：**（1）`fixed` 锁死什么（分段按钮：面积 / 周长 / 体积，默认面积）；（2）`value` 锁死的值（数，默认 12）；（3）`claim` 被挑战的猜想（文字，如“面积越大，周长越大”）。

**端口：** 进：`shape`（`shape`——被拖动的形状，连进来）；出：`isCounter`（`bool`，是不是反例）、`measure`（`num`，被比较的那个量，如周长）。

**算什么：** 约束强制：拖动形状时，`fixed` 的量保持 `value` 不变（拖长，宽自动缩——约束是硬的，拖不动违反约束的形状）；`isCounter = (measure ≠ 原形状的 measure)`，即在同样约束值下找到了不同的量。

**四动词：** 流（形状流进来，Bool 流出去）；绑定（形状的尺寸可以绑到变量上）；比较（它内部做“约束值 vs 实测值”的比较）；变换（拖动形状就是 Shape → Shape 的变换，但约束锁死）。

**服务知识点：** 3.12 面积（“同面积不同周长”）、5.6 多边形的面积（“等底等高面积相等，周长呢？”）、8.13 特殊的平行四边形（“四个角都是直角，就是长方形吗？找反例”）、7.11 平行线与平移（“同位角相等，两直线平行——反过来呢？”）。

**画成什么样：** 一个带锁的画框：框里是形状，框顶挂一把锁（写着“面积 = 12，锁死”）；学生拖形状的边，形状变形但面积不变（另一边自动跟着变）；框下有个天平式的小刻度，显示当前周长；一旦周长 ≠ 原周长，框边变绿，跳出“反例找到了！”

**错了怎么表现：** 它不判学生的错——它帮学生找猜想的错。违反约束的拖动直接拖不动（手柄变灰），理由一句话：“面积锁在 12，拖不动”。找到反例时，猜想板（3.1）上的预测自动裁决为假。

**为什么别的软件没有：** 最接近的是 PhET Area Builder：可拼方块造形、双屏并排比较，教师材料明确写“同面积可有不同周长”，可直接用来找反例——但无“锁定面积 + 自动判定反例”的专用构造器，约束靠人工维持；Polypad 只有五格骨牌教案，靠学生人工数格（查证表 6 号行）。“约束是硬的、判定是自动的”这一层，8 个平台都没有。

**优先级：P1。** 猜想板的搭档（猜想 → 反例 → 裁决）；§3.3 的第二环。

### 3.8 迭代器（Iterator）——形态首创

**解决什么：** E2（没有时间/迭代）。数列、折纸翻倍、复利、龟兔赛跑——这些“一步一步长出来”的数学，现在没有器材。迭代器是“起点 + 规则 → 序列”的机器，带播放：一步一步长出来，学生看到规律是怎么长的。

**字段：**（1）`start` 起点（数，默认 1）；（2）`rule` 规则（分段按钮：+d / ×r / 自定义 a·x+b，默认 +2）；（3）`step` 步长/倍数（数，默认 2）；（4）`n` 走几步（步进器：1–20，默认 5）。

**端口：** 进：`start` 也可以连进来（一个数流进来当起点）；出：`seq`（`seq`，第 n 项函数）、`table`（`dist`？不——是序列的表，kind 记 `seq`，数据表器材可接）、`nth`（`num`，第 n 项的值）。

**算什么：** `a(1) = start`，`a(k+1) = rule(a(k))`；`nth = a(n)`；播放时按步生成，`seq` 的 `nth` 函数即递推本身（范畴论 §1.1：序列是函子 ℕ → 值，不是图里的圈——迭代不连圈，用“步”展开）。

**四动词：** 流（起点流进来，序列/第 n 项流出去）；绑定（`start`、`step` 可绑到变量上）；比较（无）；变换（规则本身就是 `Fn`：`a(k) → a(k+1)`）。

**服务知识点：** 1.16 找规律（主——“重复的单元、预测下一个”）、7.3 有理数的乘除法、乘方与科学记数法（“2 的 10 次方是怎么长出来的”）、6.10 百分数（二）（复利：本金 × (1 + 利率)^年）、9.3 二次函数的图象和性质（二次增长）。

**画成什么样：** 一条横着的传送带：起点在左端，规则写在传送带上方的牌子（“每次 ×2”），每按一次播放键（或点传送带），长出一格（带数字的小方块），格子排成一行；下面同步长出表（步数 | 值）和图（点落在坐标平面上）。播放键是 ▶/⏸，速度可调。

**错了怎么表现：** 学生猜的第 n 项错了（猜想板连进来），迭代器不判错——播放到第 n 步，正确的格子长出来，跟学生的猜并排摆着，差值一目了然。规则设错了（比如想 ×2 设成了 +2），长出来的序列和预期不一样，学生自己看到“长得不对”。

**为什么别的软件没有：** 递推人人会算（GeoGebra 有 `IterationList` 命令，Desmos 支持递归 `f(n)=f(n−1)+2` 并可生成表），但都是命令/公式形态，没有“起点 + 规则 + 播放一步步长出来”的开箱器材；PhET Function Builder 是“输入穿过规则出表”，不是递推迭代（查证表 1 号行）。形态首创。

**优先级：P0。** E2 的主器材；`seq` kind 落地的第一件器材。

### 3.9 撒点器（Sampler）——形态首创

**解决什么：** E4（没有随机/估计）。蒙特卡洛估 π、估面积、抽样估计——这些“用随机逼近确定”的数学，现在只有骰子一个随机源。撒点器是“往图形里撒点，用比例估计”的机器。

**字段：**（1）`n` 撒几个点（步进器：10–1000，默认 100）；（2）`shape` 撒在什么图形里（点选台面上的一个图形，默认圆）；（3）`speed` 撒多快（分段按钮：一次撒完 / 慢慢撒，默认慢慢撒——看得见点数在涨）。

**端口：** 进：`shape`（`shape`——撒点的区域）；出：`inside`（`num`，`count` 维度，落在图形里的点数）、`ratio`（`num`，`ratio` 维度，inside / n）、`estimate`（`num`，估计的面积或 π 值，维度跟随被估计的量）。

**算什么：** 均匀随机撒 n 个点到包围盒里；`inside` = 落在图形内的点数；`ratio = inside / n`；`estimate = ratio × 包围盒面积`（估面积）或 `4 × ratio`（估 π，正方形包圆时）。

**四动词：** 流（图形流进来，点数/比例/估计值流出去）；绑定（`n` 可绑到变量上——“样本量越大越准”就是拖 `n` 的滑杆）；比较（`estimate` 可连进比较器，跟真值比）；变换（无）。

**服务知识点：** 6.5 圆（主——“π 是怎么估出来的？撒点估 π”）、3.12 面积（“不规则图形的面积，撒点估”）、9.10 列举法求概率与频率估计（“频率稳定在概率附近”就是撒点）、7.16 统计调查与直方图（抽样估计）。

**画成什么样：** 一个带喷枪的画框：框里是目标图形（比如圆），点按喷枪撒点（红点在圆外、蓝点在圆内），点数实时涨；框下三行数：圆内 X 个 / 共 Y 个 / 估计 π ≈ Z。慢慢撒时，估计值上下跳动、慢慢收敛到 3.14 附近——收敛本身就是要看的东西。

**错了怎么表现：** 估计值不准（n 太小，估计 2.8），撒点器不判错——它把“误差”本身显示出来：估计值旁边写“±0.3”（按 `1/√n` 的直觉给，不用公式推导，写“点越多，晃得越小”）。学生拖大 `n`，看着估计值晃得越来越小，就是“大数定律”。

**为什么别的软件没有：** 蒙特卡洛 π 的小动画到处都是（GeoGebra、Desmos 都有教师/用户自制），但没有一家做成“图形连进来、点数/比例/估计值连出去”的可连线器材；PhET Plinko 是落球堆直方图（逼近二项分布），不是往图形撒点估面积（查证表 2 号行）。形态首创。

**优先级：P1。** E4 的主器材；`ratio` 维度落地的第一件器材。

### 3.10 分布查看器（Distribution viewer）——形态首创

**解决什么：** E3（数据不是一等公民）的另一半。骰子的 `counts` 还在 props 里，数据表不接输入——分布查看器是“任何分布值流进来，实时变直方图”的通用显示器：骰子连进来是骰子分布，撒点器连进来是估计分布，抽样调查器连进来是样本分布。

**字段：**（1）`bins` 分几组（步进器：2–12，默认 6）；（2）`show` 显示什么（分段按钮：频数 / 频率 / 累计，默认频数）；（3）`mark` 标什么（分段按钮：不标 / 平均数 / 中位数，默认平均数——一条竖线标在图上）。

**端口：** 进：`dist`（`dist`——骰子的分布、撒点器的分布、抽样调查器的样本分布都能进）；出：`mean`（`num`，平均数）、`median`（`num`，中位数）、`mode`（`num`，众数）。

**算什么：** 从 `dist.counts` 按 `bins` 分组画直方图；`mean`/`median`/`mode` 从分布直接算（不是从原始数据重算——分布就是数据）。

**四动词：** 流（分布流进来，均值/中位数/众数流出去）；绑定（无）；比较（无）；变换（分布 → 直方图是 `Dist → Shape` 的变换）。

**服务知识点：** 7.16 统计调查与直方图（主）、9.10 列举法求概率与频率估计（“频率稳定在概率附近”看直方图）、4.7 条形统计图（直方图和条形图的区别）、5.13 折线统计图（分布随时间变）。

**画成什么样：** 一块直方图板：横轴是值，纵轴是频数，柱子随分布实时长高/变矮；平均数是一条金色竖线，中位数是一条蓝色竖线，两条线不重合时，学生看到“平均数被极端值拉走了”。柱子可点：点一根柱子，高亮它代表的那一组数据从哪来（依赖追踪）。

**错了怎么表现：** 分组分错了（bins 太少，形状全糊在一起），查看器不判错——它在旁边写“试试多分几组？”并给一个“自动分组”按钮。学生以为直方图 = 条形图时（7.16 的常见误解），查看器把“组距”和“个数”两个量同时标出来，区别看得见。

**为什么别的软件没有：** 直方图命令人人有（GeoGebra `Histogram`、Desmos `histogram(L)` 都是内置函数；PhET Plinko / Center and Variability 是落球实时堆直方图的固定仿真），但没有一家做成“任意 `dist` 值连进来就实时成图”的通用器材——PhET 的是固定仿真（只能看它自己的球），GeoGebra/Desmos 的是函数调用（要写命令），Polypad 要制表再成图两步（查证表 12 号行）。形态首创。

**优先级：P1。** E3 的验收物之一（骰子 → 分布查看器 → 均值/中位数流出去）；`dist` kind 落地的显示端。

### 3.11 抽样调查器（Survey sampler）——形态首创

**解决什么：** 7.16 的核心误解：“样本越大越好，不管随机不随机”。抽样调查器让学生亲手做抽样：总体是一堆人（或球），学生选抽样方法（随机 / 方便 / 有偏），抽出来估计总体比例，再跟真值比——有偏抽样估出来是错的，错得明白。

**字段：**（1）`method` 抽样方法（分段按钮：随机 / 只抽前排 / 只抽男生，默认随机）；（2）`n` 抽几个（步进器：5–100，默认 20）；（3）`question` 问什么（文字，如“喜欢足球吗？”）。

**端口：** 进：`population`（`dist`——总体分布，连进来；也可以用容器当总体）；出：`sample`（`dist`，样本分布）、`estimate`（`num`，`ratio` 维度，估计的比例）、`bias`（`bool`，这次抽样有没有偏）。

**算什么：** 按 `method` 从总体抽 n 个；`estimate = 样本中“是”的比例`；`bias = (method ≠ 随机)`——有偏抽样直接标出来，不用等结果。

**四动词：** 流（总体流进来，样本/估计流出去）；绑定（`n` 可绑到变量上）；比较（`estimate` 连进比较器，跟真值比）；变换（总体 → 样本是 `Dist → Dist` 的变换）。

**服务知识点：** 7.16 统计调查与直方图（主——“样本要随机、有代表性”）、9.10 列举法求概率与频率估计（“试验次数越多，频率越稳定”）、5.4 可能性（“样本比例 ≠ 总体比例”）。

**画成什么样：** 一个抽奖箱：箱子里是总体（小人图标，一半红一半蓝，比如喜欢足球的 30%）；学生摇箱子抽 n 个，小人一个个跳出来排成一行；下面写“估计喜欢足球的占 X%，总体真值是 30%，差 Y%”。有偏抽样时，箱子只开一侧的门（只抽前排），抽出来的小人明显一边倒，箱子上亮黄灯“这次抽样有偏”。

**错了怎么表现：** 有偏抽样估错了，调查器不打叉——它把“抽样方法”和“估计误差”并排摆着：随机抽 20 个差 5%，只抽前排差 25%，学生自己看到“方法错了，结果就错了”。`bias` 灯亮着，错因写在灯旁边。

**为什么别的软件没有：** 抽样调查的课人人有（ST Math、DreamBox 都有统计与概率单元），但没有一家做成“选方法、抽样本、估比例、跟真值比”的可连线器材；PhET 的 Center and Variability 是固定仿真（踢球距离），不是通用抽样器。形态首创。

**优先级：P2。** 7.16 的专用器材；E4 的第二件。

### 3.12 变量实体 Var（Variable）——形态首创

**解决什么：** E1（没有真正的变量/代数式）。`sym` 是具名数字（x 等于几），不是变量。Var 是台面上的一个具名变量：有名字、有类型，拖上台面，多个器材的属性绑到它上面，改它一个地方，全跟着变。变量是实体，不是属性（设计文档 §4.2 的关键决策）。

**字段：**（1）`name` 名字（文字，如 x、n、r，默认 x）；（2）`type` 类型（分段按钮：数 / 点 / 函数，默认数）；（3）`value` 值（数，滑杆 + 数字框，范围由类型定）。

**端口：** 出：`value`（kind 跟随 `type`，维度跟随被绑的属性——Var 本身不带维度，维度从用它的地方来）。进：无（Var 是源头，不接受输入——自由对象）。

**算什么：** `value = value`（它就是它自己）；绑到它上面的属性由 `syncBinds` 同步（已有机制）。

**四动词：** 流（值流出去，给所有绑它的属性）；绑定（它是绑定的源头——别的器材绑到它上面）；比较（无）；变换（无）。

**服务知识点：** 5.5 简易方程（“x 是还不知道的数”——Var 就是 x 的器材化）、7.6 解一元一次方程（“把 x 剥出来”）、7.14 二元一次方程组与消元（两个 Var：x 和 y）、8.15 一次函数（“y = kx + b 里的 k 是变量”）、9.3 二次函数（“a、b、c 都是变量”）、6.12 比例（“比值 k 是变量”）。

**画成什么样：** 一张变量卡：卡上写大大的名字（x），下面是滑杆 + 数字；卡边是虚线（表示“我是自由的，不依赖谁”）；被绑的属性在卡下列出来（“长方形的宽、圆的半径都绑着我”）。拖卡上台面，点“绑定”再点别的器材的属性，就绑上了（已有手势）。

**错了怎么表现：** Var 没有“错”——它只是一个值。但绑错了会表现出来：把 Var 绑到“分母”上、值调到 0，分式器材亮 `err`（分母不能是 0）；Var 的值超出被绑属性的范围时，属性保持原值，信号条写原因（已有机制）。

**为什么别的软件没有：** 概念人人有——GeoGebra 滑杆就是全局变量，Desmos 字母一键变滑杆，Polypad 也有变量滑杆 + 组件互链——但没有一家把它做成“可拖上画布的器材、再用连线绑到别的器材属性上”的形态：GeoGebra 的绑定靠在公式里写变量名，Desmos 的变量只活在左侧表达式列表里（查证表 3 号行）。形态首创，不是概念首创。

**优先级：P0。** 设计文档步骤 3 的验收物（“一个变量驱动三个组件”）；E1 的地基。

### 3.13 参数族（Parameter family）——形态首创

**解决什么：** 统一报告 §3.4（一个实验变出一类问题）。XP 的 `build` 是手写 JS，数字写死——“鸡兔同笼”永远是 35 头 94 腿。参数族是一个带滑杆的实验模板：头数、腿数是参数不是常数，拖滑杆出一类问题；答案从数变成表达式。

**字段：**（1）`params` 参数表（2–3 个参数，每个有名字、范围、当前值，如头数 20–60、腿数 40–200）；（2）`answer` 答案形式（分段按钮：数 / 表达式，默认数——拖到“表达式”时，答案显示成含参表达式，如“兔 = (腿 − 2×头) ÷ 2”）。

**端口：** 进：`params`（`num`——参数可以连进来，也可以直接在模板上调）；出：`family`（`seq`，一类问题的序列——每个参数值对应一个问题）、`answerExpr`（`fn`？不——是表达式，kind 记 `fn` 的兄弟：现阶段用 `num` + 文字标注，`Val` 加 `expr` kind 是后续工作，见 §5）。

**算什么：** 参数每变一次，实验重建一次（`build` 用参数值重跑）；`answerExpr` 由参数代数式拼出来（模板作者写一次表达式，参数变，表达式里的数跟着变）。

**四动词：** 流（参数流进来，问题族流出去）；绑定（参数可绑到 Var 上——“头数 = n”就是参数族 + Var 的组合）；比较（无）；变换（参数 → 问题是模板变换）。

**服务知识点：** 4.16 鸡兔同笼（主——报告 §3.4 的原例子：35/94 → 滑杆 → 一类问题 → 头数 = n 时答案是表达式）、7.7 实际问题与一元一次方程（“设未知数”就是参数化）、9.4 二次函数与方程及应用（“a 变了，图怎么变”）。

**画成什么样：** 一张实验卡，卡上有 2–3 根滑杆（参数），卡下写“这是第 N 个问题”，旁边一排小点表示问题族（每个点是一个参数组合，点一下跳到那个问题）。答案区有开关：数 / 表达式。

**错了怎么表现：** 参数调到无解组合（头 35 腿 30——腿比头还少），参数族不判错——它把问题标灰，写“这个问题无解，换个参数试试”，无解本身就是要学的（方程组无解）。

**为什么别的软件没有：** 滑杆参数人人有（GeoGebra、Desmos 的核心用法就是拖滑杆得一族曲线；PhET Curve Fitting 有滑杆调参数），但没有一家做成“实验模板 + 参数滑杆 + 答案变表达式”的机制——GeoGebra 的答案仍是数值/图形，Desmos 的是通用参数控件，不是问题族（查证表 9 号行）。形态首创。

**优先级：P1。** 步骤 7（实验改数据）的下游；C10（难度来自选择）的一部分——参数就是选择。

### 3.14 赛跑 / 时间轴（Race）——形态首创

**解决什么：** E2 的另一半（时间不只是“钟面显示几点”，时间是“两个量随时间比快慢”的轴）。龟兔赛跑、两个人同时出发谁先到、一次函数图象上的追及——这些“随时间比”的数学，现在没有器材。

**字段：**（1）`t` 时间（滑杆：0–60 秒，带播放键 ▶/⏸）；（2）`speed1`、`speed2` 两人的速度（数，可连入）；（3）`finish` 终点（数，默认 100 米）。

**端口：** 进：`v1`、`v2`（`fn`——两个人的“路程—时间”函数，或 `num` 速度值）；出：`pos1`、`pos2`（`num`，`length` 维度，当前位置）、`winner`（`bool`，谁先到）、`time1`、`time2`（`num`，`time` 维度，各自用时）。

**算什么：** `pos = v × t`（匀速）或 `pos = fn(t)`（变速时函数值）；`winner = (time1 < time2)`；时间到终点停下。

**四动词：** 流（速度/函数流进来，位置/胜负流出去）；绑定（速度可绑到 Var 上）；比较（胜负就是比较）；变换（时间 → 位置是 `Fn` 的求值）。

**服务知识点：** 4.4 三位数乘两位数（“速度 × 时间 = 路程”）、8.15 一次函数（“路程—时间图象，斜率就是速度”）、6.12 比例（“速度一定，路程和时间成正比”）、9.3 二次函数（“加速跑，路程是时间的二次函数”）。

**画成什么样：** 一条横着的跑道（0–100 米），两个小人（龟和兔，或甲和乙）在跑道上，头顶有时间轴；按播放键，时间走，小人跑；先到终点的小人举旗，`winner` 灯亮。下面同步画两条路程—时间图（斜率就是速度）。

**错了怎么表现：** 学生以为“跑得快的一定先到”（起跑晚呢？），赛跑不判错——让起跑晚的兔子先跑 10 秒，龟后出发但速度快，最后龟先到：图象上两条线交叉，交叉点就是“追上”的时刻。错的直觉被跑道本身纠正。

**为什么别的软件没有：** 运动仿真人人有（PhET 有 Forces and Motion；GeoGebra 有教师自制的 CarRace 模拟，时间滑杆 + 速度滑杆 + 电子表格记时间–距离），但没有一家做成“两个量随时间赛跑、带终点裁决”的内置器材——GeoGebra 的是教师自制单个作品，Desmos 的是 ticker 用户自制（查证表 11 号行）。形态首创。

**优先级：P2。** E2 的第二件；一次函数的“图象”落地的器材。

## 4. 器材之间的新连线：5 组“一个动作，多个领域”

每组写清：搭法（哪些器材、怎么连）+ 一个动作 + 一起动的东西 + 教哪个点。

### 组合一：猜想 → 反例 → 裁决（猜想板 + 反例构造器 + 判断灯）

**搭法：** 反例构造器（锁面积 = 12）→ 猜想板（预测“面积越大，周长越大”，`actual` 连反例构造器的 `measure` 周长）→ 判断灯（接猜想板的 `verdict`）。
**一个动作：** 拖反例构造器里的形状（面积锁死 12，从 3×4 拖成 1×12）。
**一起动：** 周长从 14 变成 26 → 猜想板裁决“猜错了” → 判断灯由绿变红 → 证明脚手架（另搭）生成“因为面积都是 12、周长是 14 和 26，所以面积大周长不一定大”。
**教哪个点：** 3.12 面积、5.6 多边形的面积。统一报告 §3.3 的完整闭环（预测—反例—裁决—证明）第一次在台面上走通。

### 组合二：变量驱动全台（Var + 长方形 + 黑箱 + 数轴 + 判断灯）

**搭法：** Var（x）→ 长方形的宽（绑定）、圆的半径（绑定）、黑箱的输入（连线）；黑箱输出 → 数轴；天平 `equal` → 判断灯。
**一个动作：** 拖 Var 的滑杆（x 从 3 变到 5）。
**一起动：** 长方形变宽、面积变、黑箱输出变、数轴上的点往右移、判断灯（“面积 > 20 吗？”）由红变绿。
**教哪个点：** 5.5 简易方程、8.15 一次函数、6.5 圆。统一报告 §3.2 的“一个动作，四门课”——几何、算术、函数、关系同时在场。

### 组合三：统计全链条（骰子 + 分布查看器 + 数据表 + 比较器 + 猜想板）

**搭法：** 两个骰子（`dist` 输出）→ 分布查看器（直方图）→ 数据表（合计/平均/最大三个端口）；分布查看器的 `mean` → 比较器（“平均 > 7 吗？”）→ 判断灯；猜想板（预测“掷 100 次，和是 7 出现最多”）。
**一个动作：** 点“掷 100 次”。
**一起动：** 直方图长起来（7 的柱子最高）、数据表三数更新、均值竖线移到 7 附近、比较器输出真、判断灯亮绿、猜想板裁决“猜对了”。
**教哪个点：** 7.16 统计调查与直方图、9.10 列举法求概率与频率估计。E3 的验收场景：骰子 → 表 → 图 → 判断，全程是值在流，不是截图。

### 组合四：迭代长出函数（迭代器 + 坐标平面 + 参数族 + 赛跑）

**搭法：** 迭代器（起点 1，规则 ×2）→ 坐标平面（每一步的点落在图上）；参数族（规则里的 2 是参数，滑杆调）；赛跑（迭代器的 `nth` 当速度，另一个迭代器 ×3 当对手）。
**一个动作：** 点迭代器的播放键（一步一步长出 1、2、4、8、16）。
**一起动：** 坐标平面上的点越长越陡（指数增长的图象）、参数族滑杆一拖（×2 变 ×3，整条曲线变陡）、赛跑里 ×3 的小人追上 ×2 的小人。
**教哪个点：** 1.16 找规律、7.3 有理数的乘方、9.3 二次函数、4.4 速度×时间=路程。时间、函数、赛跑三个新器材第一次连在一起。

### 组合五：抽样会骗人（抽样调查器 + 撒点器 + 分布查看器 + 误差放大镜）

**搭法：** 容器（总体：全班 40 人，12 人喜欢足球）→ 抽样调查器（方法：随机 / 只抽前排）→ 分布查看器（样本分布）；撒点器（估总体比例的另一种方法）；误差放大镜（拖到抽样调查器的 `estimate` 上）。
**一个动作：** 把抽样方法从“随机”切到“只抽前排”。
**一起动：** 样本分布一边倒、估计值从 30% 跳到 60%、误差放大镜把“差 30%”放大展示、分布查看器的均值竖线移走。
**教哪个点：** 7.16 统计调查与直方图（“样本要随机、有代表性”）、9.10 频率估计。E4 的验收场景：方法错了，结果就错了，错得看得见。

## 5. 施工建议（按设计文档 09 的 9 步顺序）

| 步骤 | 落在哪的新器材 | 风险 | 验收标准 |
|---|---|---|---|
| 0. 黄金路径基线 | 无（已做：e8c5f78，61 全、2 部分、89 无） | 无 | 147 个实验都有黄金路径记录（已做） |
| 1. 值类型 + 维度代数 | 撒点器（`ratio` 维度落地）、比较器（维度相同才能比）、容器（`count` 维度） | `Val` 形状变，73 处 check 同步改（ports 加法过渡） | 基线全过；`mul(length,length)=area` |
| 2. ports 通用化 | 判断灯（`Bool` 端口落地）、分布查看器（`dist` 端口落地）、比较器（`Bool` 输出） | 信号文字一字不能变 | `.tx===`/`.tx.includes` = 0（已是 0，保持） |
| 3. 命名变量 + 绑定补全 | **变量实体 Var**（本步骤的验收物）、参数族（参数绑 Var） | `syncBinds` 8 遍收敛改拓扑序 | 一个变量驱动三个组件；`g6_bind` 仍过 |
| 4. Bool 类型 + 比较端口通用化 | **判断灯**（本步骤的验收物）、比较器 | `Bool` 是新 kind，link 验证要加 kind 检查 | 天平 `equal` 能连进判断灯 |
| 5. 黑箱藏规则 + 规则库 | 撒点器（规则库的另一种“藏”：估计方法不预设） | `g8_box` 实验要重写步骤 | 练习模式看不到规则 |
| 6. 数据表接输入 + Dist 类型 | **分布查看器**、**抽样调查器**（`dist` 的生产端与消费端）、撒点器（输出 `dist`） | 骰子 `counts` 在 props 里，迁移要小心 | 掷 100 次，表和图自动更新 |
| 7. 实验改数据 + 步骤稳定 ID + predict 步骤 | **猜想板**（本步骤的验收物：predict 步骤类型的器材化）、**反例构造器**（反例是 predict 的验证手段）、**参数族**（实验模板化） | 最大的一批迁移；分 P 数组分批 | XP lint 全过（≥3 步、有 predict、读端口） |
| 8. 类型对象合一 + 增量求值 | **证明脚手架**（依赖图显式化之后才能做）、**误差放大镜**（读信号条 + 步骤 ID） | 改动面最大；分批 + 基线 | 新器材只改一处；基线全过 |

**分批建议（按依赖关系，不按编号）：**
- **第一批（步骤 1–2，P0 打底）：** 比较器 + 判断灯 + 分布查看器——Bool 与 Dist 两个 kind 落地，风险小，验收清晰。
- **第二批（步骤 3–4，P0 核心）：** 变量实体 Var + 参数族——代数进入台面；Var 是后面一半器材的源头。
- **第三批（步骤 6，P1 数据）：** 撒点器 + 抽样调查器——Dist 的生产端；分布查看器已在第一批，链条闭合。
- **第四批（步骤 7，P0 过程）：** 猜想板 + 反例构造器 + 迭代器 + 赛跑——预测与时间进入台面；`seq` kind 落地。
- **第五批（步骤 8，P0/P1 收尾）：** 证明脚手架 + 误差放大镜 + 容器——依赖图显式化之后才能做，放在最后。

**每批的通用验收：** 基线（开场 147 条 + 黄金路径）全过；新器材只改一处（一个类型对象）；XP lint 全过（新实验 ≥3 步、有 predict、读端口）；云端真机复测（不是桩测试）。
