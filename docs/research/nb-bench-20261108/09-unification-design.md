## 0. 目标与验收

**目标一句话：台面是一个世界，一套定律。** 48 种器材共用一个值模型、一套互动语法、一个求值模型、一种实验模型。学生学到的是数学，不是 48 个小工具。

**验收标准只有一条：学生能搭出新东西吗？** 学生搭出一个我们没写过的实验，统一就对了；模型很漂亮但学生只会照着做，统一就错了。每加一层抽象要问：这层让哪个学生动作变简单了？答不上来，不加。

**验收数字（做完时）：** 信号文字匹配（`.tx===` / `.tx.includes`）= 0；`evaluate` 里 `e.type===` 分支收进类型对象（目标 0 处散落分支）；XP lint 全过；基线（开场 147 条 + 黄金路径）全过；widget < 6MB。

## 2. 值模型：`Val = {kind, dim, data}`

`val()` 从返回裸有理数 Q，改成返回带类型的 `Val`。Q 不用重写，包一层就行。

| kind | data | 说明 |
|---|---|---|
| `num` | 有理数 `{n, d}` | 现在的 Q 原样保留 |
| `point` | `{x: Val(num), y: Val(num)}` | 方程组的解、反比例的过点、抛物线的顶点都是点 |
| `interval` | `{lo, hi, loOpen, hiOpen}` | 不等式的解集 |
| `fn` | `{apply: (Val) => Val, label}` | 直线、黑箱规则都是 `fn` |
| `dist` | `{counts: {值: 频次}}` | 骰子的 `counts` 从 `props` 迁到 `ports.dist` |
| `bool` | `true/false` | 比较的结果 |
| `shape` | `{type, props, derived}` | 长方形/圆/三角形，派生量是 `num` |
| `seq` | `{nth: (n) => Val, label}` | 第 n 项函数（数列、生长） |

**维度表（9 种，够用到初中毕业）：** 个数、长度、面积、体积、重量、钱、时间、角度、比值。

**维度代数（写进类型表，不用手写清单）：**
- `mul` 的维度 = 输入维度之积（长度 × 长度 = 面积；面积 × 长度 = 体积）。
- 黑箱（线性函数）保维度：输出维度 = 输入维度。
- `adder` 要求输入同维度（已有的规则，保留）。
- 拒绝从“手写清单”变成“从类型表推导”：数轴拒绝面积、天平拒绝面积，都是“维度不匹配”这一条规则的实例，不再是两句写死的话。

## 3. 互动语法：四种动词补全

台面上的每一次互动都是一句数学句子。四种动词就是全部语法。

| 动词 | 数学句子 | 现状 | 补全 |
|---|---|---|---|
| 流 Flow | `A + B = C` | TYPES 字段：11 种能出 `value`、1 种能出 `fn`、7 种能进 `value`、1 种能进 `fn`、1 种能进 `bool`（判断灯）；`OUT_PORTS` 能连的派生端口：数据表 3 个 + 天平 1 个 + 骰子 2 个；其余 32 种派生端口仍是只读数据 | 推广到全部 8 种 kind：任何端口都能连到接受它的端口；`accepts` 从 `'value'/'fn'` 改成 kind 列表 |
| 绑定 Bind | `A = B`（同一） | `s.binds` + `syncBinds` 拓扑序（889d056）；变量 x 是独立实体（eb10248），一个变量驱动三个组件已验证（344dc9b）；属性 = 表达式已做（72d1b8d/a2e5972，ƒx 界面）；解除绑定回到绑之前的值（0ff19dc） | 命名变量：`Var` 是独立实体（有名字、有类型，出现在器材架上，像数字卡一样拖出来）；多个组件绑同一个变量；属性 = 表达式（`r = 2x + 1`，不只是 `r = x`） |
| 比较 Compare | `A > B`、`A = B` | `Bool` 类型有了：天平 `equal` 口输出 `bool` Val，能连进判断灯（d8cd1a3）；判断灯器材已做 | `Bool` 类型 + 比较端口通用化 + 新器材“判断灯”（显示真/假，能连） |
| 变换 Transform | `f(A) = B` | 规则在练习/考试里藏起来了（993520e）；规则库做了 3 种（42f1078：线性/平方/倒数），分段待做 | 藏规则（练习/考试不显示，考完揭示）+ 规则库（线性/平方/倒数/分段）+ `Fn` 类型通用化（角 → sin/cos/tan 就是现成的黑箱） |

**绑定补全的关键决策：变量是实体，不是属性。** `Var` 有名字（x、n、r……），有类型；任何组件的属性都可以绑到变量上；改变量，所有绑定的地方一起变。这一步把“绑定”从“一个值驱动一个属性”升级成“一个变量驱动整个台面”。

## 4. 求值模型：显式依赖图 + 拓扑序

**现状：** `evaluate` 是按需递归（`val(id)` 记忆化递归 + `busy` 防重入）；`afterChange` 每次全量 `evaluate(S)`；`syncBinds` 已改拓扑序（889d056，每条绑定只写一次）；undo 是 80 层整场景 JSON 快照。

**改三步，不一次做完：**
1. **显式依赖图**：`links` + `binds` 合并成一张图（边 = 依赖）。`reachAll` 已经横跨两者做循环检测——把它升级成图的正式表示。
2. **拓扑序**：求值按拓扑序算，不再按需递归。好处是求值顺序可预测、可解释（依赖链就是证明的骨架，见 §6）；坏处是没有了——拓扑序和按需递归在小规模下性能一样。
3. **增量重算（需要时再做）：** 脏标记——改一个器材，只重算它的下游子图。**现在不做**：46 器材 / 152 实验的规模，全量重算的成本是 `O(实体 + 连线)`，浏览器毫无压力。触发条件：单场景实体数 > 200，或实测 `evaluate` 单次 > 16ms（掉帧阈值），再做。提前做增量是过度工程。

**解锁：** 依赖追踪（选中组件，高亮整条依赖链——“这个数从哪来，到哪去”）；求值可解释（证明脚手架）；性能天花板抬高。

## 5. 对象模型：一个类型 = 一个对象

一个类型 = 一个对象，包含：字段（fields）、端口（ports：出什么、进什么、什么 kind、什么维度）、求值（evaluate 的那一段）、信号（signal：从端口派生显示，文字一字不改）、画法（DRAW）、动作（actions）。

**迁移办法：** `evaluate` 的 80 处分支收进类型对象。分批：先 8 个新类型（黑箱、数据表、x 砝码等 4e63ef2 之后加的），再老类型。每批跑基线。

**做完的标准：** 加新器材只改一处（一个类型对象），不用在 5 个地方各写一段。

## 6. 实验模型：步骤改成数据

**现状（15:32 更新）：** 224 处 `check` 仍是手写谓词 `(S, D) => boolean`，未改成数据；步骤已有稳定 ID（201 步，`xpId:sN`，596d3b3）；`why` 讲推理的 lint 规则（check-xp.js 规则 3）现在 0 个失败（007c37b 改了 13 个实验的 why）——但规则很宽松，`why` 仍是手写文字，未从依赖链生成；没有预测步骤类型（93/93 个实验都没有预测步）；属性 = 表达式已做（72d1b8d/a2e5972），但“答案是表达式”（参数化实验）仍是未来——需要 `expr` 值类型。

**改成：**
- 步骤 = 数据：`{id: xpId:sN, type, expect, hint, score}`，`expect` 是结构化期望（端口值、绑定关系、比较结果），不再是手写谓词。
- 步骤 ID 稳定：机械生成 `xpId:sN`，错题本、今天复习、家长端都用它定位“丢在哪一步”。
- 步骤类型加一种 `predict`：学生先填预测值，再动手验证；预测对错本身记分，但不罚分——猜错是学习，不是失误。
- `why` 从依赖链生成：台面从 D 的依赖图生成“因为 A 所以 B”的文字（“因为长方形的宽是 4、长是 3，所以面积是 12”），不再是背下来的一行字。
- 实验 = 模板 + 参数：`build` 里的写死数字改成参数（数字卡滑杆），一个实验变出一类问题（鸡兔同笼 35/94 → 滑杆 → 一类问题；头数变成变量 n → 答案是表达式）。

**XP lint（`tools/check-xp.js`）：** ≥3 步、有 predict 步、why 讲推理不只给答案、不匹配信号文字、不按插入顺序取器材（不用 `filter(...)[N]`）。新实验不过 lint 不合并。

## 9. 护栏（违反任何一条就停下来）

1. **ports 是加法，不是替换。** `d.value` 已删除（5fcfdfa：读值统一走 `qv(d)` = `d.val.data`，`d.ports` 仍是加法层）。D 的现有键（`d.tilt`、`d.equal`、`d.tot`、`d.terms`、`d.L`、`d.R`、`Ln`/`Rn`）在迁移完成前一字不动。
