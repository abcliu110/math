# 组件之间的数学联系：反孤岛设计

日期：2026-11-08 01:24 JST。Iris 的要求：只关注实验台如何抽象；组件之间不要做成信息孤岛；属性要更多更强大；组件的抽象化；更好用；从数学角度思考组件之间的联系。这篇只想抽象，不改代码。基准：新主线 `f29bb3f`（43 种器材、144 个实验）。

## 0. 孤岛的现状（数过代码）

孤岛有三层，一层比一层深：

- **没有输出端口（算出来的东西出不去）**。43 种器材，7 种有输出端口（数字卡、分数条、合并器、乘法器、除法器、人民币、直线），36 种没有输出（其中 3 种只能接收不能输出）。新加的 19 种全是孤岛——连一个能输出的都没有。
- **没有输入端口（属性只能手调，进不来）**。圆的半径只能在卡里拖滑杆，不能绑一张数字卡；角的度数不能绑一条直线；长方形的宽不能绑一个算式。属性是死的，只能手调。
- **没有共享状态（同一个数不能多面显示）**。1/2 在分数条上、在数轴上、在扇形图里是同一个数，但台面上要手动连线才能同步，而且连线的意思是“喂进去算”，不是“就是同一个”。

最能说明问题的是新器材：它们明明算出了真东西，但全写在信号条的一行字里——

| 器材 | 算出了什么 | 在哪 | 能流出去吗 |
|---|---|---|---|
| 数据的分析 | 平均数、中位数 | 信号条文字 | 不能 |
| 勾股定理 | 斜边 c = √(a²+b²) | 信号条文字 | 不能 |
| 一元二次方程 | 判别式、根 | 信号条文字 | 不能 |
| 方程组 | 解 (7, 3) | 信号条文字 | 不能 |
| 三角函数 | sin/cos/tan | 信号条文字 | 不能 |
| 相似 | 相似比、面积比 | 信号条文字 | 不能 |
| 反比例 | 过点 (2, k/2) | 信号条文字 | 不能 |
| 不等式 | 解集 x < −1 | 信号条文字 | 不能 |

连步骤判分都只能去匹配那行字的中文：`"斜边 5，是勾股数"`、`"解集：x ＜ -1"`、`"根：2、3"`、`sin = 0.50`。改一个字，实验就坏。算出来的东西只配当一行字，这是孤岛最彻底的形态。

另外两处小证据：卡片只显示“连进来的”，不显示“连出去的”；连线是两条裸线，上面没有流的值。

## 1. 从数学看，组件之间有四种联系——这才是抽象的核心

连接本身就是数学关系。四种动词：

**（1）流（Flow）**：一个值从源头流向消费者，消费者拿它算。现状：只有这一种，而且只在 7 种器材之间。数字卡 → 合并器 → 数轴。

**（2）绑定（Bind / 同一）**：两个组件显示的是同一个数。改任何一个，另一个跟着变。这不是“流”，是“同一”。数学上这就是链接表征（Lesh）：1/2 在分数条上、在数轴上、在扇形图里、在小数里，是同一个数。现状：没有。

**（3）比较（Compare / 关系）**：两个东西之间的关系，输出一个真值或关系符。天平：左边 = 右边？左边 > 右边？两个三角形：全等？相似比是多少？两条直线：平行？现状：比较的结果只写在信号条里（“左边重 1/4”），不是一个能流出去的值。

**（4）变换（Transform）**：一个函数作用在一个值/图形上，得到新的值/图形。黑箱输入输出机就是变换；平移/旋转/对称也是变换（现在 shape 的 dx/rot/mirror 是内部属性，不是连接）。现状：没有。

现在的抽象只有一个动词（流），而且动词表只有 7 个主语能用。这就是孤岛的抽象根源。

## 2. 变量：一等公民的胶水

变量是一个有名字、有类型的共享值。x 是变量；方程 x+3=8 是变量 x 和常数之间的关系；函数 y=2x+1 是变量之间的依赖。

变量一次解决三个孤岛问题：

- 同一个数多面显示 = 多个组件绑定到同一个变量。
- 属性被驱动 = 属性的值就是一个变量（或一个表达式）。
- 代数进入台面 = 变量 + 关系（方程就是两个表达式之间的比较连接）。

电子表格类比：**台面就是一张带图画的电子表格**——每个组件是一个单元格，单元格里可以是常数，也可以是引用其他单元格的公式；连线就是引用。学生拖线 = 写公式，但不用写字。

具体：数字卡可以是一个变量（命名 x）；圆的半径可以绑定到变量 x；改 x，圆跟着变。这就是“属性被驱动”。

## 3. 派生值都是端口——反孤岛第一定律

**每个组件算出来的东西，都能流出去；每个组件能调的东西，都能被别的组件驱动。**

派生值端口目录（按新代码核对过的算出物）：

- 数据的分析：平均数、中位数、极差（→ 数值端口）
- 勾股定理：斜边 c、三个正方形面积 a²/b²/c²（→ 数值端口；c² 的面积关系就是勾股定理本身——把 a² 的面积和 b² 的面积连进合并器，得到 c²，定理本身就是一次连线）
- 一元二次方程：判别式、根、根的个数（→ 数值端口）
- 方程组：解 (x, y)（→ 点端口；几何意义就是两条直线的交点——应该能直接落在坐标平面上）
- 三角函数：sin/cos/tan（→ 数值端口；角到数的映射，就是黑箱的雏形）
- 相似：相似比、面积比（→ 比值端口）
- 反比例：k、过点 (2, k/2)（→ 点端口）
- 不等式：解集（→ 区间端口，直接画在数轴上）
- 圆：周长、面积；长方形：面积、周长；三角形：第三个角；角：种类（锐/直/钝）；人民币：总值；钟面：时间值（可加减）；骰子：分布；条形图/折线图/扇形图：总和/最大/平均
- 圆周角 ↔ 圆心角：圆周角 = 圆心角的一半（关系连接，输出一个等式验证）

改法：D 里每个算出物变成有名有类型的端口（`d.ports = {mean: {kind:'number', value}, ...}`），DRAW 照常画字，但值可以连出去。步骤判分改读端口值，不读中文——“斜边 5”这个检查从匹配字符串变成读端口值，改一个字不再弄坏实验。

维度标签跟着来：面积端口是面积维度，不能连到天平上（天平称重量）；长度能连到数轴上；时间能加减。接错线的报错从“只接收数”变成“天平不称面积”。

## 4. 属性即端口——属性更多更强大，从连接的角度重做

属性分三种（按连接分，不按上一篇的“状态值/显示方式/行为约束”分）：

- **可驱动属性（in-port）**：能被别的组件的值驱动。圆的半径、角的度数、长方形的宽、直线的 k/b、三角形的角——都应该是 in-port。拖一张数字卡的蓝点到圆上，问“把圆的半径绑到这个数？”——绑完改数字卡，圆跟着变。
- **派生属性（out-port）**：算出来的，只读，但能流出去（见 §3）。
- **内部属性（internal）**：只影响显示（π 取值、显示格式、透明开关）。这些不用连。

“属性更多更强大”就有了标准：**每个组件至少 1 个可驱动属性 + 至少 1 个派生端口**。上一篇的“每种 2–4 个属性”保留，但加这一条——否则属性再多也是孤岛里的自言自语。0 属性的 5 种（合并器/乘法器/除法器/天平/坐标平面）按这个标准重做：合并器的“运算”可以是可驱动属性；天平的盘容量、灵敏度是可驱动属性；坐标平面的 x/y 范围是可驱动属性。

## 5. 具体联系目录（从数学出发，组件对组件）

1. **分数条 ↔ 数轴：同一数（绑定）**。1/2 在条上和在数轴上是同一个点；拖条上的点，数轴上的点跟着动。
2. **分数条 ↔ 扇形图：部分与整体**。分数是整体的一部分；扇形是整体的划分；分母变了，两边一起变。
3. **数字卡 ↔ 圆的半径：绑定（长度）**。数字卡的值驱动圆的半径；圆的周长面积跟着变。
4. **长方形 ↔ 数轴：派生值流**。面积/周长是数值端口，可以流进数轴比较大小。
5. **长方形 ↔ 天平：不能连**。维度检查的例子：面积不是重量。报错要说出原因。
6. **直线 ↔ 坐标平面：函数图像**。直线是函数在平面上的像；交点是派生值（点端口）。
7. **方程组 ↔ 坐标平面：解就是交点**。sys 的解 (x, y) 是点端口，直接落在坐标平面上——代数与几何的同一。
8. **二次函数 ↔ 坐标平面：抛物线**。顶点、对称轴、与 x 轴交点都是派生值（点/数值端口）。
9. **勾股定理：a² + b² = c² 是三个正方形面积的关系**。见 §3。
10. **相似：比例关系**。相似比 k 是比值端口；对应边成比例——两条边的比值可以连进合并器验证。
11. **三角函数：角 → sin/cos/tan（变换）**。输入角，输出三个数——这就是黑箱的雏形。
12. **圆周角 ↔ 圆心角：关系（比较）**。圆周角 = 圆心角的一半——两个角组件之间的关系连接，输出一个等式验证。
13. **骰子 → 数据表 → 条形图：抽样 → 数据 → 分布（流 + 聚合）**。骰子的分布是输出端口，流进数据表，数据表流进条形图。
14. **钟面 ↔ 数字卡：时间是数**。钟面输出时间值（可加减）——3:20 + 40 分钟 = 4:00 是时间运算。
15. **十格阵/数位块 ↔ 数字卡：计数与符号（绑定）**。7 个方块 = 数字 7；拿走一个方块，数字卡变成 6。
16. **人民币 ↔ 数字卡：钱是数（绑定/流）**。1.35 元可以进合并器。
17. **数据的分析：三个数 → 平均数/中位数/极差（聚合）**。聚合是“多变一”的流。
18. **不等式 ↔ 数轴：解集是区间（绑定）**。ineq 的解集直接画在数轴上——解集不是一行字，是数轴上的一段。

## 6. 更好用（连接的可用性）

- **拖端口时高亮所有兼容端口**（类型匹配的发光），不兼容的变暗；悬停说原因（“天平不称面积”）。现在是拖过去放下才 toast 拒绝——拒绝应该发生在拖之前，而不是放下之后。
- **快捷连接**：双击组件，弹出“能连到什么”（兼容目标菜单）。
- **卡片显示“连进来的”和“连出去的”**（现在只有连进来）。
- **依赖追踪**：选中组件，高亮整条依赖链（上游从哪来、下游到哪去）——像电子表格的“追踪引用单元格”。数学就长在依赖链里：这个数从哪来，到哪去。
- **线上有值**：悬停连线显示流过的值（现在线是裸线）。
- **绑定手势**：把端口拖到另一个组件的属性上（不是端口上）= 绑定。拖数字卡到圆上，问“把半径绑到这个数？”

## 7. 实现顺序

1. **派生值端口**：D 里每个算出物变成有名有类型的端口；步骤判分改读端口值（先做 data/pyth/quad/sys/trig/sim/hyper/ineq 这 8 个新类型——它们的检查现在全是匹配中文字符串，最脆弱）。
2. **维度标签 + 端口类型检查**：接错线报错说出原因。
3. **绑定**：变量 + 属性即表达式（数字卡是变量；属性可绑变量）。
4. **比较**：布尔输出端口（天平的 = / > / <，全等/相似验证）。
5. **变换**：黑箱输入输出机（角 → sin/cos/tan 就是现成的雏形，把它做成通用机器）。
6. **可用性**：拖时高亮兼容端口、依赖追踪、线上有值、卡片双向。

## 8. 边界

- 循环依赖要拒绝并解释（“A 依赖 B，B 依赖 A，绕回来了”）——但迭代是例外：迭代是时间维度的循环，用“步”展开，不算真循环。
- 不是所有东西都要连：连接过多会乱。连接是数学关系，不是装饰——没有数学意义的连接不要给端口。
- 性能：evaluate 现在是全量重算；绑定多了之后，43 种器材、144 个实验的规模还撑得住；真到瓶颈再做增量求值，不要提前。
