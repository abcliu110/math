# 新实验器材设计（第三批）：理化生方法、元器材、老师家长器材

日期：2026-11-08。只设计、不改代码（冻结中）。基准：主线 `17d4103`（lab-nb.html 1527 行，46 种器材，152 个实验）。设计约束见设计文档 `docs/research/nb-bench-20261108/09-unification-design.md`：值模型 `Val = {kind, dim, data}`（8 种 kind、9 种维度）、四种动词（流/绑定/比较/变换）、一个类型 = 一个对象、求值是依赖图 + 拓扑序。

## 0. 一句话结论

15 种新器材，分三个方向：**方向一**（3 种）把理化生实验室的方法搬进数学——滴定、控制变量、对照实验；**方向二**（6 种）元器材，操作对象不是数、而是台面本身——记录器、出题器、批改器、器材制造器、快照对比器、环境调节器；**方向三**（6 种）给老师和家长的器材——布置作业器、全班丢分看板、实验报告器、分享器、改进清单、家长简报器。其中 **9 种是世界首创**（器材形态意义上，8 个平台查证）：**滴定管、控制变量器、对照实验台、记录器、批改器、快照对比器、布置作业器、全班丢分看板、改进清单**（查证细节见 §7）；另有 5 种形态首创，1 种功能已有（分享器——Polypad/Desmos/GeoGebra 的分享功能已等价，只差“分享器本身是一件台面器材”这个形态）。方向二逼出了 8 种新 kind（`scene`/`ops`/`xp`/`score`/`text`/`type`/`task`/`report`），见 §6——8 种 kind 不够用了，这本身就是统一模型要补的一课。

## 1. 方向一：把理化生实验室的方法搬进数学

**这个方向的思路是什么。** Iris 最早的要求是“把生物化的方法引入到数学中来”。NB 实验室的理化生方法不是“器材长什么样”，是“怎么做实验”：滴定是一滴一滴加、看临界点；控制变量是一次只变一个量；对照实验是两组只差一个条件。数学软件的问题恰恰是：它有“算”的器材，没有“怎么做实验”的器材。这一方向的 3 种器材，每一种都是一条理化生方法论的器材化——学生用的不是“更快的计算器”，是“科学家做实验的方法”。NB 自己没有数学实验台（公开渠道找不到 NB 的数学功能，见 §2），所以这 3 种方法它也没有搬过——这是我们的机会，不是跟它学的。

### 1.1 滴定管（Burette）——世界首创 ★

**原来是理化生的什么做法：** 化学滴定。滴定管里装着标准溶液，一滴一滴往烧杯里加，烧杯里有指示剂；加到某一点，指示剂变色——那一点就是滴定终点，终点体积就是要测的量。方法的本质是“一点一点加，看临界点在哪里”，不是“一次算出来”。

**搬进数学后解决哪个数学问题：** 找临界点——方程的根、两条直线的交点、不等式翻转的点。学生现在的做法是“解方程算出来”，滴定管的做法是“一点一点试、看什么时候变”：二分逼近找根，本身就是一种数学方法，但台面上没有器材让它发生。

**字段：**（1）`step` 每滴加多少（分段按钮：1 / 0.1 / 0.01——滴数越小越精确）；（2）`target` 滴向谁（点选台面上的一个函数——被滴定的对象，如直线 y=2x−6）；（3）`indicator` 指示剂（分段按钮：过零点 / 达目标值 / 不等号翻转）。

**端口：** 进：`f`（`fn`——被滴定的函数）、`start`（`num`——从哪里开始滴）；出：`point`（`point`——找到的临界点）、`drops`（`num`，`count` 维度——滴了几滴才到）、`crossed`（`bool`——指示剂变色了没有）。

**算什么：** 从 `start` 起，每滴 x += step，算 f(x)；当符号变号（或达到目标值、不等号翻转）时停下；`point` = 夹住临界点的区间 [x_prev, x]（或插值得到的交点）；`drops` = 滴数。

**四动词：** 流（函数流进来，临界点/Bool 流出去）；绑定（`step` 可绑到 Var 上）；比较（它内部就是比较：滴之前 vs 滴之后，符号变了没有）；变换（滴定是反复求值——`Fn` 被一次次求值）。

**服务知识点：** 7.6 解一元一次方程（“x 是几？一点一点试”）、8.15 一次函数（“y=0 的点在哪？”）、7.15 不等式与一元一次不等式组（“不等号在哪翻转？”）、9.4 二次函数与方程及应用（“抛物线和 x 轴交在哪？”）。

**画成什么样：** 一根竖着的滴定管（带刻度），下面一个烧杯；每点一下龙头（或按播放），一滴落进烧杯，烧杯里的液体涨一点；指示剂变色那一滴，烧杯整杯变色（蓝变红），滴定管上亮出“终点”标记；管旁的数轴上标出临界点所在的区间。滴是点按，不是拖——“一滴”本身就是一个动作单位。

**错了怎么表现：** 滴数太大（step=1），一滴就跳过了临界点——烧杯变色了，但数轴上的区间很宽（“临界点在 3 和 4 之间，到底在哪？”），滴定管写“滴太大了，跳过去了，换 0.1 再滴”。往反方向滴（越滴离临界点越远），指示剂永远不变色，烧杯一直苍白，写“往反方向滴，永远到不了，换个方向”。错的不是答案，是“找临界点的方法”。

**为什么别的软件没有：** 化学滴定仿真到处都是（PhET 酸碱溶液、pH 标度是化学原版），但那是化学的滴定，不是数学的“逐滴逼近临界点”。数学里最接近的是 GeoGebra 上的二分法小品“Metode Bagi Dua”：输函数、定区间、点 Step 逐次折半、点 Zoom 看清当前区间——有“逐步逼近根”的功能，但它是教师手写的单用途演示，不是可复用的台面器材，更不能连线传值或被判分读端口；Desmos 里只有用户自搭的二分法图示，无官方器材。把“逐滴逼近 + 指示剂变色 + 滴数计数”做成一台器材，8 个平台没有。查证细节见 §7（1 号行）。**世界首创的挑战点：** 二分法本身是标准数值方法——如果哪家把二分法做成了“逐滴逼近 + 指示剂翻转”的器材形态，主张即被推翻；目前查到的只是教师手写的演示小品。

**优先级：P1。** “找临界点”这个动作第一次有了自己的形状；二分逼近是 7–9 年级的通用方法。

### 1.2 控制变量器（Variable controller）——世界首创 ★

**原来是理化生的什么做法：** 控制变量法。科学实验的铁律：一次只变一个量，其他量保持不变，否则不知道结果是谁的作用。NB 力学模块让你调重力加速度、空气阻力——环境参数本身就是“被控制的变量”。

**搬进数学后解决哪个数学问题：** 多变量场景里“只变一个量，看结果怎么变”。长方形面积同时取决于长和宽，学生两个一起拖，面积变了，却不知道是谁让它变的。控制变量器把“一次只变一个”从一句口头要求变成一个台面上的锁。

**字段：**（1）`active` 正在测哪一个变量（点选台面上的一个字段——唯一解锁的那个）；（2）`locked` 锁住了几个（`num`，`count` 维度，只读推导值）；（3）`log` 记录（开关：开 = 记下主动变量每变一次、结果跟着变多少，默认开）。

**端口：** 进：`scene`（`scene` kind——整个场景，连进来）；出：`active`（`text`——正在测的变量名）、`effect`（`num`——主动变量每变 1，结果变多少，如“宽每加 1，面积加 3”）。

**算什么：** 除 `active` 外的所有字段上锁（台面强制执行：`act('set')` 打在被锁字段上被拒绝，理由一句话）；`effect = Δ结果 / Δ主动变量`（差商，直接算出来，不是写上去的）；`log` 记下（变量值 | 结果）的对照表。

**四动词：** 流（场景流进来，效应值流出去）；绑定（`active` 可绑到 Var 上）；比较（效应值本身就是比较：变之前 vs 变之后）；变换（锁字段是场景 → 场景的变换）。

**服务知识点：** 5.6 多边形的面积（“只变宽、长不动，面积怎么变？”）、8.15 一次函数（“只变 k、b 不动，直线怎么转？”）、6.5 圆（“只变 r，周长和面积谁变快？”）、4.16 鸡兔同笼（“只变头数，腿数怎么变？”）。它是跨年级的方法器材，不是某一年级的器材。

**画成什么样：** 一块锁板：台面上每个参数对应一把小锁，正在测的那把锁是开的（绿色）、其余全是关的（灰色）；锁板下面是一张对照表（变量值 | 结果），每测一次多一行。换变量测时，先点一把新锁（旧锁自动关上）——“一次只测一个”是物理动作，不是口头要求。

**错了怎么表现：** 想改被锁的变量，字段晃一下、 stays put，旁边写“这个变量锁住了，先测完当前这个”。想同时改两个变量，第二个改动被拒绝，写“一次只变一个，变了两个就不知道是谁的作用了”。错的不是答案，是“做实验的方法”——方法错了，器材直接挡住，不让错发生。

**为什么别的软件没有：** “控制变量”是科学课的口头要求，PhET 仿真里常作为教学提示出现，但没有一家把它做成“锁面板 + 效应值 + 对照表”的器材；GeoGebra/Desmos 的滑杆一次只能拖一个是默认行为，不是显式的锁定机制——学生随时可以换一个滑杆拖，没有任何东西记录“你刚才在测哪一个”。最接近的实物是 PhET 气体仿真 Gases Intro / Gas Properties 的“Hold Constant”：选 Temperature / Volume / Pressure 之一锁定，再变另一个量看结果——语义最接近，但它是写死在单个物理仿真里的 3 个预设变量，不是通用的台面锁面板，不能锁任意数学参数、不记录“这次在测哪一个变量”、不能拖上台面绑到别的器材。把“一次只变一个”做成台面上的锁，8 个平台没有。查证细节见 §7（2 号行）。**世界首创的挑战点：** PhET 的 Hold Constant 是显式的“锁定其余变量”机制——如果 PhET 把它从单个仿真里抽出来、做成通用面板，主张即被推翻。

**优先级：P0。** 它是方法论本身；跨年级；设计文档步骤 3（变量）+ 步骤 6（数据）的交汇点——效应值就是“数据”。

### 1.3 对照实验台（Twin bench）——世界首创 ★

**原来是理化生的什么做法：** 对照实验。两组实验，除一个条件外完全相同；结果的差，就是那一个条件的作用。方法的本质是“差值即证据”。

**搬进数学后解决哪个数学问题：** 两种解法、两种策略、两种估计方法，到底谁更好——不是凭感觉，是并排跑、算差值。学生现在的做法是“做完一个再做一个，凭印象比”；对照实验台让两个场景同时跑、差值实时算。

**字段：**（1）`diff` 差在哪一个条件（点选一个字段——两组唯一不同的那个）；（2）`metric` 比什么（分段按钮：结果值 / 步数 / 用时 / 丢分）；（3）`sync` 同步跑（开关：开 = 两组同步推进，默认开）。

**端口：** 进：`sceneA`、`sceneB`（`scene` kind——两个场景）；出：`delta`（`num`——度量值的差）、`firstDiff`（`text`——两组从哪一步开始不一样，如“第 2 步”）、`winner`（`bool`——按度量值，哪组更好）。

**算什么：** 两组场景各自求值（或读各自的结果）；`delta = 度量A − 度量B`；`firstDiff` = 两个场景状态最早不同的步骤；`winner` = 按 `metric` 比较的结果。

**四动词：** 流（两个场景流进来，差值/Bool 流出去）；绑定（`diff` 可绑到 Var 上）；比较（它本身就是比较）；变换（无——它只读、不改）。

**服务知识点：** 5.3 小数除法（“两种算法，谁的步数少？”）、4.16 鸡兔同笼（“假设法 vs 列表法，谁快？”）、7.16 统计调查与直方图（“随机抽样 vs 方便抽样，估计差多少？”——接第一批抽样调查器）、9.10 列举法求概率与频率估计（“两种估计方法，谁更准？”）。

**画成什么样：** 两张小台面并排（A 组 / B 组），中间一条竖分隔线；唯一不同的那个条件在两边都描金边（“就差这一个”）；下面一条“差”横条，实时显示 `delta`；两组从哪一步开始不一样，那一步上插一面小旗。同步跑时，两边的操作镜像进行（A 组拖一步，B 组自动走对应的那一步）。

**错了怎么表现：** 两组差了不止一个条件，台面拒绝比较，写“两组差了不止一个条件，比不出是谁的作用——先把别的条件调成一样”。度量值不可比（比如一组比的是面积、一组比的是周长），`delta` 不出，只写“这两样东西不能比”。错的不是答案，是“对照的方法”——对照不成立，器材直接说出来。

**为什么别的软件没有：** 分屏对比、两个图并排显示，各家都有（那是视图布局）；但“两组、只差一个条件、差值自动算”这个对照组语义，没有一家做成器材。PhET 的仿真里常有“对比”教学提示，GeoGebra 可以开两个视图，但那是人眼在比，不是台面在算差。最接近的是 Desmos Activity Builder 的 Two-Graph Screens：能把两个图并排跑、教师可手写连线把左图的值传进右图、加按钮对比结果——但没有任何“对照组”语义：不保证两组只差一个条件、不自动算差值（差值要教师每活动手写 f−g），不是开箱即用的器材；搜“control group / A-B + Desmos/GeoGebra”返回的只是拿这些平台做实验组/对照组的研究论文，产品内无此功能。查证细节见 §7（3 号行）。**世界首创的挑战点：** 结论是“没有/未查到”，是方向一里证据最干净的一行；唯一的弱点是 ST Math / DreamBox / Graspable Math 三家需登录，公开渠道只能判“未查到”，不能断言其登录墙内绝对没有。

**优先级：P1。** “差值即证据”是科学方法的核心；它是控制变量器（1.3）的搭档——一个锁变量，一个比两组。

## 2. 方向二：操作台面的器材（元器材）

**这个方向的思路是什么。** 前两批的器材操作对象都是数、形、量；这一方向的器材操作对象是台面本身——场景、操作记录、题目、分数、器材定义。统一报告的验收标准是“学生能搭出新东西吗”——元器材就是把这个验收标准本身做成器材：学生录下自己的操作、改一个量重放、把场景变成题、按步骤判分、自己造一个新器材。这些事在别的软件里是“平台级功能”（历史面板、教师后台、自定义工具对话框），不在台面上；元器材把它们从后台搬到台面上，变成可以拖、可以连、可以绑的东西。代价是值模型要扩：8 种 kind 不够用了，见 §5。

**新 kind 一览（本方向用到，定义见 §5）：** `scene`（整个台面状态）、`ops`（操作记录）、`xp`（题目定义）、`score`（按步得分记录）、`text`（文字值）、`type`（器材定义）、`task`（作业单，方向三用）、`report`（实验报告，方向三用）。

### 2.1 记录器（Recorder）——世界首创 ★

**解决什么：** “刚才那串操作，再换个数走一遍。”学生做完一串操作（拖、连、改值），想换个数重做——现在只能从头再拖一遍。记录器把操作录下来，可以回放；关键是“改一个量重放”：把录好的操作序列里某个数改掉，整段操作按新数重跑一遍，结果跟着变。

**字段：**（1）`mode` 模式（分段按钮：录 / 播 / 改量重播）；（2）`speed` 播放速度（分段按钮：慢 / 中 / 快）；（3）`swap` 换哪个量（点选记录里的一个数——重播时被替换的那个量）。

**端口：** 进：`ops`（操作记录——学生动手时台面实时喂给它；也可以从另一台记录器连进来）；出：`replay`（`ops`——重播后的操作记录）、`result`（`scene`——重播后的台面状态）。

**算什么：** 录模式下记下每一个 `act`（动作、参数、时间）；播模式下按顺序重放；改量重播时，把 `swap` 指定的数替换成新值，再重放——每一步的 `act` 参数都跟着换。

**四动词：** 流（操作记录流进来，重播后的场景流出去）；绑定（`swap` 可绑到 Var 上——“换的那个数就是 x”）；比较（无）；变换（重播是 `ops → scene` 的变换）。

**服务知识点：** 跨年级的过程器材。4.6 除数是两位数的除法（“刚才试商 7 的那串操作，除数换成 48 再走一遍”）、1.9 凑十法（“刚才 9+4 的拖点，换成 8+5 再走一遍”）、7.6 解一元一次方程（“刚才移项的那串操作，换个数再走一遍”）。

**画成什么样：** 一台录音机：磁带上有刻度（每一格是一步操作），红点是录制键，▶/⏸ 是播放键；`swap` 槽里放着要换的那个数（金色）。播放时，台面上的器材按记录一步一步自己动起来（像有人在操作）；改量重播时，磁带上那一格的数字先变色，再重播。

**错了怎么表现：** 录好的操作、底景变了（录的时候台面是 A，现在是 B），记录器拒绝重播，写“底景变了，这段录音对不上——先回到录的时候那个场景”。换的量让某一步走不下去（比如把除数换成 0），重播停在那一步，那一步标红，写“第 5 步走不下去了：除数是 0”。错的不是答案，是“重播的条件”。

**为什么别的软件没有：** 最接近的是 GeoGebra 的作图协议（Construction Protocol）：步骤列表，可逐步回放作图过程——但它只能重放“作图步骤”，拖拽操作本身不进协议；滑块改参能让整个作图实时重算，但它不是“录下点/拖/连/改值的自由操作序列、再改序列里某个数重跑”；Graspable Math 只有变形历史展示，Desmos 只有撤销/版本恢复，无改量重放。把“录制 + 改量重播”做成一台可连线的器材，8 个平台没有。查证细节见 §7（4 号行）。**世界首创的挑战点：** GeoGebra 作图协议 + 滑块的组合已经覆盖了“重放 + 改参重算”的一半——记录器的首创主张建立在“自由操作序列的录制 + 序列内改量重播”这两点上，如果哪家补上这两点，主张即被推翻。

**优先级：P1。** “同一做法换个数再走一遍”是泛化的第一步；它是出题器（2.2）和批改器（2.3）的上游——没有操作记录，出题和判分都没有输入。

### 2.2 出题器（Problem setter）

**解决什么：** 学生当出题人。学生把台面上的一个场景变成一道题（带题目、带判定规则），发给同学做；同学在自己的台面上打开这道题做，做完出题器自动判对错。统一报告的验收标准“学生能搭出新东西吗”——出题器就是“学生能出新题吗”的器材化。

**字段：**（1）`title` 题目（文字，如“天平平了吗？x 是几？”）；（2）`rule` 判定规则（点选一个端口 + 一个期望值，如“天平 `equal` = true”）；（3）`hint` 提示（文字，可选）。

**端口：** 进：`scene`（`scene` kind——要变成题的场景）；出：`xp`（`xp` kind——题目定义）、`card`（`text`——可分享的题卡）。

**算什么：** 把 {场景快照（当 `build`）、判定规则（当 `expect`）、标题、提示} 打包成一道题；题号机械生成 `stu:<作者>:<n>`；题目进实验库，带 `author: student` 标记，单列在“同学出的题”里。

**四动词：** 流（场景流进来，题目流出去）；绑定（无）；比较（判定规则本身就是比较）；变换（场景 → 题目是 `scene → xp` 的变换）。

**服务知识点：** 跨年级。5.5 简易方程（“我搭的天平题，x 是几？”）、3.12 面积（“我搭的长方形题，面积是几？”）、4.16 鸡兔同笼（“我出的鸡兔题，兔有几只？”）。

**画成什么样：** 一台出题机：场景从左边推进去，右边吐出一张题卡——卡上有标题、题目、一道“做这道题”按钮；卡的背面写着判定规则（出题人可见，做题人看不见——“答案藏在卡背面”是出题器的规矩）。

**错了怎么表现：** 没有判定规则的题出不来——出题器拒绝，写“没有判定规则的题没法判，选一个端口当答案”。起始状态就已经做完了的题（比如天平一搭上就平了），出题器亮黄灯警告，写“这道题在起始状态就已经做完了，改改起始状态再出”。

**为什么别的软件没有：** Desmos Activity Builder、GeoGebra Classroom 都是教师建活动、派发给学生——出题人是老师，不是学生；Polypad 的分享是分享画布，不是“场景变题目 + 判定规则 + 同学做完自动判”。把“学生把场景变成题”做成一台器材，8 个平台没有。查证细节见 §7（5 号行）。

**优先级：P0。** 学生当作者的第一件器材；设计文档 §0 验收标准的直接落地。

### 2.3 批改器（Grader）——世界首创 ★

**解决什么：** 步骤判分本身变成看得见的器材。现在判分是后台逻辑（`submitExam` 里算）；批改器把它拖上台面：连进一道题（`xp`）和一段学生操作（`ops`），它逐条步骤打分，输出每步得分 + 丢在哪步。

**字段：**（1）`strict` 严格程度（分段按钮：只看结果 / 看步骤 / 看步骤 + 过程）；（2）`showWhy` 显示丢分原因（开关：开 = 每步丢分旁边写原因）。

**端口：** 进：`xp`（`xp` kind——题目定义）、`ops`（`ops` kind——学生的操作记录）；出：`scores`（`score` kind，一步一条）、`total`（`num`，总分）、`lost`（`text`——丢在哪步，如“第 2 步”）。

**算什么：** 按 `xp.steps` 的 `expect` 数据（步骤 ID `xpId:sN`），逐条检查操作记录里有没有满足期望的新动作；每步得分/满分输出一条 `score`；`lost` = 第一条没得分的步骤。

**四动词：** 流（题目 + 操作记录流进来，得分记录流出去）；绑定（无）；比较（它本身就是比较：实际 vs 期望）；变换（操作记录 → 得分记录是 `ops → score` 的变换）。

**服务知识点：** 跨年级。总清单 H1（考试报告只有分数、无错因、无“下一步练什么”）的器材化——批改器就是“下一步练什么”的来源：丢的那步直接连回练习。

**画成什么样：** 一枚批改章 + 一张成绩单：成绩单上每一步是一个小格子，重播走到哪一步，那一步的格子就盖一个章（绿 ✓ 或红 ✗）；最下面是总分；丢的那步被红笔圈出来，旁边写原因（`showWhy` 开时）。

**错了怎么表现：** 判一道没有步骤 ID 的题（老的手写 `check` 题），批改器拒绝，写“这道题的步骤没有编号，判不了”——这条拒绝本身就是 F5 迁移的执行者：老题必须先改成步骤数据，才能被批改器判。操作记录不是做这道题的（`ops` 的 `xpId` 对不上），也拒绝，写“这段操作不是做这道题的”。

**为什么别的软件没有：** NB 的按步骤打分是后台智能评分系统（秒级出分、定位扣分步骤），ASSISTments 的自动批改是平台功能，GeoGebra Groups 只有选择题/示例答案的 Check 按钮加教师反馈——判分都在后台，不在台面上。把“判分规则本身”做成一台可拖上台面的器材（连进题目和操作记录就出分），8 个平台没有。查证细节见 §7（6 号行）。**世界首创的挑战点：** NB 的按步骤打分在功能上最接近——如果 NB 把它的智能评分做成台面上的一台器材，批改器的首创主张即被推翻。

**优先级：P0。** H1 的验收物；它是方向三全班丢分看板（3.2）的上游——看板读的就是批改器输出的 `score`。

### 2.4 器材制造器（Apparatus maker）——形态首创

**解决什么：** 学生自己造一个新器材。统一报告的终极验收是“学生能搭出新东西吗”——制造器把这句话推到顶：学生选名字、选 2–4 个字段、选进/出端口、选算什么（从一个小公式库里选），点“造出来”，新器材立刻出现在器材架上，能拖上台面用、能连线、能被判分。

**字段：**（1）`name` 名字（文字）；（2）`formula` 算什么（分段按钮，从公式库选：a·x+b / x² / a+b / a−b / a×b / a÷b / max / min）；（3）`inPorts` / `outPorts` 进出端口（点选 kind：从 8 种 + 新 kind 里选）；（4）`fields` 字段（2–4 个，从字段库选：数/滑杆/分段按钮）。

**端口：** 进：`formula`（`fn`——算什么）、`spec`（`text`——字段/端口的规格文字）；出：`newType`（`type` kind——新器材的定义）。

**算什么：** 生成一个类型对象 {name, label, fields, ports, compute}，注册进 `TYPES`；新类型立刻出现在器材架上（带 “NEW” 标签 + 作者名）；它可以被拖、被连、被绑、被判分——和原生器材没有区别。

**学生自己做的器材，怎么进实验库、怎么被判分（任务明确要求回答）：** 制造器自动从新器材的出端口生成步骤检查——每个出端口的值都是一条可检查的期望（“输入 3 时输出 = 7”）；制造器要求作者声明一条“什么算对”的规则（在一个出端口上写期望值），没有这条规则造不出来；题目（`xp`）的 `expect` 读的就是这条规则；XP lint 读端口，不读手写谓词，所以学生造的器材自动过 lint 的端口检查；学生出的题进实验库时带 `author: student` + `reviewed: false` 标记，单列在“同学出的题”里，老师点“已审”后才进正式库；判分走批改器（2.3），读声明的期望值。

**四动词：** 流（公式/规格流进来，新类型流出去）；绑定（造出来的器材字段天生可绑）；比较（无）；变换（规格 → 类型是台面上最元的一次变换）。

**服务知识点：** 跨年级。它是设计文档 §0 验收标准的终极形态；也是设计文档步骤 8（类型对象合一）的验收物——“加新器材只改一处”，学生造器材就是这句话的证明。

**画成什么样：** 一间小作坊：墙上有四个槽（名字槽、公式槽、字段槽、端口槽），学生把选项卡拖进槽里，点“造出来”，作坊门打开，新器材“走”出来、跳上器材架，头顶顶着 “NEW” 和作者名。

**错了怎么表现：** 没有出端口的器材造不出来——作坊拒绝，写“没有输出口的器材没法用，加一个输出”。公式的输入和进端口对不上（比如公式要两个数、进端口只有一个），拒绝，写“公式要两个数，进端口只有一个”。名字和已有器材重了，拒绝，写“已经有这个名字的器材了，换个名字”。

**为什么别的软件没有：** 最接近的是 GeoGebra 的“自定义工具”（Create New Tool）：从一个作图定义新工具，输入对象 → 输出对象——但它定义的是几何作图，不是“选字段、选端口、选公式”的器材；造出来的工具进不了步骤判分、进不了实验库。Polypad、Desmos 没有用户自定义器材的机制。把“造器材”本身做成一台器材（造出来的东西立刻能用、能连、能被判分），8 个平台没有。查证细节见 §7（7 号行）。**从世界首创降级为形态首创的原因：** GeoGebra 自定义工具确实做了“用户定义新工具”这件核心事（指定输入/输出对象、起名字、可当命令用、可存为 .ggt 文件）——器材制造器与它的差别只在“字段/端口/公式库”三件套和“进器材架、可被判分”的台面语义，差别不够大，不足以支撑世界首创的主张，改为形态首创。

**优先级：P0（但排最后做）。** 它是终极验收物，但依赖类型对象合一（设计文档步骤 8）——在那之前造出来的器材没地方注册。施工顺序见 §6。

### 2.5 快照对比器（Snapshot comparator）——世界首创 ★

**解决什么：** “我刚才那一步到底改了什么？”学生做了一串操作，回头想知道“改之前 vs 改之后”——现在只能靠记忆。快照对比器把台面的两个状态（快照 A 和快照 B）并排比较：同一个量变了多少、在哪一步开始不一样。

**字段：**（1）`a` 快照 A（点选一张已存快照）；（2）`b` 快照 B（点选一张已存快照）；（3）`what` 比什么（分段按钮：值 / 位置 / 连线 / 全部）。

**端口：** 进：`snapA`、`snapB`（`scene` kind——两张快照）；出：`diff`（`text`——变化清单，如“宽 3→5，面积 12→20”）、`count`（`num`，`count` 维度——变了几处）。

**算什么：** 两个场景逐个实体比对（属性、位置、连线、绑定）；输出变化清单；`count` = 变化处数。

**四动词：** 流（两张快照流进来，变化清单流出去）；绑定（无）；比较（它本身就是比较）；变换（场景 × 场景 → 变化清单是 `scene × scene → text` 的变换）。

**服务知识点：** 跨年级的过程器材。5.6 多边形的面积（“改之前面积 12，改之后 20，变的是宽”）、8.15 一次函数（“k 从 2 变 3，图怎么变的？”）、7.6 解一元一次方程（“移项之前和之后，等式两边各是什么？”）。

**画成什么样：** 两张拍立得照片并排，变化的地方在两张照片上都描金边圈出来；下面是一张变化清单（“宽：3 → 5；面积：12 → 20；多了一条连线”）。点清单上的一条，两张照片上对应的器材同时高亮。

**错了怎么表现：** 两张快照一模一样，`diff` 是空的，写“两张快照一模一样，没什么可比的——先改点什么再比”。两张快照不是同一个实验的，亮黄灯警告，写“这两张不是同一个实验的，比了也没意义”，但还是把变化清单列出来（标明是跨实验对比）。

**与方向一对照实验台的区别（必须写清楚）：** 对照实验台比的是两个**活的**场景并排跑（空间上的并排，两组同时进行，只差一个条件）；快照对比器比的是同一个场景在两个**时间点**的快照（时间上的前后，改之前 vs 改之后）。一个是空间对照，一个是时间差分；一个算 `delta`（度量值的差），一个算 `diff`（变化清单）。

**为什么别的软件没有：** 版本对比、撤销历史、双屏显示，各家都有（那是平台功能）；但“两张快照并排、变化清单自动算”做成一台可拖上台面的器材，8 个平台没有。最接近的是 Desmos 版本历史（2026 年 6 月上线）：只能按缩略图/时间浏览并恢复单个旧版本，无“两个快照并排、自动算差值、定位分叉步骤”的机制；GeoGebra 作图协议只能单线逐步回放。查证细节见 §7（8 号行）。**世界首创的挑战点：** 平台外的 Wolfram NotebookDiff 有笔记本 diff 机制（不在 8 个平台之列，不计入本次查证）——如果把它算进来，快照对比器的主张要降级。

**优先级：P2。** 它是“反思”这个动作的器材化；依赖场景快照机制（F6 场景版本化）。

### 2.6 环境调节器（Environment dial）

**解决什么：** “规则变了，结果怎么变？”台面上的规则现在是写死的：π=3.14、满十进一、四舍五入。环境调节器把这些全局规则变成可调的：改一个环境设定，全台面的器材按新规则重算。学生看到的不是“答案变了”，是“规则本身在起作用”。

**字段：**（1）`pi` π 取多少（分段按钮：3.14 / 3 / 精确值）；（2）`carry` 进位规则（分段按钮：满十进一 / 满百进一）；（3）`rounding` 舍入（分段按钮：四舍五入 / 去尾 / 进一）；（4）`range` 数轴范围（分段按钮：0–10 / 0–100 / −10–10）。

**端口：** 进：`scene`（`scene` kind——要按新环境重算的场景）；出：`scene`（`scene` kind——同一个场景，按新环境重算后）。另外它有一个全局效应：环境设定是台面级的，不只影响连进来的场景——这一点见 §5（环境不是值，是全局量）。

**算什么：** 按环境参数重新跑 `evaluate(S)`：π 值、进位规则、舍入方式代入计算；所有派生值更新。

**四动词：** 流（场景流进来，场景流出去）；绑定（环境字段可绑到 Var 上——“π 就是 x”）；比较（无）；变换（它是整个场景的变换）。

**服务知识点：** 6.5 圆（“π 取 3 时，圆的周长是多少？和取 3.14 差多少？”）、4.11 小数的意义和性质（“四舍五入 vs 去尾，0.55 变成 0.6 还是 0.5？”）、1.15 100以内加减法（一）（“满百进一的世界里，23+5 是多少？”）、3.3 测量（“数轴范围变了，点还放得下吗？”）。

**画成什么样：** 一块控制面板（像恒温器的面板）：四个旋钮/开关；拧一个旋钮，整个台面“闪”一下（所有器材重算、数值跟着变）；台面角落常驻一个小徽章，写当前环境（“π=3.14 · 满十进一”）。

**错了怎么表现：** 环境不是对错问题——改环境让某道题的期望答案变了，台面不判错，受影响的实验亮黄灯，写“环境变了，答案也变了——这道题在新环境下的答案是 X”。“规则变了结果就变”本身就是要学的。

**为什么别的软件没有：** NB 力学模块可调重力加速度、空气阻力——那是物理环境原版；数学软件的全局设置（Desmos 的设置、GeoGebra 的选项）是设置面板，不是台面上的可调对象，更没有“改一个设定、全台面重算并显示徽章”的机制。查证细节见 §7（9 号行）。

**优先级：P2。** 它是“规则本身”这个概念的器材化；依赖求值模型的环境参数化（设计文档步骤 1 的延伸）。

## 3. 方向三：给老师和家长的器材

**这个方向的思路是什么。** 总清单 K 组（K1–K4）和 L 组（L1–L2）要的东西，现在都是“后台功能”的形状：教师端、家长看板、统计报表。但这个台面的规矩是“一切都在台面上”——所以方向三的器材把老师和家长要的东西也做成台面上的器材：布置作业是一台发作业的机器，丢分统计是一块热力图板，实验报告是一台自动生成报告的机器，分享是一架纸飞机，改进清单是一块待办板，家长简报是一封信。使用者是老师/家长，但形态仍是器材——拖上台面、连线、读数据、输出结果。数据来源是现成的四把钥匙（见每节的“读什么数据”）：`math-lab-proc-v1`（跨次考试统计）、`nb-lab-exam-v1`（每道题的丢分记录）、`nb-lab-practice-v1`（练习进度）、`nb-lab-find-v1`（发现记录）、`math-inquiry-v1`（探究作业/报告/发现）。

**一个必须先说清楚的诚实点：** 现在的丢分记录是按中文步骤 label 记的（`lost: {label: count}`，没有稳定 ID）——方向三的器材现阶段按（实验号 + 步骤 label）聚合；设计文档步骤 7（步骤改数据 + 稳定 ID `xpId:sN`）做完后，改按 ID 聚合。Label 可能在不同实验里撞车（两道题都有“把 x 调到 5”这一步），聚合时以（实验号，label）为键，避免撞车。样本太少时（尝试 < 5 次）不显示丢分率，只显示“样本太少”。

### 3.1 布置作业器（Homework assigner）——世界首创 ★

**解决什么：** 总清单 K1——老师发实验，学生交场景 + 发现。现在没有布置入口（`math-inquiry-v1` 有 taskId 的提交结构，但台面不写）。

**字段：**（1）`xp` 布置哪道题（点选实验库里的一道题）；（2）`due` 截止时间（文字，如“周五晚上”）；（3）`note` 老师的话（文字，如“先猜，再动手”）。

**端口：** 进：`xp`（`xp` kind——要布置的实验）；出：`task`（`task` kind——作业单 {taskId, xpId, due, note, submissions: [{学生， 场景， 发现， 时间}]}）。

**读什么数据 / 写什么数据：** 读实验库（XP 定义）；写 `math-inquiry-v1`（taskId = `hw:<日期>:<n>` 的作业记录 + 学生的提交）。

**算什么：** 生成作业单；学生打开作业单做，做完把场景 + 发现交回来；作业器上实时显示交了几个、没交几个。

**四动词：** 流（实验流进来，作业单流出去）；绑定（无）；比较（无——它是收集器）；变换（实验 → 作业单是 `xp → task` 的变换）。

**服务谁：** 老师（发作业）+ 学生（接作业、交场景）。老师在台面上用它：点一道题、写截止时间、点“发下去”，作业单就出现在学生的实验库里。

**画成什么样：** 一个信箱 / 作业板：实验从左边推进去，右边吐出一张作业卡——卡上有标题、截止时间的邮戳、老师的话；卡分两栏（交了 / 没交），每栏是学生名字；点一个已交的名字，那个学生的场景在他自己的台面上打开（只读，可点“再看一遍他的操作记录”）。

**错了怎么表现：** 布置一道没有步骤的题，作业器拒绝，写“这道题没有步骤，没法收”。截止时间写成了过去的时间，亮黄灯警告，写“截止时间已经过了——是想补发吗？”

**为什么别的软件没有：** NB 教师端有“班级作业”页（标题公开，流程未验证，登录墙后）；Desmos Activity Builder、GeoGebra Classroom 是教师后台派发活动——作业是后台功能，不是台面上的器材。把“作业单本身”做成一台器材（学生交回的是场景，不是选择题答案），8 个平台没有。查证细节见 §7（10 号行）。**世界首创的挑战点：** Desmos Activity Builder（教师建活动、派给班级、学生用班级码加入、教师仪表盘实时看进度）和 GeoGebra Classroom（由活动建班级、发码/直链、实时看全班学生构造、可暂停课程作为截止）在功能上已覆盖“布置 + 回收 + 看进度”——布置作业器的首创主张建立在“作业单本身是台面对象、学生交回的是场景 + 发现”这两点上；NB 教师端称“一键发布任务、批量派发与收缴”，但公开页只有标题 + 登录提示，流程未验证。

**优先级：P0。** K1 的验收物。

### 3.2 全班丢分看板（Class loss board）——世界首创 ★

**解决什么：** 总清单 K4 + L1——哪一步全班都丢，一眼看到。现在没有聚合：每道题的丢分只记在自己的 `nb-lab-exam-v1` 里，老师看不到全班。

**字段：**（1）`xp` 看哪道题（点选一道题，或“全部”）；（2）`window` 看多久（分段按钮：本周 / 本月 / 全部）；（3）`sort` 怎么排（分段按钮：丢分率 / 丢分人数）。

**端口：** 进：`scores`（`score` kind——全班的按步得分记录，从 `math-lab-proc-v1` + `nb-lab-exam-v1` 聚合）；出：`board`（`text`——排好序的丢分清单）、`worst`（`text`——丢得最惨的那一步）。

**读什么数据：** `math-lab-proc-v1`（跨次统计：每道题考过几次、每步丢分）+ `nb-lab-exam-v1`（每道题的 `lost: {label: count}`）。

**算什么：** 按（实验号，步骤 label）聚合丢分；丢分率 = 丢的次数 / 尝试次数；排序；输出热力图数据。

**四动词：** 流（得分记录流进来，看板流出去）；绑定（无）；比较（排序本身就是比较）；变换（得分记录 → 看板是 `score → text` 的变换）。

**服务谁：** 老师。老师在台面上用它：点一道题、看热力图、点最红的那格。

**画成什么样：** 一块热力图板：行是实验，列是步骤，格子按丢分率着色（绿 → 黄 → 红）；最红的那格在跳动；点一格，显示丢那步的学生名单和他们的错法（如果记了）；板顶写“全班最卡的一步是：g4_16 第 2 步（82% 丢分）”。

**错了怎么表现：** 样本太少（某步只被尝试了 2 次），那格不着色，写“样本太少，先别下结论”。步骤 label 在不同实验里撞车时，看板以（实验号，label）为键，绝不把两道题的同名步骤合并算。

**为什么别的软件没有：** ASSISTments 的教师报告有常见错答统计，NB 教师端有“班级掌握水平”，DreamBox/ST Math 有教师仪表盘——但那些都是后台报表页面，不是台面上的一块板。把“按步骤聚合丢分”做成一块可拖上台面的热力图板（读本地记录、不上传），8 个平台没有。查证细节见 §7（11 号行）。**世界首创的挑战点：** NB 官网称“自动汇总高频失分考点，学情全景可视”“自动跟踪全步骤细节、精准定位扣分项”，ASSISTments 的教师报告按题统计全班表现与常见错答（3 人以上相同错答即常见错答）、可据此决定讲哪题，DreamBox 另有按标准/班级的 Progress / Standards Report 网格视图——看板的首创主张建立在“行=实验、列=步骤、颜色=丢分率”的热力图 + “它是一块可拖上台面的板”这两点上；检索中出现的热力图（如 Magma、Gyanmai）不在 8 平台之列，不计入。

**优先级：P0。** K4 + L1 的验收物；它是改进清单（3.5）的上游——清单读的就是看板的数据。

### 3.3 实验报告器（Report generator）

**解决什么：** 总清单 K2——实验报告（NB 是目的/原理/器材/步骤/结论；数学版是猜想/试了什么/发现/还想问）。现在只有“我的发现”文本框，没有报告。

**字段：**（1）`style` 报告样式（分段按钮：简版 / 完整版）；（2）`include` 包含什么（分段按钮：只含已验证的 / 含猜错的）。

**端口：** 进：`scene`（最终场景）、`ops`（操作记录）、`guess`（猜想——从第一批猜想板连进来）、`finding`（`text`——学生的发现，从“我的发现”连进来）；出：`report`（`report` kind——{猜想， 试了什么， 发现， 还想问}）。

**读什么数据 / 写什么数据：** 读操作记录（`nb-lab-practice-v1` 的 `ops`）+ 发现记录（`nb-lab-find-v1`）；写 `math-inquiry-v1`（报告，带实验标题 + 时间戳）。

**算什么：** 猜想格 = 猜想板上锁定的预测；试了什么格 = 操作记录逐条转成一句话（“把宽从 3 调到 5”“连了两条线”）；发现格 = 学生的发现文本 + 依赖链的结论（读证明脚手架的 `chain`）；还想问格 = 学生自己填一句（唯一手写的格子）。

**四动词：** 流（场景 + 操作记录 + 猜想 + 发现流进来，报告流出去）；绑定（无）；比较（无）；变换（记录 → 报告是 `ops → report` 的变换）。

**服务谁：** 学生（写报告）+ 老师（读报告）。学生做完实验，拖报告器上台，四格报告自动长出来，补一句“还想问”，点“交上去”。

**画成什么样：** 一张四格报告卡（2×2：猜想 / 试了什么 / 发现 / 还想问）；前三格自动填写（带“正在写”的动画），第四格是空行，等学生写；卡的右上角有个“交上去”按钮。

**错了怎么表现：** 台面是空的（没有操作记录），“试了什么”格显示“还没动手，先做实验”，“交上去”按钮是灰的，理由一句话：“先做，再写”。猜想格空着（学生没猜），报告照样能交，但猜想格写“这次没猜，下次先猜再动手”。

**与第一批证明脚手架的区别（必须写清楚）：** 证明脚手架生成的是推理文字（“因为……所以……”）；实验报告器组装的是整份四格报告（猜想/试了什么/发现/还想问）并保存提交。脚手架是报告器的一个零件（发现格读它的 `chain`），不是同一个东西。

**为什么别的软件没有：** NB 的实验报告是浮动窗口 + CKEditor（学生自己填目的/原理/器材/步骤/结论）——手填的表，不是自动生成的。把“按操作记录自动生成报告”做成一台器材，8 个平台没有。查证细节见 §7（12 号行）。**不标世界首创的原因（方向三里最易被挑战的一件）：** NB 考试/自测模式里学生点“实验报告”按钮、填完后系统按步骤打分、生成诊断报告（“统计实验操作过程中出现的问题”“直接定位并溯源具体步骤中的得分与扣分原因”）；另有两则非官方营销文案称 NB“自动生成标准实验报告、数据变化曲线”“自动生成包含实验目的、步骤记录、现象分析的结构化报告模板”——后两则未在 NB 官网/手册原文中验证到同等表述，只能算弱证据。实验报告器的主张建立在“自动”的定义上：NB 的“自动”是自动评分/诊断，报告主体仍是学生手填；本器材的“自动”是按“猜想板 + 操作记录 + 发现文本”自动拼出“猜想/试了什么/发现/还想问”四格报告——如果 NB 的“自动生成标准实验报告”属实且就是按操作记录拼的，主张即被推翻，改为形态首创。

**优先级：P0。** K2 的验收物。

### 3.4 分享器（Sharer）

**解决什么：** 总清单 K3——分享实验。现在没有分享（旧台面有 JSON 配置码，新台面无；统一报告核实：保存/分享/导出全是 0）。

**字段：**（1）`include` 带什么（分段按钮：只带场景 / 场景 + 实验引用 / 场景 + 操作记录）；（2）`expiry` 有效期（分段按钮：不过期 / 7 天）。

**端口：** 进：`scene`（要分享的场景）；出：`code`（`text`——分享码，一串短码）、`link`（`text`——链接）。

**算什么：** 把 {场景（含版本字段——F6）、实验号（如果有）、操作记录（如果选了）} 序列化成一串紧凑的码；对方把码贴进自己的台面，场景原样出现——是活的拷贝，可以继续改，不是截图。

**四动词：** 流（场景流进来，分享码流出去）；绑定（无）；比较（无）；变换（场景 → 分享码是序列化变换）。

**服务谁：** 学生（分享给同学）+ 老师（分享给全班）。学生搭好一个场景，拖分享器上台，点“复制码”，发给同学；同学贴进台面，场景活过来。

**画成什么样：** 一架纸飞机：场景从左边推进去，右边飞出一张码卡——卡上有分享码、一个“复制”按钮、卡上写着里面装了什么（“场景 + 实验 g4_16 + 12 步操作”）。

**错了怎么表现：** 分享空台面，分享器拒绝，写“空台面没什么可分享的”。分享旧场景（没有版本字段的 F6 之前存档），分享器给它盖上当前版本号，亮黄灯警告，写“这是旧场景，打开时按当前版本读”。

**为什么别的软件没有：** 分享功能各家都有（Polypad 分享画布链接、GeoGebra 分享链接、Desmos 分享、NB“分享实验/复制链接到 PPT”）——但那些是“把作品发出去给人看”，重点在传播；分享器的重点是“对方打开即原样复现、可继续改”，而且分享码本身是一件台面器材的输出（可以连进布置作业器当作业附件）。查证细节见 §7（13 号行）。**诚实修正：分享器的功能已有等价物——不标任何首创。** 查证结论是“有”：Polypad“保存画布后每个 Polypad 有唯一 URL，可分享给他人；学生保存后如在教师班级中，会自动出现在教师仪表盘；学生可复制一份继续做”；Desmos 的 Save and Share 生成链接，对方打开可拖动滑块/移动点、可保存副本到自己账号再编辑；GeoGebra 公开分享的工作表“任何人可用并复制一份”。功能上已等价——场景变成链接/码，对方打开即原样复现、可存副本继续改。分享器剩下的新东西只有形态（“分享器本身是一件台面器材”、分享码是它的输出端口、可以连进布置作业器当作业附件），所以本器材不标世界首创、也不标形态首创，只写“功能已有，形态是台面器材”。

**优先级：P1。** K3 的验收物；它是布置作业器（3.1）的搭档——作业单里附的码就是分享器出的。

### 3.5 改进清单（Improvement list）——世界首创 ★

**解决什么：** 总清单 L1 + L2——丢分数据回流到作者。现在没有回路：丢分数据记下来了，但没人告诉实验作者“哪一步要重写”。

**字段：**（1）`threshold` 多少算“要重写”（步进器：丢分率 50%–90%，默认 80%）；（2）`scope` 看哪些实验（分段按钮：全部 / 某一年级 / 某一道题）。

**端口：** 进：`scores`（`score` kind——全部学生的按步得分记录）；出：`list`（`text`——排好序的改进清单）、`top`（`text`——最要改的那一步）。

**读什么数据：** `math-lab-proc-v1` + `nb-lab-exam-v1`（与 3.2 同源）。

**算什么：** 按（实验号，步骤 label）算丢分率 = 丢的次数 / 尝试次数；过滤掉低于阈值的；按丢分率倒序；每条写建议（按丢分模式自动生成：“提示不清”/“步骤太大，拆成两步”/“起始状态有歧义”）。

**四动词：** 流（得分记录流进来，清单流出去）；绑定（无）；比较（排序本身就是比较）；变换（得分记录 → 清单是 `score → text` 的变换）。

**服务谁：** 实验作者（写实验的人——老师或 Iris）。作者在台面上用它：看清单、点一条、跳到那道题的步骤编辑、改完打勾。

**画成什么样：** 一块待办板：每条是一张卡，卡上有步骤、丢分率红条、一条建议；改完一条，点卡上的勾，卡变绿、沉到底。板顶写“最要改的一步：g4_16 第 2 步（82% 丢分）”。

**错了怎么表现：** 样本太少（某步尝试 < 5 次），那条不上榜，只写“样本太少，先别改”。丢分率 100% 但只有 1 次尝试的步不上榜——清单拒绝“一次丢分就判死刑”。

**为什么别的软件没有：** 教师看学生错题，各家都有（ASSISTments、DreamBox 的教师报告）；但“按丢分率给内容作者提改进建议、数据回流到实验本身”的闭环，没有一家做成台面上的器材——NB 的综合统计是给老师看学生，不是给作者看实验。查证细节见 §7（14 号行）。**世界首创的挑战点：** 最接近的是 ASSISTments 的 Instructional Recommendation / Common Wrong Answer Feedback：报告里有“灯泡”标记的教学建议，点开看“当学生在这题上挣扎时，同行教师会怎么做”；常见错答反馈是众包的教师建议——但 IR-CWA 的接收者是任课教师、内容是“这题怎么教”，不是“按丢分率排序、告诉内容作者哪一步要重写”；8 平台内未查到任何一家把全班/全校丢分数据按步骤丢分率排序、回流给实验作者并指导重写的闭环。结论是“没有/未查到”，是方向三里证据最干净的一行。

**优先级：P1。** L1 + L2 的验收物；它是全班丢分看板（3.2）的下游——看板给人看，清单给作者改。

### 3.6 家长简报器（Parent brief generator）

**解决什么：** 家长一眼看到孩子这周怎么样、该练什么。现在家长端有本周清单和体检表（app.js 里已有），但没有“一页简报 + 一键复习清单”的生成器。

**字段：**（1）`window` 看多久（分段按钮：本周 / 本月）；（2）`detail` 详细程度（分段按钮：一页 / 详细）。

**端口：** 进：`records`（`score` kind——孩子的练习 + 考试 + 发现记录）；出：`brief`（`report` kind——一页简报）、`reviewList`（`text`——复习清单）。

**读什么数据：** `math-lab-proc-v1`（考试统计）+ `nb-lab-exam-v1`（丢分）+ `nb-lab-find-v1`（发现记录）。

**算什么：** 本周练了几条实验、考了几次、丢得最多的 3 步、发现了几条；复习清单 = 丢的步骤（F5 后按 `xpId:sN`，之前按 label），点一下整批加进“今天复习”。

**四动词：** 流（记录流进来，简报 + 清单流出去）；绑定（无）；比较（排前 3 丢分最多的步）；变换（记录 → 简报是 `score → report` 的变换）。

**服务谁：** 家长。家长在台面上用它：点“生成本周简报”，一页信出来，点“一键加进今天复习”，孩子的复习清单就建好了。

**画成什么样：** 一封信（一页卡片）：第一行“本周练了 5 条实验，考了 2 次”，中间“丢得最多的 3 步”，下面一句孩子最新发现的原文（引用的），最下面一个按钮“一键加进今天复习”。

**错了怎么表现：** 这周没有记录（新学生），不出一张空简报，写“这周还没练过，先去做一道实验”。

**为什么别的软件没有：** NB 没有独立家长端（公开渠道只有家长社区讨论，见 NB 功能研究报告 §4.3）；DreamBox/ST Math 有家长报告/仪表盘——但那是“看孩子分数”的页面，没有“一键生成复习清单”的机制。把“简报 + 一键复习清单”做成一台器材，8 个平台没有。查证细节见 §7（15 号行）。**不标世界首创的原因：** 最接近的是 DreamBox Family Dashboard（家长仪表盘）+ Assignments：家长可看孩子使用量、进度、标准掌握情况，“May Need Attention（需关注）”的课组排在最前；家庭订阅者可手动给孩子布置作业，包括 Review（复习）类作业——“家长看仪表盘 + 手动选课组布置复习”已很接近，只差“自动生成一页本周简报 + 一键把丢的步骤加进今天复习”。ST Math 只查到教师看单个学生使用量/进度的报告，未查到家长仪表盘或家长简报。NB 无家长端这一点得到公开渠道的佐证：NB 官网只提教师/学生/学校，用户协议只提到未成年人注册需监护人陪同/授权，未提到家长看数据的功能；另有家庭会员营销文案称“70% AI 督学 + 30% 家长引导”，但那是家长陪伴角色，不是家长端产品。

**优先级：P2。** 家长端是我们自己的设计（NB 没有可抄的）；它是方向三里最轻的一件。

## 4. 新器材组合：4 组新实验 / 新流程

### 组合一：学生出题流水线（方向二内部）

**记录器 + 出题器 + 批改器 + 分享器。** 学生先做一道题（操作被记录器录下来），再把做完的场景用出题器变成一道新题（带判定规则），分享器把题发给同学，同学做完，批改器按步骤打分、指出丢在哪步。流程：做题 → 出题 → 发题 → 做题 → 判分。统一报告的验收标准“学生能搭出新东西吗”——这条流水线就是“学生能出题、能判题吗”的完整流程。任务要求的那一组（记录器 + 出题器 + 批改器 = 学生出题给同学做）就是它，分享器是发题的那一步。

### 组合二：临界点全流程（方向一 + 方向二）

**滴定管 + 记录器 + 批改器。** 学生用滴定管找一元一次方程的根（逐滴逼近）、找二次函数的零点；操作被记录器录下来，改一个量（步长从 1 换成 0.1）重播，批改器按步骤打分——每一次“滴”的尝试都是一步，批改器看得出“第几次滴错了方向”。“找临界点”这个动作本身第一次有了可回放、可判分的过程记录。

### 组合三：对照实验进课堂（方向一 + 方向三）

**控制变量器 + 对照实验台 + 全班丢分看板 + 改进清单。** 老师在课堂上用控制变量器锁住所有变量、只留一个可调，用对照实验台并排跑两组（只差一个条件），全班做完，全班丢分看板显示哪一步全班都丢，改进清单告诉实验作者哪一步要重写。流程：老师做对照 → 学生做 → 看板显示丢分 → 清单回流给作者。一堂课的教、学、评、改，四个器材串起来。

### 组合四：从学生造器材到老师收作业（方向二 + 方向三）

**器材制造器 + 出题器 + 布置作业器 + 实验报告器。** 学生用器材制造器造一个新器材（比如“一个算 a·x+b 的机器”），用出题器把带这个新器材的场景变成一道题，老师用布置作业器把它发成作业，全班学生做完，实验报告器自动生成四格报告交上去。流程：造器材 → 出题 → 布置 → 做题 → 交报告。学生从“用器材的人”变成“造器材、发作业的人”；老师收到的不是选择题答案，是场景 + 报告。

## 5. 与第一批、第二批的配合：3 组跨批组合

### 组合一：猜想 → 滴定 → 判断灯（第一批 + 第三批）

**猜想板（第一批）+ 滴定管（第三批）+ 判断灯（第一批）。** 学生先在猜想板上猜“临界点在哪里”（比如“方程 x²−2=0 的根在 1.4 和 1.5 之间”），再用滴定管逐滴逼近（0.1、0.01 步长），判断灯在每一步亮绿/亮红——“猜对了没有”不是老师说的，是灯说的。猜想板的预测、滴定管的动作、判断灯的裁决，三件器材各干各的活。

### 组合二：试商的过程第一次被录下来（第二批 + 第三批）

**试商台（第二批）+ 记录器（第三批）+ 批改器（第三批）。** 试商台是第二批最有创意的器材（治“试商”这个没有确定性算法的步骤）；但它的问题是“试商的过程看不见”——试错了几次、每次试了几，操作完就没了。记录器把试商的全过程录下来（第 1 次试 7、余数太大、第 2 次试 6……），批改器按步骤打分——“试商试了几次、每次错在哪”第一次有了可回放、可判分的记录。

### 组合三：通分切割器 + 证明脚手架（第一批 + 第二批）

**通分切割器（第二批）+ 证明脚手架（第一批）。** 学生用通分切割器把 1/2 和 1/3 都切成 6 份（2/6 和 3/6，切出来的 1/6 就是两者的差），再用证明脚手架生成推理文字（“因为都切成了 6 份，所以 1/2+1/3=5/6”）。两批各出一件器材：切开看等价、说出为什么。（原组合里的显微镜随 12:00 决定一起砍掉。）

## 6. 8 种 kind 不够用的地方：新 kind 清单

设计文档 09 的值模型 `Val = {kind, dim, data}` 有 8 种 kind。方向二、三的器材操作的对象不是数，是台面本身——8 种 kind 不够用，要加 8 种。每一项都写清“为什么必须是一个独立的 kind，而不是塞进已有的 `text` 或 `num` 里”：

| 新 kind | 结构 | 为什么必须独立（不能用已有的 kind 代替） |
|---|---|---|
| `scene` | {entities, links, binds, seq, nid}——整个台面状态，就是现在的 scene 对象 | 它是台面本身的状态；用 `text` 序列化会丢“可连线、可重算”的语义；`scene` 是对照实验台、快照对比器、分享器的输入输出 |
| `ops` | {acts: [{t, args, at}], base: scene}——操作记录 | 操作记录是时间序列，带“重放”的语义；`seq` kind 存的是值序列，不是动作序列；记录器和批改器的输入 |
| `xp` | {id, title, grade, domain, tools, q, why, build, steps: [{id, type, expect, hint, score}]}——题目定义，就是设计文档 §6 的“步骤改数据” | 题目是结构化的（步骤、期望、分数），不是一段文字；出题器和批改器的输入输出 |
| `score` | {xpId, stepId, got, max, at}——按步得分记录 | 得分记录是结构化的（步骤 ID、得分、满分、时间），不是一个数；批改器的输出、看板和清单的输入 |
| `text` | 字符串——名字、日志、报告格子、分享码 | 最轻的一个 kind；名字、日志、分享码、报告格子都是文字值，不带数学语义；不加它，`text` 字段就只能塞进 `num` 里 |
| `type` | {name, label, fields, ports, compute}——器材定义，就是设计文档步骤 8 的类型对象 | 器材定义是元对象（定义了别的器材），不是值；器材制造器的输出；不加它，学生造的器材没地方注册 |
| `task` | {taskId, xpId, due, note, submissions: [{学生， 场景， 发现， 时间}]}——作业单 | 作业单是“实验 + 截止时间 + 提交列表”的结构，不是题目本身；布置作业器的输出 |
| `report` | {猜想， 试了什么， 发现， 还想问}——四格实验报告 | 报告是四格结构，不是自由文本；实验报告器和家长简报器的输出 |

**环境不是 kind——它是一个全局量。** 环境调节器改的是台面级的规则（π 取多少、进位规则、舍入方式），不是某一个器材的输入值。`scene` kind 里不含环境；环境是求值模型的全局参数（设计文档 §3 求值模型的延伸：`evaluate(S, env)`）。这一点是模型上的缺口：设计文档 09 没有“环境”这个概念，环境调节器把它暴露出来了。

**依赖关系（哪些新 kind / 新器材依赖设计文档的哪一步）：**

- 批改器 → 设计文档步骤 7（步骤改数据 + 稳定 ID `xpId:sN`）：没有步骤 ID 的题判不了。
- 器材制造器 → 设计文档步骤 8（类型对象合一）：没有统一的类型对象，学生造的器材没地方注册。
- 实验报告器 → 设计文档步骤 7 + 第一批证明脚手架（发现格读脚手架的 `chain`）。
- 方向三的老师器材 → 设计文档步骤 7（丢分记录按 ID 聚合，而不是按 label 聚合）。
- 快照对比器 → F6（场景版本化）：快照要有版本号才能比。
- 分享器 → F6（场景版本化）：分享码里要带版本字段。

## 7. 查证方法与结果

**查证方法：** 8 个平台（Polypad、GeoGebra、Desmos、PhET、ST Math、DreamBox、Graspable Math、NB 实验室），公开网页（`browser.search` + `browser.open`）。每种器材的结论分四档：有（同类器材已存在）/ 类似（有近似功能，但形态或关键机制不同）/ 没有（公开渠道查不到）/ 未查到（登录墙后，无法验证）。“世界首创”的意思是器材形态首创——拖上台面、能连线、能绑属性、能被判分——不是数学思想首创。平台级后台功能（教师仪表盘、自动批改系统）算“类似”，不算“有”，因为它们不是台面上的器材。**方法上的诚实点：** 方向二的查证代理只用了 `browser.search` 检索、没有 `browser.open` 逐页细读——方向二 6 行的判定以各平台官方文档/帮助页的检索摘要为准，证据强度低于前两批（逐页细读）。方向一、方向三的查证方法见各自代理的回报。

**查证分工：** 方向一（5 种）由查证代理 A 负责，方向二（6 种）由查证代理 B 负责，方向三（6 种）由查证代理 C 负责。三份查证结果回报后，本节填表；表里的结论如与各节“为什么别的软件没有”不一致，以表为准，各节随之改写。**三份全部已填（2026-11-08 10:47 UTC）：方向一 5 行（代理 A）、方向二 6 行（代理 B）、方向三 6 行（代理 C）。方法上的差异：** 代理 A 用了 `browser.search` + `browser.open`；代理 B 只用了 `browser.search`、没有逐页细读——方向二 6 行的判定以官方文档/帮助页的检索摘要为准，证据强度低于前两批；代理 C 用了 `browser.search` + `browser.open`，但 `https://www.nobook.com/web-exam` 的一次 `browser.open` 失败、未重复尝试——方向三里引用该页的结论以搜索结果摘要为准。ST Math / DreamBox / Graspable Math 三家需登录，公开渠道只能判“未查到”，不能断言其登录墙内绝对没有——三位代理一致认了这一点。

### 8.4 “世界首创”可能被推翻的点（按主张强度排）

**主张最硬的三件（查证结论“没有/未查到”，8 平台内无等价物）：**

- **对照实验台**：结论“没有/未查到”。最接近的 Desmos Two-Graph Screens 只有“并排两图”，无对照组语义（不保证只差一个条件、不自动算差值）。弱点：ST Math / DreamBox / Graspable Math 登录墙内未查到。
- **快照对比器**：结论“没有/未查到”。最接近的 Desmos 版本历史只能恢复单个旧版本，无“两个快照并排、自动算差值、定位分叉步骤”。弱点：平台外的 Wolfram NotebookDiff 有笔记本 diff 机制——如果把它算进来，主张要降级。
- **改进清单**：结论“没有/未查到”。最接近的 ASSISTments IR-CWA 是给任课教师的教学建议，不是给内容作者的重写清单；8 平台内无“丢分数据按步骤丢分率排序、回流给实验作者”的闭环。

**主张中等的六件（查证结论“类似”，竞品是后台功能或单用途演示，差别在“台面上的器材”）：**

- **滴定管**：竞品是 GeoGebra 二分法小品（教师手写单用途演示）+ PhET 化学滴定（化学原版）。如果哪家把二分法做成了“逐滴逼近 + 指示剂翻转”的器材形态，主张即被推翻。
- **控制变量器**：竞品是 PhET 气体仿真的 Hold Constant（写死在单个物理仿真里的 3 个预设变量）。如果 PhET 把它抽出来做成通用面板，主张即被推翻。
- **记录器**：竞品是 GeoGebra 作图协议 + 滑块（已覆盖“重放 + 改参重算”的一半）。主张建立在“自由操作序列的录制 + 序列内改量重播”这两点上。
- **批改器**：竞品是 NB 按步骤打分（后台智能评分系统）。如果 NB 把它的智能评分做成台面上的一台器材，主张即被推翻。
- **布置作业器**：竞品是 Desmos Activity Builder / GeoGebra Classroom / NB 班级作业（教师后台派发 + 后台看进度）。主张建立在“作业单本身是台面对象、学生交回的是场景 + 发现”这两点上。
- **全班丢分看板**：竞品是 NB 实验测评 + ASSISTments 教师报告（后台报表，粒度是题/考点，不是步骤）。主张建立在“行=实验、列=步骤、颜色=丢分率”的热力图 + “它是一块可拖上台面的板”这两点上。

**已降级 / 未标首创的八件：**

- **器材制造器**：已从世界首创降级为形态首创。GeoGebra 自定义工具确实做了“用户定义新工具”这件核心事，差别只在“字段/端口/公式库”三件套和“进器材架、可被判分”的台面语义。
- **出题器**：未标首创，形态首创。Desmos Activity Builder / GeoGebra Classroom / Polypad 的教师建题 + 分享机制是最接近的竞品；主张建立在“学生当出题人 + 判定规则 + 同学做完自动判”的闭环上，但代理 B 把它列为方向二里最易被挑战的三件之一。
- **环境调节器**：未标首创，形态首创。NB 物理环境（可调重力加速度、空气阻力）是原版，各平台的全局设置面板是近似物；主张建立在“调的是数学规则、改一条全台重算、环境本身是台面对象”三点上，但代理 B 把它列为方向二里最易被挑战的三件之一。
- **实验报告器**：未标首创，形态首创。NB 已有自动评分/诊断报告，非官方文案更称“自动生成标准实验报告”——如果后者属实且就是按操作记录拼的，主张即被推翻。
- **家长简报器**：未标首创，形态首创。DreamBox Family Dashboard + 手动布置复习作业已很接近，只差“自动简报 + 一键进复习清单”。
- **分享器**：功能已有，不标任何首创。Polypad / Desmos / GeoGebra 的分享功能在功能上已等价（场景变链接，对方打开即复现、可存副本继续改），只差“分享器本身是一件台面器材”这个形态。
