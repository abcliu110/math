现在器材最大的三个问题是：**(1) 删一个被绑定的器材会让整个台面崩溃、须重载（U01，新发现，唯一的崩溃级故障）；(2) 实验根本不是实验——141/152 个是 2 步“连线→读答案”模板，全库 0 个预测步（U02–U04）；(3) 合并器减法模式卡面上写着错误的等式“5 + 3 = 2”（U05，新发现，触发最常见）。**

### 最严重的新发现：U01——删绑定源，台面崩溃

完整证据链（合成人亲自在代码里核对过，行号为准）：

1. `case 'del'`（:306）：`delete E[a.id]; s.links=s.links.filter(...)`——**只删实体和连线，不碰 `s.binds`**。
2. `val()`（:353-356）：`const e=E[id]; … if(e.type==='num')`——对不存在的 id **无守卫**，`e.type` 直接抛 TypeError。
3. `evaluate` 的绑定校验（:390-391）：对每个仍有绑定指向它的实体，`valQ(b.from)`——若源已被删，这里抛错。
4. 调用链无任何 try/catch：`commit`（:577）→ `act`（:299）→ `syncBinds`（:293，`const Dd=evaluate(s)`）→ 抛错；`afterChange`（:588，`D=evaluate(S)`）、`track`（:594）、改名处理（:810）、缩放/顶点拖动（:842/:845）每次都重算重抛。
5. 后果：**删完那一下之后，台面冻住**——每次操作都抛错，`afterChange` 不跑、`render` 不跑；撤销快照在抛错前已算好但没入栈（:577-582 的 push 在 `act` 返回之后），不过 Ctrl+Z 恢复更早的快照仍可工作；重载一定恢复，因为悬空状态从未写入 localStorage（写存储也在 `afterChange` 里，抛错后没跑到）。
6. 触发条件极常见：任意实验里绑过属性的器材被删——删除是工具条/设置卡/Delete 键上的常规操作（:818/:823/:875），学生不需要做任何奇怪的事。

第二崩溃点：设置卡 `:794` 读 `S.entities[bd.from].name`——打开被删源的目标器材的卡片时同样抛错（但 `evaluate` 通常先抛到）。

修复只需三处之一即可根治（建议全做）：`case 'del'` 同时删掉以它为源/目标的 binds；`val()` 对不存在的 id 返回 null；`evaluate` 的绑定校验先判实体存在。
